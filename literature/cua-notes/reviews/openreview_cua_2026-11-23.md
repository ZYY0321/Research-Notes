# CUA / GUI Agent：OpenReview 审稿记录（2026-11-23）

这批只收公开审稿里能对上原文的投稿，用来看什么样的工作会被接收或拒绝。已从 Testing-Survey 2026-10-29 的 43 条里排除同论坛 id。分数和引文都来自 2026-11-23 对 `https://api2.openreview.net/notes/search` 的返回，没有用记忆补。

拉取方式：`notes?forum=<id>` 当天返回 403（ChallengeRequiredError），论坛网页同样 403。改为用投稿 note 上的 `Submission<编号>` 做 `group` 过滤，用检索词 `the`、`review`、`score` 取回该投稿下的 note，再按 note id 合并。`references?referent=` 返回空列表，看不到审稿旧版本，所以「rebuttal 有没有改分」只写审稿人或 meta-review 原文里写明的句子；没写就记未查到。

分数是 rating 字段里的数字，没有改写成口头档。这批里 ICLR 2026 见到 2/4/6/8，NeurIPS 2025 见到 4/5，COLM 见到 3–8。meta 原文若自己写了 BA/BR，表里照引，不另做对照表。

## 归纳

这节对照的是 `/tmp/rn/literature/cua-taste.md` 第三节（审稿人要什么），不是截断检测那条实验问题。下面每条都只来自这 50 条新记录。

### 录用时最常被认下的

1. **把「做完没有」拆开，或指出旧榜测不到的失败。** OpenApps 的 Reviewer_CTPq 写 "The paper identifies a key blind spot in existing agent benchmarks: reliability across app variations." Meta-Review 接着把它收成可复现的界面变化评测。Where Did It Go Wrong? 的 Decision 写 "lets the work move from ranking agents to diagnosing them: separating exploration-limited from execution-limited failures"。How to Train Your LLM Web Agent 的 Decision 写 "the first systematic analysis of compute allocation between supervised fine-tuning and reinforcement learning"。An Illusion of Progress? 的 Decision 写 "highlighting their capabilities and limitations"。AgentRewardBench 的 Decision 写 "a 1.3 k-trajectory benchmark to see how well LLM “judges” agree with humans on web-agent outcomes"。The Art of Building Verifiers for Computer Use Agents 的 Decision 把贡献写成 "reliable verification"，并点出和人工判断的一致性、假阳性下降。

2. **放出别人能接着用的数据、基准或环境，并且数字跟着上去。** Web-Shepherd 是 NeurIPS Spotlight，Decision 写步级评估 "outperforms GPT-4o in terms of accuracy by a large margin"，同时放出 WebPRM Collection（Decision 写 40K step-level preference pairs）和 WebRewardBench。Scaling Computer-Use Grounding via User Interface Decomposition and Synthesis 也是 Spotlight，Reviewer_iKhP 认的是 GUI grounding 这个瓶颈，以及 JEDI 这种大规模合成数据；Decision 写 OSWorld-G 有 564 条细标注。OpenApps 是 ICLR Oral，Meta-Review 写它轻、可扩展，能做大规模复现。RedTeamCUA 是另一篇 Oral，Meta-Review 写现有框架 "either lack isolated web environments or cannot evaluate OS-level harms"，这篇用混合沙箱测 "web-based injections trigger harmful OS actions"。

3. **新意落在界面操作自己的难点上。** GUI-Actor 的 Decision 写 "The approach is novel within GUI grounding"，认的是不再直接生成坐标。GUI-G1 的 Decision 写现有 R1-Zero 式训练会 "degraded performance, reward hacking, or overfitting"，改的是输入模板、框大小奖励和难度目标。GUI-Shift 的 Meta-Review 把核心写成用无标注轨迹做 K-step GUI Transition，避开昂贵的自然语言标注。The Art of Building Verifiers 的 Reviewer_ozbx 写验证难是因为 "screenshots, sometimes a11y trees, and the multi-step nature of these tasks"。

### 拒稿和撤稿时最常出现的

1. **被写成已知零件的拼装，或和同期 GUI 论文撞车。** Ferret-UI Lite 的 Meta-Review 写 "the main decision-driving concern is limited novelty"，并写成 "a well-executed compilation of known ingredients (SFT + RL, data mixture/curation, reward designs similar to prior GUI RL works, CoT prompting, zoom-in grounding)"。GAIA 的 Reviewer_JEcH 写 "appears somewhat incremental"，因为 critic 和 data flywheel "mainly combine existing elements such as Test-Time Scaling and iterative filtering"。Learning GUI Grounding with Spatial Reasoning from Visual Feedback 的 Meta-Review 写 "the AC recommend rejection"，理由是没有证明比已有裁剪方法好，"espacially GUI-ARP"（原文拼写）。GUI-Spotlight 的 Meta-Review 写 "The core idea and paradigm share similarity with previous approaches"，并写 "Lacking validation in GUI agent tasks"。DKRF 四条都是 4 分，Reviewer_Guzq 写组件 "appear closely aligned with existing paradigms in RAG-based agents"。CODA 被拒，没有查到 meta-review；Reviewer_gKdc 给了 6，同时写 "decoupled planner-executor design ... is well established"，Reviewer_JvNe 写 "Lack of Critical Baselines"。

2. **和同基座、未饱和的公开榜比，没有拉开；或者只在自己的榜上测。** MobileWizard 的 Reviewer_VG1Y 写 "The improvement on ScreenSpot-v2 is marginal. MobileWizard-7B achieves 93.0%, while its base model already reaches 92.4%"。V2P 撤稿，Reviewer_BMnm 写 "ScreenSpot-v2 is saturated with baselines already achieving >90%"。ReGUIDE 的 Meta-Review 写，不和 GTA-1、Aria-UI、UI-AGILE、GUI-G2 比，SOTA "were unsubstantiated or potentially misleading"。GUI-360° 的 Meta-Review 写 "Self-benchmark only; no out-of-distribution tests"。GUI-Spotlight 的 Meta-Review 还写比 GTA-1-7B 更差。GAIA 的 Meta-Review 把不公平对比写成一条：对照模型只用了 30k 子集，而 ICM 用了更大的 flywheel 数据，并且 "training data were drawn from the same benchmarks used for evaluation"。

3. **榜本身没有换来新认识，或打分方式站不住。** BrowserArena 的 Meta-Review 写 arena 式 Elo "is not fully correlated to the success of tasks"。GUI-360° 同一条 meta 写泛化结论没有外部验证。A3 撤稿，Reviewer_DsBE 写结果和已有榜上的模型排序对不上，"UI-TARS-1.5 and Qwen2.5-VL perform nearly the same here, despite large known differences"。这三条都不是「做了基准就会被拒」：OpenApps、macOSWorld、Where Did It Go Wrong? 也是基准，录用理由是测出了旧榜测不出的东西。

有一条 6 分不够保证录用。Learning GUI Grounding 是 6、6、4、4，meta 仍写建议拒。MobileWizard、BrowserArena、GUI-360° 也都有一条 6，结果是拒稿。反过来 Go-Browse 是 6、4、4、4，ComputerRL 是 6、4、4，都是 Poster。ComputerRL 的 Meta-Review 写 "All reviewers agree that the work makes a strong contribution by successfully scaling reinforcement learning to challenging desktop settings." 低分审稿人写算法新意有限，meta 仍把「把在线 RL 扩到真实桌面」当成贡献。

**被强化**

- Spotlight / Oral 仍是别人能用的东西，外加一个认识。这批的四篇是 OpenApps、RedTeamCUA、Web-Shepherd、Scaling Computer-Use Grounding。

Process based rewards have been well understood..."，Decision 仍接收，依据是超过 GPT-4o，加上数据集和评测基准。同期 GUI-PRA 撤稿，五条分是 2、2、2、4、4。Look Before You Leap 是事前 critic，NeurIPS Poster。GAIA 也是 critic，被拒。过不过不取决于名字里有没有 reward，取决于有没有被核过的资源，以及数字是不是在公平对比里拉开。

**新增**

- 自动判分能不能信，可以单独当贡献。The Art of Building Verifiers 的 Decision 写和人工判断的一致性、假阳性下降。AgentRewardBench 的 Decision 写 "the first to target LLM judges for web agents"。Web-Shepherd 放出 WebRewardBench 来评过程奖励模型。Enhancing GUI Agent with Uncertainty-Aware Self-Trained Evaluator 问的是训练轨迹噪不噪，Reviewer_3VNW 写 "proposing an efficient, cost-effective, and domain-adaptive evaluator"。
