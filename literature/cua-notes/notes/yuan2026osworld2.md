## 一段话介绍
OSWorld 第一代的任务短，强模型在后来的 OSWorld-Verified 上可以到八成以上。这篇把尺度拉到熟练的人大约要 1.6 小时的流程：邮件、银行、报销、报销规则还可能在做题途中被新消息改掉。环境用自托管网站，避免真实网站改版。评分先看最终环境状态上的检查点，开放式判断只用掉总分的 11.53%，而且单题不超过一半。最强设置仍只有两成题按二值完成标准做完，部分分大约五成五。作者看轨迹后的判断是：局部点击和写代码大多能做，丢的是约束、中途新信息、该问用户时却猜，以及做完不核对。

## 动机
§1 原句：

> While Claude Opus 4.8 reaches 83.5% on OSWorld-Verified, suggesting desktop computer use is largely solved, the tasks behind this number are short and narrow.

后半句他们写：这些题很少跨过一两个应用，奖励的是做完一段自包含操作。高分因此会把「端到端工作做完」的稀少盖住。83.5% 是他们引用的旧榜数字，不是本表测出来的。

## 方法（或资源构成）
108 题。人完成时间中位数约 1.6 小时，约是 OSWorld 1.0 两分钟中位数的 48 倍；69.6% 的题估计超过一小时（§2.2.1）。按指令，64.8% 的题至少要两个应用或服务；把实际跑起来用到的也算上，是 75.9%，平均 2.44 个（表 1）。大约九成题来自内部标注员从教程、文档和日常工作改出来的流程，合成提议只当点子，因为假文件、浅流程和奖励漏洞太多（§2.1.1）。

环境在真实桌面上加自托管服务：邮箱、银行、团队聊天等 31 个网站，外加原来的办公软件和一批专业工具。每题有一份连贯的用户资料。需要问人时，模拟用户只根据这道题预先写好的知识回答（§2.1.2）。有的题会在执行中途注入邮件或聊天，让任务状态变掉。

评分：最终状态对所有检查点打分，不要求检查点按固定顺序出现，平均 27.25 个检查点。功能检查优先；图像、邮件措辞这类用带二元清单的模型评判，每条提示要在标好的正确状态和易混的错误状态上都稳，才采纳。模型分占总分 11.53%，单题不超过 50%（§2.1.3）。

质量保证包括生成单元测试、人再做一遍、前沿模型轨迹，用来查奖励漏洞和漏判。正文没有把这三关的通过率列成一张表。

教学例子（来自图 1 的报销流程，不是我编的）：要按一份教程在旧报销系统里提交，金额得从杂乱收据里抽出，还要到邮箱和银行记录里对上，中途新邮件会改约束，员工信息在旧报告里，对不上时要问用户。

## 实验
- 表 3 是 500 步主结果，108 题平均。批量工具：Claude Opus 4.8 二值 20.6%、部分分 54.8%，每题约 72.4 美元、481.8 次工具调用、输出约 224K token、103 步。同表 GPT-5.5 二值 13.0%、部分分 49.5%，工具调用 149.8，输出 37.1K。单步动作的 Opus 4.8 是 18.5% / 49.3%。正文另写，这些模型在 OSWorld 1.0 上的二值准确率在 79–83%。
- §4.1.2：恢复和修补加在一起，各模型都低于预算的 7%。Opus 4.7 的恢复不到 2%、修补大约 3%。这是轨迹活动分类，不是自动指标。
- §4.3：人觉得难的题里，76.3% 对模型也难；人觉得容易的题里，只有 11.1% 对模型也容易，44.4% 仍然难。阈值是示意性的（部分分 >0.7 / 0.3–0.7 / <0.3）。
- §4.4 的失败不是「点不准」。任务 052：弹窗在动，截图里关闭按钮的坐标到点击时已经过期。任务 035：聊天里的新规则到了，计划还停在旧规则。任务 024：该用 ASK_USER 要缺失材料时，较弱的轨迹直接交了不完整申请。
- §4.2 安全是旁路分析：GPT-5.5 和 Opus 4.7 共 216 条轨迹里，大约 14% 的任务抽取隐藏应用状态，大约 33% 绕过用户看得见的界面。原文用 about。
- 能支持的：在这 108 题、这套检查点下，文中最强配置的二值完成远低于他们引用的 OSWorld-Verified 高分；部分分明显高于二值分，说明很多题做了一截。
- 支持不了的：20.6% 不能直接和 OSWorld 1.0 的 12% 或后来的 80% 相减当成「能力退步」。题的长度、应用和评分单位都变了。作者自己的对照是同一批前沿模型在两套题上的位置，不是同一个检查器。

## 局限
- 作者承认的（§6）：职业和领域没有盖全，现象分析和职业分析是诊断不是普查。扩题很贵。总分会随题组搭配和智能体随机性变。自托管环境里的固定痕迹，以后可能被针对。
- 我看到的：模拟用户和中途注入是这套基准的新现象，正文把模拟用户的单独验证放在附录 E.1，我没有把附录里的一致率当成主证据。11.53% 的模型分被限制住了，但「邮件是否得体」这种检查点仍可能带进裁判偏差。安全比例是约数，而且只覆盖两个模型。

## 品味判断（本模板最重要的一节）
1. 问题从旧榜单饱和长出来：引言直接用 83.5% 当靶子。换一个没有自托管网站和百小时标注的团队，做不出这 108 题；换一个会读轨迹的团队，可以在现有长轨迹里先数「中途信息被忽略」和「点击落在过期坐标」，不必先造完整基准。
2. 表 3 的 20.6 对 54.8 最能说服审稿人，因为它同时反对两句套话：一句是「高分说明做完了」，另一句是「低分说明完全没动」。§4.4 的过期点击是最好的单例。
3. 可模仿的实验：不要先造 100 道新题。从已有轨迹里抽「动作坐标对的是前一帧」和「约束出现在中途消息里」两类，每类 20 条，由人标。若两类占失败的大头，再决定值不值得做动态环境和模拟用户。评分上同时报二值完成和检查点部分分。
4. OSWorld-Pro（2609.24890）也在做过程分，用的是逐步子目标和 LLM 裁判，不是最终状态检查点。GraceBench、GUITAR（已收）在手机上拆过程。这篇没有和它们比过程指标，它的对照对象是 OSWorld 自己的短任务高分。

## 和 CUA 评测 / 换路鲁棒性的关系（公开层面）
过期点击就是「动作还没生效，画面已经变了」。只看最终文件对不对，会把这种时机错误和「从来没找到按钮」记成同一种失败。换布局之后若元素还在动，需要动作前后的同一画面证据，而不是只比最终检查点。
