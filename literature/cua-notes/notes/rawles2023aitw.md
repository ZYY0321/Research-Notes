## 一段话介绍
AitW 收集的是人在模拟器里按自然语言指令操作安卓手机：屏幕、手势、指令都有。规模比当时的手机数据集大一个数量级以上。动作不是「点某个按钮 id」，而是具体手势，包括在轮播上横滑这种必须给出位置的操作。数据盖了安卓 10 到 13、Pixel 2 XL 到 Pixel 6。作者训练了一个 Transformer 行为克隆和一个把屏幕收成 HTML 的 PaLM 2 提示代理，用离线的动作匹配打分，因为在线环境不给奖励。

## 动机
> "This dataset poses a new challenge: actions available through the user interface must be inferred from their visual appearance."（摘要）

他们还把动作空间从「点 UI 元素」换成精确手势。理由是真实界面里，很多操作对不上一个干净的控件框，例如轮播的横滑（摘要）。评测上的动机写在 §5.2：在线看人盯着代理做完全程又贵又容易看走眼，所以要一个便宜、可重复的离线分数，并承认它不准。

## 方法（或资源构成）
采集分两段（图 1）：人先在模拟器里把任务做完；再用事后转写（hindsight relabeling）把轨迹切成更短的单步指令。应用状态会随机化，逼人演示「先导航到那个页面」而不只是最后一下。

arXiv HTML 表 2 的构成：

| 子集 | 轨迹数 | 屏幕数 | 指令数 |
|---|---|---|---|
| GoogleApps | 625,542 | 4,903,601 | 306 |
| Install | 25,760 | 250,058 | 688 |
| WebShopping | 28,061 | 365,253 | 13,473 |
| General | 9,476 | 85,413 | 545 |
| Single | 26,303 | 85,668 | 15,366 |
| 合计 | 715,142 | 5,689,993 | 30,378 |

标准划分是每个子集按轨迹 80/10/10。另有四种泛化：没见过的安卓 13、指令模板里没见过的主语、没见过的动词、没见过的应用域（§4）。

动作匹配（§5.2）：动作类型必须相同。点击算对，如果落在对方 14% 屏幕距离以内，或者落在同一个检测框里（匹配时把框放到 240%）。滑动只比主轴是横还是竖。部分匹配 = 正确动作数 / 轨迹长度；完全匹配 = 部分匹配恰好为 1。

行为克隆吃 OCR 和检测出的图标，不吃原始像素。PaLM 2 代理只能点检测出的元素，点不了任意坐标。

## 实验
- 表 4 报的是部分匹配，五个划分的列是 Standard、Version、Subject、Verb、Domain。BC-history：73.1、63.2、68.5、70.4、59.7。BC-single 标准划分 68.7，域划分 52.2。BC 在全测试集上评，置信区间正文写小于 0.1%。
- LLM 因为贵，每个划分随机抽 288 条。表 4 里 LLM 的数是带置信区间的，PDF 抽取把区间和数字缠在一起，这里不引用那些点估计。正文另给了一句干净的：标准测试集上，有 33% 的轨迹含「只给了坐标、对不上检测元素」的点击，这种动作 LLM 代理做不出；在它做得出的动作上，LLM-hist-5-CoT 部分匹配 58%（§5.3）。
- 图 3 用一小部分 GoogleApps 轨迹请人做在线判断。正文说部分匹配和人判的「真完全成功」相关，自动的完全匹配是下界，因为另一条合法路径（系统返回键和应用内返回键）会被判成不同（§5.2）。
- 能支持的结论：随机切分上，带两步历史的行为克隆大约七成步骤能对上演示；换应用域掉到六成附近；只靠检测框的 LLM 会系统性错过坐标型动作。支持不了的：73.1 不是任务成功率。14% 屏幕距离和 240% 的框都偏松，部分匹配高不等于用户觉得做完了。

## 局限
- 作者承认的（§6.1）：标注员不能代表全球用户；内容是英文网页；人用鼠标键盘而不是手指，操作习惯会变；只有手机，没有平板。§7 补了一条：一件事常常有多种做法，未来的评测应该放过那些做对了但不匹配演示的动作。
- 我看到的：GoogleApps 占 625,542 / 715,142，多样性没有「71 万条」这五个字看上去那么大。指令数在 GoogleApps 只有 306 条，大量轨迹是同一说法的重复。SeeClick 后来改成按指令切分，就是在躲这个泄漏；那是后话，但这篇的标准划分确实按轨迹随机切，测试指令会在训练里出现。

## 品味判断（本模板最重要的一节）
1. 问题来自数据空白，不是来自一个新损失。换一个有众包和安卓模拟器的实验室可以做，贵在规模和组织方式：四个安卓版本、八种分辨率、以及按动词/主语模板切，而不是只丢一个 zip。
2. 最能说服审稿人的是表 1 的规模对比加上表 4 的五列。规模说明「以前的数据不够做这个实验」，五列说明「换版本、换说法、换应用，掉分的方式不一样」。只报 71 万条，没有这五列，就会变成纯资源海报。
3. 可模仿的实验：收集轨迹时故意随机初始状态，再按「没见过的说法 / 没见过的平台版本 / 没见过的应用」各留一个测试集，用同一个模型报五列。同时用人判一个小子集，看自动分和人判是否同向（他们的图 3）。自动分的匹配规则（距离、框放大倍数）要写进正文，不然后人无法知道 73 分有多松。
4. 它没有比的：没有像素输入的多模态模型作为主结果（§7 把这件事留给以后）；没有在线任务成功率作为主表。DigiRL 之后的在线强化学习使用了这份数据，但那不是这篇能声称的。

## 和 CUA 评测 / 换路鲁棒性的关系（公开层面）
§5.2 和 §7 已经把换路写成指标缺陷：返回键的两种点法功能相同，距离匹配却判错。部分匹配又会把「大部分步骤像演示」说成较高分。读 AitW 上的数字时，要先问清是部分匹配、完全匹配，还是人判的任务成功。
