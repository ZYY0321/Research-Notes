# SeeAct：GPT-4V 会做网页任务，前提是有人替它把计划落到正确的元素上

## 一段话介绍
SeeAct 用 GPT-4V 看渲染后的网页截图，先用文字说出下一步打算点什么，再把这句话对到 HTML 元素和操作（点击、输入、选择）。评测落在 Mind2Web 上，并加了一种当时少见的设定：用浏览器在活的网站上把整条任务跑完，由人看着判断是否做成。人替它点中元素时，90 题里做成 51.1%；模型自己选元素时降到 37.8%。作者据此说，通用网页智能体的计划能力已经有了，卡在细粒度定位。

## 动机
> "HTML code is noisier than the rendered visuals and has a lower information density."（§1）

文中举例：图 1 那张截图有 423 个 HTML 元素，GPT-2 分词要 186,490 个文本 token，GPT-4V 的视觉 token 只要 1,445 个（§1）。所以他们改成先看图。真正的发现不是「看图更好」，而是看图之后计划对了、手还是点歪。

## 方法（或资源构成）
输入是任务说明、当前网页截图、以及已知的 HTML 元素和它们在画面上的位置。两步：LMM 先产生文字计划；再做 action grounding，选出元素和操作。他们比了四种定位：元素属性、在图上画框编号（类似 set-of-mark）、把元素列成文本选项（Choice）、以及人工把计划对到正确元素（Oracle）（§2.3，表 3 题注）。

离线指标沿用 Mind2Web：元素准确率、操作 F1、步成功率；整任务成功要求每一步都对，所以离线整任务分很低。在线评测用 Playwright 把动作变成浏览器事件，人盯着可能改动真实状态的操作，并判断任务是否完成。为了能和离线比，他们只改写了过期的时间（比如机票日期），在三个测试划分上共 90 题（§4.2）。网站失效的题从对应划分重抽。

具体例子：计划写「去 iPhone 分类」，定位要找到对应按钮并执行 CLICK。人工定位就是人来完成这后半步。

## 实验
- 表 3 是每个划分 30 题的子集，报的是步成功率。人工定位 61.9 / 65.0 / 62.1（cross-task / website / domain）。文本选项 Choice 是 39.1 / 32.7 / 42.0。在图上画框只有 20.3 / 13.9 / 23.7。属性法 16.1 / 12.1 / 19.0。画框失败的原因作者写了：模型描述的元素常常是对的，但对不上图里的编号，也就是空间位置幻觉。
- 表 4 是整任务成功率，分母是这 90 题，不是 Mind2Web 全测试集。在线：FLAN-T5-XL 8.9，GPT-4 13.3，SeeAct Choice 37.8，SeeAct Oracle 51.1。离线零容错时 Oracle 只有 13.3，允许错一步也只有 27.8。正文的解释是：离线只存了一条参考路径，活网站上另有走法。
- 能支持的结论：在这 90 题、人在回路的在线设定里，把定位换成人工，整任务成功率从 37.8 到 51.1，定位是可见的瓶颈；离线整任务分会低估。支持不了的：不能把 51.1 说成 Mind2Web 全量成绩；Choice 仍然要 HTML，不是纯视觉。
- 结论把在线人工定位写成 “a success rate of 50%”，表 4 是 51.1。结论又说最好的自动定位比 oracle 低 20–25 个百分点。表 3 上 Choice 和 Oracle 的差，我用两行相减是 22.8、32.3、20.1。Cross-Website 那一列大于 25。结论是粗数，表是细数。

## 局限
- 作者承认的（§6）：细粒度视觉定位仍是主要难点；在线和离线不一致，因为同一任务有多条计划。影响声明（§7）：在线实验里他们人工拦下了可能有害的动作；实验限于非登录任务（在线工具那一段）。
- 我看到的：90 题、每个划分再抽 30 题，都是子集。人工定位本身用了标注员，51.1 是「计划对了、手是人的」上限，不是一个可部署系统。画框编号这种后来很流行的做法，在这篇里是差的方法，但分母只有 30 题。

## 品味判断（本模板最重要的一节）
1. 问题是做着实验撞上的：文字计划看起来对，一接地就掉一截。换一个能调用 GPT-4V、又能改 Mind2Web 的团队可以做。难复制的是在线那一半：要人看着真网站，还要处理网站改版。
2. 最能说服人的是表 4 那一列在线数字：同一模型，只把定位从自动换成人工，37.8 到 51.1，而纯文本 GPT-4 停在 13.3。一句话就把「会不会做」拆成了「会不会看」和「点不点得中」。
3. 可模仿的实验：挑一个已有基准的一小段任务，固定计划模型，只替换落地方式（人工 / 结构候选 / 纯坐标），同时报离线单路径分和在线整任务分。两个分的差就是「换路被误判」的大小。不要只报一个总成功率。
4. 它没有比的：没有和随后专门做定位预训练的 SeeClick 在同一在线协议上比；CogAgent 被放进相关工作，不是这张在线表的对手。安全拦截是人工的，没有自动化的有害动作检测。

## 和 CUA 评测 / 换路鲁棒性的关系（公开层面）
这篇把「离线参考路径判失败、在线其实做成了」写成了实测：表 4 里 Oracle 离线零容错 13.3，在线 51.1。换路鲁棒性如果还用单条参考轨迹打分，会把这截差当成模型不行。
