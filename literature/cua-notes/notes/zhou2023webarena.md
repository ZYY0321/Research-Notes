## 一段话介绍
WebArena 把电商、论坛、代码协作、内容管理四类真实开源网站打包成 Docker 镜像（带 gym 接口），数据从真实对应站点导入。另外放了地图、计算器、便签等工具和维基百科、使用手册等知识站点。任务是 812 条高层自然语言指令，例如「告诉我 2023 年 3 月在食品上花了多少钱」，成功不看动作像不像，而是用验证器检查网站状态或答案。最强的 GPT-4 智能体只做成 14.41%，人是 78.24%。

## 动机
> "Current environments for evaluate agents tend to over-simplify real-world situations."（§1，原文如此）

作者列了三个问题（§1）：环境简化导致任务多样性不足；有的环境是静态资源，智能体只能访问采集时缓存过的状态；评估只比对动作文本，不管执行是否功能正确、不考虑替代解法。

## 方法（或资源构成）
- **环境**（§2）：4 个自部署网站（购物、论坛、协作开发、内容管理），状态转移是确定的，由网站本身实现。独立于线上网站，所以可复现。
- **任务**（§3）：241 个模板、812 条具体指令（平均每个模板 3.3 条，§3.1），由作者按标注指南撰写，每条是高层意图。分三类：信息查询、站内导航、内容与配置操作。另设「不可完成任务」，期望智能体回答 N/A，用来看它会不会编造答案（§3.1）。
- **怎么判成功**（§3.2）：信息类用 exact_match、must_include、fuzzy_match（后者用 gpt-4-0613 判语义是否等价）比对标注答案；操作类用程序检查网站状态是否满足要求（Figure 1 里的 check_repo、check_readme、check_answer）。
- **基线**（§4）：少样本 in-context 的 LLM 智能体，观察空间是带元素 ID 的无障碍树，例如 `click [1582]` 点「加入购物车」。
- **一个具体例子**（Figure 1）：「创建名为 NolanFans 的仓库，在 README 里列出诺兰的奥斯卡获奖电影」。验证器去检查仓库和 README 内容，哪怕智能体点击的路径与参考不同也算成功。

## 实验
- **想回答什么**：当时最强的 LLM 在这个环境里能做到什么程度？推理（CoT）和「不可完成」提示各有多大影响？
- **主结果**（Table 2，端到端成功率 SR，%）：

| CoT | UA 提示 | 模型 | SR | 不可完成任务上的 SR_UA |
|---|---|---|---|---|
| ✓ | ✓ | TEXT-BISON-001 | 5.05 | 27.78 |
| ✓ | ✓ | GPT-3.5 | 8.75 | 58.33 |
| ✓ | ✓ | GPT-4 | 11.70 | 77.78 |
| ✓ | ✗ | GPT-4 | 14.41 | 44.44 |
| - | ✓ | 人类 | 78.24 | 100.00 |

- **分析**（§5.1）：
  - GPT-4 把 54.9% 的可完成任务误判为不可完成。去掉 UA 提示后，整体 SR 从 11.70 升到 14.41，但识别不可完成任务的能力从 77.78 降到 44.44。一句提示就能让结果差几个点。
  - 在「至少成功过一次」的 61 个模板里，GPT-4 只在 4 个模板上达到 100%，说明同模板不同变体难度不同（如「fork metaseq」与「fork 所有 Facebook 仓库」）。
- **能支持的结论**：当时的 LLM 离人类很远；指令措辞对智能体行为影响大。
- **支持不了的结论**：作者提出「缺少主动探索和失败恢复」是原因（§1，原文是 hypothesize），文中没有做干预实验验证。

## 局限
- **作者承认的**：主文里没有找到专门的局限节，结论只说需要更强的鲁棒性（§7）。附录没读。
- **我看到的**：
  - 任务由作者自己写，812 条来自 241 个模板，模板内变体共享推理结构，实际独立难度点少于 812。
  - 只有文本观察（无障碍树），不测视觉；后来的 VisualWebArena 补上了这一块。
  - 对「不可完成」的设计很好，但 N/A 子集只有少数几个任务（原文给的是比例 SR_UA，没写绝对个数，我没去数）。

## 品味判断
1. **问题怎么发现的？** 对比当时的环境，找出「简化、静态、只比文本」三处硬伤，逐条补上。其他团队也能想到，难在把四类网站的数据、Docker 和验证器全做完；这是纯工程量门槛。
2. **最能说服审稿人**（我的判断）：摘要里同时放 14.41% 与 78.24% 两个数字，一句话说清「差距很大且可复现」。
3. **可模仿**：评测做成「状态检查而非轨迹对比」；顺手放一小批不可完成任务，用来测编造倾向；用一个提示开关做消融（UA hint），把「模型能力」与「提示设计」分开。
4. **没比的工作**：没有视觉模型的对照；也没有测同一任务多次运行的方差（Table 2 单次数字）。

## 和 CUA 评测 / 换路鲁棒性的关系（公开层面）
评估看最终状态，所以天然容许不同路径，这是「换路」之后还能判成功的前提；但它没有刻意构造换路扰动，只是任务模板内变体多。
