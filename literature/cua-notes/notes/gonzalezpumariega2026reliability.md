## 一段话介绍
榜单通常报一次运行或多次里取最好的那次。这篇在 OSWorld 上把同一题连做几次，看是不是每次都成功。他们用的 Pass^k 估计的是「k 次全部成功」的概率，和代码界常见的 pass@k（k 次里至少成功一次）方向相反。图 1 的文字写：Agent S3 加 GPT-5，Pass@10 大约 78%，Pass^10 大约 36%。更硬的数字在表里：即便温度设为 0，Pass^1 到 Pass^3 仍然掉一截；把壁纸、鼠标大小、停靠栏位置、图标主题、时区换成不影响任务对错的另一套，Claude 的稳定成功题显著变少。

## 动机
§1 原句：

> if an agent can succeed at a task once, what prevents it from doing so reliably?

他们把执行拆成三块：题目怎么写、智能体怎么做决定、执行时的随机性。三块各做一个干预，而不是只报一个方差。

## 方法（或资源构成）
每题执行 n 次，成功次数记为 c_x。Pass^1 是平均成功率 c_x/n。Pass^n 是 n 次全对的题的比例。比较两种设置时，McNemar 只数「从不稳定变成三次全对」和「从三次全对变成不稳定」的题，统计量是 b−c。Wilcoxon 看每题成功次数的增减，能抓住 1 次变成 2 次这种还没到全对的变化。

随机性实验有两档（§3.1）：一是温度 0 加 batch-invariant 推理；二是另外生成一份高层计划，以后几次都跟着这份计划走。外观实验（§3.2，附录 F 表 5）改的是壁纸、光标（24/48/16 px）、停靠栏（左/下/右）、图标主题、时区。作者写这些都不改变应用功能和任务对错。扰动条件是：三次里第一次用原环境，后两次用两套外观。

指令实验把任务说明改写成更贴近评分脚本的说法，并避免把题变成送分题（§4.1）。计划实验从过去轨迹里抽计划再跑，作者写明用了真值来标成功，以免 judge 噪声混进来（§5.1）。

模型包括 GPT-5、Claude Sonnet 4.6、Kimi 2.5，以及 Qwen-3VL-8B、OpenCUA、UI-TARS-1.5-7B。有现成脚本的用 OSWorld 默认，否则套 Agent S3，表里标 (S3)。

## 实验
- 表 1 问温度 0 能不能让开源模型更稳。Qwen 的 b−c = −20，OpenCUA = +20，UI-TARS-1.5 = +19，都标了显著。三个模型的 Pass^3 都低于 Pass^1。固定高层计划能缓和 Qwen 的退步（b−c 回到 −1），相对随机基线并没有普遍变好。
- 表 2 问外观。Claude 基线 Pass^1 0.702、Pass^3 0.612，扰动后 0.675 和 0.557，b−c = −20，Δc_x = −0.080，带星号。GPT-5（S3）b−c = −10，未标显著。Kimi 的 Pass^3 本来就低（0.357），扰动后几乎不动。
- 表 3、表 4 是改指令和多轮计划。澄清指令后多个模型的 Pass^1 和 Pass^3 上升。把上一轮反馈写进计划，GPT-5 和 Kimi 上升，Claude 在第一轮显著变差（b−c = −15）。作者猜测和 Claude 偏爱代码解法、行为 judge 看漏环境变化有关，这是解释，不是单独的测量。
- 能支持的：同一题的三次成功率低于单次平均；关掉采样不能在所有模型上换来稳定；不影响对错的外观变化，仍会让 Claude 的「三次全对」变少。
- 支持不了的：不能把 b−c = −20 读成「有 20 道题变失败」。b 是变稳的题数，c 是变不稳的题数，−20 是两者之差。总题数正文实验节没有写出，所以百分比无法从这一个数还原。

## 局限
- 作者没有单独的 Limitations 节。§6 承认：确定性解码不能在所有模型上提高可靠度；固定策略能稳住，但不能稳定超过随机基线；从过去轨迹抽计划，收益看模型和计划质量，Claude 会变差。
- 我看到的：OSWorld 用了多少题，§2.3 和 §3 都没写。图 1 的 78% 和 36% 是图注里的大约数。计划迭代依赖真值标签，部署时没有这份标签。外观扰动只覆盖附录 F 那五类桌面属性。

## 品味判断（本模板最重要的一节）
1. 问题来自榜单只报一次或报最好的一次。做这件事需要能重复重置的环境和成对统计，不需要新模型。换一个有 OSWorld 账号和重置脚本的团队可以做核心对照。
2. 表 2 最有力：任务对错按作者的设定没变，稳定成功的题却净减少 20。图 1 的 Pass@10 对 Pass^10 适合放进引言，数字是大约值。
3. 可模仿的实验：每题跑 3 次，主表同时给 Pass^1 和 Pass^3。再做一组只改壁纸、光标、停靠栏的重复，任务检查脚本保持原样。若 Pass^3 掉了而检查脚本没改，不可靠就来自执行，不是题目变了。
4. 他们没有和「盲重放」（D'Oro 等，2605.08261）对打。重放问的是静态环境能不能背答案；这篇问的是看屏幕的策略自己稳不稳。两篇合在一起，才把「环境不变」和「策略乱跳」分开。

## 和 CUA 评测 / 换路鲁棒性的关系（公开层面）
换路或改界面之后只跑一轮，Pass^1 的涨跌会把「这题本来就时好时坏」算进去。外观级的界面变化已经能让三次全对变少，所以换布局之后的掉分，要有一组已知不影响任务对错的对照，才能归到布局语义。
