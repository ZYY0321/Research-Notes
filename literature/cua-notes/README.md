# CUA 文献笔记：规范（子 agent 必读）

## 目的
积累「好 CUA / GUI Agent 论文长什么样」的判断力（taste），不是做综述。两类材料：
- **A 经典好文**：已被会议接收、被广泛使用或引用的代表作，回答「为什么它好」。
- **B 近期热点**（2026-06 至今，arXiv 号 26xx）：回答「现在大家在争什么、哪些问题还空着」。

读者是做 CUA 评测与换路鲁棒性研究的研究生，要的是：它怎么发现问题、怎么论证、证据够不够硬，以及我们能偷什么写法。

## 硬规则
1. **每篇必须打开原文**（arXiv abs + PDF / HTML）。读不到全文就标 `仅摘要`，不要写方法和数字。
2. **数字、原句必须来自原文**，写明表号 / 节号 / 页码。不确定就写「未核实」，不要补。
3. **venue 要核实**：会议接收（OpenReview / 官网 / ACL Anthology）才写会议名；否则写 `arXiv 预印本`。不确定写 UNVERIFIED。
4. arXiv 号要真实打开过。**打不开的链接不收**；不要凭记忆编号。
5. 不写公司数据，不写我们没发表的想法。「和我们的关系」只写公开论文层面的可借鉴点。
6. 中文，口语，能讲给外行听。术语第一次出现用白话解释。不要 AI 腔开场（「值得注意的是」「本文开创性地」）、不要对仗排比、不要谄媚拔高；少用否定句，直接写看到了什么。
7. 单篇精读控制在 15 分钟；读不动的降级为只填大表一行。

## 每篇产出两样东西
### 1. 单篇笔记 `notes/<第一作者小写><年份><关键词小写>.md`（A 类和 B 类中最值得读的 A 级才写，每人 4–6 篇）
按 `_template.md`。

### 2. 大表一行（所有收进来的篇都要有）
写进你自己负责的 `rows/<你的主题代号>.md`，列固定为：

| 日期/venue | 论文 | 问题（一句话） | 它检查了什么默认假设 | 发现问题的方式 | 解决方式 | 最强证据（数字+表号） | 作者承认的局限 | 我看到的没解决点 | 品味 | 可模仿的一点 | 读深度 |

品味评分：
- **A 值得模仿**：问题新、证据硬、结论会改变别人做法。
- **B 有一个点可借**：整体平常，但有一个具体做法值得拿。
- **C 跟风**：换名字、小改进、证据弱。写出 C 的理由，这和 A 一样有价值。
