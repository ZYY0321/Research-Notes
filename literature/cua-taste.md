# CUA 文献品味

## 一、现在大家在做什么（2026-11）

| 问题 | 风向 | 代表工作 | 还能不能进 |
|---|---|---|---|
| 榜单饱和后怎么测得更难 | 更长、跨应用、要追问用户、混用工具 | OSWorld 2.0、MobileWorld | 新榜单门槛高，要有新认识 |
| 成功率太粗，要看过程 | 从「完没完成」转向「怎么失败的」 | GraceBench、GUITAR、AGMem | 正在变热，诊断类已有几篇 |
| 结果到底能不能信 | 查答案有没有依据、完成声明是否属实 | EVIDENT、Done Is Not Correct | 热，GUI 上还不多 |
| 动作生效了吗 | 动作后核验、失败后恢复 | VeriGUI | 核验加训练已有人做，要找新切口 |
| 结构树和画面对不上 | 成对干预，看模型信哪个通道 | Do GUI Agents Believe Their Eyes | 诊断有了，缓解方法成本还高 |
| 训练卡在奖励上 | 过程奖励、状态锚点、在线 RL | GUI-Shepherd、GSAR、UI-TARS-2 | 拥挤，小改奖励容易被说成换名 |
| GUI 和工具混用 | 混合动作空间 | UI-TARS-2、MobileWorld、UltraCUA | 已拥挤，只适合当分析维度 |
| 自动造环境和任务 | 模型自己出题、写验证器 | SPADE、GSAR | 大厂在做，资源门槛高 |

## 二、好文章怎么发现问题

1. **指出大家默认但没检查的假设。** Believe Their Eyes 问的是「模型的判断到底来自像素还是结构」，用成对干预直接测。
2. **把一个粗指标拆开。** GraceBench 把成功率拆成偏离、停滞、恢复；EVIDENT 把成功拆成有依据和无依据。
3. **从榜单的异常里找问题。** MobileWorld 的出发点是 AndroidWorld 已超过 90%，旧榜单区分不出模型了。
4. **用可控干预得到因果证据。** 比观察日志更有说服力。
5. **结论能让别人改变做法。** 好的发现会告诉读者下次该怎么测、怎么训。

## 三、好文章怎么解决问题

AI 会议的公开审稿（Testing-Survey `reviews/`，43 条投稿记录，样本小）显示：

- Spotlight 和 Oral 几乎都是**社区能直接用的开放资源 + 一个新认识**，例如 OS-Atlas、AgentTrek、OpenCUA、ScaleCUA。
- 审稿人反复要三样：在公开榜单上和同一基座比、证明数据真的让模型变好、新意落在 GUI 本身的难点上。
- 常被说成「换了名字」的做法：SFT 后接 RLVR、过程奖励模型、规划—执行—反思、先探索后写指令。

## 四、读一篇论文时记什么

每篇只填这一行，超过 5 分钟就放弃细读：

| 字段 | 写什么 |
|---|---|
| 日期 / 来源 | arXiv 号或会议 |
| 问题 | 一句话 |
| 默认假设 | 它推翻或检查了大家的什么默认看法 |
| 发现问题的方式 | 干预、拆指标、榜单异常、失败分析…… |
| 解决方式 | 资源、方法、训练、诊断 |
| 最强证据 | 一个数字或一张表 |
| 没解决的 | 作者承认的局限 + 我看到的 |
| 品味评分 | A 值得模仿 / B 有一个点可借 / C 跟风 |
| 可模仿的一点 | 一句话 |

## 六、省额度的积累方法

用便宜的模型或其他 AI 每周跑一次，把下面这段发给它。**它只负责收集和填表，判断留给你和主窗口。**

```text
检索最近 7 天 arXiv cs.AI、cs.CL、cs.CV、cs.HC、cs.SE 中关于 computer-use agent、GUI agent、
mobile agent、desktop agent、agent benchmark、agent verification 的论文。
先按标题和摘要筛到最多 10 篇，优先选：有公开榜单或开放资源、指出了新的失败现象、
做了可控干预、来自活跃团队。
每篇打开原文，按下面字段输出一行 Markdown 表格：
日期 | 论文链接 | 问题 | 它检查了什么默认假设 | 发现问题的方式 | 解决方式 |
最强证据（数字必须来自原文，并写明表号或节号） | 作者承认的局限 | A/B/C | 可模仿的一点。
看不到全文的标「仅摘要」，不要猜。最后用三句话写本周风向：什么变热了、什么已拥挤、
有什么问题还没人做。
```

**每周的用法：** 把结果贴进第五节 → 花 10 分钟把 A 类论文读一遍 → 第一节的风向有变化就改一行。
