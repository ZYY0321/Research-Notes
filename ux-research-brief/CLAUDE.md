# 给远程 Claude Code 的工作规则

你在一台**不能做实验**的机器上读这个仓库。你没有鸿蒙真机、没有 macOS 虚拟机、没有 45GB 数据，也不要调付费 API。你的价值是：**拿账本互相质证、把口述变成实验卡、写论文和汇报段落、复核文献划界、找出没来源的数字、提醒哪条线卡住了。**

**只读 `ux-research-brief/` 这个目录。** 同仓库其他目录（个人规划、其他项目）与本研究无关，不要引用、不要总结、不要写进任何成稿。

开始之前按顺序读：`STATE.md` → `CLAIMS.md` → `numbers.csv`。其余按需。

## 硬规则

1. **数字必须引用 `numbers.csv` 的 id。** 没有 id 的数字一律写成「待核」，不许进成稿。
2. **不许升级证据等级。** 五级：真值 / 规则扫描 / 存档重判 / 模型标签 / 单例。模型标签不能写成真值，存档重判不能写成留出集，单例不能写成普遍现象。用户的话跳级了，先指出，再写。
3. **看 `numbers.csv` 最后一列「禁止写法」。** 例如不要写「静态准确率 100%」「吻合率 90%」「复现了 8 个工具」「布局树不可靠」。
4. **口径冲突就停下来问**，不许自己挑一个（冲突清单见 `evidence/口径矛盾清单.md`）。
5. **写作时「发现」是主句，「方法」是宾语。** 先说看到了什么、机制是什么，再说我们的做法。
6. **汇报对象是软件工程背景的导师**：他要的是机理性、可被推翻的发现，不是工作量清单。不要把训练、轨迹规模当主角。
7. 引用文献前对照 `related/` 里的划界表；三张表口径不同，见 `related/README.md`。

## 你做不到、也别假装做到的事

- 不要说「已经在真机上验证」。仓库里的数字都是别人（她）跑出来、写下来的，你只能核对一致性。
- 不要凭空补数据、补实验结果。要补，就写成「实验卡」放进 `experiments/`，状态标「未开始」。

## 研究主线（一句话）

当观察通道不完备（布局树 / AX 树有盲区）、动作可能静默失败时，系统怎样靠**阳性对照 / 独立核验通道**先确认「状态读对了、动作真生效了」，再下结论。

## 范围提醒

- 这个仓库只讲实验室口径下的研究。不要在任何文件里写求职、个人规划相关内容。
- 密钥、华为原始数据、CUA 原始轨迹不在这里，见 `NEVER.md`。
