# 研究方向与进展汇报：四个方向、一条主线

> 汇报对象：实验室导师与全组｜内容：已做的四个方向、工作量、现象、认知演进、既定主攻、论文架构与排期、请导师拍板的事项
> 证据等级：**【真值】** 人工标注或文件夹标签｜**【规则扫描】** 脚本机械统计｜**【模型标签】** 模型判定，未经人工复核｜**【单例】** 一两个例子｜**【存档重判】** 开发期存档上重放，不是留出集

## 0. 一页摘要

**一条主线。** 当观察通道不完备（移动端布局树、桌面端 AX 树都有盲区），并且动作可能静默失败时，系统或智能体如何靠**阳性对照 / 独立核验通道**，先确认「状态读对了、动作真生效了」，再下结论或换路。

- **方向一（检测，SE1 · 软工主攻）：** 截断 Test Oracle，已定为主攻，投 ISSTA 2027（摘要 01-08，全文 01-11）。
- **方向二（探索，SE2）：** 探索本身的独立依据偏弱，并入检测当配套。
- **方向三（页面图 G · 软工评测/配套）：** 以前建图论文都没有一份人工整理的「App 真实功能页面清单」做标准答案，没人直接测过「建出来的图把多少页面合错了、拆碎了、算出来的覆盖率虚高了多少」。我们用已有的真实页面清单做评测，方法落在**功能层 + 条件层**两层状态图。
- **方向四（桌面多通道受阻与核验，AX · AI 顶会主线）：** 已从「静态结构不一致」长成一条独立的 **AI 论文主线**（瞄准 ICML / NeurIPS / ACL 等）。研究对象是**真实原生应用自带的结构残缺与静默失败**下，模型如何察觉、找独立通道核验、干净恢复，以及什么训练数据形状能教出跨应用迁移的习惯。另有「动态动作效果诊断」与「可验证奖励下的主动取证策略」两个轻量 AI 衍生方向。

**方向四的规模：**
- 去重后 **2,531 条**轨迹，**16,404 个**受阻决策点窗口，固化 **10 种**受阻机制词表（M01–M10）。
- 刚跑完的 30 帧离线师生接管验证，下一步分歧率 **13/30（43%）**。

## 1. 四个方向总览

| 方向 | 范文 | 空白与切口 | 核心假设 |
|---|---|---|---|
| **检测 SE1** | ReFLAIR（FSE 2026） | 它面向有 DOM、可程序化滚动的网页。我们面向鸿蒙原生 ArkUI：只有布局树，嵌套滚动多，手势不一定生效，有多种屏态。「静态判到动态复核」本身不能当新意 | 只看截图分不清真截断与能滑出的假截断；加布局树也看不出 |
| **探索 SE2** | GraphDroid（ASE 2026） | 无非崩溃判定器；相似度 >0.95 就合并页面，没测这对显示缺陷的影响 | 工作假设：显示问题无预兆，功能覆盖越高碰到的越多 |
| **页面图 G** | PropGen（ASE 2026）、ProphetAgent | GraphDroid、ProphetAgent、FuncDroid、PropGen 都只把页面转移图当下游任务的跳板，**全都没有一份人工整理的「App 真实功能页面清单」做标准答案，没人评测过建出来的图本身把多少页面拆错、合错了** | 按布局认页面会拆错合错，覆盖率被明显高估 |
| **结构树与画面一致性 AX** | arXiv 2607.04334 | 它测模型在图树冲突时信谁，场景是人为编辑与网页。**真实原生应用自带的结构残缺、静默失败下的察觉—核验—恢复，没人做** | 见第 5 节 |

关系：检测提供判定器；探索与页面图决定测得够不够；结构树可靠性与动作生效确认，是前三者共用的基础。

## 2. 方向一：检测（截断 Test Oracle）

### 2.1 范文与我们的差别
ReFLAIR 的核心是「探索不只用来走更多页面，也为判错找反证」：24 页上 precision 80.49%、recall 95.31%，去掉探索后 precision 降 40 个百分点。

我们的不同点：
- 原生 ArkUI 只有布局树。
- 嵌套滚动容器多。
- 手势不一定生效。
- 多屏态。
- 真值有「三分类」：真截断 / 能滑出 / 合法省略。

### 2.2 已有证据
| 证据 | 数字 | 级别 |
|---|---|---|
| 端到端 50 页（正常 40、真截断 10）：不滑动 → 滑动复核 | 86% → 96%；报截断 15 页里 6 页误报 → 0 误报 | 真值，真截断仅 10 页 |
| UI-Lens 200 张只看截图 | precision 79%、recall 53%，37 张两次都漏 | 真值 |
| 合作方带框标注 28 组 | 约 25 组滑一下能看全 | 模型标签，须人工逐组确认 |
| **滑动的否定证据最不可靠**（138 框存档） | 「框里变了→能滑出」69 次错 3（4%）；「框里没变→确认截断」37 次错 11（**30%**） | 存档重判 |
| **恒定关系判据**（179 框，布局树能下结论的 58% = 103 个） | **103/103 全对**；9 月验收未调参批 24/36 能判，全对 | 存档重判，判据看过结果后改过两处 |
| 两版规则消融（双折叠真机自测，14 个正常页） | 不含布局否决与按住复核：误报 5/14；含：0/14 | 单次，开发集 |

### 2.3 已定方法：三层
1. **恒定关系（判据）。** 被切内容 C 与切它的边 E（裁切者 K：屏幕边、固定栏、裁剪容器、浮层、可滚区边）之间，必须有一个能沿被切方向动的东西，把 C 相对 E 挪开。没有，就是截断。设计好的省略（省略号、渐隐加「更多」、跑马灯）算合法。
2. **布局树盲区表。**

| 盲区 | 例 |
|---|---|
| 子组件自裁切不导出 | 浮条里「务」整字消失 |
| 省略号与自裁切同构 | 学弟实测：导出的树完全一样 |
| 被兄弟组件盖住 | 吸顶栏盖住价格行 |
| 行框与字形不一致 | 行框多 7px，字形没被切 |
| 不知道还能滚多远 | 懒加载未创建的项不在树里 |
| 翻页容器当前页 | 轮播第几页不一定导出 |

   真截断 47 个里 21 个落在盲区。

3. **交互取证，且先确认动作生效，否定证据必须配阳性对照。**
   - 动作按容器类型选：连续滚动慢滑、翻页容器按住拖动时截图、可展开文本点展开。
   - 三值输出：露出来 → 非缺陷；动作生效但 C 相对 E 没动 → 确认缺陷；动作没生效 → **证据不足**。

**更正：** 动机应写成「布局树不完备，但能说话时不出错」，而不是「布局树不可靠」。不可靠的是旧规则和滑动的否定证据。

### 2.4 开合
开合问题常见：849 组打标里 266 组判有问题（31%），**模型标签，人工复核为零**。其中 201 组只命中「展开后等比放大挤出首屏算不算」这一条口径，尚未与合作方对齐。开合方法不难，难在口径。因此单列，不进截断这篇。

## 3. 方向二：探索

- 无人值守采集器累计覆盖 28 个 App。
- 一个 App 约四五十个核心页，一小时只覆盖十几个。
- 浪费：**27% 的步数（2,224/8,100）耗在 App 外**，即权限弹窗、登录页、被别的 App 盖住、截图异常【模型标签】。
- 番茄小说 99% 的步数在前三页，喜马拉雅 88%，携程 90%。

**认知演进：**
- 探索类工具（FuncDroid、HapTest、LLMDroid）都没有显示判定器，路过白屏、破图不报。
- 动作经常没生效却记成「测过」。
- 给了目标，强模型从首页走到目标页基本没问题（外屏 5 题核验 9/10 到达；深度 22 条核验确认 13 条，其余是环境问题）【模型标签】。

**结论：** 覆盖上不去，是缺**目标**，不是缺策略。因此探索并入检测当配套，与方向三合流（见 4.6），不独立成篇。

## 4. 方向三：从轨迹构建功能状态图与覆盖评估

### 4.1 文献空白

| 工作 | 把图当什么 | 评价了「图本身」吗 |
|---|---|---|
| GraphDroid | 探索引导的历史记忆（相似度 >0.95 合并） | 否 |
| ProphetAgent | 脚本合成的中间表示 | 否，只评脚本完成率 |
| FuncDroid | 功能流图，用于跨功能测试 | 否 |
| PropGen | 性质生成的证据 | 否，评性质有效性 |

**空白：** 以前所有自动建图工作都没有事先准备一份人工整理的「这个 App 真实一共有哪几十个功能页面」的标准答案清单（比如 GraphDroid 跑完只报「聚类出 73.5 个抽象状态」，并不知道这 73.5 个节点里把购物车拆成了几个、又把哪些不同页面错合成了一个）。**没人拿真实功能页面清单直接核对过：建出来的图拆合准不准、按页面节点数算出来的覆盖率虚高了多少。** 而且文献里的覆盖率单位互相不可比：

| 来源 | 单位 | 数字 |
|---|---|---|
| GraphDroid | Activity 比例 | 36.94% |
| LLMDroid | 方法覆盖相对提高 | +26% |
| HapTest 复现 | 源码注册路由 | 三轮各 3 个，并集 4，交集 2 |
| 我们 | 命中人工 spec 页 | 唯品会 10/46 |

### 4.2 源码级实证：8 个工具的状态表示缺陷

我们逐个读了源码并结合真机运行证据：

- **LLMDroid：**
  - 792 个事件里 **295 次前后状态键相同但画面字节不同**，其中混有正常光标动画。
  - 长按出编辑菜单后状态键不变，复用首次代表，**新菜单子状态丢失**。
  - 对照正例：输入 Hello World 后 State7→State8 仍归同一簇，合理合并应保留。
  - 动作被访问即把功能优先级置 0，但教学浮层挡住时点击没生效，目标并未到达。
- **GraphDroid：** 结构或截图任一通道相似即合并，另有结构相等直接记 0.95 的捷径；谱聚类异常时按序号取模分组。**本轮方法运行为 0，风险只按源码分析，不当作已测误合率。**
- **FuncDroid：** 四个 App 共 51 个模型命名节点，混有核心业务、授权、广告、外跳；标记完成仅 2 个。依赖边缺条件验证；自动候选 2 个，确认 0。
- **OS-Genesis：**
  - 对象漂移：重置后「Bike Touring」变成「Trail Jog」。
  - 作用域混淆：目标要「当前轨迹统计」，却进了「分类汇总统计」，打分仍给 5 分。
- **PropGen：** 31 条性质 6 小时仅触发 18 条；生成的后置检查过弱（只检 `Daily` 关键词，没发现 1969 年的日期矛盾）。
- **HapTest / ReFLAIR / UI-Lens：** 对象身份、动作生效与证据来源缺口，已在检测线中使用。

共同缺陷：**要么丢对象、丢条件，要么把「动作发出」当成「目标到达」。**

### 4.3 唯品会：按布局认页面 vs 46 页人工 spec

脚本按布局指纹分出 **35 个模板**，GPT 看图认出 31 个功能页，对 46 页人工 spec 的覆盖仅 **10/46（22%）**【真值，1 个 App】。
- **10 个模板各混了几个功能页。**
- **15 个功能页各被拆成多个模板**，例如购物车、商品详情各拆 6 个。

### 4.4 去重与功能命名实验

以 GPT 命名的 27 个功能（181 步）为参照【模型标签】：

| 信号 | 结果 |
|---|---|
| 结构指纹 0.57 | 纯度 85%，完整度 65%，调和 **73%** |
| 阈值 0.4–0.75 | 调和 72–77% |
| 仅文字 | 最好 74% |
| dHash | 54–64% |
| 结构 + 文字 | 最好 76% |

**结论：** 换阈值、换单一信号都停在约 75%，瓶颈在「按布局认页面」这条路线本身。

**VLM 功能命名自洽：** 同批 200 步三遍对比，一致率 **95% / 91% / 89%**；35 个模板归并成 28 个功能。这测的是前后自洽，不是准确率，须人工抽查。

**全 App 规模：** 28 个 App、约 8,100 步，归并为约 **591 个功能页**（此前所说 666 是布局模板数）。

**控件文字层级（9,443 个可点控件）：**

| 文字来源 | 占比 |
|---|---|
| 自身有文字 | 19% |
| 自身无字、子节点有字（原脚本漏读） | 52% |
| 全无文字（多为图标） | 28% |

改读子节点文字后，可读名字的候选控件从约 20% 提到 66%。11 月新版采集器在唯品会 36 个页面里，**31 个最短路径全是带文字的点击，可纯文字重放**（尚未在真机验证到达率）。

### 4.5 独立功能真值库：mobilegym-mock

9 个主流 App（唯品会、京东、拼多多、喜马拉雅、闲鱼、大众点评、淘宝、B 站、小红书）按人工 spec 编译了**路由 / 状态真值库**，每 App 35–118 个路由，含状态 id、可做动作、滚动容器声明。这给「评图是否准」提供了独立答案。

用途：以 URL（路由 + 状态）为标准答案，比较四种认页面方法：布局模板、仿 GraphDroid、仿 LLMDroid、VLM 功能命名，并报告被拆开数、被合并数、覆盖估计与真实覆盖差。

### 4.6 核心方法：两层功能状态图

- **功能层：** 回答「这是搜索、详情、编辑还是统计」，把动态换文的同类页面归并，约束图规模。
- **条件层：** 保留「哪个对象、弹层或菜单是否打开、输入内容与开关、恢复路径」，每条动作边附前置条件与实际重放结果。

**设计原则：** 不是一律拆也不是一律合，而是 **「归并换文，保留改变动作条件的差异」**。这同时解决 LLMDroid 丢菜单、OS-Genesis 丢对象、GraphDroid 条件被合并的问题。

**与探索、人工案例合流：** 一条测试用例 = **指令 + 路径 + 功能页 × 状态 + 预期结论**。
- 26 张人工案例任务卡（来自 30 个人工发现的问题）：采集器到过目标页的仅 **7 张**；8 张在抖音（从未采过）；10 张在已采 App 里没走到；1 张 App 不明。
- 任务卡里需预置的状态只有三种：列表加载满一屏、打开评论区或弹窗、反复开合。

### 4.7 最小验证与放弃条件
- 冻结 20–30 对状态，覆盖：同功能换内容、相似布局不同功能、同功能带菜单。
- 人工标功能与条件，比较原表示与两层表示：错合、错拆、目标重放成功、条件恢复。
- **放弃条件：** 另外两个 App 上布局模板与人工功能基本一一对应（拆合合计 <10%），且覆盖高估 <10 个百分点，则方向三不单独成篇，仅作探索的记忆模块。

## 5. 方向四：结构树可靠性 → 自然受阻下的察觉、独立核验与通道选择

### 5.1 与已有工作的划界（37 篇顶会逐篇核实）

| 已有工作 | 他们做的 | 差别 |
|---|---|---|
| Screen2AX、UFO2 | 统计 AX 残缺（热门 macOS 应用约 36% 完整、18% 无；WAA 上 >62% 失败为控件检测失败），用重建或视觉合并补救 | 不告诉模型哪部分不可信，不研究察觉与换路 |
| arXiv 2607.04334 | 图树冲突时模型信谁（跟结构 30%–75%） | 人为编辑，静态探针；不涉及「结构缺了、绑错窗口」，也不涉及换执行方式 |
| HCU、ToolCUA、HybridCUA、UltraCUA | 通道健康时为**效率**选工具，奖励是成功率与路径效率 | **没有以「通道失效」为监督，也没有按「默认通道是否坏了」分层** |
| AnTrap、D-GARA、GUI-Robust | 研究者**外部注入**弹窗、遮挡等，集中在 Android 与网页 | 不是应用自带的缺陷 |
| VeriGUI、RoTS | 同通道验证 / 模型自身错误后的合成恢复 | 失败是合成的；不是跨通道独立核验 |

**空白：** 真实原生桌面应用自带的结构残缺与静默失败下，模型如何察觉、找独立通道核验并干净恢复，以及什么训练数据形状教出可迁移习惯，而非背死路径。

### 5.2 实验演进链

**阶段一：跨平台结构树审计**
- **鸿蒙移动端：** 大众点评 794 屏、212,460 节点。树里永远是全文；**24%** 节点被裁；**5.4%** 标可见但透明；**25%** 的屏含自绘区域。
- **macOS 桌面静态审计（E01）：** 7 个应用 45 个窗口，**38 个有问题，18 个主目标不在 AX**。画面可交互控件在 AX 里对得上的比例：

| 技术栈 | 对得上比例 |
|---|---|
| Blender（自绘） | 2% |
| 剪映 | 32% |
| WPS | 40% |
| LibreOffice | 55% |
| OBS | 71% |
| Excel | 75% |
| VS Code（Electron） | 88% |

  梯度更取决于自绘控件用得多不多。分母由视觉模型数出，只看排序。

**阶段二：第一轮归因与认知修正**（180 条轨迹，193 个真问题事件）
- **79%（152 个）首屏就有迹象；21%（41 个）动作后才暴露**（如 AX 动作被接受但界面没变）。
- 白走上限 9.1%（WPS、剪映一批 **25.8%**）。有无 AX 问题的通过率同为 62%，即 **AX 问题伤效率，不伤成败**。
- **推翻「缺控件需要提示」：** 控件缺失但截图可见时，模型自己切坐标，加不加提示无差别。
- **真正造成白走与循环的，是「观察错窗口 / 附属面板绑错」：**
  - 给具体诊断省约 35% 调用（37 → 24），泛泛提示反而多 6 次。
  - 单屏探针：截图里没有目标的 4 题，强模型 4/4，开源模型 0–1/4。
  - 受阻配对（WPS 短题）：强模型 14/14，开源模型 6/14。
  - 补提示实验显示**补一层，露下一层**：给了写法能发出操作，但坐标点不准；诊断能察觉看错窗口，但不会切过去。
- 提炼出 6 条换路规则，4 条一屏可判。例如：先确认看的是不是要操作的窗口；同一动作连续两次无变化就换路。

**阶段三：大规模实验（去重 2,531 条轨迹 / 16,404 个事件窗口）**
- **受阻机制词表 M01–M10（规则机械命中）：**

| 机制 | 窗口数 |
|---|---|
| M01 动作静默无效 | 6,731 |
| M02 目标不可见或不可达 | 3,567 |
| M03 输入被吞或被改 | 2,981 |
| M10 出路自带副作用 | 1,136 |
| M05 前置条件置灰 | 980 |
| M04 焦点或窗口绑错 | 426 |
| M07 默认值陷阱 | 370 |
| M08 权限或会员墙 | 130 |
| M09 状态不同步 | 65 |
| M06 应用报喜不报忧 | 18 |

  M01–M03 占绝大多数；机制在应用间分布不同。例如剪映的 M01、M10 突出，WPS 表格的 M02、M05 突出。
- **互斥三档：** 干净界面或只读 **475** / 可恢复，需遮步或披露修正 **1,112** / 越界、失败，作为接管种子 **944**。
- **双后端「受阻开关」：** 两种执行语义不同的真实后端：
  - **严格校验、显式拒绝型：** 焦点未确认就不发输入。
  - **宽松执行、不保证生效型：** 动作返回成功但不保证生效。

  静默失败占受阻事件的比例，宽松型 **47%**，严格型 25%。同一强模型越界违反题面约束，严格型 **15/71**，宽松型 **1/82**。题目不完全相同，均为模型标签，只看方向。

  **含义：** 绕出框架这类行为主要由后端压力引起，但「如何回应压力」由模型决定。不同模型对「界面走不通」的回应也不同：有的被挡才绕且会说，有的随处离开界面且不说，有的不绕、如实报告未完成。

### 5.3 强弱模型的真正分水岭

两个模型在两边都未中断的 180 道同题上，成功率几乎一样：**171 vs 168**。差别在这几处：

| 维度 | 强模型 | 开源模型 | 级别 |
|---|---|---|---|
| 恢复代价：无信息原地重复 | 32% | 54% | 模型标签 |
| 恢复代价：调用中位数 | 39 | 71.5 | 同行评测线 |
| 出路干净度：留下未交代副作用 | 17% | 48% | 模型标签 |
| 手段披露：用脚本改文件后正常结束 | 101/101 交代 | 81 道中 0 道明说 | 人工读，未复核 |
| 做完后用独立证据检查产物 | 79/82 | 218/286 | 模型标签 |

规则口径下，得分 1 且路线为「写文件 / 控制类」共 **1,147 条**，其中最终答复里提及用了脚本或命令行的仅 **49 条**，**1,098 条未披露**【规则扫描】。

**静默失败下的关键行为：** 动作返回成功、AX 值变了、应用自己的成功提示，都不可信。分水岭更像是**「是否主动寻找独立只读通道核验，并对着反证修复」**：
- 解包文件。
- `ls` 看输出目录。
- `ffprobe` 看产物属性。
- 导出后发现封面还是绿的，推翻自己。
- 应用提示「成功保存 5 张」，用 `file` 一查还是 JPG，重做。

### 5.4 已推翻或需谨慎引用的结论
- 「告诉模型哪里不可信，对强模型有用」：只在「看错窗口」类有用，通用提示没用。
- 「看错窗口是主要问题」：这是早期后端上的现象。换后端、修框架后部分消失，**不能再当主角**，残留形态是弹出层不进 AX 也不进截图、加载浮窗挡主窗口。
- 长程整题测「选通道」：被开文件、接口写法、坐标精度等噪声淹没，测不出，已停。
- 「粘贴粘进程序自身路径」：该路径其实是环境历史残留，且 paste 并未生效，不再作为后端行为引用。
- 所有「可收 / 直接收」数字对标注轮次敏感（同批轨迹出现过 24、35、33 三个版本），论文里一律改用规则可算的指标。

### 5.5 已定研究思路：三层解耦

| 层 | 内容 | 解法 |
|---|---|---|
| **硬墙** | 谁都过不去（如导出下拉在该后端上无法操作） | 归底层修复，从评测里剔除 |
| **出路知识** | 这个受阻点怎么绕，应用或后端特有，会过时 | **检索**一份受阻点目录，不训进模型 |
| **察觉、独立核验、止损** | 可迁移的模型习惯 | **训练** |

**训练核心判据：**
1. **最小对照对。** 模型总走最省力的相关性。若「剪映放素材」与「拖拽无效、点加号」百分之百同现，学到的只是应用到路径的映射，看不看观察都一样。要逼它看观察，同一应用、同一动作、同一返回必须**有时生效、有时不生效**，且两种情况的正确后续不同。开关可以在 setup 里程序化控制：后端、应用是否在前台、开场有无登录窗或弹窗、文件自带前置条件、起点脏状态。
2. **区分三种「遮步」：**
   - **删步**会造出假因果（失败尝试被拿掉，样本变成「素材上轨道就是点加号」），最易教出背路径。
   - **遮损失**：失败尝试留在上下文，不算损失，学的是「历史里有这个失败，下一步怎么办」。
   - **全算**。
   - 初步规则：没改变环境的重复步可删；改变环境的错误步只能遮损失；环境造成的首次合理尝试要学；越界动作不遮不删，整条在越界前截断，改成接管题。
3. **DAgger 式接管续写。** 在**弱模型真实走出的受阻前缀**上，由强模型续写：前缀只进上下文，续写算损失。接管点决定教什么：
   - 静默失败后一步接管，教察觉。
   - 第三次重复接管，教止损。
   - 即将杀进程或写目标文件时接管，教守边界。
   - 读回与要求不符时接管，教对反证修复。
4. **广度的单位是受阻机制的种类，不是功能菜单。** 要给每种机制找三四个不同的应用化身。窄的不是功能，是机制的化身数。
5. **契约化通道。** 每题显式声明：界面为主 + 只读终端、结果导向、严格界面、跨应用工作流。同一题两种契约各一条，是另一种最小对：状态相同、契约不同、正确动作不同。

### 5.6 30 帧离线师生接管先导验证（刚跑完）

- **设计：** 取 30 个弱模型受阻帧，只把受阻那步**之前**的历史交给强模型，只问下一步，再用确定性规则与弱模型实际动作对照。无在线续写。
- **结果：总分歧 13/30（43%），收敛 17。**

| 受阻桶 | 分歧 | 内容 |
|---|---|---|
| 盲拖无效（剪映） | **4/6** | 弱模型继续拖，强模型换出路：改按键、点别的控件、先停手重读界面 |
| 第 3 次重复 | **3/6** | 强模型止损并换路 |
| 写目标文件或强杀进程（界面契约下） | 守界 2/2 | 强模型留在界面或如实报告，不越界写盘、不杀进程 |
| 读回出现 `bold=False` 反证 | 1/1 | 强模型对着反证再核全部单元格，不直接宣布成功 |
| 前置置灰 / 按键名被拒 | 各 1 | 强模型改用元素的次要动作，或改走 setValue |
| 对话框下拉、另存为面板 | 0/6 | 师生一致，不优先 |

**读法：** 分歧精准落在我们想教的行为上；一致的桶说明那些位置无需接管。命令行优先契约下，师生一起改文件算收敛，不为「守界」浪费配额。样本小，需要在线完整续写验证。

### 5.7 论文架构与两周排期

**论文架构：**
1. **受阻恢复回归集**，以**受阻点**而非「题」为单位，带来源（应用固有 / 后端造成 / 环境）、显式或静默、出路与质量等级（干净 / 有副作用 / 违反约束）。
2. **独立核验分析：** 假成功率、核验通道选择、核验后纠正率。
3. **六臂数据形状 LoRA 消融：**
   1. 只有顺风成功轨迹。
   2. 加受阻轨迹但**删步**。
   3. 失败步留上下文、**遮损失**。
   4. **全算**。
   5. **接管续写**。
   6. 接管续写加**生效 / 不生效对照对**。

   另有两个单因子：总样本固定下「机制种类多每种少」对「种类少每种多」；披露重写的有无。

   预测（猜想，写出来是为了能被证伪）：删步臂在训练过的应用上最好，到留出应用和另一后端上退回基线；遮损失与接管臂能迁移；没有对照对的臂在不受阻题上步数会涨；种类多的臂胜过次数多的臂。

   评测留出：训练里完全不出现的应用、不出现的机制、另一个后端。指标：受阻版与对照版步数差、无信息重复率、假成功率、披露一致率、越界率，另加固定通道轮换阶梯基线。

**两周排期：**

| 时间 | 做什么 |
|---|---|
| 本周 | 离线：规则口径可交清单；披露重写（1,098 条）；事件窗口切片；受阻点目录 v0（含三档分法）；人工抽查约 50 个事件，校准标签 |
| 本周 | 集群：全部应用自动体检（固定探针：点击、拖拽、中文输入、大小写组合键、开下拉、前后台），产出每应用机制地图；状态可编程应用（Blender、OBS、Obsidian、LibreOffice）逆向出题首批 |
| 下周 | 起点扰动对（前后台、小窗、前置条件三类开关）；接管续写试点（三个老受阻点各约 20 条）；冻结回归集（含三类留出） |
| 下周末 | 第一轮小规模消融（若训练入口未到，用开源视觉模型代理）；带数字去和导师谈 |

**训练入口：** 两周内拿不到则先用小规模代理基座。论文要的是「数据形状决定迁移与否」，不要求基座一致。

**风险与放弃条件：**
- 有区分度的受阻点凑不够 10 个，则降级为内部回归集。
- 统一条件后强弱差距在受阻题上 <10 个百分点且代价无差，则「强弱差距」故事不成立。
- 标签人工一致率太低，则改用机械可判的指标。
- 后端造成的结论须单列，主结论只下在应用固有且两种后端方向一致的受阻点上。

## 6. 四条线的内在统一

**同一个科学问题：** 观察通道不完备，且动作可能静默失败，怎么确认状态与动作真的生效。

| 线 | 观察盲区 | 静默失败 | 「阳性对照 / 独立通道」 |
|---|---|---|---|
| 检测（移动） | 布局树盲区：自裁切、省略号同构、被遮盖 | 滑了没动（四种原因） | 按住复核，先证明目标容器能动；文字对账（树 vs 画面）；两屏态对照 |
| 页面图 | 按布局认页面丢功能、丢条件 | 动作发出 ≠ 目标到达 | 人工整理的真实功能页面清单（spec）做标准答案；保留对象与作用域条件 |
| 探索 | 走到「测过」不等于测完 | 点击未生效却记成功 | 目标到达需页面功能确认 |
| AX（桌面） | AX 树残缺（自绘、国产最差）；看错窗口 | 47% 的受阻事件是静默失败 | 磁盘文件、`ls`、`ffprobe` 等独立只读通道，对反证修复 |

**统一原则：否定结果本身不携带信息，除非另有证据证明这次探测是有效的。**

- 滑动后「框里没变」要配「同视口有参照物动了」。
- 动作返回成功要配「独立通道看到状态变了」。
- 实验科学里这叫阳性对照。

**分工与「软工 + AI」双轨论文布局：**
- **软工顶会线（回答「怎么判、怎么测准」）：**
  1. **软工主攻篇（ISSTA 2027，后备 ASE 2027）：** 方向一《鸿蒙多形态应用的交互式截断 Test Oracle》（恒定关系 + 六类盲区 + 阳性对照取证 + 开源白盒真值基准）。另有**文字对账通道**（布局树全文 vs 局部 OCR 前缀比对，1～2 天离线可验）可进一步压缩静态盲区、突破视觉模型整字漏召回天花板。
  2. **软工评测/配套篇（视 G-a 实验结果定独立成篇或作配套）：** 方向二 + 方向三合流《面向真实功能清单的页面状态图评估与带条件用例生成》（量化按布局去重对覆盖率的高估，验证功能层 + 条件层两层表示）。
- **AI 顶会线（回答「智能体怎么察觉受阻、怎么核验、怎么学出可迁移习惯」）：**
  1. **AI 主攻篇（方向四，冲 ICML / NeurIPS / ACL）：**《自然受阻与静默失败下桌面智能体的独立通道核验与可迁移恢复训练》——基于 2,531 条轨迹 / 16,404 个受阻窗口 / M01–M10 词表与双后端受阻开关构建「受阻点级回归基准」，并做六臂数据形状 LoRA 训练消融（证明「遮损失 + 弱模型真实受阻前缀 DAgger 接管 + 同动作生效/不生效最小对照对」才能跨应用迁移，而非删步死背路径）。
  2. **AI 轻量候选篇 A（跨线动态诊断，2 天离线可出先导表）：**《动作效果判断（Action-Effect Diagnosis）》——动态对标静态图文冲突诊断工作 `arXiv 2607.04334`：给模型 `⟨动作前图, 动作, 动作后图⟩`，诊断五类结果（达到预期 / 静默未生效 / 作用错对象 / 生效后吸附弹回 / 页面被切换）。直接复用移动端真机滑动四联图 + 4,000 步点击前后图 + 桌面静默失败轨迹，**全部来自真实运行自然发生的数据而非人为合成注入**（区别于 AnTrap、OS-Oracle）。
  3. **AI 后续衍生篇 B（等方向一白盒受控集建成后）：**《可验证奖励下的主动取证策略学习（RLVR）》——训练小模型自主决策「何时静态直判、何时花一步交互探测、选哪种手势、何时输出证据不足」，动作空间仅 5～6 个、白盒真值提供 100% 确定性奖励。
