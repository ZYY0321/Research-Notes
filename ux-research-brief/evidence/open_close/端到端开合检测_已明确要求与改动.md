# 端到端开合检测：流程与验收产物要求

只整理**怎么交、交什么、流程上改过什么**。判定细则、模型怎么训，由对方算法侧准备，这里不写。

截断端到端代码已交（`交付/截断检测-v1.3.0/`）。开合这边目前交出去的主要是采集与打标材料，还没有一份像截断那样给测试人员一键跑的验收包。

## 一、验收流程上已经明确 / 按方案在做的

1. **单次用例流程（方案原文）**  
   打开指定测试页面 → 端到端记录折叠态和展开态截图 → 自动调用模型判断。  
   也就是人（或导航）先停在目标页，再切屏、截图、出结论；不是「只给一个 App、自己满世界探索找问题」那种验收形式。自由探索是收数用的，和验收主流程分开。

2. **和截断的流程差别**  
   - 截断：到页后对当前页各屏态做检测。  
   - 开合：到页后要拿到**折叠 / 展开成对**材料再判断。  
   - 开合采集从 2026-10-22 起获准用命令切显示态；报出来的问题要用手真正折一次才能当最终确认。验收现场是否允许命令切，对方书面还没锁。

3. **切屏与恢复（若开合挂进同一套真机 Agent，沿用截断已交的纪律）**  
   - 按设备补齐该测的屏态；半折、悬停不算正式屏态。  
   - 测试人员合着或展开开始都可以；开始那张图不重拍、不覆盖；测完恢复开始时的样子。  
   - 离线只传图时，不许去切 USB 真机。  
   - 每块屏 / 每一对开合结果各自出结论，不要糊成一个说不清的总结果。

4. **收数流程上改过、影响「端到端能不能跑起来」的**  
   - 协议 / 权限弹层要能过，入口 Ability 要能指定，不能写死。  
   - 带弹层、输入有字、勾选这类状态不能因为「以前测过」就永远跳过。  
   - 测试次数上限不能太小，否则额度提前用完，深层页测不到。  
   - 出现「分享截图」浮窗的当次标无效，不进正式结论。  
   - 发给 Windows 的压缩包必须用仓库的 `pack_zip.py`，禁止 Finder / 系统 zip。

5. **进页面前是否预置状态**  
   专家问卷要求进页前预置：列表满一屏、输入一半、勾选、打开评论/弹层、暂停视频等。这是流程要求；我们现有采集多数还没系统做满，端到端验收要不要强制预置，等对方确认。

## 二、验收产物上已经明确 / 按现有交付习惯要对齐的

1. **一次运行的结果**  
   - 折叠态、展开态截图（至少一对；采集侧还会留切换后不同时刻的图，给人看/打标时常用「折叠一张 + 展开稳定一张」）。  
   - 自动判断结论：至少能区分通过 / 不通过 / 不确定 / 无效。  
   - 结论要落在当次运行目录里，测试人员能指认「看哪个文件」；不要只口头报。

2. **交付包形态（对齐截断已交的做法）**  
   - 可运行代码 + 怎么安装、怎么跑、产物看哪的说明。  
   - 给测试人员：改哪些文件、怎么替换，或整包怎么下；说明要能照着做，不要假定对方懂仓库结构。  
   - 不要整仓覆盖弄丢对方已有配置（截断交多屏时踩过这个坑）。  
   - 代码更新要进约定的 GitCode 仓库 / 分支；修了 bug 要进包、进远端，不能只微信发零散文件。  
   - 需要自证跑过时：Word 图文自测报告（从哪版代码、什么命令、每页怎么点到、跑前画面、结果图、结论），结果目录随报告打 zip（截断 11-10 已定这种形式）。

3. **数据类产物（若这一期也要交数据，口径已经对外说过的）**  
   - 成对图 + 机器初标可以先交，但必须标明「机器初标、人工复核情况」。  
   - 不要把「机器报 fail 的组数」说成「已确认发现的问题数」。  
   - 「不同页面」若按布局模板统计，要写明是模板口径，不是功能页口径。  
   - 防截图导致整屏黑的 App，当次无效，不能当成「没问题」。

4. **打包**  
   外发 zip 一律 `python3 .cursor/scripts/pack_zip.py <目录> <输出.zip>`，保证 Windows 能解开。

## 三、流程 / 产物上还没书面定、交之前要问对方的

完整问题表见：`docs/开合检测/会议/2026-10-29_会上待确认问题.md`。和流程、产物直接相关的是：

1. 开合是不是这一期必验、截止日期（有人提过约 11-30，需对方确认）。  
2. 验收形式：只判给定成对图 / 已停在目标页我们切屏判 / 还要我们自己导航到页 / 还是自由探索找问题。  
3. 屏态谁切：手折、命令切、还是模拟器；要不要手折复核。  
4. 只验折叠→展开，还是双向；三折 / 阔折要不要验。  
5. 交付物清单：代码、模型、报告、数据集各交什么、交到哪个平台、报告谁写。  
6. 一组判断有没有时间限制；任务书里「端到端 ≤10 秒」适不适用于开合。  
7. 无效组、不确定组在验收计分里怎么处理。  
8. 正式判定规则以哪一版为准（影响产物字段和用例预期，细则由算法侧落实）。

没答之前：只承诺「按已冻结流程跑通到页 → 切屏成对 → 出结论与产物目录」，不要承诺探索找全或未锁定的规则版本。
