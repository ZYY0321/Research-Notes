# 讲稿（约 3～5 分钟）

对着《现状与安排》《DONE与TODO》讲。逻辑统一：**什么问题 → 现在怎样 → 大概多久 → 谁做**。

---

今天有新同学，先一句：这是浏览器里的手机模拟环境，复刻一批 App 给智能体做 GUI 训练评测。系统层管状态、重置、场景注入、跨应用；业务 App 挂上去接规范。业务大约 **32**、系统大约 **14**，盯有复刻文档的自建 **24**。淘宝咔皮上次演过，今天不重演。

---

**交付能力（L1）**  
问题：中英、深色、场景、任务、跨应用能不能成套过线。  
现状：系统骨架齐了；示范接满的是 **5 / 24**（淘宝、咔皮、播客、瑞幸、携程）。其余大多还是散着缺。多场景全库基本没铺开，场景 JSON 几乎只在这几个示范 App 上。  
多久：已有骨架大约 **0.3～0.5 人天/App**；大 App 从零英文化过 L1 大约 **1～1.5 人天**。深色壳很快，全页硬编码色跟主题还得再抠半人天到一人天。场景 JSON 通常 **≤0.5 人天**。

**跨应用**  
问题：画了支付/分享/相册，点了是真拉起还是假按钮。  
现状：真接到通道的大致就是上面那几个示范；大量 App 文案有、代码没有 startActivity。  
谁做：环境侧示范和「有入口就接」我可以带 AI 做；哪个入口「应接 / 故意假」要产品/负责人拍板。

**主链路进 Store / 假成功**  
问题：加购、提交、开关等是不是写进统一 store，还是 toast 假装成功。  
现状：跟踪表在盯；扫描看不全，要靠走查和任务读 `getState()`。  
多久：对照淘宝/咔皮补一条 P0，通常半天量级，看 App 复杂度。  
谁做：**7/31 优先各负责人提交**；我可以给提示词和对照模板、帮对账。

**走查质量（导航/筛选/种子/敏感信息）**  
问题：点了没反应、筛了不变、数据假或像真人信息。  
现状：静态扫描做过接入痕迹；种子不对、敏感信息等是 **7/21 走查和 Gate4 反馈**里冒出来的，不是扫描验业务数据验出来的。表在群里《验收反馈跟踪》。  
多久：按条修，单 App 常见问题往往零点几到一人天。  
谁做：必须负责人手点对账；我辅助合版检查、环境侧共性问题可以先捞。

**再往后（稍展开）**

合版 v1、7/31 提交之后：一是**视情况补国外生产力 App**（规划里大约 **4～8** 个），用来补品类、现在跨app基本就是支付和分享场景。二是 **GUI+Tools / tooluse**：行业方向是 GUI 和工具混合调用；我们要在 MobileGym 上接 Tools、同一套任务能切纯 GUI / 混合评测，并做对应 Benchmark（交接里已有 V6、几十个任务的底子）。**环境和 v1 App 收口后再加重**，避免 App 大改导致 Tools 返工。
