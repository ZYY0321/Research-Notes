## 3. 跨应用

**高频、建议有入口即补齐：** 支付（→ 支付宝 / 微信）、分享（→ 微信）。

| 指标 | 数量 |
|---|---|
| 文案出现「支付宝」 | 9 |
| 文案出现「微信」 | 22 |
| 文案出现「相册」 | 16 |
| 文案有支付宝、代码无 startActivity | 7：Baicizhan, Ctrip, Didi, Douban, Keep, Pinduoduo, Ximalaya |
| 文案有微信、代码无 startActivity | 约 20（除已接线应用外的多数） |

含义：界面多已画出支付 / 分享相关入口，多数尚未调用系统跨应用通道。

**其它可做的跨应用 / 系统共享（非仅支付与分享）：** 相册选图或存图、通讯录选人、打开地图导航、短信、系统浏览器打开链接、剪贴板口令、通知回跳、第三方登录外观。系统侧多数通道已有；应用侧接入很少。排期上可在支付 / 分享之外另选 1～2 条做示范。

## 5. 工作量粗估

| 事项 | 粗估 |
|---|---|
| 补中英（原缺 6 个）或深色 | 单应用约 0.5～1.5 人天 |
| 有入口则接支付或分享 | 单条路径约 0.5～1 人天 |
| 扩展路径示范（通讯录 / 地图 / 相册选图等） | 示范 1～2 人天；复制单应用约 0.3～0.5 人天 |
| 补场景 JSON | 单应用通常 ≤0.5 人天 |
| 清除 Math.random（RL 前） | 约 3～5 人天 |

**实测校准（2026-07-29 五 App 试跑，Cursor Grok 4.5，约 2.5h 墙钟）：**  
淘宝/咔皮复验很快；已有 i18n 的播客/瑞幸补齐约 **0.3～0.5 人天**；无 strings 的大 App（携程）全页 UI 英文化 + L1 约 **1～1.5 人天**。已知债：携程深层页/瑞幸品牌色未全量 token，不挡 L1 过线。记录见 `底稿/五App全量试跑/`。
