- Mobile GUI Agent 项目进展与数据策略调整
  - 当前进展同步
    - 多维度环境构造：按不同职业、性格维度初始化环境，每个维度计划构造 1000 条样本，当前已完成 3000 余条，其中 2000 条已用于模型训练。
    - 模型测试进度：当前仅完成 Android 端单 Epoch 训练测试，Qwen 3.5 模型效果达 53.8%，其余端测试因网络问题未完成，预计当日内完成并同步至群内。
    - 跨APP任务构造：采用简单拼接、全局 Query 两种方案构造长难任务，当前任务完成率偏低，核心瓶颈为轨迹循环问题。
    - 轨迹循环统计：无循环的任务完成率达 95%，存在循环的任务完成率降至 57%，未完成任务中 78% 存在循环，长难任务循环概率显著更高。

    - 训练数据问题：当前训练数据中 60%-70% 来自原始 Qwen 3.5 弱模型输出，包含大量错误步骤，会对单步 SFT 训练产生明确负向影响。
  - 核心策略调整
    - 实验记录规范：需在实验结果表中新增备注列，明确标注每轮实验的模型版本、使用数据量、超参数等信息，避免后续无法复现结果。
    - 数据生成方案：当前阶段全量使用强模型生成数据，暂不启用强弱模型切换逻辑，待基础模型迭代完成后再统一补充错误修复类数据。
    - 循环问题处理：优先对现有轨迹做筛选，直接丢弃存在明显循环的样本，暂不做改写尝试；后续调整 Prompt，要求模型主动记录关键节点。
- 环境交付特性对齐与APP开发进度
  - 现有环境能力盘点
    - 已落地基础能力：结构化数据读取、环境状态重置、多实例并行隔离、系统级剪贴板共享、跨 APP 调用底层框架均已实现，基础能力完备。
    - 待补全场景能力：多语言适配仅部分 APP 实现，需后续统一处理；跨 APP 调用仅底层支持，需补充支付、分享、相册选图等典型场景逻辑。
    - 待优化项：当前仅通过文档约束将业务数据存入统一 Store，未做全量审计，需后续统一校验；无需全量操作验证脚本，随任务配套即可。
  - APP开发节点明确
    - 交付时间节点：所有分配的商用 APP 开发任务需在 7 月 31 日前完成，目标累计交付 30 个商用 APP，当前已完成 15 个，剩余任务由对应负责人推进。
    - 后续迭代规则：所有 APP 开发完成后由张荧滢统一做后处理优化，不新增额外开发流程；后续需逐步要求开发者配套对应测试用例，避免迭代破坏原有功能。
- RL 实现方案调研与确认
  - 现有基础进展：潘正源已基于 MobileGym 框架完成 RL 基础跑通，当前使用 Qwen 3.5 9B 模型，已实现效果为 14.3%，单跑 60 步 Lora 效果达 17.1%，暂受限于机器资源未继续。
  - 核心规则确认
    - 核心待确认问题：当前主流 RL 框架对长轨迹的处理逻辑不明确，保留全量历史截图会导致上下文过长，需明确是按单步拆分还是整段拼接训练。
    - 后续动作安排：由潘正源负责调研现有开源 RL 框架的轨迹处理规则，优先参考 MobileGym 的成熟实现，待方案明确后再统一调整 SFT 数据输出格式。
    - 资源保障机制：若训练所需机器资源不足，由项目负责人协调清理占用资源，优先保障 32 卡训练资源的稳定供给。
- GUI + Tools 差异化探索进展
  - 探索背景与落地进展
    - 探索背景：当前纯 GUI Agent 赛道竞争激烈，多家商业团队预计 8-9 月将发布高效果模型，因此将 GUI+Tools 混合调用作为核心差异化方向推进。
    - 现有落地进展：已为 10 余个 APP 完成 200 余个工具的开发，工具直接复用环境底层业务函数，可保证 GUI 操作与工具调用的效果一致性。
  - 验证集建设与后续规划
    - 验证集建设：已完成 V4 版本的验证集，包含 76 条跨 APP 混合调用任务，可有效区分不同模型的混合调用能力，部分场景下工具调用增益显著。
    - 待优化点：当前部分验证脚本的覆盖范围不足，存在仅匹配特定结果、未校验全链路条件的问题，需后续逐步迭代优化。
    - 后续规划：优先完成 100 条左右的高质量验证用例，打磨验证逻辑准确性；训练侧可适当降低用例标准，快速扩充样本量，根据 SFT 效果调整投入。
