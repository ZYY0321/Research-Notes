# 全量交付口径（纠正）

此前演示面「先接一点」不够。要对齐「系统层能力 + **两个示范 app 全量接好**」，才能用实测估其他 app 改造成本。

## 全量 = 这两 app 上下列能力都可用、可演示

| 能力 | 全量完成定义 |
|---|---|
| **数据 / 可验证** | 业务真值在 store；拟出可跑的示范任务；judge 读 getState；可配场景注入 |
| **多数据** | 命名场景注入后 store+UI 都对；任务在 empty/常规场景下仍可判定 |
| **中英文** | 页面/组件 UI 文案进 `strings`/`strings.en`，OS `setLocale` 后整 app 跟随（种子数据专名可保留中文） |
| **主题/深色** | 跟 OS `darkMode`：`colors`+`colorsDark`+CSS vars；页面用 `bg-app-*` / `text-app-*`，不是写死浅色 |

## 可验证展示方式

不是「全功能 walkthrough 包」，而是 **拟任务 + 现场跑判定**：

- 淘宝：已有 suite（如 `AddItemToCart`）+ empty_cart 场景
- 咔皮：新建 `bench_env/task/kapi` 任务（报销开关、记一笔等）+ empty/reimburse 场景

## 成本评估怎么用这两个 app

全量做完后，记录人天 → 作为「一个中等电商 / 一个记账 app 接满 L1」的样本，再外推他人 app（按页面数、硬编码量分层）。
