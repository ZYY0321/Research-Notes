# 口径修正：两类「检查」不要混

会里说的「最终可验证」，指的是 **数据和任务交付**：

| | 交付可验证（主线） | 构建期检查（辅线） |
|---|---|---|
| 目的 | 已有任务能否用 store 判定成功/失败；多套初始数据下是否仍可判定 | 合版前评估「改起来贵不贵」、有哪些坑要返工 |
| 产物 | 任务 `check_goals` + `getState`；场景注入 | `scan_binding_risks` 等 hint；走查意见 |
| 不是 | 用来给 app「打分写得咋样」的交付物 | 不是对外验证脚本包 |

**多数据**属于交付主线（训练/评测多样性），不是构建检查。
