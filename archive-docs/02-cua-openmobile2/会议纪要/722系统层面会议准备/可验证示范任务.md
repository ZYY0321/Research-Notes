# 可验证示范任务清单（全量口径）

演示的是 **任务级判定读 store**，不是全功能脚本包。

## 咔皮（新建 suite `kapi`）

| 任务 id | 模板大意 | 场景注入 | 判定（getState） |
|---|---|---|---|
| `ToggleReimburse` | 把「午餐不报销」标成报销 | `kapi/reimburse_mix` | `bills[b_demo_off].reimburse === true` |
| `AddExpenseBill` | 空账本上记一笔支出 | `kapi/empty_bills` | `bills.length === init+1`；budget 仍在 |

跑法（需模拟器 :3000）：

```bash
# 例：列出
python -c "from bench_env.task.registry import TaskRegistry; print(TaskRegistry().list_tasks('kapi'))"
```

## 淘宝

| 任务 id | 作用 |
|---|---|
| `AddItemToCart` | 已有：加购 → cart 出现该商品 |
| **`AddItemToEmptyCart`（新建）** | 先注入 `taobao/empty_cart`，再加购 → 明确展示「多数据 + store 真变」 |
| **`PayOrderWithAlipay`（新建）** | 结算并用支付宝支付；判定新单 `payMethod==支付宝` 且已付；**exclude** 微信 subscriptions 长度不变 |
| `ClearAllUnread` 等 | 已有 suite，可按需抽 1 条作辅演示 |

## 会上演示顺序（建议）

1. 注入 empty_cart / 打开购物车（空）→ 切英文 Tab「Cart」→ 切深色  
2. 跑 / 手走 `AddItemToEmptyCart` → 读 `cart` 变长  
3. 咔皮：`ToggleReimburse` 前后读 `reimburse`  
4. 淘宝结算 → 支付宝（跨 app）→ `PayOrderWithAlipay` 口径  
5. 口头：若前端硬编码、store 不变，这些任务会 FAIL —— 这就是交付可验证
