## 4. 关于怎么写交接文档的经验（避免下一个窗口重复犯错）

用户对"给别人看的文档"反馈了很多轮，规律很明显，总结一下：

- **不要把"我们自己怎么验证/怎么审计判分逻辑"这类内容写进给外部协作者的文档**——她反复强调这个（审计脚本细节、"判分逻辑怎么验证过"这两块内容都是先加进去又被要求删掉的）。这类内容只在**给她自己看**的文档（比如这份、`04-...md`）里才有意义。
- **不要用抽象术语不解释就抛出来**（比如"边界"），要么解释清楚，要么如果跟对方任务无关就整段删掉，不要含糊其辞。
- **不要大段重写文档**——她明确说过"不要老是把之前重要的东西删了"，宁可用增量的 `StrReplace` 编辑，也不要为了响应一条新反馈就重写整个文件，容易把之前改对的内容又冲掉。
- **给外部协作者的文档，优先级顺序应该是**：环境怎么起 → 任务/代码具体在哪（要具体到文件路径和真实任务原文示例，不能只给目录名）→ 怎么判断任务有没有完成（要有具体机制说明，不能一句"读state打分"带过） → 怎么接外部 agent/工具调用。
- **她要的是具体、可核查的东西**（真实任务原文、真实文件路径、真实数字），不是概括性描述。
