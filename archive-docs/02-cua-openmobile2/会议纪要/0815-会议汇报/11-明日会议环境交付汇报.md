# 周报：环境验收、新任务与 GUI+Tools 实验

---

## 一、本周干了啥

这周有休息，其余时间主要做三件事：**把环境收到能交付、做一批新的 GUI+Tools 任务、用轨迹当探针查 App 质量。**

1. **新复刻 App 验收与修补。** 从代码、默认数据、导航声明、App Tool 和截图里核对每个 App 真正能走的链路。人走查之外，用 Agent 轨迹找人手容易漏的断点（地址不回写、搜索叠栈、日期选择器滚不动、滚动带着分类走等），修了一批再准备复跑。
2. **新做了一批更接近真实用户目标的任务。** 不只是查一个字段或写一条笔记，而是跨页面筛选、填写、确认、回读。当前保留 **31 个新复刻 App、218 条任务、137 个 App Tool**。
3. **跑 GUI-only / Hybrid 对照，并在评审台上逐条看。** 先看轨迹，再在模拟器里自己走；每条只判：可运行、题要改、还是 App 走不通。失败先归因到环境 / 任务 / 数据 / Agent / 基础设施。

这周 218 条是新任务、新 App 面上的质量探针，语义 verifier 还没铺完，**不报 SR**。

### 4. GUI 与 App Tool 同一业务世界

社区：GUI-only benchmark 假定 App 永不开放接口，API-only benchmark 假定全部开放。现实是部分 App 会以查询、草稿、定位这类能力开放，敏感提交仍留在界面。社区缺的是：**同一任务、同一初始态、同一终态判定**下，比较「只点屏幕」和「点屏幕 + 调用该 App 已开放的能力」。这里的 Tool 与 GUI 写同一 store，不是环境外第二套假数据。  
本轮实验：这就是第二实验本身。当前交付的是**固定 Tool 配置**（137 个，按前台 App 暴露；查询/定位/草稿为主，敏感提交走 GUI），不是已经做好的「开放度旋钮」。


| 特性                    | 现状                                                                             |
| --------------------- | ------------------------------------------------------------------------------ |
| App Tool              | **137 个**，与 GUI 共用 store；Runtime 只暴露当前前台 App 的 Tool。                           |

## 三、本周实验结论

问的是：给了现在这一套固定 Tool，模型用不用、用得对不对。不是「Tool 越多越好」，也不是已经做成了「开放度可调」。

Hybrid 新跑次 **176 / 218 已出，还没跑完。** 调过 Tool 的只有 20 条（共 44 次）。COMPLETE 是模型自己说做完了，这批还没有完整判定，**不报成功率**。上周 183 条有判定：纯 GUI 约 58%–60%，Hybrid 按难度约 70%–90%。

### 1. Tool 在，但模型大多没调；调了也往往太晚

176 条里只有 20 条用了 Tool。菜鸟先在寄件表单里点了 21 步，第 22 步才去调驿站列表；倒数日在日期选择器里转了约 40 步，第 41 步才调草稿。所以现在看起来 Hybrid 没有明显优势，首先是**没用上**，还不能说这套 Tool 没用。

原因：模型默认按屏幕往下点；Tool 又是进了当前 App 才出现，此时界面路线已经定了，不到卡住不会去换一条路。有的题目标本身也不在 Tool 覆盖的范围内，不调是正常的。

### 2. 真正省步数的，是一次填好好几个字段

倒数日用 Tool 一次写好笔记本、重复、提醒、置顶，界面上只点保存：大约 5 步对上纯 GUI 的 14 步。上周记账一次写入、购物车一次核对，也是这类。价值在「少翻好几页」，不在调用了几次。

原因：这些字段在界面上分散在好几个子页，点屏幕必须逐项进去；Tool 是对着同一份数据一次写完，少的是翻页和漏填，不是少点了两次无关的按钮。

### 3. 这个 App 没有 Tool 时，模型有时会直接放弃，而不是改去点屏幕

拼多多一条：Hybrid 第 4 步就说「没给这个 App 的 Tool，做不了」然后停了；同一题纯 GUI 还在继续点。所以「没调 Tool」要分成两种：有 Tool 却不用，和没有 Tool 却当成任务失败。

原因：Hybrid 模式下模型把「有 Tool」当成任务能做的前提，把「没给快捷方式」理解成「这条路不存在」，没有退回纯点屏幕。这是模型策略，不是环境把 GUI 关掉了。

### 4. 步数更少，不一定是做成了，也可能是更快发现做不成

番茄待办一条：要找的待办本来就没有。Hybrid 用搜索 Tool 8 步确认没有就停了；纯 GUI 翻了 34 步。如果只报「Hybrid 步数更少」，会把「更快放弃」算成「Tool 有用」。

原因：Tool 直接问数据层，空结果一次就能确认没有；点屏幕只能一页页找，找不到也不知道是没有还是没翻到。步数比的是「多快做出判断」，不是「多快做对任务」。

### 5. 和 Claude 的分歧

它说的「先看有没有、有没有调用、调用有没有改路径」可以用。  
不把「开放度」讲成这周已经做成的事。我们交的就是现在这一套固定 Tool。

原因：开放度要成为实验变量，得真的做出几档配置再对照；当前只有一档，拿它当贡献是把还没做的事说成已经做了。

1. 环境按 7 月验收表可交：可验证、可重置、真实系统交互；本轮新增 GUI 与 137 个 App Tool 共用 store。
