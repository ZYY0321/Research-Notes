# 2026-07-21 App 人工走查全量问题记录

## 1. 记录范围

本文记录 2026-07-21 在 `main` 分支模拟器中人工体验发现的问题。当前是体验走查结果，不代表已经覆盖每个 App 的全部页面；“没有写到”不等于“没有问题”。

截图证据位于：`图片收集/`。

严重级别：

- **P0 阻断**：核心链路走不通、导航错误、返回卡死、状态与界面矛盾、筛选/搜索得到错误结果。
- **P1 严重**：主业务明显缺失、大量可见入口无效、运行时数据不联动、页面与真实 App 明显不符。
- **P2 体验**：局部视觉不还原、Emoji、图文重叠、数据不够丰富等；如果成片出现，应整体按 P1 处理。

## 2. 跨 App 共性结论

### 2.1 当前验收不能只看“按钮有反应”

不少页面能切换高亮、弹出 Toast 或记录一个状态值，但实际列表、统计结果、个人动态和展示文案没有变化。正确验收方式应是完整走一条常用链路，并验证每一步的可观察结果。

最低要求：

1. 从首页进入主业务；
2. 执行搜索、筛选、选择或创建；
3. 验证结果列表或详情确实变化；
4. 返回相关聚合页，验证数据已联动；
5. 逐级返回首页，确认没有循环和错跳；
6. 重新进入页面，验证应保留的数据没有恢复成硬编码初始值。

### 2.2 真实 App 是唯一事实源

疑似存在根据同类 App 自行补页面和按钮的情况。例如唯品会购物车出现“去凑单”，需要回到真实唯品会截图或录屏核对，不能因为淘宝有类似交互就直接照搬。

处理原则：

- 有真机证据：按证据实现。
- 没有证据：向采集者确认或补拍。
- 无法确认且非核心：移除入口。
- 禁止保留 AI 猜测出的页面、文案和业务流程。

### 2.3 同组 Tab 和按钮必须能力一致

一个页面展示了完整 Tab 组，用户自然会认为每个 Tab 都可用。不能只有第一个有内容，其余仅切高亮或完全无响应。若短期不实现，宁可缩减为真实且可用的范围，也不要展示大片空壳。

### 2.4 状态和数据必须统一管理

搜索历史、评论、动态、筛选条件、音质设置、统计周期等不应分别硬编码在页面组件里。应由 App store/defaults 提供统一事实源：

- 构建时种子数据保证多样性；
- 用户操作通过 action 写入运行时状态；
- 所有依赖页面订阅同一状态；
- 刷新或重新进入页面时遵循真实产品的持久化规则。

### 2.5 长期记录类 App 的种子数据不足

记账、任务、阅读、习惯等 App 只准备某一天的数据，会直接导致周/月统计、时间轴、趋势图和筛选功能失去意义。主列表至少应有 5 条多样数据，长期记录类还应覆盖多个日期和多个分类。

### 2.6 视觉资产和布局仍需人工把关

共性问题包括：

- 用彩色 Emoji 代替真实图标；
- 直接用通用线框图标，未核对真实 App；
- 显眼图片缺失或使用低相关占位；
- 图片与文字重叠；
- 页面结构过度简化；
- 展开弹层后背景异常空白。

视觉质量不能只由 AI 自评，必须对照真机截图逐页检查。

## 3. 分 App 问题

### 3.1 百词斩

整体判断：主要学习功能基本可用，但页面视觉还原度不足，功能完整性不均衡。

发现：

- **P1：部分 Tab 的功能几乎未实现。** 若一个完整 Tab 暂时没有有效功能，应考虑从当前交付范围移除，而不是保留空壳。
- **P1：商城商品详情中的多个 Tab 点击后没有实际页面或内容切换。** 代码中 `MallDetailPage.tsx` 的“商品/晒单/推荐/详情”只更新 `dtab` 和文字样式，主体区域没有按 `dtab` 分支渲染，因此用户观察成立。
- **P1：学习主页面与真实 App 的结构、视觉密度和资产风格差距较大。**
- **P2：多个显眼图标呈通用线框风格，需要逐项核对真实 App 图标来源。** `res/icons.tsx` 是手写通用 SVG；其他页面还直接使用了 🎒、🎮、🎧、📝、🐶 等 Emoji。
- 商城页已经有较完整的商品图片，这是正向项，但不能用商城资产完成度掩盖学习主流程的视觉问题。

代码核查结论（对“没有生成图片”的修正）：

- “百词斩没有生成图片”这一说法不准确。`assets/` 下已有 83 个文件，包含单词图、商品图、文章图和头像，并有 `gen_assets.py` 生成脚本。
- 图片引用链路本身是正确的：`assets/index.ts` 用 `import.meta.glob` 引入本地 PNG，`components/common.tsx` 的 `WordImage`、`ProductImage`、`ArticleImage` 会优先渲染这些图片，缺失时才回退为 CSS 色块。
- 商城列表确实通过 `ProductImage` 正确显示本地商品 PNG，截图中的商品图不是远程临时链接。
- 因此准确的问题应表述为：**已有且正确引用了部分生成图片，但首页和大量功能页仍使用通用手绘 SVG、Emoji 或简化布局，资产风格没有按真实百词斩统一，导致整体还原度低。**

截图：

- `图片收集/百词斩.png`
- `图片收集/百词斩2.png`

整改验收：

- 每个保留的主 Tab 至少有一条可完整走通的链路；
- 商品详情 Tab 切换后标题、内容或状态必须真实变化；
- 对照真机截图复核首页布局、底栏图标和学习卡片；
- 明确列出图片、SVG、图标组件和 Emoji 的使用清单，替换显眼占位资产。

### 3.6 喜马拉雅

整体判断：搜索、持久化、返回、设置展示和深层交互均存在严重问题，是本轮应优先整改的 App 之一。

- **P0：选择不同音质后，选中状态有记录，但页面展示始终是“高清音质”。**
- **P0：进入“三个点/更多”并向下滑动后，页面会自动回到顶部。**
- **P0：互动消息的页面跳转目标错误。**
- 搜索、历史、设置值和展示文案疑似由不同状态源控制。

- `图片收集/喜马拉雅1.png`

## 4. 整改优先级

第一批（先修阻断）：

- Flomo 导航、遮罩和返回；
- 唯品会返回/导航错误；
- Boss 直聘筛选与兼职 Tab；

- 番茄 ToDo 统计周期不联动；

- 拼多多购物主链路；

第三批（统一提质）：

- 替换 Emoji 和低保真占位；
- 增加跨日期、跨分类、多状态种子数据；
- 修复图文重叠和页面样式偏差；
- 为每个 App 增加一条完整高频链路的运行时回归走查。
