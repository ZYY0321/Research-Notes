# App 复刻：认领清单 + GitHub 协作说明

分两部分：一是 App 怎么认领，二是把项目拉下来之后怎么组织文件、怎么提交。

---

## 一、认领规则

- App 按难度分 5 档：**高=5 / 中高=4 / 中=3 / 中低=2 / 低=1**。
- **每档各认领 1 个，共 5 个，难度合计 15 分**——这样每人工作量自动均衡，不会有人全是硬骨头。
- **表里的 App 只是参考**。认领后可以换成**同类型**的别的 App（例：把「滴滴」换成「高德打车」「T3」，把「知乎」换成「即刻」），只要难度相当、且不和下面「已有 App」重复即可。
- 认领后在该行「负责人」列写名字，先到先得。

> 抢 App 别各自改这个文件再推 git（同一文件 6 人并发会冲突）。先在一份在线表格里抢，抢完由一人统一回填、提交一次。

### 已有 App（不要重复做）

## 三、文件怎么组织

拉下仓库后，和复刻有关的就四类东西：

| 路径 | 是什么 |
|---|---|
| `docs/` | 流程文档（手册、pipeline 规范），以及每个 App 的复刻中间产物 `docs/<app>-replication/`（spec.json、审核页、清单等） |
| `tools/` | 审核页生成、走查标注、各类校验脚本 |
| `trial_apps/mobilegym/apps/<App>/` | App 代码，结构统一：`pages/` 页面、`components/` 组件、`data/` 假数据、`manifest.ts` 身份、`navigation.declaration.ts` 导航 |
| `<app>_images/` | 你拍的真机截图，**只在本地**，不进仓库 |

你做一个 App，AI 只会动**两个属于这个 App 的文件夹**：`apps/<App>/`（代码）和 `docs/<app>-replication/`（过程产物）。别人的 App 在别的文件夹，互不相干。

新 App 由平台扫描 manifest **自动识别，不需要改 OS 层或任何公共文件**——这是 6 个人能并行而不冲突的原因。唯一的公共文件是依赖锁文件：正常复刻用不到新依赖，AI 若提出要装包，先在群里同步一下。

## 四、GitHub 基本操作

仓库：`https://github.com/ZYY0321/mobilegym-mock`（**private，只有被邀请的协作者能看到**）

> ⚠️ 两条 git 操作别搞混：
> - **拉最新代码/规范** = `git pull`（往下拉，随时可做）
> - **交你做好的 app** = 推到你自己的分支 + 开 PR（往上交，由组长审核合并）
>
> **任何人都不要直接 `git push origin main`**——main 是大家共享的、始终要能跑的分支，直接推容易把它搞乱。一律走 PR，由组长统一 merge。

**一次性准备**
- 组长把仓库设为 **private**（Settings → General → Danger Zone → Change visibility），再在 Settings → Collaborators 把每人加为协作者（否则看不到、也推不上去）。
- 各自安装 Git、Node ≥ 22，拉下项目并跑通模拟器：
  ```bash
  git clone https://github.com/ZYY0321/mobilegym-mock.git
  cd mobilegym-mock/trial_apps/mobilegym
  npm install && npm run dev      # 打开它给的地址即可看到模拟手机
  ```

**开自己的分支（一人一条，只开一次）**
```bash
git checkout -b zhang          # 用你的名字，你的几个 App 都在这条分支上做
```
平台会扫描加载所有 App，一个没写完的 App 推到 `main` 会拖累所有人的 `npm run dev`。所以大家各自在自己分支上干活，`main` 始终保持能跑。

**每做完一个 App（在自己分支上提交、推送到你自己的分支）**
```bash
git add trial_apps/mobilegym/apps/Jingdong docs/jingdong-replication
git commit -m "京东复刻：阶段④审核通过"
git push -u origin zhang        # 推到你自己的分支 zhang，第一次带 -u，之后直接 git push
```

**一个 App 完整能跑了 → 开 PR，等组长合并（不要自己合 main）**
1. 推完分支后，到 GitHub 仓库页面点 **Compare & pull request**，base 选 `main`、compare 选你的分支 `zhang`。
2. PR 里写清做完了哪个 App，勾一下下面的保真四要素自查（见 `docs/collaboration-and-doc-update.md`）。
3. **由组长审核 + Merge**。合并后，别人 `git pull` 就能看到你的成果了。

合并进 main 后，想继续下一个 App，先同步一下再干：
```bash
git checkout zhang
git merge main                 # 或 git pull origin main，把别人已合并的成果同步到你分支
```

> 为什么不自己 `git push origin main`？因为 8 个人都往 main 直推，只要有人手滑或没先同步，就可能把 main 弄乱、连累所有人跑不起来。统一走 PR、由组长一个人把关 merge，main 才始终干净可跑。

**两条约定**
- 提交时**只 add 你自己 App 的两个文件夹**，不要 `git add .`。
- 截图不进仓库——`.gitignore` 已忽略所有 `*_images/`，正常提交不会带上。

**几个常用命令**
| 想做的事 | 命令 |
|---|---|
| 看当前改动 | `git status` |
| 拉最新代码/规范 | `git pull` |
| push 被拒（落后于远端） | 先 `git pull` 同步，再 `git push` |
| 误把截图加进了暂存 | `git rm -r --cached <app>_images` 后重新 commit |

操作中拿不准，把 `git status` 的输出连同报错发给 AI，它会给出下一步。
