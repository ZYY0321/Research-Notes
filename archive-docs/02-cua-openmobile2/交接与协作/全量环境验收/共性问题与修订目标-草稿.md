## 1. 先讲清楚：这套 App 是拿来干什么的

这套 App 不是产品，是 **GUI agent 的实验环境**。我们在上面做三件事：

1. **收集数据**：让 agent（或人）在 App 里执行任务，记录"看到什么界面 → 做了什么操作"的轨迹，用来训练模型。
2. **设计任务**：比如"把一件蓝色 XL 的卫衣加入购物车""给帕梅拉的帖子点关注""退掉某一单"。任务要有明确的、可程序化验证的完成标准。
3. **评测**：agent 跑完任务后，脚本读 `store.getState()` 判断任务是否完成。**判分不看界面截图，看 store。**

所以修 bug 的标准和普通产品不一样。普通产品问"体验好不好"，我们问两个问题：

- **这个 bug 会不会让做对了的 agent 被判失败？** 比如 agent 正确地点了"关注"，但状态没写进 store，验证脚本读出来是"未关注"——这就产生了一条假的失败数据（假阴性）。这种数据混进训练集，模型会学到"点关注是没用的"；混进评测集，我们分不清是模型不行还是环境坏了。
- **这个 bug 会不会让某类任务根本没法设计？** 比如点任何一个商品都跳到同一个商品页，那"找到 X 商品并购买"这类任务就没有区分度——agent 随便点都"对"，这类任务直接作废。

反过来，纯视觉瑕疵（圆角不对、字体偏大）既不影响判分也不影响任务设计，可以先放。这就是全文优先级的来源：

- 🔴 **必须修**：会让任务无法完成，或完成了无法验证
- 🟡 **建议修**：会缩小可设计的任务范围，或降低数据可信度
- ⚪ **暂不处理**：不碰上面两条的，先放

## 3. 共性问题详解

每类按同一结构写：**本质 → 为什么对实验重要 → 期望目标 → 怎么发现 → 实例**。实例只列典型的，逐 App 完整清单见附录 D。

### 3.1 操作结果没有真正落进 store 🔴

**本质**：界面上"看起来成功了"，但状态只存在于某个页面的 `useState` 或一个 toast 里，没有写进统一 store；或者写了，但少填了字段；或者写了，但只有一个视图去读它，别的视图还是硬编码的初始值。

**为什么重要**：判分读的是 `getState()`。没落库 = agent 做对了也判失败，产生假阴性数据。这是所有问题里对数据污染最直接的一类。

**期望目标**：P0 主链路的每个关键操作（加购→购物车数量变、下单→订单列表出现、付款→支付状态更新、发评→评价列表出现、关注→关注列表更新、消息已读→红点消失）写入统一 store；写入时把影响各视图可见性的字段（时间戳、分类、优先级等）全部填齐；所有展示该状态的视图读同一份数据。

**怎么发现**：做一次操作后切到别的 Tab 再切回来，结果还在吗？同一状态在两个页面都有展示的，两边一致吗？新建一条数据后，去每个理论上该看到它的视图找一遍。代码层面：搜主链路操作的 handler，看它调的是 store 的 action 还是本地 `setState`。

**实例**：京东（微信支付成功回来无标识；"退款中"订单仍可再点申请退款；足迹不更新）、腾讯视频（开通会员支付成功回来会员状态不变）、大众点评（评价选的相册图片没持久化）、唯品会（发的评价刷不出来）、苏宁（消息红点不消、清空聊天无效、退款订单同时出现在两个列表）、Keep（关注状态跨视图不一致）、滴答清单（四象限新增任务没传 `dueTs`，"今天"视图永远看不到，只在收件箱里）。

### 3.2 跳转参数硬编码 🔴

**本质**：跳转时没把 id 带过去（或带的是写死的值），点列表里任何一条，进去都是同一个固定对象。

**为什么重要**："找到特定对象并操作"是一大类任务。所有入口都通向同一个对象，这类任务就没有区分度，评测无效。

**期望目标**：所有带参数的跳转（商品 id、订单 id、地址 id、演员 id）把正确参数带进目标页。

**怎么发现**：同一个列表里点第 1 条和第 2 条，进去的内容必须不一样。对每种列表都做一次。特别注意"编辑"类入口：点"修改地址"进去的应该是这条地址的回填页，不是空白新增页。

**实例**：京东（退款固定商品、"修改地址"跳空白新增页、"立即购买"结算整个购物车、收藏店铺点不进）、腾讯视频（演职员都跳同一个演员）、猫眼（电影和演职人员错配）、大众点评（评价点不进单条详情）。

### 3.3 返回死循环与死路 🔴

**本质**：导航栈管理不对。两种表现：两个页面互相 push，返回来回横跳；错误状态页没有任何可点元素，彻底被困。

**为什么重要**：agent 退不回根节点，这个 session 后面的所有任务作废——单个 bug 能造成的最大面积数据损失。

**期望目标**：任意路径连按 5 次返回能回到首页；错误状态页必须有返回或重试按钮；筛选用页内 BottomSheet 弹层，不新开页面；Tab 切换一律 `mode: 'replace'`。

**怎么发现**：走到最深的页面连按返回数次数；刻意触发错误态看还有没有能点的东西；跑导航声明图的环检测工具能自动扫出候选环。

**实例**：唯品会（筛选是独立页面，返回陷入"商品页→筛选页"循环，已修）、腾讯视频（推荐列表连续点进新剧无限叠层）、猫眼（选座"订单信息缺失"页无任何按钮）、喜马拉雅（搜索页↔结果页互推）、闲鱼（发布 Tab 用了 push，一行修复）、菜鸟（返回只回上一页，不回主功能页）。

### 3.4 搜索/筛选叠进导航栈 🔴

**本质**：搜索/筛选的每次操作都往历史栈里叠一层，而不是页内状态变化。

**为什么重要**：agent 取消搜索要逐层弹出历史，产生大量无效操作，学到"取消→取消→取消才能回家"的错误模式；且搜索态下底部 Tab 常常消失，agent 失去所有快速导航手段。

**期望目标**：搜索的清空/取消是页内状态变化，取消一次直接回到搜索前的页面；底部 Tab 在任何状态下保持可见。

**怎么发现**：连续搜两个不同的词，然后点取消——一次就该回到搜索前的页面。

**实例**：Keep（两次搜索叠两层，取消按 4 次才回主页，全程 Tab 消失）、番茄小说（同根因，且搜索是它的主链路，几乎绕不开）。

### 3.5 按钮无响应 / 反馈只有 toast / 界面突变 / 弹层被遮 🔴

**本质**：agent 和环境之间"动作→反馈"的约定被破坏。四种形态：点了没反应；反应只是一个几秒就消失的 toast；有反应但界面跳到非预期位置；弹出的东西被别的层遮住。

**为什么重要**：agent 靠截图感知世界，截图有延迟。点了没反应或反馈消失太快，agent 分不清"成功""失败""没发生"，会重复操作；弹层被遮更隐蔽：再点一次反而把弹层关了，陷入"点→看不到→再点→关掉"的循环。

**期望目标**：核心链路按钮必须有实际响应，且响应以持久的界面变化呈现（状态标签、列表项、页面跳转），toast 只能作附加提示；操作完成后页面停在结果附近，不自动滚回顶部；所有弹层 z-index 高于底部导航栏。非核心功能可以标"暂未开放"，核心链路不行。

**怎么发现**：把主链路每个按钮点一遍，问"界面上留下了什么持久变化"；做一次编辑后看页面停在哪；把每个"⋯"、加号、分享按钮点开看弹层是否完整可见。

**实例**：京东（搜索框出不了键盘、购物车无删除入口）、百词斩（阅读页切集/字号/播放全无响应）、唯品会（收藏"管理"出不来删除态）、Slack（加号无响应、待处理项目只能标完成不能新增）、滴滴（货运"功能未开放"只有短暂 toast）、小日常（编辑打卡后滚回顶端；"⋯"菜单被底部 Tab 遮住）。

### 3.6 多条路径要都通、且结果等价 🔴

**本质**：同一功能有多个入口，有的断了，有的走完结果和另一条不一样。

**为什么重要**：任务描述写的往往是最自然的那条路。这条路断了，agent 按正常思路走就被判失败——功能明明存在，假阴性。结果不等价更隐蔽：agent 选了看起来更快的路，走完规格不对，验证失败，错的是环境。

**期望目标**：到达同一功能的每个入口都能走通；不同入口走完的结果等价，或明确标注差异。

**怎么发现**：对每个核心功能，刻意找第二条路走一遍，走通后比较两条路的最终 store 状态是否相同。

**实例**：Keep（"管理日程→添加训练"只能从空的想练清单选，此路不通）、猫眼（想看清单里的演出点不进订票，必须回首页重搜）、苏宁（快捷加号 vs 详情页加购规格不同）、淘宝闪购（快捷加购后底部无结算入口，比真机多一步）。

### 3.7 筛选/排序不跟当前上下文 🟡

**本质**：筛选/排序不作用于当前搜索词和品类，而是跳到一批无关内容；或切换父级 Tab 后子筛选残留。

**为什么重要**："在当前结果里筛出特定商品"是一大类任务，筛选乱跳则结果无法预测，任务无法设计也无法验证。

**期望目标**：筛选/排序只作用于当前上下文；切父级 Tab 时子筛选自动清空；筛选后列表有可观察的变化。

**实例**：唯品会（搜"裙子"点颜色 Tab 跳到鞋子）、大众点评（餐厅 Tab 筛了"日料"，切到奶茶咖啡 Tab 筛选还挂着）、京东（搜索结果的综合/推荐/筛选栏无效、国补专栏切 Tab 列表不动）、滴滴（订单筛选 Tab 点任何一个都是"暂无相关订单"）。

### 3.8 环境与真实 App 的偏差 🟡

**本质**：哪怕功能都能走通，环境和真机的偏差本身就是污染。三种：初始状态不对（一打开就是特殊模式）；数据太少太同质（任务设计不出来）；真机自动发生的步骤在环境里要手动触发（agent 学到假的操作序列）。

**期望目标**：无操作时显示正常默认状态；至少 3 个品类/关键词能搜出明显不同的结果，评论/推荐按归属对象区分；真机自动触发的步骤环境里也自动触发。**购物类 App 可直接复用拼多多的商品数据扩品类**（现有 App 里数据丰富度最高的）。

**实例**：淘宝闪购（默认就显示"夜间远距离配送"）、京东（几乎全是电子类商品、冰箱评论里混着电脑和食品评论）、腾讯视频（各剧评论区雷同）、大众点评（只有美食，"玩乐"Tab 里还是食物，必吃榜换城市数据不变）、滴滴（司机接单要手动点才跳转）。

### 3.9 专项：深色模式 / 中英双语 🟡

要求：`res/strings.ts` + `res/strings.en.ts`、页面走 strings hook；有 `colorsDark`、页面用 `bg-app-*` / `text-app-*` token；切英文后排版不乱。另注意京东出现过 **App 内切语言把整个模拟器系统语言切了**的问题——App 设置只能影响本 App。

- 仅缺深色：Baicizhan、Boss、Xiaorichang、Ximalaya、FanqieXiaoshuo、Maoyan、Meiyou、Weibo、Broadcast、Luckin、Didi、Keep、Tencentvideo
- 缺中英+深色：FanqieTodo、Vipshop、Daysmatter、Ctrip、Douban、Flomo



### 3.10 ⚪ 暂不处理

时间紧时可以跳过：视觉细节（轻微重叠、圆角字号、状态栏配色）；非主链路大类标"暂未开放"（借贷/保险/企业账号/硬件扫码）；多点一次但能到达的（番茄小说阅读后返回多按一次；滴滴"我的"进订单跳到行程 Tab）。判断标准始终是那两问：**会不会让做对的 agent 被判失败？会不会让某类任务无法设计？** 都不会，先放。

## 4. 讨论项：系统能力接入（分享/相册/剪切板/支付）

走查里反复出现一类问题：分享显示"功能未开放"、复制没进剪切板、下载不进相册、支付不走跨 App 支付桥。**这些大多不是 App 逻辑写错了，是两边没对齐**：系统层只能调用 App 在 `manifest` 里声明过的接口，App 自己写一套私有逻辑，系统层不认，这个能力对评测框架就是"不存在"的（比如菜鸟复制快递单号后，验证脚本读系统剪切板永远是空的）。负责人侧则不清楚系统层有哪些能力、标准接法是什么、该谁改。

已就绪的能力和标准接法：


| 能力               | 标准调用方式                                                                    | 已知未接入              |
| ---------------- | ------------------------------------------------------------------------- | ------------------ |
| 跨 App 支付（微信/支付宝） | `window.__OS__.startActivityForResult('com.mobilegym.PAY', {...})`        | 猫眼、苏宁 等            |
| 系统分享             | `window.__OS__.startActivityForResult('com.mobilegym.SHARE', {...})`      | 猫眼、Slack、淘宝闪购、菜鸟 等 |
| 系统相册/图片选择        | `window.__OS__.startActivityForResult('com.mobilegym.PICK_IMAGE', {...})` | 小日常（下载卡片）等         |
| 系统剪切板（复制）        | `window.__OS__.copyToClipboard(text)`                                     | 菜鸟（复制快递单号）         |


是否就定为"App 里有这类入口的一律由负责人改成标准调用，系统侧不逐个代接"，并把上表发给负责人自查。另有三个小待定项：支付密码是否统一"任意 6 位通过"（优酷疑似只认 123456，agent 无从知道密码）；各 App 默认地点是否统一（猫眼提出）；生图版权（出现过迪士尼内容，是否全换虚构）。

## 5. 合并与催修

现有流程本身没有大问题，本轮暴露的主要是两点，对策都是"催及时"：

1. **改动要及时开 PR、及时合**。这轮出现过分支从旧节点切出、合并时和 main 上的系统接线冲突的情况（京东），自动合并还引入过一个不报冲突、只在运行时崩溃的悬空引用；也有负责人把上千行改动堆在个人分支不开 PR（cjl，唯品会 1481 行、微博 1236 行），人联系不上时险些作废。→ 要求：提 PR 前先合最新 main；改完当天开 PR（draft 也行），以 PR 为唯一交付信号。
2. **点名的问题要及时修、及时更新状态**。唯品会的 P0 返回死循环 07-21 就点名，挂了 17 天；豆瓣、Flomo 代码早修好了但跟踪表还挂着"待处理"。→ 对策：定期把附录 D 按 App 拆条发群里 @负责人，只发 🔴 和截止日期；点名后若干天无回应的，由 AI 代修并抽查后合并关闭（本轮对点评、唯品会、拼多多已这么做过）；合并时由合并人顺手更新跟踪表。

| 2   | 四象限新增任务颜色与同优先级其他任务不一致（`quadrant` 未映射到 `priority`） | 新建流程走了不同的数据路径，同优先级任务外观不一致，干扰 agent 对优先级的视觉判断   | 新建任务按象限设置对应优先级         | 🟡  |




### 跨 App 共性问题


| #   | 具体现象                | 为什么重要 / 影响                 | 预期结果                                               | 涉及 App          |
| --- | ------------------- | -------------------------- | -------------------------------------------------- | --------------- |
| 1   | 支付密码疑似硬编码为 `123456` | agent 跑支付任务时无从知道密码，任务无法完成  | 密码框接受任意 6 位数字即视为成功                                 | 优酷及其他有密码支付的 App |
| 2   | 深色模式缺失              | "深色模式下完成某任务"整个维度无法设计和评测    | 补充 `colorsDark`，页面用 app 色 token                    | 见 3.9 节列表       |
| 3   | 中英双语缺失              | "把 App 切到英文再操作"整个维度无法设计和评测 | 补充 `strings.ts` + `strings.en.ts`，页面走 strings hook | 见 3.9 节列表       |
