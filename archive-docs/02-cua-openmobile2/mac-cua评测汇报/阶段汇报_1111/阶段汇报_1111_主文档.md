# Mac 端 CUA 刷数据进展：WPS 表格、剪映、美图秀秀

## 概要

- 三个应用共出了 522 道基础操作题（WPS 表格 262、剪映 137、美图秀秀 123），另外在 WPS 文字/演示、LibreOffice、OBS、Obsidian 上补了几十道。
- 用 DeepSeek v4.1-flash 和 Opus 5.5 在 Sky 后端上各跑了一遍，每道题跑一次。跑出来的轨迹做了逐条自动评审，初步判断能用的约 250 条，还没有人工抽查，也还没有提交。
- DeepSeek 上周大面积失败的主因是联网搜索断流（框架未关 web_search）；**已汇报，生产机/集群已关**，关搜索后的重跑（E24）在推进。当前待办不要再把「联网搜索没关」列为第一项。
- 需要晨阳确认几件事，见「需要确认的事」。

## 主要发现

1. **（已处理）联网搜索曾让 DeepSeek 大量中断。** 上周数字：WPS/剪映 289 道里 106 道被搜断；关 `web_search` 后的重跑见 E24，不要再当未解决问题讲。
2. **不被打断时，DeepSeek 和 Opus 水平接近。** 两个模型都正常跑完的 180 道同题里，Opus 成功 171 道，DeepSeek 成功 168 道。被搜断的题偏难，这 180 道偏容易。
3. **数据透视表、筛选、插入图表是能做的**（以前失败多因去搜索）。剪映导出改分辨率/帧率仍难：Sky 上导出下拉点不开。
4. **DeepSeek 当年搜过的词仍是难点清单**（可写进提示），但这不是「搜索还没关」的论据。
5. **Opus 通道曾持续 502**；桥接器吞状态码的问题仍开着（见给伟鑫分册）。
6. **关搜索之后**更值得看的是：坐标/截图尺寸、CLI 产物与 WPS 评分口径、剪映 Qt 下拉、假成功与自检——应用「原文摘录 + Fable 组织」，不要只报标签计数。

## 需要确认的事

1. **怎么提交。** 集群上跑的结果是不是已经自动存到数据平台了？如果没有，是否用框架里的 `export_successful_sft.py` 导出 JSONL 后上传，上传入口是哪个？
2. **命令行优先提示下，哪些轨迹算数。** 模型实际会用到这几种做法：调用应用自带的宏；用 AppleScript 按屏幕坐标点界面；用命令行生成素材后再导入应用。这几种是不是我们想要的轨迹？
3. **带试错步骤的轨迹怎么处理。** 不少成功的轨迹中间有一段反复尝试，是整条收、去掉试错部分再收，还是不收？
4. **成功率很低的题少刷。** 剪映导出时改分辨率和帧率这类题，在下拉框问题解决前，建议先少刷或不刷。
5. **把 Sky 的已知问题写进提示。** 比如剪映里拖拽不生效、粘贴内容不对，写进提示能省掉模型大量试错。具体条目见给陈瀚的文档。

**《框架与集群问题》，给伟鑫**

6. 结果里记录提示版本与 web_search 开关；环境中断单独标记，不要记成模型 0 分。

**《Sky 后端问题》，给陈瀚**

1. 往路径输入框里 paste 没有生效，框里显示的是之前的历史记录，模型误以为粘错了内容；剪映 33 条轨迹里 28 条遇到。改用 setValue 可以绕开。
2. 剪映里拖拽素材到时间线没反应，也不报错。陈瀚判断是 Sky 拖得太快、又不能调速度。可以改点素材卡片上的「+」，但这个按钮要悬停才出现，得点两次。
3. 剪映导出窗口里的分辨率、帧率下拉框点不开，相关题成功率很低。
4. WPS 表格主窗口里按坐标点击，经常报 noWindowsAvailable。
5. 按键名区分大小写（要写 Return 而不是 return），报错时不提示正确写法，模型会挨个试。
6. 点剪映自己画的按钮（比如导出确认），可能返回成功但其实没生效。模型不检查文件的话，就会误以为做完了。
7. 截图尺寸不一致的问题，想确认是不是 Sky 这一层造成的。
8. 想法：第 1、2、5 条可以写进 Sky 的提示，文档里附了建议写法；第 3、4、6 条是原装 Computer Use 本身的行为，需要往上反馈。

**《评测与题目问题》，给鸣谦**

1. 评测 DeepSeek 时如果还开着联网搜索，会有大量任务中途断掉，成功率被严重低估。建议在评测配置里确认关掉，或者把这类中断单独统计。
2. 评分和实际结果不一致的几类：
   - 判定方式太死，比如马赛克题原来按平滑程度判断，已经改过；
   - 只看导出产物判断不了，比如「关闭原声」「只变速不裁剪」；
   - 过程有副作用但导出产物正确，比如剪映里多出一条空时间线。
   想一起定一下评分口径。
3. 剪映导出时改分辨率和帧率这类题，成败主要取决于后端能不能点开下拉框，建议评测时单独列出来。
4. 比较不同模型时，要去掉被联网搜索或模型服务报错中断的运行，否则会明显低估 DeepSeek。更公平的做法是关掉搜索后重跑一遍再比。
