**前三项说明**

**问题 1：联网断流**

- 机制：框架生成 Codex 配置时，只对走 Claude 通道的模型把 `web_search` 设为 disabled，其余模型为 live。DeepSeek 卡住时发起搜索，火山返回「账号未开通 web search」，Codex 重连 8 次后整题结束。
- 证据：WPS/剪映断流的 106 道中，97 道在断流前一步的推理里刚决定搜索。各批通过数见第二节总表。
- 限制：init 脚本断网不可行，Codex 与模型请求本身依赖网络。截至 11-10 晚，`dev/codex_v2.0`（`8134325`）中 `src/mac_cua/runtime/agent.py` 第 85 行未改。
- 文件：`/Users/zhangyingying/CUA/评测集建设/实验/E20_DeepSeek集群批量覆盖/analysis/统计_E20.md` 第 1 节；`/Users/zhangyingying/CUA/评测集建设/汇报/群消息_1110_DeepSeek联网与刷数据.md`「21:03」一段。

**问题 2：Claude 502**

- 机制：报错来自框架内的 Claude 桥接器（`127.0.0.1:<端口>/v1/responses`）。桥接器把上游任何错误统一报成 502，只记录「HTTPError」，上游状态码和请求 ID 均未保留。
- 证据：11-11 上午把一份当时失败的请求原样重发 TokenHub（`claude-opus-5-5/awsb_L/sfa`），HTTP 200，3.2 秒返回。该请求约 5 万字节，题目仅走 2 步，可排除请求本身的问题。
- 时间：集群为 11-10 约 23 时至 11-11 04:20；生产机为 00:45–02:40、03:23–06:43。11-11 08:15 起重跑正常。
- 材料间的分歧：业务线汇总称该现象「与上下文大时报 502 一致」，依据是遇 502 的轨迹更长（中位 41 个动作，未遇到的为 26 个）。重发结果更支持「上游间歇故障」，轨迹长也可以解释为请求次数多、更容易遇上故障。两种解释目前不能区分。
- 文件：`/Users/zhangyingying/CUA/评测集建设/实验/E21_Opus纯GUI与CLI优先刷数据/实验卡.md`「结果」；`/Users/zhangyingying/CUA/评测集建设/实验/review/fable_1111/facts_1111.md`。

**问题 3：stop_unconfirmed**

- 机制：模型已结束，框架停止 agent 时未能确认相关进程退出，评分不执行。轨迹仍在。
