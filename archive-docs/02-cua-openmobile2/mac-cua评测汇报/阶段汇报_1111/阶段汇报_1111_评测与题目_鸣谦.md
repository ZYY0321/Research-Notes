# 评测与题目问题

刷数据时发现的几件事，对评测也有影响。

## 1. 评测 DeepSeek 时联网搜索会造成大量中断

之前周会上提过评测时禁用 web search。目前框架只对 Claude 关了，DeepSeek 仍然开着；火山账号没开通搜索，DeepSeek 一搜任务就中断。我们这边 289 道题里有 106 道因此中断，只成功 7 道。

如果评测 DeepSeek 时还没关掉，成功率会被严重低估，而且被低估的集中在它不熟悉的功能上。建议在评测配置里确认关掉，或者把这类中断单独统计，不算作模型失败。

## 2. 评分结果和实际完成情况不一致

逐条看轨迹时发现，评分通过但其实没做完，或者评分没过但其实做对了，两种情况都有。主要几类：

- **判定方式太死**：美图马赛克题原来用「平滑程度」判断是否打了马赛克，模型实际打好了也判失败。改成「边缘细节是否明显减少」后，重跑全部通过。
- **只看产物判断不了**：例如「关闭原声」，单看导出的音频，分不清是模型关掉了原声还是素材本来就没有声音；「只变速不裁剪」，变速 1.5 倍和裁成同样时长的结果长度一样。这类需要读工程文件或逐帧比对。
- **过程有副作用但不影响产物**：例如剪映里模型绕路时多建了一条空时间线，导出文件是对的，但工程文件是乱的。评分要不要管这类情况，需要定一个口径。

## 3. 有些题主要受后端限制

剪映导出时修改分辨率和帧率：导出窗口里的下拉框在 Sky 上点不开，模型只能绕路，DeepSeek 9 道成功 3 道。这类题的成败更多取决于后端，而不是模型能力，建议评测时单独列出来，或者在下拉框问题解决前先不纳入。

## 4. 对比不同模型时要去掉被中断的运行

把 DeepSeek 和 Opus 在同一批题上比较时，如果不去掉被联网搜索或模型服务报错中断的运行，会明显低估 DeepSeek。两边都正常跑完的 180 道同题里，Opus 成功 171 道，DeepSeek 成功 168 道，基本持平。

但要注意，去掉中断后剩下的题偏容易，因为 DeepSeek 通常是卡住了才去搜索。更公平的做法是关掉搜索后重跑一遍再比。
