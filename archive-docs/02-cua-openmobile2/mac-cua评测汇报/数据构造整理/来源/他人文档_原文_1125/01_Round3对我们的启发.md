## 终值是对的，格子、符号和整列对应是错的

三道 Round2 判过、Round3 判 0 的题，坏法一样：有一个总数或一个终值对得上，逐格对不上。

清洗题。模型想点开「删除」看菜单。点下去之后，选中的格子被删掉，物料编号整列上移一格，订单和物料对不上。它看见 B2 空了，只再把 B2 清一次。检查只断言行数、表头、B2 为空，以及数量和状态的筛选条件，没有逐行对物料号。Round2 第 2.1 节的订单题已经是「异常文字写进了格子，模型看见了仍继续」。这题多出来的是：一次本意是查看的点击改动了数据；把「这一格清空」当成整列已经恢复。驱动上，「菜单按钮」一点是展开菜单还是直接删除，报告要求拿两种辅助功能动作分开复测，并写现有轨迹不够判驱动实现错误。

第二节，excel-clean：

> 主要根因是模型把局部清空当成恢复；Driver 的「menu button」默认点击是否应展开菜单，还需要对控件的 AXPress/AXShowMenu 分开复测，现有轨迹不足以直接判 Driver 实现错误。

债券题。公式能跟着变。折价摊销列写成了「票息减实际利息」，出来是负数；期末余额再减去这个负数，又回到对的数。模型读回过这个负数，随后宣布完成。Round2 这题在结果表上是 1 分，正文没有讨论符号。Round3 写明，不能把这次失败说成没有原生公式，也不能说成完全不会联动。

第二节，excel-bond：

> 不能将 C03 失败简化成「没有原生公式」或「完全不会联动」。

> 修复方向是逐列检查经济含义和符号，而非只验证公式存在与最终余额等于面值。

## 出题上可以改的判据

判据写到「这一格、这一列、这一个对象」上的值，以及符号代表的意思。全文里找得到这几个字、行数对、公式在、最后余额等于面值，Word 和债券都会漏。Round3 把这三道 0 分留成模型问题，没有改判。出题可以直接用他们写的负向样子：带空单元格、重复订单、相似编号的清洗；往 Word 表格里粘贴带制表符的文本；债券改过价格、利率、票息之后，每一列的符号仍然要对。验收写逐格、逐列含义。他们第四节写：正确样本要同时盖住模型推导、在应用里写入、以及一次独立的公式或扰动检查。

空占位和多出来的有效数据写成两条规则。Keynote 这种题，可见的三根柱子对，文件里还有没有数值的系列，现在会整题 0。他们建议检查器把两样分开，避免模板留下的空系列直接整题 0，同时多出来的有效系列仍然严格。我们这边单色图的经验是：规则收紧之前，先写明什么样的「多出来的结构」算错。没写明，就不要把 0 分讲成模型不会做图。

终值可以把错的中间列抵消掉。债券就是这样。断言如果只锁终值，这道题在我们这边会放过。扰动价格、利率、票息，再看每一列，才能把抵消打出来。

完成条件落到文件名、格子里的内容、效果是否出现。「准备保存」「表已经建好」「快捷键已经按下」都不能当完成。

裁判自己没把条款对齐时，不要改题面去要求模型多说一句固定的话。漏洞题要修的是证据合并。棒球和地标要先修预算配置。报告写其他零分题的题面已经清楚，没有发现必须改题才解得开的歧义（第四节，任务层只保留两点）。

## 质检上对照我们的六类

六类在 `/Users/zhangyingying/Research-Notes/archive-docs/02-cua-openmobile2/mac-cua评测汇报/数据构造整理/04_质检.md`。那份的范围是：评分已经通过，过程不宜直接拿去训练。Round3 重点写的是 0 分、超时和空分。有几类行为对得上，但进不了「已经通过」那个筐。质检要在打分之前分桶，不能等 1 分再套六类。

第二类，推断评分会查什么，再按这个推断选做法。Keynote 第 245 步就是：注意到空类别，推测评估会忽略空项。我们的定义和例子是「这样做之后评分通过了」，Figma 那道新建被挡住、改到别人稿子里仍判通过。这题评分没通过。只在 1 分轨迹里找第二类，会漏掉「猜了但没猜中」。这种 0 分也不要改写成图表数值错了。

第五类，中间一步判断错了，当时没有当回事。Word 数了格数就宣布两列正确；债券读到了负的摊销仍宣布完成；清洗题看见可能删掉了单元格，认为原来是空的、没有影响，只清了 B2。第五类现有的例子是「加粗没生效，看了截图仍以为生效了」。清洗这题多一句我们没写进定义的：看见了反证，把反证解释掉，再用一个局部动作充当恢复。Round2 订单题已经有「看见异常仍继续」，Round3 把「局部清空当成恢复」写成了根因。

第四类，没有新信息，仍反复做同一个操作。地图题是反复清理再导入，直到时间用完。它不完全是「同一步、没有新信息」：中途在怀疑空点，并且改成删掉整层。只数重复次数，这题可能数不进去，代价却更大。我们第四类的处理是整条过滤，把卡住的那一帧留给更强的模型续上。他们同向，多了两句：临近时限不要无备份地删整层；正确的恢复动作留下，局部断言通过就宣布完成的不要留。

第三类，评分和实情不一致。漏洞题作者复核认为做完了，原分保持空分、不改。这是「做完了，没有得到成功分」。裁判 HTTP 503 和预算预检不要塞进第三类。第三类的例子是规则判错了：该过没过，或不该过过了。503 是裁判没判完。报告的原话是：unknown 不等于这项没有证据。剪映「代码通过、裁判空分」更不能收成成功轨迹，因为代码通过只覆盖草稿名。

第一类，换了手段，最终答复里不说。这批报告没有写最终答复是否隐瞒了脚本或结束进程。Hybrid 允许界面和脚本一起用。缺 `openpyxl` 之后改走 XML，他们写成环境绕路，并写明不是债券负号的原因。按我们「脚本可以，要在答复里说清楚」的口径，只有读到答复隐瞒了，才进第一类。这里没读到。

第六类，只在某个后端或环境下才需要的绕法。删除按钮是展开菜单还是直接删除，他们留给驱动复测。浏览器「点击没变化、快捷键有效」也没有写成坐标不准。Word 里一次元素过期，重新观察就恢复了，他们不把这种报错单独算成任务失败（第四节，观察与目标有效性）。第六类仍可以记环境，不能凭「没变化」就定。缺库之后解析 XML，标明环境即可，不必新开一类坏轨迹。

六类里没有、这批有的，质检要单独留档：

只有推理、没有工具调用、也没有最终答复，框架把回合记成完成。第一类有答复，只是不交代手段。「只写了计划」至少有一句回复。这一档在上游原始输出核对之前，不要写成模型主动放弃，也不要贴业务成功或业务失败。

评不出来。服务没有返回判定，或者几条评分项对同一事实说法相反。标签用「未判定」。不要用「模型不会这个应用」或「模型漏读了页面」去填。

临近时限、没有备份就把整层删掉重做。和第四类的重复拖拽并排，不并成一类。

用一个对的终值盖住错的中间列。出题和质检一起看：轨迹上标「终值对、中间列符号错」。我们的检查器如果只断言终值，这条在我们这边会变成第三类误放，而不是像他们那样在评分里就被抓住。

抽样方式本身。跨多次运行取第一次做完，失败重试不进这 50 题。我们若也只归档选中的那一次，质检报告要写选择规则，否则通过率会被读成首跑能力。这不是一条轨迹内部的坏步骤。

## 和我们现有说法哪里冲突

先写对得上的，避免周五说成两边意见相反。

评分只看终态，1 分不等于能当界面正例收。这是核心洞见第八、九、十四条，文件在 `/Users/zhangyingying/CUA/评测集建设/实验/核心洞见存档.md`。Round3 第四节写：「50/50 是结果分与路线分分离。报告不能根据成功分推定严格 GUI 达标。」同一节写 Hybrid 以界面执行为主，命令行用来读和查，少量脚本会直接造内容，不能把整批当纯界面示范。这和「结果导向可以收、界面正例要另算」是同一句的两边。报告没有要求把脚本判成错。

异常结束和空分不贴成功或失败。我们第三类的处理是保留原分、标注、不计入能力。他们的漏洞题和 503 都是留原分、只重评、不重跑 Agent。

下面三处有张力。

结束原因不能一律从归档响应写成「模型放弃」。我们第二类把推理里的话当作模型知道自己在做什么的证据，Figma 那句是 judge may only care output。Keynote 上他们也这么用：推理里推测检查器会忽略空项，他们把这句当成模型的错，原话是「而不是猜测检查器宽容程度」。

分位数这题相反。归档里只有推理，回合被记成完成。原话是不宜写成「模型收敛能力差、主动放弃」，并且 Codex 记下的响应不能证明等于模型服务的原始输出。

质检要拆开。推理里明确在猜规则，按第二类记。只有推理、又没有最终答复的结束，先标协议边界，成因标未核。把「没有工具调用」一律记成模型选择不干，会和后一段冲突。

什么样的 0 分可以叫误判。我们第三类包含两个方向，单色图是像素正确仍被判失败，那条要留着：它是做对了被判失败。Keynote 看起来像同一类，截图上三根柱子是对的，分数是 0。他们拒绝两头，原话是不要直接记为画错图，也暂不擅自改判为 1 分。同一节把 Word、清洗、债券排除在误判之外，原话是不能因「文字都在」「最终余额对」判为评估器误判。

张力在口径。单色图是像素全部正确仍失败。Keynote 是可见柱子正确，文件里仍有空系列。把「看起来对、分数是 0」都叫误判，就和他们这句冲突。先分清多出来的是占位还是有效数据，再决定改分还是改规则。

点击没有可见变化，先不要归到模型或驱动。我们第六类有一条：控件点不生效，就改成按坐标点。那是 Sky 上读过轨迹之后的归类，这条案例仍然成立。Round3 的原话是：仅凭「没变化」不能证明 Driver 点错，也不能直接归为模型坐标不准；删除控件的两种动作，现有轨迹不足以直接判 Driver 实现错误。新轨迹在复测之前，第六类和「模型没点准」都先不要写死。清洗题记成「一次本意是查看的点击之后，数据变了」，驱动语义标成待核。

没读到、所以不能说成冲突的：

杀进程，以及最终答复隐瞒手段。Round3 正文没讨论。我们第一类仍按自己的轨迹说话。

诚实受阻当正例。分位数没有最终答复，说不清卡在哪，也不符合「没有声称做完」——它是框架替它结束的。他们建议的是有限续接一次，不是把这次结束收成正例。不要拿它填我们缺的那一类。

重复步删不删。我们这边还没有团队定论。他们没有说把重复步删掉。他们说的是局部断言通过就宣布完成的不要收成完成，正确的恢复要留。这和第四类「卡住的时刻留下」不相反。

Preview 在 Round2 是源文件被改坏，Round3 结果表上是通过，正文没有写这次有没有先做副本。不能说他们推翻了「编辑前要保护输入」，也不能说这题已经学会了。
