# 各应用可取状态清单（2026-11-26）

给荧滢和 mentor 讨论三件事：真实复杂业务题能出到多深、验证拿什么当证据、初始状态放在哪一层才重置得干净。

本轮只读了题包评分脚本、E31 已有探针和公开文档。没有打开本机任何图形应用，没有用 osascript 驱动应用，没有登录两台生产机。Figma 没有新打接口，是把 11-25 已经存下的返回又数了一遍。令牌不在本文、也不在同目录 csv 里。

证据三档：

- **实测**：某次运行或已保存的接口返回里，这个状态真的被读出来过。
- **文档**：官方文档，或我们仓库里的评分/初始化代码写了怎么读，但本轮没有再执行。
- **推测**：从产品行为推出来，没有对上的页面或代码。

「评分方能否隔离读取」问的是：评分能不能在模型碰不到的通道上读（云端只读令牌、虚拟机外）。「模型能否改」问的是同一份状态，坐在虚拟机里的模型能不能把它改掉。两件可以同时成立：Figma 文件既能被机外的令牌读到，也能被登录进同一账号的模型改掉。

## 题包里还有的应用

前七个之外，题包里已经有读取器的，按「状态在哪」归在一起。证据都是评分代码（文档），本轮没有执行 osascript，也没有跑 Blender。

**日历、备忘录、提醒事项、照片、快捷指令** 在 `zyy-e31-nologin-v1/shared/nologin_grade.py`。评分种类 `app_state`，去重后日历约 5、提醒约 6、备忘录约 7 个题号。脚本只导出名称或正文里含 `E31` 的对象，每种最多 500 条。

- 提醒事项：标题、正文、列表、完成、旗标、优先级、到期时间。
- 照片：相册名、文件夹名、文件名含 E31 的条目和是否喜爱。
- 快捷指令：文件夹、名字、动作个数、是否接受输入。动作内容不在导出里。

**Blender**：`grade_blender_file` 用 `blender -b`（后台，不开界面）跑一段读取脚本，看对象位置、修改器、名字。30 个题号。文件在本地，随镜像。模型可以改 blend 文件。这是「应用脚本在机内读，但不打开 GUI」的例子。

**LibreOffice**：ods/odt/xlsx/docx 用标准库解 XML。Calc 的求和、冻结、改表名、统计在 `prog_grade.py` 和 `e14_grade.py`。没有「必须由 LibreOffice 保存」的产品标记门。本地文件随镜像。

**Obsidian**：库目录里的 markdown，以及 `.obsidian/core-plugins.json` 等配置。随镜像。模型能改。

**文本编辑 / 预览 / 访达**：RTF 里是否有文本编辑的特征串、某词是否粗体；PDF 里的框和文本；替身和窗口视图。都是本地文件或 AppleScript。`nologin_grade.py` 的 `grade_textedit`、`grade_preview`。

## 跨应用的共性

**评分方能在模型碰不到的地方读**

- Figma 的节点树、评论、样式、少量原型跳转：只读 REST 已经打通，令牌可以只放评分侧。免费个人账号的「已发布组件」和「版本历史」接口返回是空的，变量接口按文档要 Enterprise。
- 飞书的日程、忙闲、消息、新版云文档：开放平台文档写了读接口。我们没有令牌，一条都没打通。这是「原理上能隔离，工程上还没接」。
- Mail 若改走我们自己的 IMAP，或在宿主机读 Envelope Index 的副本，也可以隔离。现行评分是虚拟机内的 AppleScript，模型碰得到。

**只能靠导出物，而且模型也能改那份导出物**

- 美图：只有保存的图片。没有工程读取器，也没有「必须由美图写出」的标记。
- 剪映基础题：只有导出的视频和音频。草稿正文按我们的代码是加密的，评分拒绝解析。
- Photoshop 的主流量题、Figma 的可评分题、WPS 的全部自动评分：证据都是虚拟机里的文件。文件格式能解析得很深（PSD 结构、xlsx 公式和筛选、docx/pptx），但模型有终端就能改同一份文件。隔离的办法是收工后把文件拷到模型写不到的地方再判，现行评分没有这一步。

**目前读不到，或读到了也不能当终态**

- 剪映的转场名称、曲线变速、具体字幕文字。
- Photoshop 的历史、当前工具、没保存的参考线；动作列表现行评分不读。
- Mail 的规则条文、签名库、密送收件人（现行脚本不取密送）；旗标只在计数器里，生产自测还注明不读真邮箱。
- 飞书桌面端上的搜索、未下载的消息和日程。本地只有登录痕迹。
- 美图的配方、历史、批量队列。
- 只活在屏幕上的面板页、对话框。验证方法把这类标成证据最弱，适合当长任务的中间步。

**和初始状态、重置的关系**

- 本地文件（PSD、xlsx、导出视频、剪映草稿目录、美图导出图、WPS 设置）随镜像重置，适合每题一份干净磁盘。
- 账号云端（Figma 文件、飞书消息和日历、Mail 服务器上的草稿和已发送）不随镜像重置。一台虚拟机清空，会碰到其他机器上同一账号的信。开跑前要有一份模型改不到的基线，评分只认基线之后的 id。
- 登录态是第三层。飞书在 11-22 的自检里，存进镜像再开回到了登录页。Photoshop 的登录能否活过快照，没有测量。WPS 登录窗和 Excel 订阅框是启动时的环境，不是作品。

**对「真实复杂业务题」的直接含义**

能出深的，是状态已经在可解析文件或已打通的云端接口里的那些：WPS 里多步改表再核对每个格子；Photoshop 里多步修图后核对 PSD 结构而不只核对一张缩略图；Figma 里先改组件再核节点树和评论，而不是只核导出 PNG。Mail 和 Apple 日历可以出「先查现有事项再决定」的题，但 Mail 现在只倒草稿的主题和正文，日历脚本只导出标题含 E31 的事件，空闲时间要另算。飞书的「查忙闲再约会」接口在文档里，接上之前出了也评不了。剪映和美图若题的对错不体现在导出像素上（哪种转场、哪套配方），现在没有终态可评。

## 需上机核

不要在她这台 Mac 上开这些应用。生产机现在在跑别的探针，下面留到机器空出来再做。每条都是只读。

1. **Mail 字典和规则文件。** 在已登录的虚拟机里打开 Mail 的 sdef，确认抄送、密送、签名、规则的属性名；只读打开 `~/Library/Mail/V*/MailData/SyncedRules.plist` 和 `Signatures/`，看规则条文和签名正文是否在盘上。不要发信、不要改规则。对照：现行 `DRAFT_SCRIPT` 不写密送。
2. **Envelope Index。** 同一台虚拟机、完全磁盘访问权限下，只读查 `messages` / `mailboxes` 的行数，和 AppleScript 倒出来的草稿数是否同量级。确认版本目录是不是 V10。
3. **旗标脚本真机走一遍。** `grade_mail_flag` 的 8 个题号，自测注记写不读真邮箱。找一封已打旗标的信，只跑计数脚本，看返回是不是比基线大。
4. **Photoshop 历史和动作。** 打开一个已有 PSD，用已授权的 ExtendScript 只读打印 `historyStates` 的名字和动作组名字，看未登录和已登录是否都能读。不要录新动作。偏好目录里的 psp，抽一个键做前后读，补上探测里「列了目录但没比对」的缺口。
5. **Figma 最近文件。** 用只读令牌试「一个账号下有哪些文件」，确认新建文件的 key 能不能在评分侧发现。不要写评论、不要改文件。原型只在「论文配图」里看到 2 条点击跳转，换一个有多条连线的文件再读一次 interactions。
6. **飞书。** 在已有测试企业、且令牌不进仓库的前提下，只读打日程列表和忙闲。桌面端「记住登录」活过快照与否，要单独一次：登好、拍快照、回滚、看还在不在登录页。本轮没有令牌，不能代打。
7. **剪映草稿字节。** 在已有草稿的虚拟机里，只看 `draft_info.json` 的前几十个字节是不是 JSON。不要解密。确认 `com.lveditor.draft` 的实际路径和 `probe.py` 里写的是否一致。
