# Figma 云端状态，能不能从评分器这一侧读出来

## 做了什么
用她的免费个人账号的个人访问令牌（存私密目录，不在仓库），只读调用 `api.figma.com/v1`，对她给的文件「论文配图」读了五个接口。原始返回在 `figma_rest/`（不含令牌）。没有写评论、没有改文件。

## 读到了什么
- **文件节点树能读**：三个页面，节点类型里有 FRAME、RECTANGLE、TEXT、VECTOR、INSTANCE 和 83 个 COMPONENT，文件里还有 1 个组件集、30 个样式、85 条组件元数据。也就是说「组件做没做、叫什么名字、被实例化几次」可以从节点树直接判，不依赖本地导出图。
- **评论能读**：每条评论带 `created_at`（精确到毫秒）、`message`、挂在哪个节点（`client_meta.node_id`）。这给了归属判据：开跑前先记下已有评论的 id 集合，收工后新增的评论就是本次产生的。
- **文件 `lastModified` 能读**，可以当粗粒度的「有没有被改过」。
- `/components` 与 `/component_sets` 这两个接口只列「已发布到团队库」的组件，免费个人账号读出来是空的，不能用，要从节点树里数。
- `/versions` 对这个文件返回空，免费账号拿不到可用的版本历史，不能当基线。

## 对周五问题的含义（倾向，不是定论）
1. **「云端状态本地读不到」只对了一半**：本地的确没有，但 REST 能读到节点树和评论，所以 115 道评不了分的题里，Figma 的组件、评论这几类**原则上是读取器欠账，不是原理限制**。还没试的：原型连线（交互数据在节点属性里，免费账号能否取到没验证）、分支。
2. **归属有现成办法**：评论用「开跑前的 id 集合」做基线，组件和节点用节点 id 集合做基线，都比对「文件有没有出现过」更硬。
3. **限制要说清**：
   - 读取要有目标文件的 key 和令牌，评分器要能拿到题里模型实际编辑的那个文件，而我们的题让模型新建文件、文件 key 事先不知道，需要从应用里或从账号的最近文件列表取，这一步没验证。
   - 令牌是个人的，团队文件要有权限。
   - 一个坏处（周会也提到）：读取通道和 agent 可用的工具如果重合，题目会退化成「读一下就能做」，所以读取只放在评分器侧，不给 agent。
