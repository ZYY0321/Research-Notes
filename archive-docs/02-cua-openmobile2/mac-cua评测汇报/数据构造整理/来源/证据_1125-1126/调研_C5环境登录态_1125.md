我们这边要回答的事：Photoshop 一个账号最多同时登录两台、且帮助页还写同一时间只能有一台在用；Mail 所有任务共用一个邮箱，并发会互相删草稿；Figma 团队账号被锁、新账号要邮箱验证；飞书桌面登录可以扫码，也可以手机号或邮箱；WPS 启动有关不掉的登录窗；Office 弹订阅提示。框架每个任务从镜像重新启动，登录态难留；不重启则上个任务的状态会累积。

## 1. 公开基准怎么处理「要登录的应用」

下面每条都是：设置、做法、代价、链接。

**OSWorld（Xie 等，arXiv:2404.07972，本次打开的是 PDF 文本）和现行仓库指南。** 设置：真实桌面虚拟机。配置文件指定一份虚拟机快照（某一时刻的整机状态，可以随时恢复），再加下载文件、打开软件等准备步骤。作者写，不为每题单独存一份快照，因为硬件状态会让每题占到若干 GB；流程是启动模拟器并回到对应快照、可选地下载文件、可选地再执行准备命令。ChromeOS 被排除，理由是功能绑在 Google 账号上，不适合公开基准。做法分两层。整机状态靠快照。需要 Google Drive 的题另走账号：现行 `SETUP_GUIDELINE.md` 要求两个账号分开——云项目管理员保持两步验证，永不进虚拟机；基准测试用户只放可丢弃的 Drive 数据。虚拟机里的 `_login_setup` 只填邮箱和密码，完成不了两步验证、通行密钥、CAPTCHA 或其他交互式验证。每个并发环境一套测试账号和凭据，因为共用一个 Drive 会让准备和评分互相干扰。浏览器登录和 Drive API 的 OAuth 必须是同一个测试用户；API token 不能代替浏览器登录。外部测试应用的刷新令牌，指南写 Google 文档为 7 天。登录过不了挑战时，用 `evaluation_examples/test_nogdrive.json`，去掉 8 道 Drive 题，369 里剩 361。代价：登录态不在快照里自动长出来，每次准备都要重新登录；并发上限等于你愿意注册并维护的 Google 账号数；令牌会过期；指南明确写不要假定手工登录能活过虚拟机重置。另一份仍能打开的文档站页面（`timothyxxx.github.io` 的 Google Account Guideline）写的是相反操作：注册空账号、忽略安全建议、关掉两步验证，并承认即使关掉，换 IP 或换设备仍会要手机验证码，而且没有永久办法，建议不要频繁换登录 IP 或设备。该页也写官方接受 369 题或 361 题两种报法。两页今天都能打开，页面上没有「旧文已废」的句子。以仓库现行指南为准时，不能再写成「OSWorld 让你关掉两步验证」。https://arxiv.org/pdf/2404.07972 https://github.com/xlang-ai/OSWorld/blob/main/SETUP_GUIDELINE.md https://timothyxxx.github.io/OSWorld/installation/google_account_guideline.html https://github.com/xlang-ai/OSWorld/blob/main/desktop_env/desktop_env.py

**OSWorld-Verified（XLANG 博客，2025-07-28，不是论文）。** 设置：约 10 人、两个月，处理 300 多条社区反馈；有问题的题优先只改评分器。做法里和登录相关的是：反爬、CAPTCHA、IP 限制改用代理、换功能相当的网站、对要人工验证的任务固定分配一个 IP；受外部网站拖累的任务，博客写正在做受控网页（simulated environments，标成 WIP）。托管初始文件从 Google Drive 迁到 Hugging Face，因为下载一多 Drive 会临时封掉所有人的下载。官网通知：8 道 Google Drive 题即使按指南配置，仍可能因 IP、网络、API 限速或地区而初始化失败；手动修好跑满 369，或去掉这 8 题跑 361，两种都允许上报。代价：登录和反爬没有被解掉，而是从分母里拿开，或换成别的站；受控网页还是进行中，博客没有给出已经替换了多少题。https://xlang.ai/blog/osworld-verified https://osworld-v1.xlang.ai/

**WebArena（Zhou 等，arXiv:2307.13854 HTML）和 VisualWebArena。** 设置：自建的购物站、论坛、GitLab、电商后台、地图、维基，各打成一份 Docker 镜像，数据在镜像里，不挂外部卷。论文附录 A.3 写每个站有一个固定角色（购物顾客、GitLab 维护者、论坛活跃用户、店主），并用预先缓存的 cookie 自动登录。仓库 `env_config.py` 把这些固定账号写死。VisualWebArena 再加一个分类广告站，`prepare.sh` 调用 `auto_login.py`，用 Playwright 登录后把 storage state 存成 cookie 文件。做法：要改数据的题，停掉并删掉容器，再从原镜像拉起，论文写这个重置从几秒到一分钟；只读题他们不要求题题重置。分类广告站另有一个 HTTP reset。代价：账号池不存在，因为整站是自己的，一个容器上的写操作会留给下一题，除非重置；并行写同一份容器会互相踩；cookie 要在评测前重新生成，过期就登不进。这是「固定账号 + 整站重置 + cookie 注入」，不是每任务一个账号。https://arxiv.org/html/2307.13854 https://github.com/web-arena-x/webarena/blob/main/browser_env/env_config.py https://github.com/web-arena-x/visualwebarena/blob/main/environment_docker/README.md https://github.com/web-arena-x/visualwebarena/blob/main/prepare.sh

**AndroidWorld（Rawles 等，arXiv:2405.14573 HTML）。** 设置：Pixel 6 模拟器、Android 13、116 个任务、20 个应用，开源应用版本钉在 F-Droid。做法：论文写选用不需要登录、数据存在本机的应用；每题有自己的初始化、奖励和拆卸；时间钉死；奖励主要用 adb 读文件系统、应用数据库和系统设置。代价：登录墙被选题排除掉了，覆盖不到银行、邮件、要账号的协作软件。应用数据目录快照（`save_snapshot` / `restore_snapshot`）出现在第三方 DeepWiki 对代码的转述里，论文正文这次没有这套 API，标未核实。https://arxiv.org/html/2405.14573

**AndroidLab（THUDM，arXiv:2410.24024；仓库 README）。** 设置：9 个应用、138 个任务，预装进 AVD 镜像。做法：选题标准写明每个应用必须离线、不需要用户账号登录，以免外部依赖和隐私问题；镜像里预置使用记录；每题开始用 adb 把时间和虚拟地理位置钉死。代价：同样是不碰登录。没有账号池，也没有 cookie 注入。https://arxiv.org/abs/2410.24024 https://github.com/thudm/android-lab/

**macOSWorld（arXiv:2506.04135 HTML）。** 设置：AWS 上的真 Mac mini（为符合 Apple EULA），每题从公开 AMI 快照启动，再用 SSH 上的 zsh 或 AppleScript 做应用级准备（拷文件、打开带内容的文档）。快照按语言复制。论文写评测结束后快照恢复会丢掉全部内容和系统改动。做法：登录态如果要留，只能烤进 AMI，或写进每题准备脚本。打开的正文没有 Adobe、Figma、邮件或飞书账号。文中的「建账号」例子是 macOS 来宾用户，不是第三方应用登录。高级应用类是否含已登录的第三方软件：没有逐题打开，未核实。代价：官方快照恢复，仓库 README 的超时参数是 1200 秒；第三方 VMware 移植写本地恢复可降到 1 分钟以内，那是移植说明，不是论文数字。https://arxiv.org/abs/2506.04135 https://github.com/showlab/macosworld

**AgentStudio（arXiv:2403.17918 HTML；在线基准 README）。** 设置：真实设备上的在线环境，205 个任务，含终端、Gmail 和 VS Code、GIMP 等 GUI；动作空间是 GUI 加 API。论文写为自动重置和评分实现了 100 多个函数。在线基准用一份 Ubuntu 22.04 Docker 桌面。做法：Google 任务要操作者自己的云项目、OAuth，首次运行 `setup_api_keys.py` 把 Docs、Drive 等 token 存到本机；建议为基准新建一个日历，并用临时邮箱当收件人。每题配置里有 reset 和 cleanup（例子：拷文件、打开、做完后删目录并杀掉进程）。代价：Google 侧的数据是真的，README 写删除文件、删除日历事件等不可逆，要求账号里不要放重要数据。README 没有写「每个并发环境一套 Google 账号」。并发互踩因此标未核实，只能从「不可逆、且账号是共享的」推出来，不把它写成他们的原话。没有虚拟机快照把登录态烤进去。https://arxiv.org/html/2403.17918 https://github.com/SkyworkAI/agent-studio/blob/main/eval_online_benchmarks/README.md

**Windows Agent Arena（微软仓库 README；`desktop_env.py`）和 UFO 文档里的 OSWorld-W。** 设置：Windows 11 企业评估版 ISO，README 写 90 天试用；先做一次约 30GB 的 golden image，里面有跑基准需要的程序。做法：镜像是「预装软件」的快照，不是论文里写过的登录态方案。本次打开的 `desktop_env.py` 里，远程虚拟机的快照回滚标成 Not implemented，改成关掉所有应用并清理任务文件。本地路径是否真的每题回滚，这段摘录没有把 revert 调用写出来，未核实。WAA 技术报告正文这次没有打开，论文里有没有写 Office 登录，未核实。另一份微软 UFO 文档（OSWorld 的 Windows 子集，49 题，含 Office 365 和浏览器）写的是：黄金镜像生成后，人进虚拟机用一个 Microsoft 账号（文档写临时账号也可以）激活 Word、Excel、PowerPoint，然后停掉客户端，把 `storage` 目录备份成新的黄金镜像。这是本次读到的最接近「把登录态烤进镜像」的桌面实践。代价：评估版系统本身有期限；同一份已登录镜像被复制到多台并发机器上时，微软账号的设备上限这次没有打开官方页，未核实；远程模式不回滚快照，上个任务的窗口状态会留下。https://github.com/microsoft/WindowsAgentArena/ https://github.com/microsoft/WindowsAgentArena/blob/main/src/win-arena-container/client/desktop_env/envs/desktop_env.py https://github.com/microsoft/UFO/blob/main/documents/docs/ufo2/evaluation/benchmark/osworld.md

**OSUniverse（arXiv:2505.03570 HTML）。** 设置：默认是 Docker 里的 AgentDesk 虚拟桌面，每题 YAML 自带容器、setup、任务和检查项。应用类是浏览器、桌面、终端、GIMP、LibreOffice 或它们的组合。做法：每题独立容器，setup 命令准备初始状态。论文结尾写，当前题目受限于「不用设置账号就能用的应用和网站」。代价：他们的选择是不收录要登录的应用，而不是做账号池或注入。没有商业软件登录方案。https://arxiv.org/html/2505.03570

**ScienceBoard（OS-Copilot 仓库镜像手册；主页任务统计）。** 设置：Ubuntu 22.04 虚拟机，六个科学应用（主页写 ChimeraX、GrassGIS、KAlgebra、Lean、TeXstudio、Celestia），169 个任务；基础设施写明基于 OSWorld。镜像手册里的账号是虚拟机本地用户 `user` / `password`，并要求勾上自动登录；客机里放 `reset.sh`。做法：本地系统账号自动登录，应用是装在镜像里的科学软件，手册没有商业云账号。每题评测是否回到快照：手册是制作镜像的步骤，不是评测循环，未核实。第三方 Agent-S 说明写他们自己用每题一台新 EC2，那是移植要求，不是上游手册。代价：不解决 Photoshop、飞书这类账号墙。https://github.com/OS-Copilot/ScienceBoard/blob/main/vm_config/manual.md https://qiushisun.github.io/ScienceBoard-Home/

**TheAgentCompany（arXiv:2412.14161 HTML；`browsing.py`；`servers/README.md`）。** 设置：虚构公司的内网，用可自建软件代替真实服务：GitLab 代替代码托管，ownCloud 代替网盘和办公文档，Plane 代替项目管理，Rocket.Chat 代替即时通信。数据是可重置的模拟数据。做法：论文写这些站可复现、可重置。代码 `pre_login` 的文档字符串写：评测前登入需要的网站，会话缓存在浏览器里，agent 不必再登。Plane 的登录动作旁注写，重置不稳定、登录失败就跳过该题——这句在代码注释里，论文 HTML 这次没有对上，未核实论文是否这么写。服务有 HTTP reset。代价：测的是「像 Slack / 网盘的开源替身」，不是飞书或 Apple Mail 的像素界面；账号是写死的一套，靠整服务重置而不是账号池。https://arxiv.org/html/2412.14161 https://github.com/TheAgentCompany/TheAgentCompany/blob/main/evaluation/browsing.py https://github.com/TheAgentCompany/TheAgentCompany/blob/main/servers/README.md

**WorkArena 与 WorkArena++（arXiv:2403.07718、2407.05291 HTML；BrowserGym 文档）。** 设置：ServiceNow 的 Personal Developer Instance，开发者计划可免费申请，评测用实例管理员账号。WorkArena++ 论文写，在拿不到专有代码的远程实例上，用安装器把主题、知识库、列表和表单钉成统一样子。做法：WorkArena++ 明确写每题开始新建一个用户、结束时删掉，使 agent 改列表列、改界面也不会影响下一题。这是本次读到的最清楚的「每任务独立账号」，账号是 API 在同一个实例里建的，不是一堆互不相通的云租户。原版 WorkArena 是否每题重置实例：2403.07718 正文这次没有定位到等价句子，未核实。代价：仍共享一个 ServiceNow 实例，开发者实例的用户数或并发上限这次没有打开 ServiceNow 的限额页，未核实；实例到期或密码轮换会让整榜停。https://arxiv.org/html/2403.07718 https://arxiv.org/html/2407.05291 https://github.com/servicenow/browsergym/blob/main/docs/src/environments/workarena.rst

### 2026 年新工作里和登录直接相关的

**OSWorld 2.0（arXiv:2606.29537v2 HTML）。** 设置：108 个长流程，真人中位约 1.6 小时。桌面仍是真软件，名单里有 OSWorld 1.0 的 LibreOffice、GIMP、Thunderbird、VS Code、Chrome，并扩展到 WPS、GitLab、Overleaf、Slack、LinkedIn 等。做法：邮件、银行、团队聊天、业务门户改成自建站，初始状态和可评分的终态都由出题人控制；除 Moodle、GitLab 这类能自己部署的，网站都改名，避免 agent 关掉标签后跑去真 Gmail。合成记录只在隐私、发布或可控性需要时使用。代价：邮件和聊天的界面不是 Apple Mail 或飞书；WPS 作为本机应用出现了，打开的章节没有写登录弹窗怎么关，未核实。自建站仍可能被记住捷径，作者把这写进局限。https://arxiv.org/html/2606.29537v2

**Echoverse（微软，arXiv:2607.28074 HTML）。** 设置：要练的能力大多在登录后面（邮件、聊天、银行、病历、内部控制台）。作者写这些不能直接拿来训练：每次都会写进真账号，两次之间没有重置，真实状态在屏幕后面。做法：把应用重做成自己拥有数据库的合成环境，状态真的会变，但可以打破、可以马上重置，评分读数据库而不是看截图。邮件、日历、银行没有公开数据集，就按约束生成种子数据。代价：见第 4 节的迁移数字。界面不是商业客户端。https://arxiv.org/html/2607.28074

**WebHarbor（arXiv:2611.03634 HTML）。** 设置：153 个 Docker 化的网站复刻、3518 个任务，其中需要登录的任务 1117 个（31.8%），会改持久状态的 1253 个（35.6%）。作者写真实网站评测被改版、访问限制和「登录后的流程覆盖太少」卡住；他们的实验里 Online-Mind2Web 约 38% 的任务被机器人检测挡住，WebVoyager 22% 的任务因网站改版过时。做法：人加编程 agent 按任务把站复刻出来，种子用户和密码写在环境里，重置回到确定的数据库。代价：复刻的是网页，不是桌面专业软件；完整复刻商业站被他们写成不现实。https://arxiv.org/html/2611.03634

**Fara-1.5（arXiv:2606.20785v2 HTML）。** 设置：在线环境盖不住的部分——登录后面、会改持久状态、成功标准就是做了不可逆动作——用合成环境。做法：前端、API、数据库和种子数据都自己管，两次轨迹之间重置数据库。另有一道门：agent 若要做账号注册、真登录、真下单、真发消息等，这条轨迹停掉并丢掉。代价：训练数据里故意没有「在真服务上登录」这一段。https://arxiv.org/html/2606.20785v2

**MAI-Gym（arXiv:2610.20939 HTML）。** 设置：手机、电脑、网页共用一条 rollout；另外合成可重置的模拟应用，其中 7 个是对照真实应用做的克隆（12306、建行、滴滴、美团等）。做法：克隆有自己的后端，两次尝试之间重置。代价和迁移数字见第 4 节。没有 Photoshop 或 Figma。https://arxiv.org/html/2610.20939

**VeriEnv（arXiv:2603.10505 HTML，打开的是站点内掌握那一节）。** 设置：把 WebArena 里的站再克隆一份，训练只发生在克隆里，把 WebArena 原站当作「真实服务」的代理。做法：可执行的奖励，不靠截图裁判。打开的实验是同一类站点上越练越强，没有测到桌面商业软件。https://arxiv.org/html/2603.10505

## 3. 登录态怎么进入轨迹质量和评分

这次没有找到一篇把「桌面 agent 遇到 Photoshop、Figma 或飞书登录墙后绕行」点成比率的论文。下面是打开的页面里，登录、验证码或环境故障被如何处理的句子。

**环境故障被从分母拿掉，或被标成坏题，而不是模型能力。** OSWorld 现行指南和文档站都写：8 道 Drive 题初始化失败时，可以改报 361 题。`desktop_env.py` 里准备失败会重试，重试尽了抛错，这段不是「记成任务失败得 0 分」的评分定义。OSWorld-Verified 把 CAPTCHA、IP 封锁写成评分信号变坏的原因，处理是代理、换站、固定 IP，或把题标成可能随环境变化。How Benchmarks Mis-Score（arXiv:2607.28367，本次打开 PDF 文本）抽了 150 条已被记为失败的公开轨迹：15.3% 的 FAIL 不该算 agent 的错（Wilson 区间 10.4–22.0），其中评分器假阴性 10.7%，题或环境坏了 4.7%（7 条）。正文举例：AssistantBench 的开放网页撞上停掉的搜索引擎和 CAPTCHA 墙；有一道 OSWorld 题在发布的虚拟机镜像上做不成。第 2.1 节把「凭据过期、真实网站漂移、专业软件改菜单或文件格式」写成任务失效的来源。他们没有单列「登录墙」这一格，4.7% 不能写成登录失败的比例。https://arxiv.org/pdf/2607.28367 https://xlang.ai/blog/osworld-verified

**有的框架选择不让 agent 看见登录，登录基础设施失败就不记这次尝试。** TheAgentCompany 的 `pre_login` 把登录做在 agent 开始之前。Plane 登录失败则跳过该题，这句只在代码注释里。Fara-1.5 把「真登录、真注册」挡在训练数据外面，轨迹直接丢掉。OSUniverse 的作者写当前题集限于不用账号的应用。AndroidWorld 和 AndroidLab 在选题时排除要登录的应用。这些都是「不要让登录失败污染能力分」，做法是不测、提前登好、或失败就跳过，不是教模型过登录墙。

**只看未登录的表面，会让基准测不到登录后面的工作，也会让裁判只能看屏幕。** Echoverse 写 WebVoyager、Mind2Web、Online-Mind2Web 的覆盖停在未登录访客能做的事，因为没有基准能把真凭据发出去或写进陌生人的账号；成功往往是「找到并读出一个值」，不是存储状态变了；没有后端时，裁判是多模态模型对截图的意见。WebHarbor 写他们实验里约 38% 的 Online-Mind2Web 任务被机器人检测挡住。这是环境故障进了活网站分数的一个公开数字，对象是网页机器人检测，不是我们的四五个桌面应用。

**共享账号会让重置和评分互相污染，这是 OSWorld 写明的。** 现行指南第 3 步：并发环境不要共用一个 Drive，否则准备和评分互相干扰。文档站的旧文用「多个人同时用同一个 Google 账号」解释他们为什么不发公共测试账号。这和 Mail 共用一个邮箱、并发互删草稿是同一类问题，只是他们的对象是 Drive 文件。

## 4. 模拟应用和真实应用，迁移上有什么结论

打开的结论都在网页或手机应用上。没有一篇给了 Photoshop、Figma、飞书、Apple Mail 或 WPS 的 mock 到真客户端的迁移数字。

**浅的模拟会把真站上的分数拉低；深的、状态连得起来的模拟会涨一点。** Echoverse 在 Allrecipes 和 Hugging Face 两个真站上比了只训浅任务和只训有依赖步骤的深任务。浅的：Allrecipes 从基座 80.0 降到 75.0，Hugging Face 停在 48.0。深的：Allrecipes 到 85.0，Hugging Face 到 65.0。作者写这只是两个域、每域几十题，说明浅世界可以比不训练更差，不是「深度值多少分」的估计。同一篇里，登录后的写操作训练迁到以公开浏览为主的 WebVoyager 时，涨幅不大；他们的代码托管世界 EchoForge 加进一个较小的训练混合后，真 GitHub 从 58.5 到 63.4（这是那次消融的数，不是全文主模型的数）。https://arxiv.org/html/2607.28074

**克隆上练会迁到真应用，但差距会变大，克隆上的涨幅不能当成真机涨幅。** MAI-Gym 用 52 个配对任务：只在 12306 克隆里做强化学习，克隆内从 36.5% 到 73.1%，真机 12306 从 28.8% 到 48.1%（加 19.2 个百分点）。克隆和真机的差距从 7.7 个百分点拉到 25.0 个百分点。作者写克隆上的收获不能完全预测真应用。这是手机上的订票应用，评测在物理手机上。https://arxiv.org/html/2610.20939

**在模拟站上训，迁到另一批真网站时可以是负的。** NNetNav（arXiv:2410.02907v2 HTML）写：把 WebArena 模拟站的示范加进真网站训练，13 个真网站里 7 个变差、6 个变好，平均降 1.3 个百分点；真网站上的同站数据则让 13 个里的 10 个变好。作者的句子是，只靠一批模拟网站上的人工轨迹，不够训出通用网页 agent。https://arxiv.org/html/2410.02907v2

**复刻站上的登录流程，会帮到别的网页基准里的登录题，帮的是网页策略，不是商业桌面。** WebHarbor 的 4B 模型在关掉 WebArena 自动登录、把账号写进题面时，总分只掉 2.7 个百分点（对照的 OpenWebRL SFT 和 RL 掉 4.9 和 3.6）。在他们自己的测试集上，认证类能力组相对对照高 13.3 个百分点。Reddit 仍几乎做不出。WARC-Bench（ICLR 2026 PDF）写 agent 在真实任务上的表现低于合成任务，并指向表 2；表 2 里真实和合成的分列数字，这次从 PDF 文本里没有抽出，未核实。https://arxiv.org/html/2611.03634

合在一起，文献支持的是：自己拥有状态的环境才能重置和评分；浅界面克隆可能有害；像真应用的克隆能把一部分技能带到真应用，同时把「克隆上已经很高」错看成「真应用也很高」。没有支持「做一个像 Photoshop 的画板，就能代替在 Photoshop 里采集轨迹」。

## 对我们这几个应用，最现实的做法和还空着的地方

**Mail。** 文献里的邮件不走 Apple Mail。OSWorld 2.0 自建收件箱，OSWorld 1.0 用 Thunderbird，TheAgentCompany 用 ownCloud 存文件而不是邮件客户端。iCloud 的支持页把「同一账号多设备同步同一个邮箱」写成正常功能，所以多台虚拟机共用一个邮箱，互删草稿是产品行为，不是配置疏忽。GreenMail 能按用户分邮箱并整库重置，但是否能作为 Apple Mail 里的账户，未核实。最现实的做法因此是：任务若必须是 Apple Mail 加 iCloud，就一台虚拟机串行，每题开始前把草稿箱清到已知状态，不要并发写同一个邮箱；任务若要的是「邮件客户端里写信、找信」，文献的做法是换成本地 IMAP 或自建收件箱，并接受界面不再是 Apple Mail。空白：没有 Thunderbird 或模拟邮箱迁到 Apple Mail 的数字，也没有 Apple 的评测邮箱。

**Photoshop。** 没有找到评测许可。官方帮助页是两台登录、一台在用、账号不能共用。OSWorld 对 Google 写明不要假定手工登录能活过虚拟机重置；UFO 对 Office 的做法是人登录一次再把磁盘存成黄金镜像。这两条不能合成成「Photoshop 登录烤进 macOS 镜像就稳」，合成本身未核实。最现实的做法是：只做不依赖 Creative Cloud 登录的本地文件题，并把「未登录时 Photoshop 自己的弹窗和默认存盘」当成环境的一部分写进初始状态；若题必须已登录，并发停在帮助页允许的范围内（两台登录、一台在用），用多个独立账号而不是把一个账号分给一个集群。空白：教育版或共享设备许可能否覆盖虚拟机农场，未核实；快照回滚之后 Creative Cloud 登录还在不在，没有公开测量。

**Figma。** 没有评测租户。邮箱注册要收一封验证邮件；Starter 只有 3 个可协作文件。教育计划是学生和教师资格，不是自动化沙盒。Enterprise 才能用 API 复制文件，和我们现在的团队锁不是同一条路。最现实的做法对齐 WebArena 的「自己的站、固定账号、用完重置」，但 Figma 没有自建版：一个并发环境一个已验证账号，文件在开跑前建好，题和题之间不要共用一个会被写的团队文件。账号能否同时登很多台桌面端，未核实，所以不能先假定账号池能堆并发。空白：没有 Figma 桌面 agent 环境的论文；团队锁没有官方的「评测时解除」。

**飞书。** 测试企业是测应用 API 的，仍要手机号，不免除桌面登录。桌面帮助写密码或验证码可以登录，扫码是另一条路；勾选记住登录后，下次打开可以不再验证。管理员可以改这些开关。最现实的两条是分开的。要真飞书客户端的像素轨迹：在镜像里用「记住我的登录状态」登一次，并且评测循环不要回到登录前的快照；并发用不同账号，并预期手机号和两步验证会卡住扩容。要的是聊天、文档、审批这种流程而不是飞书皮肤：TheAgentCompany 和 OSWorld 2.0 用 Rocket.Chat 或自建团队聊天，整库重置。空白：记住登录能否活过 macOS 快照回滚，文档和论文都没写；没有飞书 GUI agent 的公开环境。

**WPS 和 Office。** 最接近的公开做法是 UFO 文档：临时 Microsoft 账号在虚拟机里激活 Office，再把磁盘存成黄金镜像；以及 OSWorld 2.0 把 WPS 当作本机应用、把旁边的网页服务换成自建。Microsoft 365 开发沙盒给了 25 个许可和 16 个虚构用户，但是「仅用于开发、其他用途可收回」，能不能覆盖训练数据采集，本文不判断。WPS 没有找到等价的公开沙盒，学校页走的是 SSO。空白：两家都没有写「启动时关不掉的登录窗」或「订阅提示」在虚拟机里怎么处理；黄金镜像复制到多台机器后，一个微软账号会不会被踢下线，未核实。

总的空白就一件：公开工作要么不收录要登录的商业桌面软件，要么用开源替身或自建网页把登录和重置握在自己手里。Photoshop、Figma、飞书桌面端、Apple Mail 这四者，没有现成的账号池方案，也没有 mock 迁到真客户端的测量。能直接搬的只有隔离原则：并发不要共用一份会写的云状态；登录过不了就不要把这次记成模型失败；快照回滚和云端登录是两套状态，不要假设一起回来。

- Figma 一个账号能同时登录几台桌面端。文件内 200 人编辑不是这个数。
- Figma 教育年限两处口径不一致，没有并成一个数。团队锁能否用 REST API 解开，未核实。
- 飞书「记住我的登录状态」能否活过虚拟机快照回滚。测试企业能否多开桌面客户端，文档没写。某个租户是否强制扫码，未核实。
- Sandbox Apple Account 能否登录 iCloud 邮件。Apple Mail 能否把账户指到 GreenMail。
- Microsoft 365 开发沙盒登录后，Mac 版 Office 的订阅弹窗会不会消失。该沙盒用于采集训练数据是否仍算 “development”，未做法律判断。一个微软账号拷进多份黄金镜像后的设备上限，未打开官方页。
