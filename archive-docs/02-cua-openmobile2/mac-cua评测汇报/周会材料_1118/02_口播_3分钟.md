# 02 口播（3 分钟）

这周讲四段：量、质、两个发现、四个要定的点。

**先说量。** 上周说的联网搜索，框架已经默认关了，重跑没再断。命令行优先那套 399 道，DeepSeek 和 Opus 各跑了一遍。另外新出了三个题包，165 道，铺到 Blender、OBS、Obsidian、LibreOffice、Numbers、Keynote 这些不要授权的应用上，Sky 和自研 driver 同跑。

**再说质。** 手里 2500 多条旧轨迹，这周全部用脚本规则重扫了一遍，不靠 AI 打标签了。分成三档。能直接交的 475 条：评分通过，全程界面操作，没有原地重复。要处理才能收的 1100 多条：评分通过，但用脚本写过文件，或者有原地重复。剩下 900 多条不收。主线 checker 也在本地跑通了，但它放过了 15 条杀过进程的轨迹，所以不能单靠它，要和这三档一起用，细节在给晨阳的附件里。

**这周最重要的发现有两条。**

一是命令行优先那批的分数不能直接用。WPS 题的评分脚本会先查文件是不是 WPS 存过的，不是就 0 分，但题面和提示都没告诉模型。大约 100 道是这么丢的分。Opus 更听提示、更早改用脚本，所以丢得更多。鸣谦那边的评测也有这条规则。

二是界面走不通的时候，两个模型都会去直接改文件。Opus 改了 101 道，每一道都在最后说了。DeepSeek 改了 81 道，我一条条读下来，没有一道明说。这些轨迹评分是 1 分，按现在的规则会被收进去。

**四个想今天定的。**

1. 「必须 WPS 保存」这条规则，是写进题面，还是命令行题不拿它判 0 分。我倾向后者，想和鸣谦统一。
2. 用脚本改文件的轨迹算不算。我的提议是界面题里不算；命令行题里算，但最终答复要如实，DeepSeek 没说的我们可以把那段答复重写。晨阳看行不行。
3. 数据过关之后交到哪。还有上周说的「纠错轨迹比例要少」，是按条数还是按步数算。
4. 试错步骤是删掉、遮掉还是照学，我想做一次小的训练对照，需要一个微调入口，想问找谁。

环境上，DeepSeek 渠道限流和 Opus 的 502 写在给伟鑫的附件里了。办公集群昨天中午起维护，生产机昨天后半天也连不上，有两批补跑还没交上。
