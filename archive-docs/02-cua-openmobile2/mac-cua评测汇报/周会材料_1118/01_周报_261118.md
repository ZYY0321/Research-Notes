**主线checker 检查：1766 条判过，17 条有写具体问题**

1. 汉字变乱码，8 条。例：最终答复：里「我从磁盘重新读了一遍文��」。多数出在模型答复里，像是传输时把汉字切坏了，不是模型行为问题。
2. 答复声称做了其实没做的核对，3 条。例：答复说「抽帧确认画面已倒转」，实际抽了帧但从没打开看过。
3. 同一个点击原样连点三次，3 条。例：剪映里坐标点击报「找不到窗口」，模型不换做法又点了两次。
4. 答复里混进英文草稿，3 条。例：答复中间夹着「Wait file name is…Let's craft:」。
5. 答复里的数字和实际不符，1 条。答复说 47 条数据，工具读到的是 48 条。
6. 误判 1 条：把命令里正常的引号和转义符当成了混进来的特殊标记。

**有问题的数据：我们发现、checker 筛不出来**

1. 卡住的多。评分通过的轨迹 93% 遇到过卡点（DeepSeek 98%、Opus 88%），WPS 和剪映几乎条条都卡；卡点不超过 1 个的只有约 160 条。上次会上要求「卡住的要少」，这批靠筛做不到。剪映的卡点集中（70% 的轨迹遇到拖拽无效），WPS 很分散（最常见的一种也只在 14% 的轨迹里）。换后端能不能减少卡点还没有同题数据，先做 Sky / aside / 自研 driver 同题对照。
2. 最终答复不交代过程和意外。用脚本改文件是允许的（命令行优先提示还鼓励这样做），但 DeepSeek 写答复时会主动省掉过程：命令行优先那批用脚本改文件的 81 道，答复一道都没提（Opus 的 101 道都提了）；推理里常见「We should not mention internal mishap」，误建的时间线、误改的内容这类副作用也不说。不违规，但原样训练会教模型出了意外不说。建议：按轨迹事实补写答复；提示词加一句要求交代方法和额外改动。
3. 用 AppleScript 绕过 CUA 工具操作界面。框架提示词明确禁止（不要用 AppleScript、osascript、System Events 绕过工具），但评分通过的轨迹里约 70 条这样做过，最常见是用 System Events 点掉 WPS「账号登录」弹窗，其次是发按键、强行把窗口置前。默认提示下 Opus 32 条、DeepSeek 11 条，属于违规；命令行优先前缀本身写了「优先用 AppleScript」，和框架规则冲突，那批不算模型的错。建议：默认提示下的剔除或标出；前缀里的 AppleScript 去掉。（数字为粗筛，正在逐条核。）
4. 评分脚本可能误判对一部分题。看到三种：开了筛选但没设条件；用别的软件重建透视表覆盖原表；WPS 高级筛选只存了隐藏行。文件看着对，事没做对。数量还没核，我们逐题查评分脚本。
5. 大段无效重试。DeepSeek 54%、Opus 32% 的轨迹里有「没拿到新信息还重复同一操作」，最长的一条剪映拖拽试了一百多步。
6. 只在 Sky 上才需要的绕法。例：按控件点不动就改按坐标点。换后端后这类经验没用。
7. 中间步骤模型经常有错误判断。评分通过的轨迹里，近四成卡点没有报错、模型当时也没察觉。例：加粗快捷键没生效，模型看截图说已加粗，后来复查才补上。
