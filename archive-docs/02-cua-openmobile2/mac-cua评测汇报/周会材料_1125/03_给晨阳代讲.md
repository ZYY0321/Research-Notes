# 给晨阳：代讲荧滢这周进展的一段话（约 1 分钟）

荧滢这周新接了 Photoshop、Mail、Figma、飞书四个应用，用 DeepSeek 在 Sky 上跑，按官方帮助文档一个功能出一道题，题面和评分由生成模型一起写出，一共 196 道，其中能根据导出文件自动评分的有 81 道。这周卡得比较大的有两块。第一块是机器和账号：Photoshop 一个账号最多登两台设备，Mail 共用一个邮件服务器，几道题会互相干扰，Figma 有登录验证的问题，飞书需要手机扫码，飞书镜像也还没装好。第二块是验证：现在生成的评分器大多只检查尺寸、几个点的颜色和文件头，题面要求的内容对不对、结果是不是这次运行做出来的，都没有核对；而评不了分的，恰好是 Figma 的组件、协作和 Mail 的规则、设置这些核心功能。她对照了组里已有的做法：泽豪方案里先读应用状态再判断、上线前先测评分器本身，这一套可以直接当入库检查，但它默认状态能读到，而她这几个应用的状态在应用内部或云端，也测不出是不是本次运行的产物；鸣谦那边证据不够就记 null、判错就保留原分并标注，可以先沿用。解决方向是按结果存在哪里，分别选择取证方式，写在附件里。出题和质检各有一份文档，质检那份接着上周的汇总，按六类整理了评分通过但不适合直接拿去训练的轨迹，这两份我会再看一下。
