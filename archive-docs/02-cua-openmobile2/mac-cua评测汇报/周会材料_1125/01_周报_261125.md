# @张荧滢

**配置**

- 应用：本周新接 Photoshop、Mail、Figma、飞书四个，飞书镜像没装、还没开跑。
- 模型：DeepSeek v4.1-flash，后端 Sky，提示词用命令行优先前缀。
- 机器：Photoshop 一个账号最多登两台设备；Mail 在生产机和集群上跑，但是有邮件共享服务器的问题；Figma 只在集群上跑，有验证问题；飞书需要手机扫码验证。
- 出题：按官方帮助文档一个功能出一道题，题面和评分脚本由生成模型一起写出。

**数量**

- 题：196 道（Photoshop 119、Mail 39、Figma 38），其中能自动评分的 81 道，另外 115 道的结果在云端或只在屏幕上，评不了分。
- 运行：到 11-24 中午跑了 235 次，评分通过 71 次。没通过的里面，62 次是评不了分的题，55 次是环境问题，模型做完被判错的只有 9 次。Photoshop 修过环境后重跑，到 11-25 中午又通过 41 次。
- 有效数据：确认有效 0 条，上传 0 条。全部数据（含 11-17 那份评分通过 1941 条）见附件一。

**质量：评分通过不等于做成，这周的主线改成了验证**

1. 现在的评分大多只核尺寸、几个点的颜色、文件头和署名，题面要求的内容和「是不是这次做的」都没核，所以两个方向都会错：Mail 草稿题开跑前放一封旧草稿，模型什么都没做也给 1；Figma 新建被团队锁挡住，模型在推理里写「评分可能只看输出」，转去别人的设计稿里画，也给 1；反过来，评分收紧后会把整张单色的正确导出误判成 0。（均为实测，案例见附件二，验证思路见附件三）
2. 评不了分的 115 道恰好是 Figma 的组件、协作和 Mail 的规则、设置这些核心功能，能评分的大多是「画个东西再导出」，这是按功能清单出题、评分又由出题模型顺带写出造成的。（出题的现状、问题和可借鉴的做法见附件四）
3. 模型为了绕开系统授权弹框，会关掉系统通知进程或先存到别处再挪过去，答复里却不提，和上周 WPS 上「换了手段不交代」是同一类问题，数量还在数。（附件二）
4. 组里已有的做法可以借：泽豪方案里先读应用状态再判断、上线前用几类样例测评分器本身，可以直接当入库检查，但它默认状态读得到，而我们的状态在应用内部或云端，也没有测「是不是这次做的」；鸣谦那边证据不够记 null、判错保留原分并标注、自述不算证据的口径，我们照用。（附件三、附件四）

**需要确认**

- 收数据的标准 @闫晨阳：我们的提议是新评分给 1、成品由应用写出、评分能区分这次做的和原有的、每题至少一条有人看过结束画面，四条同时满足才算可收录；交付时每条带评分版本、走的路线、有没有关过进程或绕过弹框、答复有没有交代。答复没交代手段的轨迹是改写后收还是不收，签名为空的能不能收，也请一起定。
- 账号：要登录的应用都有这个问题，之前 WPS 的登录窗、Office 的订阅框也是。数据能不能刷、能刷多快，先由账号决定：Photoshop 一个号只能登两台机器，Figma 团队被锁，Mail 和飞书用的是自己注册的号。后面扩量需要测试号或付费席位，想请 mentor 协调。【她填：@谁】
