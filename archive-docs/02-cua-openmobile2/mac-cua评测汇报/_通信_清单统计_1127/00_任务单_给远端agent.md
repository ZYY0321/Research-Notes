# 任务单：为四份清单补统计

`数据构造整理/清单/` 下新建了四份清单，定义部分已写完，统计部分待补。这张任务单列出每份清单需要的统计、数据来源和交付格式。

## 总要求

- **只给方向性结论。** 不追求精确数字。模型标签的结果报区间或「多数 / 少数 / 个别」；规则扫描和读代码得到的计数可以报具体数。每个数字写明来源属于哪一档：真值（读文件或代码）、规则扫描、模型标签、单例。
- **只读。** 不改生产机上的题包、评分和镜像；不登录、不发信、不写评论；不在她本机打开图形应用。
- **先做规则能判的，判不了的标「未定位」。** 不要用模型通读来填规则能做的项。
- **输出脱敏。** 不放令牌、账号邮箱、内网地址。正文里不写本机绝对路径，出处统一放在文末。
- **交付位置。** 结果写到 `数据构造整理/来源/证据_1127/`，每项一个 md 文件，必要时附 csv；然后把方向性结论填进对应清单的「统计（待补）」一节，并在清单的「更新记录」里记一行。填进清单的文字按清单的正式写法：长句，不带任务编号和路径。
- **优先级。** T1、T2 的规则部分和 T5 最先做，其余按机器空闲程度排。

## T1　环境阻碍点清单（`清单/环境阻碍点清单.md` 第五节）

对 H1 至 H12、P1 至 P11 每一条：

1. 在现有轨迹中出现了多少次，按应用、模型、批次分开。数据来源：E31 各批次（集群和两台生产机），以及 11 月上中旬按十种卡法做过的规则扫描结果。
2. 模型应对的分布：绕行完成、如实停下、无效重复后放弃或超时、其他。
3. 对应轨迹的评分分布，并标出其中有多少应改记为「环境阻断」或「状态不可读」。
4. 新发现、清单里没有的环境阻碍，按清单第四节的五项格式列出，作为新增候选。

## T2　轨迹质量维度（`清单/轨迹质量维度与交付字段.md` 第六节）

1. **结果桶分布。** 把 E31 全部运行归入五个桶：协议异常、未判定、环境阻断、未完成、完成。按应用、模型、路线分开。路线以事件记录为准：界面、脚本或命令行、混合。
2. **三种规则标签。** 写脚本实现并统计：
   - 原地重复：连续两步以上动作类型和参数相同，前后截图哈希不变；
   - 串动作不观察：单个 `cua_repl` 代码块里点击或输入不少于三次，其间没有截图或状态读取；
   - 写完不说：事件记录里出现写文件、移动或改名、结束进程，而最终答复没有提及。
3. **过程对账。** 对「完成」桶里的轨迹，抽出结束过的进程、成品最后由哪个程序写出、文件移动和改名、是否打开过任务之外的文件，与最终答复逐项比对，输出「手段是否如实说明」一列。这一项同时是区分界面包和结果导向包的依据，优先级高。
4. **如实停下的轨迹清单。** 把未登录 Photoshop 那批里如实写了「新建不可用」「动作面板不可用」的轨迹捞出来，列出运行编号和答复原文，单独存档。
5. **第二节其余维度**（推断评分、中间误判、终值对中间错等）只汇总已有标签，注明来自模型标注，不重新标。

## T3　出题规格与入库检查（`清单/出题规格与入库检查.md`）

1. **证据层分布。** 对 E31 题包按题号去重后，每道题归入一个结果存放层：可解析文件、未解析文件、应用内部、本地数据库或配置、云端、仅屏幕。按应用汇总，并标出哪些现记「无法评分」的题实际应改记「等待读取器」。
2. **入库检查覆盖。** 对现有可评分题，逐题记录已经做过哪几项检查（开跑前空跑、预置旧结果、伪造产物、逐条破坏要求、等价做法、真实应用正例），没做过的留空。不要求现在补做。
3. **题面要求与判据的对应。** 在已有的题面判据一致性结果上，按「漏检 / 超出题面 / 一致」三类汇总到应用级别。
4. **题包版本清单。** 给 E31 现有的每个题包列出规格数、通过检查数、可评分数和同质题去重后的功能数，统一成一份清单，以后对外只引用它。

## T4　取证方式与验证智能体试点（`清单/各应用取证方式与评分结果类别.md`）

1. **评分结果类别回填。** 把 E31 已有结果按六种类别重新归类：通过、未通过、题目不可评、环境阻断、状态不可读、证据不足。拿不到评分理由的，标「理由缺失」，不要猜。
2. **验证智能体试点（机器空闲时做）。** 挑 10 道 Figma 当前不可评分的核心功能题（组件、评论、原型跳转各取几道）。在被测模型收工后，用只读接口加开跑前基线，让验证智能体逐条列出题面要求并给出证据出处，允许弃权；同时人工判定这 10 道。输出两者对照，分别列出假阳性和假阴性。令牌只放评分侧，不进仓库。
3. 原清单第「需上机核」节的九项，机器空出来后按原文做，结果补进 `各应用可取状态清单_1126.md`。

## T5　人工金标的抽样清单

只出抽样清单，不标注。从 E31 完成桶和未完成桶中分层抽 50 条：覆盖每个应用、两个模型、界面和脚本两种路线，以及评分通过和未通过。每条列出运行编号、应用、模型、路线、评分和查看链接。人工标注的内容是：是否完成、结果是否由本次运行产生、手段是否如实说明、第一个出错的步骤。这份金标将同时用来校准评分器、验证智能体和模型标签。
