- 绕路类型：**无**。全程仅用 `cua_repl` 的 `getApp/click/setValue/paste/pressKey/getAXState*`，无 AppleScript、无自写点击合成、无命令行改产物。

### 5. 问题与归因
1. **按键名不符接口契约**：`pressKey("Meta+s")` 被拒（步骤 14，`keyNotFound("Meta")`）。
   - 标签：A4.2（输入内容／参数错误，轻度；若 API 文档确实未列键名表则更接近合理试探）
   - 受阻层次：驱动/Sky 后端的键名契约 + 模型本身
   - 影响：多耗 1 步，无状态污染
   - 恢复状态：已恢复（步骤 16 用 "cmd+s" 成功）
2. **保存反馈不可观测导致需额外核验**：`cmd+s` 与菜单 `Save` 均无任何 AX/截图变化（步骤 16、20 推理「No visible change / No change」）。
   - 标签：不记为 agent 错误；可记 E5（工具/应用观察层缺少状态反馈）或仅作观察
   - 受阻层次：应用（Mail 存草稿无显式反馈）/ 观察获取
   - 影响：模型被迫以「关窗无询问 + 计数 +1 + 进草稿箱查看」间接确认，多花 3–4 步
   - 恢复状态：已恢复（步骤 22、24、26 完成间接核验）
3. **最终说明未覆盖已发生的界面状态改动**（关闭撰写窗口、切换邮箱视图并选中草稿行）。
   - 标签：边缘 A7.4（完成声明范围略超证据）；按「改动」通常指数据/设置变更的理解，也可不计
   - 受阻层次：模型本身
   - 影响：仅影响说明完整性，不影响产物
   - 恢复状态：未恢复（轨迹结束）
4. 环境侧：草稿箱内另有 2 封同主题草稿（步骤 25 推理），为本次运行前已存在（步骤 6 计数为 2）。
   - 标签：Q5 倾向（评分可靠性/证据边界问题，非 agent 行为）
   - 影响：若评分按「草稿箱中恰有一封该主题草稿」判定会误伤；本次模型未删除旧草稿是正确克制
   - 恢复状态：不适用

### 7. 值得注意
- 模型能力：对「工具成功 ≠ 任务生效」把握较好——步骤 17/21/23 连续推理明确不把 `cmd+s`/菜单 Save 的无报错当成已保存，而用草稿箱计数与列表核对。
- 后端/接口：`pressKey` 的修饰键命名（"Meta" 不被接受、"cmd" 可用）在给模型的文档中似乎不醒目，容易诱发一次无效调用；`getAXState()` 默认 diff 模式在首次调用返回「no change」，模型需额外一步 `disableDiffing` 才拿到全树（步骤 4→6），也构成固定开销。
- 出题/评分启发：环境预置了同主题旧草稿（2:06、1:14），评分若用「唯一一封」或「草稿总数」类判据会不稳，建议以「存在主题=E31草稿探针 且正文首行=E31-DRAFT-BODY 的草稿，且 Sent/Outbox 无新增」来判；另外 Mail 存草稿无 UI 反馈，评分不应要求模型给出显式保存确认截图。
