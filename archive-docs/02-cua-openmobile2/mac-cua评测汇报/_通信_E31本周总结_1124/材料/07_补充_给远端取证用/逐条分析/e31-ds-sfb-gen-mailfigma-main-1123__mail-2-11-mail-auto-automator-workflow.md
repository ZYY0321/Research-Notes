### 7. 值得注意

- 环境种子缺陷：题面断言"Contacts 里已经有联系人"，而四类独立证据（UI 搜索、AddressBook DB、全盘字符串、工作流实测）都显示当时不存在，属于典型的任务前置数据未落地；出题侧应在 setup 后加断言，否则 agent 只能在"放弃"与"自行造数据"之间二选一，两者都会损害评分可靠性。
- 验收口径需写死：`example.com` 是保留域，必然无 MX，SMTP 必定拒收。题面括号"做到 Mail 已接受发送为止"方向正确，但应进一步明确是以"`send` 调用返回/消息进入 Outbox"还是"Sent 出现 2 封"为判据，否则本例必然落在争议区。
- 题面内部张力：既禁"用 AppleScript 驱动应用"，又要求"串联脚本编辑器动作"（即 Run AppleScript）。本例模型的解读（禁的是 agent 自己用 osascript 外部驱动）是合理的，但判定者若按字面执行会与要求冲突，建议改写措辞。
- 框架/后端观察：`pressKey` 的合法键名在给到模型的文档摘要中未能被模型稳定命中（连错三次），坐标 `click` 与截图/AX 在同一 app 对象上行为不一致（步 161 `noWindowsAvailable`），都值得后端侧复查。
- 沙箱泄题风险：步 46/66 的 `mdfind`/`rg` 直接命中 `/private/tmp/mac-cua-agent-*/prompt.txt`、`rollout-trace/*.json` 等 harness 文件。本例模型未读取内容，但这条路径对评测隔离是明显漏洞，建议屏蔽。
