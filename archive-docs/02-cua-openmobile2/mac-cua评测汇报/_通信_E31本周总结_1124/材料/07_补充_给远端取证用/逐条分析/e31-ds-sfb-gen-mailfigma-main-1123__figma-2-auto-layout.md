### 5. 问题与归因
1. **团队锁定阻断标准新建入口** — 标签 E3（访问控制与认证障碍）；受阻层次：应用（Figma 账号/套餐侧）；影响：无法走「New Design file」，改为复制建档，带来多余文件内容；恢复状态：部分恢复（任务目标达成，但新建方式与题面字面不完全一致）。证据：步骤 13「Your team is locked」、15 弹窗始终无控件、24/27 锁定横幅。
2. **坐标点击/拖拽返回 `noWindowsAvailable`** — 标签 E5（工具／框架／应用异常）；受阻层次：驱动或 Sky 后端；影响：无法用画布拖拽绘制矩形、无法右键菜单，被迫全部改走 AX 元素与属性面板，显著增加步骤；恢复状态：已恢复（步骤 81–84 改用 AX 后可正常创建）。证据：步骤 29、37、79 三次同一报错，而同期 `click(索引)` 正常。
3. **`setValue` 只改 AX 值、未提交到 Figma 控件** — 标签 E5（调用契约与实际执行不一致）；受阻层次：驱动或 Sky 后端 ×Figma Web 输入实现；影响：gap 4、子元素宽度等「看似已设」实则未生效，直接导致首版产物错误；恢复状态：已恢复（步骤 175–195 改为「click→Command+a→typeText→Return」后生效）。证据：步骤 114 AX 显示 gap=4 但步骤 148 导出高仍为 48；步骤 161 AX 显示 12 而步骤 163 子节点仍「1 Fill」。
4. **把 AX 返回值当作状态已生效** — 标签 A5.1（当前控件状态判断错误）；受阻层次：模型本身；影响：步骤 120 对外声明「间距 4、四边内边距 6 和双向 Hug 已设置」，与随后 12×48 的实际产物冲突，产生一次无效导出与一轮返工；恢复状态：已恢复（步骤 149–151 通过终端像素校验自我发现）。
5. **误按按键造成非预期编辑** — 标签 A4.1/A4.4（操作对象与时机偏差，焦点在画布而非图层树）；受阻层次：模型本身；影响：步骤 153 Frame 位移 1px（未还原，无实质影响）、步骤 165 进入矢量编辑模式（步骤 167 Esc 退出）；恢复状态：步骤 165 已恢复，步骤 153 未恢复但残余影响可忽略。
6. **按键名多次被契约拒绝** — 标签 A4.2（参数值错误，属有限探索）；受阻层次：模型桥接/框架文档（按键命名未在可见 API 文档中给出，且 `Shift` 大写被拒、`shift` 小写可用）；影响：步骤 73、95、128 三次报错，仅增加少量成本；恢复状态：已恢复（76、97、130 找到可用写法）。按分类口径属合理探索，不计为实质错误。

- 首版错误导出（148）虽为失败，但其后的「校验—定位—修复—复验」闭环是正向样本，建议保留。

### 7. 值得注意
- **Sky 后端/驱动**：同一应用下 `click(索引)` 可用而 `click([x,y])`/`drag` 持续 `noWindowsAvailable`（步骤 29/37/79），对 Electron 类应用的画布型操作形成硬阻断，建议排查窗口句柄解析。
- **`setValue` 语义风险**：对 Figma 这类受控输入，`setValue` 会改写 AX 暴露值却不触发应用提交（步骤 114 vs 148、161 vs 163），极易诱导模型形成虚假「已生效」状态；建议驱动层补充提交语义或在返回中区分「已写入/已提交」。
- **按键命名**：`Enter` 不可用需 `Return`，`Meta` 不可用需 `Command`，修饰键 `Shift` 大写被拒而 `shift` 可用（步骤 73/95/128/130），对模型是纯试错成本，建议在工具文档内明示。
- **对出题/评分的启发**：环境账号处于「团队锁定」状态会使「新建 Design file」这一步无法按字面完成，评分需明确「复制既有文件得到新文件」是否计入满足；另建议把「产物像素级正确」作为主判据——本例若只看 UI 面板数值（步骤 120）会误判为已完成。
- **模型能力亮点**：主动用终端对产物做像素级校验并据此返工（148–151、206–208），是桌面 GUI 任务中少见的闭环验证行为。
