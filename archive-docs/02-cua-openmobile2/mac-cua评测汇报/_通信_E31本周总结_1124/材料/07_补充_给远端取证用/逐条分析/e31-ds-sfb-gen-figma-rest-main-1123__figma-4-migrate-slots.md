### 5. 问题与归因
**主要问题**

1. 迁移覆盖面窄，是否满足「库迁移」口径存疑
 - 标签：（争议）A7.3——依据不足，不作为成立标签；相关推理见步113。
 - 预期→实际→原因：期望把现有组件库迁移到 slots → 实际仅 1 个组件集的 1 个重复项（3 层）转 slot（步90–116），同组件集另 6 层与另 3 个组件未动；步113 显示模型已识别到可继续，步114 直接转入建实例。原任务只写「一个现有组件库」，未写「全部组件/全部重复项」，故不能断定不达标；未排除的解释是模型按「一个组件集即一个库单元」理解。
 - 受阻层次：模型本身（范围决策）。影响：评分可靠性与交付完整度存疑，不影响文件产物存在。恢复：未恢复（未补做、未在步200 说明取舍）。

2. 最终说明的改动范围声明与记录不一致
 - 标签：A7.4（轻微）。
 - 预期→实际→原因：应如实列出题面未要求的改动 → 步200 称「仅新增该展示页面和导出画板，未做题目未要求的其他修改」，但步7 改了应用更新设置、步157–165 给预览帧加了背景色与留白；原因可能是把帧美化视为「导出画板」的一部分（合理但未明示）。
 - 受阻层次：模型本身。影响：证据可信度/人工复核成本。恢复：未恢复。

**次要问题／运行异常**

3. 坐标 `click`/`scroll` 持续 `noWindowsAvailable`
 - 标签：E5（工具/框架/应用异常）。证据：步52、56、58、60、72 失败，同期 `app.click(9)`（步66）、`getScreenshot`（步64）正常 → 调用契约与实际执行不一致。
 - 受阻层次：驱动／Sky 后端。影响：无法点击画布与展开图层树，产生步49–88 的大量迂回；是本轨迹步数膨胀的主因。恢复：部分恢复（找到 AX/Find 替代路径完成任务，坐标能力始终未恢复）。

4. `pressKey` 键名不合契约导致一次状态回退
 - 标签：A4.2。证据：`"CMD"`（步34）、`"Meta"`（步36）、`"Enter"`（步127）、`"esc"`（步131）均 `keyNotFound`；步131 的 `Escape` 撤销了页面重命名（步133–134 模型自述「rename didn't commit」），同次 `cmd+v` 未执行。
 - 受阻层次：模型本身 + 框架（键名规范是否可见无法确认，见不确定项）。影响：额外 ~8 步成本。恢复：已恢复（步194 重命名成功）。

5. 跨页粘贴与 `typeText` 失效
 - 标签：E5（证据较弱）／合理探索。证据：步42–43 `typeText` 对 Find 字段无效（随后 paste 成功）；步136 自述 `cmd+v` 无效，原因未定位（步119 组合调用中 `click(50)` 报 invalid element ID，`cmd+c` 是否生效无法确认）。
 - 受阻层次：未知（框架/应用焦点）。影响：改走 Assets 路线，成本小。恢复：已恢复（步143）。

6. 对实例「文字标签缺失」的归因未专门核验
 - 标签：无成立标签（列为待验证假设）。证据：步144 自述新实例无标签并推测与 slot 默认内容有关；步147 包帧后截图被判为标签可见，之后未再专门核验导出图内三个标签。影响：导出画面内容正确性缺独立核验。恢复：无法判断（我无法看图）。

### 7. 值得注意
- 模型能力亮点：把 Figma 的 Find 搜索结果列表当作可访问的图层选择器，从而在屏幕阅读器支持被系统设置锁死（步82–83「Adapt content for screen readers」为 disabled）、坐标操作不可用的双重限制下仍完成嵌套层选中与右栏操作；对更新弹窗选择「下次启动安装」而非立即安装，主动规避了「不要重启进程」的约束。
- 后端/框架问题：坐标 `click`/`scroll` 在元素 `click` 可用时持续 `noWindowsAvailable`（步52–72）值得作为 Sky 后端缺陷单独跟踪；`pressKey` 键名规范（仅小写 `cmd`/`Escape`/`Return` 可用）建议在 API 文档中显式列出，可省掉本轨迹 4 次失败试探。
- 对出题/评分的启发：题面「迁移一个现有组件库」缺少覆盖口径（是否要求所有组件/所有重复项、是否要求保留并演示 slot 的可替换性、是否要求发布库——步32 文档提示发布需付费计划），易产生 Judge 争议；若评分关心「slot 真的可插入不同内容」，宜在题面要求导出图体现 slot 内被替换的内容。
