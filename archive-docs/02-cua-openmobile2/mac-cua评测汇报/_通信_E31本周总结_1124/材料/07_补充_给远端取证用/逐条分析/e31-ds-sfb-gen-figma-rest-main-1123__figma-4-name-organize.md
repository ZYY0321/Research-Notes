### 7. 值得注意
- 驱动能力缺口：`getApp` 报告有窗口而 `click([x,y])` 返回 `noWindowsAvailable`（步 34/38），对 Figma 这类画布应用几乎等于禁用了画布直接操作；本例靠"矩形工具 + Return 在选中容器内生成图形"这一非常规技巧才绕开，建议后端修复坐标点击或题面明确可用能力。
- 文档缺口：`pressKey` 的按键命名未在 cua_repl 文档出现（步 45 重取文档仍无），模型被迫 `strings` 驱动二进制；应补按键表，否则会诱导 agent 去读 harness 内部文件/自身 trace（步 48 已发生，属可审计风险）。
- 出题/评分启发：Figma 的"斜杠层名→导出为子目录"与"单层导出弹目录选择器而非 Save 面板"（步 163/169）使"命名含斜杠 + 指定导出文件名"天然互斥；题面应明确是否允许层名临时改名导出、或是否允许 shell 重命名，否则该题的"应用自交成品"判据必然产生争议（本例核心争点）。
- 模型能力亮点：识别 `cmd+d` 产生的是实例并用 Object 菜单 Detach（步 109–116）、发现 X/Y setValue 失效后换 `shift+方向键` 并按 10px 量算位移（步 151–154）、主动回滚自己误移的既有 Frame（步 180–182），状态追踪与自查意识较强。
