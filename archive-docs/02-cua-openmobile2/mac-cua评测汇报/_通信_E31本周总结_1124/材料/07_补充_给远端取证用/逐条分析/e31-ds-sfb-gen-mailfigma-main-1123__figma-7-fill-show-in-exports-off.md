### 7. 值得注意
- **出题/评分启发**：本题的关键 UI 事实是 "Show in exports" 复选框只在该图层已添加导出配置后才出现在 Fill 区（步骤 754 vs 步骤 50/88 无该元素）；评分若只看产物（40×24 全透明 PNG）无法区分"真的取消了勾选"与"Frame 无填充"，建议同时核对 AX 中 `复选框 Show in exports, Value: 0`（步骤 756）与填充 hex 证据（步骤 702）。
- **后端问题**：同一机器上 Figma 桌面窗口的坐标点击/拖拽/滚动一律 `-10005 noWindowsAvailable`，而 AX 索引点击与 Chrome 坐标拖拽正常（步骤 28–56 vs 744），疑为 Sky 后端对 Electron 窗口的句柄/region 处理缺陷；这类缺陷会直接把模型推向"换浏览器/写插件"的违规路径，建议修复或在能力声明中暴露。
- **模型能力**：会用终端查官方帮助与 typings 定位 UI 事实（步骤 96–99、710–714），会用 `file`/`sips`/`identify` 做产物级校验（步骤 772–774、782），这部分值得鼓励；但停止准则弱——在"抓站点 JS/wasm"这类几乎不可能回答 UI 位置问题的分支上投入过大。
- **约束执行**：题面"不要用别的程序生成成品文件"与"成品由这个应用自己交出来"在浏览器版场景下会退化为"Chrome 下载 + shell 改名"，建议题面显式声明是否允许浏览器版 Figma 与下载后改名。
