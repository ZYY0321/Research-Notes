### 6. 能否收为训练轨迹

**不收。**
理由：
- 任务成功的关键输入（40 行真实状态）来自步骤 162–164 的命令行读 xlsx，而非 GUI 识读；作为桌面 GUI agent 的正例会鼓励"GUI 做不动就用 shell 读产物"的捷径。
- 含模型自身的高危错误操作：步骤 180–187 误删全表、步骤 144 保存错误结果、步骤 48/65 误触对话框复选框。
- 轨迹极长且含大段无效探索（步骤 24–56 对同一下拉框近 10 次尝试），信噪比低。
- 若必须利用，可只保留步骤 1–22（规范的状态读取 + 从功能区坐标点击失败回退到菜单栏 AX 路径）作为"应用内换路"片段；步骤 24–56 可作为"AX 不可达控件"的失败/换路教学样本，但必须遮掉步骤 48/65 的误触与 58–59 的视觉转录决策，以及 144 之后的所有 shell 读产物与误删段落。

### 7. 值得注意

- **Sky/驱动侧**：同一对话框内复选框点击可生效、而 QTableWidget 内嵌下拉框对点击/键盘完全无响应（步骤 24–56 vs 48），提示 WPS Qt 控件与 CUA 点击注入存在兼容盲区，值得单独做 backend 排查用例。
- **接口契约**：pressKey 的合法键名未在可见文档片段中给出，导致 `Alt/option/Shift` 连续报 `-10005 keyNotFound`（步骤 42/44/79），而小写组合可用；建议在工具说明中显式列出键名表，可直接避免本案的手工转录分支。
- **出题/评分启发**：本题若只校验「状态分组顺序 + 表头 + 行数 + 扩展名」，模型用命令行读值生成排序键仍可满分；建议评分补充"是否引入/残留辅助列、筛选元数据、临时文件"，并限制/记录 shell 对产物的读取，以区分真 GUI 能力与工具绕行。
- **风险行为**：在无备份情况下先保存未验证结果（步骤 144），以及未确认选区就执行整列删除（步骤 180–186），都是桌面 agent 的典型高危模式，可作为安全性评测点。
