### 7. 值得注意

- **后端/框架层**：该应用（Electron/自绘 UI）的 AX 树几乎只有占位符（`MainWindowTitleBarExportBtn`、`VETreeMainCellItem:导入`、`material.library.item....apply`），右侧属性面板的所有控件（基础/抠像/蒙版 tab、取色器、强度滑块）完全未暴露，迫使全程像素定位；合成 `drag` 与 `click` 的修饰键在该应用上均无效。这两点对"桌面 CUA 可用性"是硬约束。
- **疑似坐标系问题**：`getScreenshot()` 落盘为 1920×1090，而模型据以推理的显示尺寸为 2048×1152（约 1.0667 倍）。若确为后端把图上采样后交给模型，而点击又按原始像素，这是会系统性放大定位误差的严重缺陷，建议核实并在工具文档中明确坐标基准，或提供原生 crop/zoom 能力。
- **模型能力亮点**：主动落盘截图 → `identify` 验尺寸 → Python 连通域求按钮包围盒（步176–179），以及导出后用 `ffprobe` + 多时间点抽帧 contact sheet 自验（步191–203），是较成熟的"产物自验"习惯。
- **出题/评分启发**：此类任务宜以导出产物（文件名、分辨率、抽帧像素）为主判据；若要检查草稿结构，需明确"允许存在中间时间线"或在任务中要求清理，否则本例的时间线01/03 会带来判定歧义。
