 - 标签：E5（工具／框架／应用异常）
 - 受阻层次：驱动或 Sky 后端（也可能是 WPS 的 Qt 自绘窗口未被后端识别为可用窗口；无法从记录区分）

### 7. 值得注意
- 模型能力面：窗口恢复思路好（空白窗口 → 菜单栏「窗口」→ 选中文档窗口，步 11–16）；对工具契约的自省较强（步 34 分析 `noWindowsAvailable` 的可能成因、screenshotId 仅限 Windows）；对任务边界把握正确——明确拒绝用 shell 直接改 xlsx、拒绝用「艺术字」替代「文本框」（步 40、44）。
- 后端问题：WPS（Qt 自绘）场景下，AX 树只暴露功能区标签按钮而不暴露内部图标，而坐标点击又返回 `noWindowsAvailable`，等于该类任务在当前后端下无可行路径；建议排查 Mac 端 `app.click(Vec2)` 的窗口解析与 Retina 坐标换算，并补充截图坐标空间说明。
- 模型桥接问题：未开通的 web search 不是「工具返回错误」而是直接打断生成流（8 次重连后 case 终止），建议把此类插件错误降级为可捕获的工具失败，避免整条 case 作废。
- 出题/评分启发：本题的评分应能区分「模型未做」与「后端不可点」；建议配套采集 xlsx 磁盘产物（是否存在 drawing/textbox）与保存时间戳作为硬证据，并预置最小可用的 GUI 路径（例如确保功能区图标在 AX 中可点击）再投入评测。
