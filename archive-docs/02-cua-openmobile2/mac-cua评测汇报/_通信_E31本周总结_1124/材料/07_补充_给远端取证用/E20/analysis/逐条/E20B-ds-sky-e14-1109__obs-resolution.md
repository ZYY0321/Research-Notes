### 5. 问题与归因
**主要问题**

1. 点击 OK/Cancel 触发 `App quit` 异常（步骤 17、36）
 - 标签：**E5（工具／框架／应用异常）**
 - 受阻层次：应用（OBS 崩溃）或驱动/Sky 后端（点击后进程终止/会话失效），二者未能区分；步骤 22 的「did not properly shut down」提示支持确实发生了非正常终止。
 - 预期→实际→原因：预期点 OK 提交并关闭设置对话框 → 实际返回 `-10005: App quit` 且进程消失 → 尚不能排除 OBS 自身在分辨率变更后崩溃、后端在窗口销毁时误判/杀进程两种解释。
 - 影响：使「按 Cmd+Q 正常退出以保存」的流程无法按设计执行；制造了一次额外重启与 Safe Mode 弹窗。
 - 恢复状态：部分恢复——模型重开 OBS 并验证设置确实已保存（步骤 22–28），但「正常退出」这一状态未恢复。

2. `pressKey("cmd+q")` 未产生任何效果（步骤 30–34）
 - 标签：**E5** 与 **A4.2/A4.3** 均不能排除，证据不足以定责（并列候选，不重复计数）
 - 受阻层次：未知（后端键名语法 / 模态 Settings 对话框吞掉快捷键 / 事件未送达）
 - 预期→实际→原因：预期发送 ⌘Q 退出 → getState 两次仍 `isRunning:true`、AX 无变化、无报错 → 模型自己在步骤 29/35 推理中即承认不知道 pressKey 的键名约定；没有返回值可判断按键是否真的被派发。
 - 影响：任务明确指定的退出手段未完成；退出改由异常事件达成。
 - 恢复状态：部分恢复（退出结果达成，指定手段未达成）；模型未尝试同为 GUI 的等价路径（菜单栏 OBS → Quit，步骤 5 的 AX 树中元素 61 可见）。
