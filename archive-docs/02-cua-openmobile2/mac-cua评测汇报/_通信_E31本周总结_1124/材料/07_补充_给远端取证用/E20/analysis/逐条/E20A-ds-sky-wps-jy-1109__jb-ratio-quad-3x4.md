### 7. 值得注意
- **坐标系契约缺陷（框架/桥接）**：模型可见图像被缩放到 1680 宽，而 `click/drag` 需要 1920×1090 原始像素坐标，文档未声明。模型靠"点击后光标在截图中的位置"反推比例（步61→68）是很强的自诊断能力，但这类标定在每条 CUA 轨迹里重复付出 10+ 步成本，建议后端直接在截图返回中附带原始尺寸或统一坐标系。
- **自绘 UI 的 hover/drag 盲区（后端-应用）**：剪映素材卡片的"添加到轨道"入口依赖 hover 覆盖层，AX 树里只暴露一个无语义的 `…quad6.mp4.apply` 按钮且 `click(9)` 无反应（步50–52）；`drag` 在换算坐标后仍无效（步87）。建议后端提供 `moveMouse`/`hover` 与带中间轨迹的慢速拖拽原语，否则剪映类任务的"素材入轨"会系统性失败。
- **评测环境配置**：本条轨迹的终止原因是 web search 未开通（步102–114）。此类 provider 侧能力缺失会把"模型卡住"转成"运行中断"，污染失败归因，建议在跑 CUA 批次前关闭或预置联网工具。
- **出题启发**：若该版本剪映确实只能靠 hover + 拖拽入轨，这条任务对当前后端可能接近不可完成，应先做一次人工可行性验证，再据此决定是否计入模型能力评分。
