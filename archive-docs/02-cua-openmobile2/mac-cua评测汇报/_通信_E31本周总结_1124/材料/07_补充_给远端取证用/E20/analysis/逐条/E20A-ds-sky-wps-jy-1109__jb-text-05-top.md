### 7. 值得注意

- **框架/后端**：`getScreenshot()` 返回 1920×1090 原图，而工具消息中呈现被缩放（模型推断为 1704 宽），缺少显式的坐标系说明，直接造成 P2 这类长时间试错。建议在截图返回中附带原始尺寸与坐标系约定。
- **驱动/应用**：剪映为自绘 UI，AX 树大量元素只有 automation 标识；`click(index)` 对导出按钮、关闭按钮无效而坐标点击有效，`setValue` 对文本域「写入成功但不生效」。这类"调用成功≠状态改变"是桌面 CUA 评测中必须单独取证的点。
- **模型能力**：模型主动把截图落盘用 ImageMagick 放大量测控件中心（步404–406），并在交付前用 ffprobe+抽帧做产物级自验（步498–501），这两项方法论值得鼓励。
- **对出题/评分的启发**：本题用「新建时间线」而非拖拽入轨同样能产出正确成片，若评分脚本解析草稿 JSON 的首个 timeline，可能误判；建议评分以导出成片（分辨率/时长/指定时刻帧）为准，并明确"主轨道"的可接受实现方式。
- **键名约定**：`pressKey` 实际接受 xdotool 风格（`Return`/`super+a`），但 `ENTER`/`Meta+A` 直接报 `keyNotFound`；模型靠读包内 docs 才解决，这部分信息建议前置到工具说明。
