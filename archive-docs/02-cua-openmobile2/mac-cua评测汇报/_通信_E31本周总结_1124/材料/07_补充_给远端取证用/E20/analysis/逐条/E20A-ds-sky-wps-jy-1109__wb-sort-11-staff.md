### 7. 值得注意
- 模型能力：AX index 使用相当严谨——每次操作前都重取 AX（步骤 103 重取后用新索引 3 而非旧索引 2），注意到了索引随树变化而偏移；用名称框 `setValue` 精确设选区/活动单元格是本任务中很好的 CUA 技巧；对外说明（步骤 50、79、90、93、136）与实际状态一致，无夸大完成声明。
- 框架／Sky 后端问题（建议专门复现）：①同一窗口上 AX 点击正常而坐标点击返回 `noWindowsAvailable`；②`windowNotFoundAtPosition((1266,809))` 显示输入坐标被放大 ~1.79 倍，截图像素坐标与点击坐标空间不一致且无文档说明；③Qt 自绘的 WPS 排序对话框组合框在 AX 中退化为无属性「文本」节点，焦点进入后连 focused 元素都不再报告。这三点叠加后，WPS 表格类任务在当前后端上几乎只能走「菜单栏 + 名称框」这一条很窄的通道。
- 对出题/评分的启发：wb-sort 类任务若要求用 WPS 排序对话框，应先验证该对话框在当前 CUA 后端的可操作性，或在任务中明确允许的替代入口（如允许 shell/openpyxl、或改用「开始→排序和筛选」可 AX 化的入口）；另外运行环境里 web_search 未开通会直接把 agent 的流打断（而不是返回工具错误让其继续），这会把本可继续的 GUI 任务变成硬终止，建议在 harness 层把该类工具失败降级为可恢复错误。
