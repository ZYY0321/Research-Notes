### 7. 值得注意

- **坐标系陷阱**：同一后端下，截图以 1737×973 呈现而点击 API 使用 1920×1090 原始坐标，是本条轨迹最大成本来源（步骤 16/33/37 连续三次落空）。建议在工具说明中显式给出"呈现尺寸 vs 原始尺寸"或提供换算 API，并在出题/评分时把"是否自行发现并换算"作为能力观测点而非失败点。
- **WPS 图表标题的 AX 可达性差**：选中标题后 AX 仅给出右侧面板按钮（步骤 45「标题选项/文本选项/…」），文本本身不可寻址，F2/右键/三击均无反馈；需要"先直接粘贴试探是否已在编辑态，再 Command+a 替换"这种经验性序列（步骤 59→61）。这类应用可作为 AX 覆盖不足场景的专门用例。
- **产物级核验是本条的亮点**：步骤 70–72 用 `unzip -p | xmllint | rg` 同时验证 `barDir`、`grouping`、`<a:t>` 标题与三处 `<c:f>` 数据引用，比仅凭截图断言更强；但应提醒模型同时核验"有无多余 drawing 对象/源数据未被改"。
- **`keyNotFound` 的良性特性**：错误抛在同一 code 块第一条语句，后续 paste/Return 未执行，模型在步骤 48 正确判断"no effect"，这是多语句同块调用的一个有利约定，值得在文档中明示。
