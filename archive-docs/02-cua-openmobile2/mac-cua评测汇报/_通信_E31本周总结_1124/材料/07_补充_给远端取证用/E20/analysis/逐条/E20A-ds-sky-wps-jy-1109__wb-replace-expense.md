### 5. 问题与归因
1. **工具返回异常：`nodeRepl.emitImage received an unsupported value`（步12）**
   - 标签：E5（工具／框架／应用异常）
   - 预期→实际→原因：预期 `getAXStateAndScreenshot` 在菜单弹出状态下返回可用截图并 emit；实际 emit 收到不支持的值（很可能 `s1.screenshot` 为空/非法），AX 文本仍正常返回。支持原因是框架在该窗口状态下截图获取失败；尚未排除的解释是调用写法在该状态下返回结构不同。
   - 受阻层次：驱动/Sky 后端或框架层
   - 影响：无实质影响（同步返回的 AX 树已足够让模型在步14 找到窗口条目），仅损失一次视觉证据。
   - 恢复状态：不适用/已恢复（后续步14 起截图均正常返回 `[images=2]`）。
2. **`find` 遍历中出现权限拒绝、命令 exit=1（步39）**
   - 标签：E6（执行环境异常，轻微）
   - 预期→实际→原因：预期遍历 `/Users/admin` 定位文件；实际目标文件已打印且 stat 成功，但 `/Users/admin/.codex/tmp/arg0: Permission denied` 导致退出码 1。原因为沙箱/目录权限，与任务无关。
   - 受阻层次：系统权限
   - 影响：仅噪声，核验信息已取得。
   - 恢复状态：不适用。
3. **任务未明确授权命令行而使用 shell 做产物核验（步39–45）**
   - 标签：无行为错误标签（不计 A4.3：核验目的明确、方法合法、未改产物）；作为规范边界问题记录。
   - 受阻层次：未知（取决于该案例的授权口径）
   - 影响：不影响任务完成与数据正确性；但若该案例按"GUI-only"口径评分，会影响该轨迹作为纯 GUI 正例的可用性。
   - 恢复状态：不适用。
- 模型侧未发现 A1–A8 类可证实错误：范围未限定到 C 列这一点，模型以步26「查找全部」先行核对匹配位置来替代，属有依据的方案选择；步31–32 模型明确识别结果列表为 stale（"Old list remains; expected stale"），未发生 A5.3。
