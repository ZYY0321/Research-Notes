# 框架为什么不评这 7 道

两台用的都是 `/Users/user/mac-cua-sky-p3/.venv/bin/mac-cua`。10:20 的 `-h` 子命令是：`server`、`provenance`、`diagnose`、`doctor`、`model-check`、`cluster`、`image`、`tasks`、`run`、`rerun-incomplete`、`cleanup-run`、`resume`、`verify`、`reduce`、`retry`、`serve`、`report`、`report-campaign`、`runs`、`status`、`cancel`、`logs`、`download`。没有 `regrade`。

和「只补分」有关的几条，做的都是别的事：

- `retry`：在**同一个**批次目录里为指定题再开一次模型。`--id` 可重复，`--jobs` 默认由调用方给。它不读旧成品。
- `rerun-incomplete`：把未评分的题继承到**新**批次再跑模型。`--dry-run` 也要拿该批次的 `.run.lock`。当前这批正拿着排他锁。
- `resume`：把这个批次里还没封卷的题接着跑。现在跑就会插进正在做的题。
- `reduce`：用本地 Codex 从轨迹重新生成 state，不评分。
- `cleanup-run`：只补做虚拟机清理，不评分。

停机失败时，评分和收文件都在同一道门后面。生产机 `/Users/user/mac-cua-sky-p3/src/mac_cua/evaluation/attempt.py` 在确认停机之后：

```text
if not stop_receipt.safe_to_grade:
    raise InfrastructureFailure('Agent and control components were not confirmed stopped',
        code='control.stop_unconfirmed', ...)
```

`safe_to_grade` 要代理停住并且控制器停住。这 7 道都是 `agent_stopped: false`、`controllers_stopped: true`，所以抛了这个错。抛错之后不会走到 `grade = timed('grade', score_task)`。收成品也要同一条件：`stop_receipt.safe_to_grade` 为真才调用 `collect_guest_outputs`。这 7 道的 `grading_started` 都是 false，目录里没有 `grading/`，也没有 `outputs/`。

清理仍会做。`result.json` 的 cleanup 是 `confirmed: false`、`policy: controller_only`、`controller_absent: true`、`host_verified: false`。按这个策略，框架把清理当成已经完成，以后的 `retry` 会新建 `attempt-002`，不会回到旧虚拟机。

评分读的是客机路径，不是轨迹里的文字。例如剪贴蒙版的 `evaluation.py` 只核 `~/Desktop/e31-newapps/out/ps-2-11-clipping-mask.png` 的尺寸、两个取样点和 Photoshop 署名。轨迹里模型自己的像素打印不能代替这张 PNG。
