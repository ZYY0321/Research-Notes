本次会议围绕模型评测、外包体系、RL 融合、数据处理以及模型间关系等多个关键议题展开讨论，明确了各项工作的重点方向和后续计划，内容如下：
- 模型评测
  - 评测实验进展
    - 实验情况：孙文秀介绍针对达华老师提出的 36 小时完成全量评测问题，以 1T 的 Kimi k 2.5 模型进行实验。在下载速度 100 兆每秒时，6 小时可启动服务，但在全集数据集上评测超 48 小时，使用四台 H100 机器在 reasoning 较长输出数据集上速度慢、易卡顿，服务端还常崩溃，重启一次约 1 小时，且需人盯守。
    - 问题分析与应对：林达华指出评测应针对 200B - 300B 体量模型。孙文秀认为后续测试可能遇到类似问题，此次实验旨在提前发现并解决。预计年前修复问题，实现稳定评测和更优任务编排。
  - 评测资源与策略
    - 资源协调：林达华强调用大量训练资源进行短时间集中式并发评测，若孙文秀需 500 卡测试，应给予相应支持并在短时间内完成后释放。路少卿提醒提前协调资源，优先选用国内资源，避免评测周期延长。
    - 测试集选择：林达华建议使用 Sensebench 测试集进行初步筛选，因其能代表业务视角且有可控的测试量，预计半天可出结果，之后再考虑全量测试。
  - 千问三 Max thinking 模型分析
- 模型能力评估：孙文秀介绍千问三 Max thinking 模型推理能力大幅提升，检索尚可但方式零碎，编程能力受批评，应对用户情感处理较弱，指令跟随有进步，但社区反馈不强烈。
- 原因分析：卢乐炜认为该模型不开源，主打推理与用户实际应用体感脱离，且未关注前端编程等热门方向，导致缺乏爆点。林达华强调模型开发应注重新 feature 开发，便于下游开发者和用户直接使用，以提高传播性。

  - 模型与用户体验
- 用户体验差异：孙文秀对比千问与 sense wonder 2 模型，指出用户在实测中对模型能力有不同期望，如行程规划、代码编写等方面。用户对模型出现幻觉、不理解意图、响应过慢的容忍度极低。
- 认知塑造建议：林达华提出模型塑造的认知应与能力优势相匹配，避免用户用常规标准测试非主打强项的模型。路少卿表示以往突出模型优势效果不佳，需考虑表达方式和市场认知。后续将组织市场部等相关人员线下讨论。

- 外包体系
  - 外包现状与问题
    - 数据共建问题：孙文秀提及与 AI lab 进行数据集共建，预计 10 号完成榜单，13 号上线，但回收的外包标数据无法使用，需重做。这表明找外包时应提供对应工具，以发挥其最大能力。
    - 外包渠道与机制：武焕介绍外包主要来源为在校大学生和供应商，大学生适合做人工采集标注，供应商适合长期社招兼职做开发工作。路少卿补充专业标注数据多通过代理商联系学校资源获取，但目前供应商标注渠道资源积累不足。
  - 外包体系建设计划
    - 体系搭建目标：林达华认为第一季度需密集组建高效外包支撑体系，避免核心研究员大量参与数据标注工作。少卿将牵头与 HR 开会梳理外包体系，涉及研究院人力分层逻辑。
    - 实施步骤：初期研发深度参与，待一套外包流程跑顺后进行大规模复制。林达华要求乐炜整理对 HR 的需求当天提供给他，以便与春娟沟通，完善外包资源渠道。
- RL 系统与融合
  - RL 系统进展
    - 新推理后端接入：姚勇强汇报将新推理后端 lightllm 接入训练并换成 FSDP，精度曲线稳定，Neo 验证已接通，纯语言和多模态部分曲线精度正常。但 Neo 整体速度比原来的 30BA3 慢，将 DIFF 减到 3 时，速度比 A3 慢 20% - 30%。后续需完成代码合并、推理层面优化和显存问题修复。
    - 邓瀚铭观点：邓瀚铭认为新结构性能有提升，切换效率问题不大。
  - RL 融合问题与解决方案
    - 融合效果与问题：马征介绍 RL 融合已融入所有专题 task，但存在初始 reward 高、融合后 hacking 现象、梯度 norm 不稳定等问题。初始 reward 高可能因新 base model 能力变强，导致部分指标提升不明显；hacking 现象在指令和工具调用中较多，需增加弱规则防止；梯度 norm 不稳定可能因任务多导致梯度冲突，需持续观察。
    - 解决策略探讨：马征提出可考虑分阶段进行 RL 训练，如在每个 step 只做一部分任务，提高训练效率；后续与各专题协助构建高质量 RL 数据，缩小数据规模，确定测试 Benchmark，融合 OCR 相关数据，并尝试先各专题做 RL 再进行 model merge 的方法。闫洁建议统计各 task 的 reward 影响，查找解决梯度冲突的资料；洪嘉伟提及 GDPO 设多任务可能有帮助，但马征认为其主要解决同一任务中多个 reward 的问题，与各任务冲突关系不大。
  - 资源分配调整：林达华认为 RL 融合需更多资源和时间投入，目前 64 卡的资源投入无法满足需求，建议重新分配资源，甚至可从部分专题中抽调资源支持。卢乐炜和马征确认目前资源沿用旧库，每周只能跑两个实验，林达华要求本周落实资源调整。
- 数据更新与优化
  - 主线集成数据更新
    - 数据更新内容：吴思雷介绍截止本周，更新了两大版 SIP 数据，包括基于千问 3 的各专项数据和所有业务数据。最新 SFT 效果显示，与开源的 QWEN 3 VL 相比，多模态领域有较大提升，部分指标超过或打齐；与上一版未做 MINI training 的 SFT 相比，多模提升明显，但纯文本指令跟随无涨点问题待解决，长文相关数据正在补充。
    - 数据质量与验证：林达华关注数据质量验证机制，卢乐炜介绍预训数据采用分片验证再合并的方式，instruction 类数据通过模型重刷和过滤进行验证。林达华担心数据过于拟合特定领域，要求 review mid 训练数据。
    - DPO 与 MID training 更新：DPO 迁移到千问 3VL 上有提点，尤其在指令跟随和支持领域，但推理文本有掉点问题待解决。MID training 方面，多模数据对尾类数据打标，补充了部分数据；语言数据进行过滤和验证，code 数据对指令有意外提升效果，洪嘉伟将合并各 domain 的语言数据进行 middle train。林达华要求亚冰整体 review code 相关数据，关注其对模型的影响。
  - 长文数据处理
    - 长文训练策略：吴思雷介绍针对 longbench 榜单建立合成数据管线，融入千问 3VL 和 Deepseek3.2 的打标流程，分阶段训练。对比直接涨到 128K 和从 32K 逐步涨到 128K 的训练方式，未看到明显增益，后续将直接采用 128K 的长文训练。目前长文数据合入 s 最新的 SFT 模型，longbench 有明显涨点。
    - 长文评测与资源安排：林达华认为 longbench 较老，社区前沿更关注 agent 长文测试。张行程建议分两阶段处理长文问题，先建立涉及长文的评测体系，再将相关数据分解到现有专题。林达华提议设立长文集成组，集中研发资源，负责长文相关数据集成和 Benchmark 综合结果。路少卿反馈目前专题拆分较细，但资源分散，需集中 review 资源投放逻辑，形成 top - down 的资源分配方案。
  - 指令数据治理与模型优化
    - 数据治理情况：李晨霞介绍指令前段进行 SFT 数据治理，因切换到 30 view 后指令跟随 bench 掉点，排查出小浣熊、Omni 数据和方生括数据对指令有干扰。针对方生括数据，姣姣分析发现可能因训练数据工具定义形式单一，测试数据模拟真实场景定义随意，导致模型 overfit，已安排后续优化计划；小浣熊数据提测给姣姣观察；Omni 数据将随 5O 优化进行处理。
    - RL 与 5O 进展：基于思雷给的 944 训练了一版 RL 模型，自评各 bench 有不同幅度提升并已合并。5O 方面，建立了评测集，对现状进行摸底，发现业务侧模型与开源模型有差距。李晨霞提出单独训一个原生的 instruct 模型，以更好达到业务目标，但会增加维护成本，相关问题已反馈给乐炜评估。
    - 业务数据影响与处理：林达华观察到业务调回来的小浣熊等数据对整体基础通用能力有负向效果，提出可能形成多个集成模型，探讨后训练的合理安排和数据配比问题。张行程认为可将下游 SFT 数据加到 middle train 并精简后加到 SFT 中，以减少对模型的破坏。史亚冰分享百度处理业务数据的经验，建议对重要业务配合数据准入和质量控制，不重要业务可在发布模型后进行预训。林达华要求基础线负责人梳理分合逻辑流程图，小范围讨论后重新配置资源。
- 各专题进展
  - 代码专项
    - 现状梳理与规划：史亚冰介绍本周梳理代码专项现状和业务需求，下周初将产生初版规划并与王老师沟通。他认为模型 code 能力评估有三个递进层次，即公开 Benchmark 指标、可感知评测和真正应用到实际生产中。
    - 本周进展与问题：任远航汇报本周非 a 任务聚焦在 LCB 上，新的 DASD 策略对推理提升显著，后续将在训好的 SFT 模型基础上进行 RL 提升。但 RL 目前指标无明显变化，可能因 response 设置不够大且训练时间短；NV 的 Cascade 集成配方训练后期有崩溃问题待排查；LCP 评测与官方评测有细节差异，已优化 reward 使其对齐。agent 任务年前重点做 SFT，目前评测基建已无问题，采用社区数据有明显提升，预计年前将评测速度 scaling 上去。
  - 推理专项
    - 模型缺陷分析与数据补充：马征介绍推理专项换用千问 3 base 后，分析其在多个 benchmark 上的缺陷，重点在复杂图表、大学学科类、多模数学立体几何和智力题等方面。通过补充数据，在 ocreasoning、GBQA 和 Sensebench 等榜单上有提升，但立体几何数据缺乏，后续考虑购买。
    - SFT 问题与优化：做千问三 SFT 后训练时遇到指令跟随问题，通过补充指令拉回分数，在主线关注的 10 个 Benchmark 上平均提升一个点。目前数据涵盖多种类别，但仍需持续补充。
  - 可靠推理专项
    - 技术方向规划：肖鹏介绍可靠推理技术方向，包括提升模型内存可靠和模型内生可靠推理能力。内存可靠方面，结伴博弈的 Mesh 工作已完成训练流程复现，目前以蒸馏方式积累教学 model 的 ORM 数据；PRM 线因数据扩展难度和业务效果问题，优先级暂时放低，后续优先探索 agent 的 PM。同时新增外部工具交叉验证的可靠推理方向，先在编程工具上跑通流程，积累工具能力后再考虑协作工具。
    - 技术路径分析：闫洁认为可靠推理技术路径明确，包括模型预训练增强、后训练增强和外部工具辅助，其中 midotraining 和解题判题模型、通用编程验证可 scale up，优先发展；在专门领域，如 PRM 和形式化验证，在小领域可应用，但大领域存在问题，可在局限领域探索价值。
  - 工具调用与评测专项：么天阔汇报内部方式 code 评测集框架初步搭建，本周预计初步跑通；与大众志团队合作，对方春节前完成框架重构；Multi teacher on policy distill 算法在支持 Megatron 时还在 debug。针对评测发现的工具调用场景下指令跟随问题和常用信息抽取复读问题，正在构建子集和补充数据解决。API 文档采集需求已同步，等待供应商反馈；真实用户 query 采集第一波可用性差，需更换供应商。通用工具调用切换到 qwen 3 vl 后点数降低，后续将基于思雷新训的 MI training 进行训练并优化方案。通用 RL 用自己数据训练有涨点，但合入马征的完整 RL 数据后无提升，将清洗数据并提供高质量 IO 数据给马征，共同分析问题。深度搜索完成基建工作，数据持续刷取和管理，正在探索 Titan scaling 和 context manager 策略，因高轮次和超长上下文场景，重新设计 RL 中 turn reward 计算方法，目前实验受限于轮数和 TOKEN 限制，正在优化。
  - OCR 专题
    - Neo OCR 进展：沈锐介绍 Neo 方面积累约 39 万新数据，加入训练后在 ocrbenchv 上指标从 42 提升到 59，超过原主线模型。后续还将补充约 1500 万公开数据，当前主要制约是训练数据量不足。
    - 通用 OCR 进展：通用 OCR 有两个更新模型，基于 Qwen 3VL30BA3B thinking 迭代的模型，解决原主线 SFT 数据导致指标下降问题，重刷 7 万数据后掉点缓解；完成 SFT 数据按图片类型分类，后续将重刷约 300 万复杂文档类数据。分析 30BA3B 模型短板在 grounding、parsing 和 reasoning 方面，已积累 700 万数学论文类图像数据，完成 reasoning 数据生成流水线，预计春节前刷完 SFT 数据，春节期间完成 400 万 reasoning 数据生成。轻量化小模型采用 siglib 2 系列的 Vit 加上千万 2.50.5B 的 LLM 架构，推理速度达标，后续将用主线 SFT 进行训练。
  - 交互专题
    - 数据采集与处理：郭贺伟介绍交互专题在数据层面，已拿到 1 万小时真人数据（播客、访谈、影视剧等）进行初步管线验证并微调一版模型，后续 300 万小时数据预计 3 月底处理完成，最终留存约 30 万小时有效多轮对话训练数据。人工管线的采集、改写和打分流程已基本转通，人员规模接近 100 人。本周与产品确定通用口语拟人口语化对话标准，用于指导数据采集、改写和 rank 一致性。
    - 模型能力评估与问题：目前模型在指令跟随和知识问答点数上与主线接口数据训练的模型基本持平，但与开源的 VL 模型有差距。交互与各专题耦合性强，后续需共同考虑提升方案。林达华提出思考交互模型与主线推理型模型的迭代关系，少卿将组织小范围会议，乐炜和行程参与，明确多模态 agent、理解智能与生成结合、交互等模型的迭代关系和生产关系，重新分配资源。
