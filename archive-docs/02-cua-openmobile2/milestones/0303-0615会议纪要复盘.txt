总结
[白板: OZvWwVArOh0QXCbxCFUczEWJnOh]
本次会议围绕 PPT 数据合成、模型训练、标注评测、实验等工作展开讨论，参会人员汇报了工作进展、存在问题，并共同探讨解决方案与后续计划，内容如下：
- PPT 数据合成与模型效果
- 本周工作成果
- 数据合成与交付：韩世凡汇报本周合成 PPT 轨迹数据，完善蒸馏管线，整合 PPT query 合成策略，增加 query 多样性，交付带文件输入和不带文件输入及多种应用场景的数据，共 20K query，利用 nanobot 蒸馏管线蒸馏 20K，具体数据样本量和 TOKEN 长度统计在链接中。
- 模型微调与测试：交付数据并微调模型后，在王博提供的 14 个 PPT 测试 demo 上查看生成效果，分析模型存在的问题。
- 存在问题
- API 不稳定：假期蒸馏时 Gemini3 的 3.1 Pro API 不稳定，联系人员后才稳定蒸馏，影响蒸馏速度。
- 模型生成效果不佳：27B 模型在 14 个样本测试中，5 个未按指令生成 html 格式 PPT，1 个生成 PPTX 文件，9 个中有 4 个效果基本不可用；部分模型生成的 PPT 只有标题，无实质内容，不擅长使用 search 功能。
- 解决方案
- 优化技能：配合王博针对模型问题优化各环节技能，通过抽样迭代完善蒸馏管线性能。
- 后处理策略：马征提出后续造数据时增加后处理，去除不好的数据，目前训练数据仅进行规则化过滤，缺乏基于 PPT html 排版效果的过滤评测。
- 标注与评测工作
- 标注系统搭建与测试
- 系统搭建与数据测试：刘承杰本周搭建好标注系统，用 Gemini 3.1、Claude 4.6、GPT 5.4 四个模型对 200 条中文 Benchmark 图片重新标注打分，与人工标注结果对比，发现人工与模型打分差异较大，仅两个图片 10 个维度完全相同，Gemini 表现与人工较贴近。
- 问题分析与策略调整：刘承杰认为人工标注结果存在一定问题，后续对提示词进行修改，重新跑数据时卡住，需查看结果。下周计划优化提示词和策略，跑 200 条英文数据。
- 评测方案改进
- 第二版评测尝试：张荧滢针对第一版 Benchmark 问题进行第二版尝试，输入覆盖 5 种类型，前置提取评估约束，进行单页质量和全套 PPT 一致性、内容检测，输出综合评分。
- 核心改进与效果：核心改进包括将 10 个维度 012 打分映射为缺陷数量，增加惩罚机制，提升视觉短板检测敏感度；新增前置约束提取，依托固定约束评估，结果显示一套 PPT 平均约 8 条约束，满足率 78.4%，但 agent 间区分度差。
- 实验与问题：尝试让评分模型基于任务完成度和 checklist 对 PPT 对比排名，能区分内容空洞和详实的 PPT，但与人类盲评数据一致性不高。当前与人类盲评一致性中等，下周在新 query 上扩跑，优化内容维度。
- 后续优化方向
- 算法拟合与人工介入：马征提出通过 200 张图片拟合算法，找到维度不一致处，人工介入调整，以人工标注为基准，算法进行 double check。
- 打分调整与同步：将打分压缩为 0 和 1，与做测评的同学同步，解决打分不一致问题。
- 更新盲评数据：更新人类盲评数据，让内部做 PPT 相关的同学参与标注，计算一致性。
- 美学评估标准：待设计实习生下周入职后给出美学评估标准，加入评测体系。
- 模型训练工作
- Reward model 训练
- 训练过程与问题：王浩在 base 模型上直接做 GPO 效果不佳，使用 3000 条标注数据合成 SFT 数据进行训练，用刘承杰修正后的中文 Benchmark 测试，SFT 可大幅提高模型圈线检出率，但内容完整性维度 recall 值下降，降 po 后模型在美观层面得分上升，质检层召回率下降，仅提供图片让模型找错能力不足。
- 后续计划：统计训练集各维度是否平衡，优化训练数据；调整奖励模型函数，避免模型训练过于保守；通过大模型合成 SFT 数据，与刘承杰沟通保证 SFT 和 Benchmark 检出结果一致；重新构造数据时将 0、1、2 合并为 0 和 1。
- 数据核审与模型鲁棒性
- 数据过滤与训练：秦世龙本周进行无插图数据过滤，用大模型筛选将 66K 数据筛成 60K 左右，用规则映射筛选剩 20K 左右并训练 4B 模型，效果难以评定；进行带插图 html 生成管线，已生成 6K 左右数据，因网络中断暂停。

- 处理流程：王博介绍目前将 PPTX 转成 html 数据，先用第三方 API 或库将 PPTX 内容转成 SVG 格式，再将 SVG 转成 html。目前 200 万页 PPT 中约 100 多万页已完成转 SVG 步骤，但未得到最终的 html。
- SVG 缺陷：SVG 存在字体识别不佳、所有元素用 path 形式绘制、统计图表处理不当等问题。比如字体不能很好识别，规则图形也按路径绘制，原生自带图表当成纯图处理。
- html 优势：html 格式更规范，实现手段更多样，目前对标闭源模型生成 html 的能力比生成 SVG 能力强。
- 引入 SVG 原因：因无直接将 PPT 转 html 的工具，且 PPT 本身的 Openoffice XML 处理相对复杂，先转成 SVG 可简化处理。
[图片是PPTX转HTML数据处理流程图。原始PPTX文件含10万个PPT、近200万页DDX数据，经第三方API转换为SVG格式，包含完整页面绘制。SVG存在字体识别不佳、元素用path绘制、原生图表转纯图等缺陷。SVG转HTML时，规则图形转HTML元素、文本转div队列、去除不可见模板内容。HTML有格式更规范、模型生成能力强、实现手段多样的优势。但目前存在不规则图形处理、图片转语言描述、模板背景分离等待解决问题。该图与文档中介绍的html优势、引入SVG原因及待解决问题等内容相关。]
- 待解决问题
- 不规则图形处理：目前对 SVG 中的不规则图形无好的处理手段，只能保留成 SVG，后续可筛查，先处理简单的。
- 图片处理：代码生成任务中图片难以生成，目前图片以 base64 形式插入，后续考虑将图片变成纯语言描述。直接将不规则图形当图片处理可能会对模型产生干扰。
- 模板和背景处理：指定模板或背景图让模型生成内容，目前头部模型效果一般，4.0 阶段测试不太能做到基于图像内容的布局规划。训练数据可将输入图片的背景换成描述，生成的 html 中用占位符表示图片位置。但目前抠图成功率低，难以将背景图分离。
- Benchmark 相关讨论
- 现有调研情况
- 张荧滢调研：张荧滢调研自然语言生成 PPT 场景的 Benchmark，主要是直接生成的，部分与 ground truth 图片比较，但不是单纯一张图片还原。涉及 auto present、PPTC Benchmark 等工作。
- 开源 Benchmark 不足：王博指出开源 Benchmark 大多从 LR、偏传统 CV 评估或光谱思路对比，准确率不高且不稳定，CV 评估 BIAS 较大，目前难以满足需求。
- Benchmark 构建思路
- 人打方式：目前先采用人打方式，需设计相关 metric，后续专门开会讨论标 reward model 数据。
- 分类设置：马征认为目前分类如汇报战略方案等不太适合作为 Benchmark 分类，建议以真实场景如学术、金融等定义类别，每个类别先准备十几个样本数据，后续可根据情况添加新类别。
- 工具调研与参考工作
- 工具调研
- Python PPTX 库：用户 932335 介绍 Python 自动化转化 PPT 有两种方式，其中 Python PPTX 库很久未更新，直接调库有功能不支持，只能还原重要文本和图片，一些细节参数无法调整，如文本框圆角半径。
- 网页直接转换：网上有可将 PDFX 直接转换成 html 的网站，但有使用限制，如时间、使用次数和 PPT 大小限制。Adobe 公司和 WPS 的 API 要么转成 SVG，要么用 CV 方式做 OCR 识别重绘，还原效果一般，且 OCR 识别可能导致字体信息丢失。
