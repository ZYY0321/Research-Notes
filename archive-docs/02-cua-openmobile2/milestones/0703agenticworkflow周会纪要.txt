- 模型研发进展
  - 数据过滤与模型更新
    - 数据过滤管线完善：上周对数据过滤管线进行密集拉通和完善，本周新生产的模型基于相关过滤和数据合成有不错提升。
    - 代码规划推进：核心团队与亚冰、嘉伟等相关同学重新梳理代码规划，分成三大块 track 推进，集中员工和实习生从评测着手，争取一两周搭建起来，以牵引万亿模型参数代码计划。
  - 9B 模型研究
    - 目标设定与路径探索：范嘉楠提出 9B 模型目标是让其达到 55 分，以搭建 AI for AI 路径，林达华强调需明确从模型分数到团队基础设施的中间步骤和里程碑，后续卢乐炜表示会和嘉楠、嘉伟继续讨论。
    - 训练问题与经验总结：本周推进 9B 模型时遇到问题，如使用 GPT 模式不理想，需固化原子 skill 并建立机制避免反复问题；AOSS 不互通，回退到原始方案；toolcall 调用幻觉问题，需人工指示；D 盘被清，提醒备份数据；知识部分旧 skill hub 使用存在 bug，需修复。
  - 27B 模型集成
- 路线走通与效果提升：洪嘉伟表示 5 - 6 月集成 27B、12B 模型遇挫折，现全面切到 sota 模型，集成路线走通，最新 27B 模型加 40 万条高质量 clue 效果明显，接近 v4 - flash。
- 问题与规划：暴露代码短板、基数据质量旧、编排能力不足等问题。7 月 27B 底座模型向中体量切换，集中人力打通代码能力，盘点基数据升级，探索 GM5.2 思维链，补充 Coding 基数据。

- 数据处理情况
  - 小浣熊项目进展
    - 各模块开发进度：刘文民介绍小浣熊 agent 框架数据埋点完成方案评审并开发，下周提测；system sql 重构先调通数分流程，做公共模块抽取和 skill 重构；27B 模型适配到测试环境，需优化训练；PPT 对接 lora 模型，预计本周完成，下周部署测试；数据分析完成主要调试开发，增加控制功能；memory 完成核心开发，进行联调，下周提测；桌面端持续优化，打通飞书 bot 和微信 bot。
    - 活跃用户数据：林达华询问小浣熊近一周活跃用户情况，刘文民表示数据在安亚处，后续林达华表示回头询问。
  - 回流数据问题
    - 编码问题修复：么天阔提到回流数据上周正常，本周因编码格式问题出现乱码，正在修复，周二到周四数据缺失。
    - 复现结果分析：邱添羽将 6 月 15 - 21 日数据加到网站，用 Hermes 复现 270 条测试题，其中 172 条 DeepSeek 打标为沙盒完备可复现，新答案约 40% 答对。分析框架问题和模型能力不足的区别，计划用 opus 值 4.7 或 4.8 模型重跑部分题。
  - 通用 agent 规划
    - 能力达标与问题解决：么天阔表示通用 agent 各子专项能力达标，subagent 初具能力，长文数据构造完成待验证，搜索能力符合预期，browseuse 内部榜单构建预计本周或下周完成。后续优化数据流程，提升数据质量，打通专项安排，建立测试和问题发现机制，维护刷数据管线。
    - 数据协同与规划：林达华询问长文数据与模型训练的协同逻辑，么天阔表示数据做好后交给嘉伟训练，还涉及 PPT、Coding 等常规数据。后续计划走 OPD 路线进行数据合版。
- 量化与集成工作
  - 量化目标与进展
    - 目标达成情况：肖鹏表示 6 月量化目标是在 benchmark 上追平头部开源模型，基于 27B 训练有提升，能追平三有 CP 能力，但集成效果待关注。
    - 后续规划：8 月除在集上拿分，还希望实现横向拉通，同时强调 8 月要实现有效集成。目前交流数据效率是卡点，后续会持续交流，保证数据质量。
  - 集成问题与解决
    - 集成难题分析：林达华指出集成效果不佳会影响投入逻辑，要求肖鹏和嘉伟对齐中间格式等问题。闫洁认为可能存在小浣熊和 deerflow 等 harness 不同的情况。
    - 数据协同思考：林达华强调各子专项数据协同问题，要求先理清楚逻辑，避免资源分散。洪嘉伟建议尝试 GM5.2 模型，辛昱磊表示会拉齐相关事宜。
- Coding 规划与进展
- 整体目标与拆分
  - 目标设定依据：史亚冰提出 Coding 基建模型目标是达到 GM5.2 的 85 能力分位，认为此目标体感上可用，且从数据和环境累积角度有挑战但可实现。
  - 能力拆分与规划：将 Coding 能力拆分为 Terminal、前端、Swe 和基础兜底四大能力。Terminal 按既定计划开展，关注 bench 3.0；前端编程注重基础代码实施能力和动态视觉可交互 IDFA 场景，用自建评测集和 Defects bench 驱动；思维编码从传统向进阶能力转变，弃用 Wifi bench，聚焦 pro 数据集；兜底能力注重问题均衡、集中 case 优化和协同能力，用 LCB 等基础 benchmark 和主线评估复集解决问题。

  - 各部分进展
    - Terminal 进展：任远航表示 7 月 Terminal 目标完成，修复社区数据，terminal chat 数据效果好，接近 3.7 Max；验证修复价值，合并数据效果待优化；集成 DPO 有提升，但训练后期有掉点，后续继续补充数据。
    - 前端进展：郑昊表示前端处于起步阶段，计划评测模型在基础和通用前端的能力，针对薄弱点造数据。
    - 技术集进展：洪嘉伟介绍从 Coding 基数据筛出 3 万条难题，补充开源 RL 难题共 5.6 万条，验证有 9 个点提升，但 first step bench 有掉点，后续补全 domain 数据；用 GM5.2 模型刷数据进度慢，观察其思维链与克劳德相似但啰嗦，待验证结果决定用哪个模型刷。
  - 规划细化与集成
    - 规划细化要求：林达华要求史亚冰细化 Coding 规划，明确重点突出的特色、补短板的位置和数据工程规划，后续两人会找时间详细对接。
    - 集成考虑：史亚冰表示设计会考虑主线模型集成问题，与乐炜、嘉伟开会讨论。林达华强调分阶段达成目标，辛昱磊表示下周专题对扣点事情。
- Agent 相关进展
  - Agentv4 与 Memory
    - Agentv4 目标达成：罗嘉鹏表示 Agentv4 7 月初基本无 bug，可在内部场景投入使用，8 月上旬持续完善框架功能。
    - Memory 推进情况：Agent memory 7 月初在小浣熊投入使用已推进较大一步，后续解决存在问题，预计上线时间如文民所说；8 月初希望新范式达到可使用程度。
    - Skill 开源项目：Skill 开源项目目前数量为 4.6K，与预期 6K 有差距，后续一个月改善易用性和体验，嵌入 UI 界面，调优运行时间。
    - 其他方面进展：agent safety 和 vision 的 browser agent 进展有 delay，8 月初继续推进，产出有效数据加入主线模型训练；短期内同学抽调到专项一支持，部分更新较少；Agentv3 评测集制作，桌面 agent 待明确分工；Practic Memory 一期框架完成，二期解决记忆更新和存储问题，proactive memory 处理用户轨迹待评测；自动化 skill 方面，博的 PPT progress ui 开发接近完成，预计短期内推出。
  - 集团级 Agent 框架：林达华提到 CNI 后续会有 vlog 逻辑，投入更多工程力量建设集团级 agent 框架，拉通和协调各方面工作。
- Infra 与评测工作
  - Infra 进展
    - 训练优化：杨波表示舒岩合入 DP 负载不均衡，训练速度提升 8%，GM5.2 在 B300 上跑通单层，后续检查技术报告细节，修复线上 bug 和答疑。
    - OPD 进展：姚勇强介绍 OPD 确定硬件支持，下周接好 topk 的 doc feed 返回；VR 初版跑通，推理和训练共用卡，正在写 Teacher 和训练模型共用卡方案；Remote Agent 搭建动态环境，走通 27B 小环境场景，全异步 9B 在 8 个节点走通，大 setting 待验证。
    - 算法侧进展：吴泽寰表示 OPD 接入 coding 任务，9B 模型训练曲线符合预期，27B 实验有 gradnorm 凸起待分析；考虑 MOPD 方案，各 domain 按最佳配方训练后蒸馏到学生；文档分析新增镜像变种和环境随机性，agentv4 集成到 VR 测试成功，agentv3 预计下周完成集成；搜索尝试接入新任务，长任务和工具功能集成进展中。
  - 评测进展
    - 线上模型监控：杨益博对线上模型监控，定位到 claude code 版本升级路由链路变化和沙滩入客中断问题，分别进行适配和排查修复；采用新的 token 统计指标，构建端到端 harness 评测集，嘉伟模型比线上模型高 0.2 - 0.3 分，接近 DeepSeek base flash；后续拓展题目数量和维度，参考开源评测方案提高稳定性。
    - 模型评测问题：洪建操评测多个模型，发现多模态调用报错、平起 bench V2.0 分数低、部分模型缺少权威渠道、国内模型并发能力低等问题；评测流程自动化基建方面，集成 MCPverse 和 Hermes 主观集，构建评测镜像，完成 ECS 自动化评测流程大部分，下周部署到马来集群；数据集集成方面，1 兆上下文开源数据集 MRCRV2 集成到 sensebench，但部分模型超上限得 0 分，AA 榜单 Terminal Bench Hard 集成流程已跑起，分数待对齐。

  - 资源到位与研发：辛昱磊表示 8 台 B300 资源周三前到位，杨波和世豪已在机器上进行训推框架研发。
  - 数据交付 SOP：辛昱磊搭建训练数据交付 SOP，周末实验，没问题下周正式投入使用，可实现数据专题交付人员统一入口交付数据，质检记录可视化并关联数据 feature 信息和集成训练版本。
