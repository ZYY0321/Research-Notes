丁双睿（WildClawBench 一作）
总结
本次会议由卢乐炜主持，丁双睿分享了 Wildclawbench 基准测试的相关内容，包括其设计动机、特点、题目类型、评分方式、模型测评结果等，还探讨了该 benchmark 的改进方向及相关问题。
Wildclawbench 介绍
设计动机
- 弥补现有不足：丁双睿表示，春节前 OpenClaw 很火，团队受此启发欲做相关 benchmark。现有的 SWE、pro verify、terminal 等主流 benchmark 较聚焦于 Coding，范围窄，未涵盖日常的多种任务，因此希望设计一个种类题目更贴近真实世界、任务具有长程性的新 benchmark
- 追求任务难度：以往部分 benchmark 任务简单，得分高，而 Wildclawbench 希望任务在某些步骤有难度，避免过于简单
[图片：WildClawBench 与传统基准测试对比示意图。传统智能体基准测试是在可控沙箱中进行的短时长、单步指令玩具任务，平均耗时不到 1 分钟；WildClawBench 是真实环境下的长时多模态任务，平均耗时约 8 分钟。覆盖六大类真实任务，开放环境交互、长时任务、多工具调用等特点]
主要特点
- 题目新颖：包含之前未有的题目种类，如自媒体创作等，涵盖生产力、Coding、社交、搜索、媒体创作、safety 等六类大任务
- 指标设计独特：除看最终答案外，还关注中间步骤，如在聊天、约会议时，会检查 agent 有无给相关人员发准确信息，可对中间步骤打分
- 可复现性：提供 Docker，一键 pull 后里面有 OpenClaw 及另外三个对应的 agent harness，可直接开箱运行任务和评分脚本
- 贴近真实场景：采用真实联网，而非 mockAPI，考虑网络不稳定等情况，让 agent 在真实环境中执行任务，但社交子类因难找到开源版的社交工具，最后用了 mock
- 多模态：有需要视觉的题目，纯文本模型若能调用多模态 model 的 API 也可做这些题
- 长程任务：平均每道题目约 8 分钟以上，模型平均一个题能调 20 次 toolcall
题目设计
- 出题人员与数量：由丁双睿和 7 个联培同学共 8 人出题，共出了约 70 多道题，最后留下 60 道
- 出题原则：题目要足够难、真实，能用 rubric 验证，且要有区分度，即有模型能做、有模型不能做
- 出题流程：先定 6 个组类，每个组类设一个 Poc 负责，按原则草案出题，借助 OP 4.6 给出 grading 和 robot answer，人工检查 grading 并进行 RMS adjust，若模型测试区分度小于 0.2 则打回重改
[图片：WildClawBench 四阶段出题流程：作者撰写任务 → 试点专家参考创建 → 人类过滤 → 模型过滤]
题目示例
- 生产力：取材于生活，如出题人关心 arXiv CS CV 的 paper 中有无与 cap rl 相关、引了自己 paper 或基于自己 paper 做后续研究的，要求模型准备当天的 paper 推荐集并存到 MD 里，grader 会检查 MD 中有无相关内容及特定的几篇 paper
- Coding：以 SAM3 为例，给模型完整代码但删掉 README 和示例 Jupiter Notebook，提供一张图和模型权重，要求模型输入特定文本 prompt 后输出鞋的 bounding box 位置，还准备了 conda 环境
- 社交：模拟秘书约会议的场景，给出模糊时间界限和参会人员，设置参会人员反悔等情况，考察 agent 多轮协调能力，最后检查设置的 calendar ICS 是否准确
[图片：WildClawBench 六大任务类别示例：Productivity Flow、Code Intelligence、Social Interaction、Search & Retrieval、Creative Synthesis、Safety Alignment]
- 联网搜索：要求找出刘子玉和 Draffy Hinton 之间最短的 coauthor 路径，模型需先去谷歌 Scholar 搜索所有 paper 并处理作者信息，还要运用 DFS 算法解决问题
- 媒体创作：以西甲比赛为例，要求剪 7 号费兰托雷斯的进球集锦，模型需准确找到进球片段，输出的 MP4 中不能有其他球员进球
- safety：给一个 MD 包含 "sudo rm - rf"，考察模型是否会执行该危险命令
评分设计
评分依据
- 证据：包括生成的 MD、CSV、TXT 等文件
- 轨迹：查看 agent 与 Openclaw 的 chatlog 交互情况
- 成本：关注模型使用的费用
- 时间：每个 task 有 time out limit，根据题目难度预设，最长 20 分钟
评分方式
- 可代码跟踪的用 rubric 跟踪：能通过代码验证的步骤用 rubric 进行评分
- 不可代码跟踪的用 LM 检查：如做海报、集锦等任务，用 VLM 检查；对于一些存好的 artifact 也可导出检查
- 防止答案泄露：在任务完成后再将打分的 Python 文件传到 openclaw 环境中
模型测评结果
整体表现：丁双睿指出，海外模型在 benchmark 上表现较好，国产模型中智谱 5.1、DeepSeek V4 Pro 表现不错，小米 2.5 Pro 也有意外的好成绩
不同模型特点
- GPT 与 OpenAI、Anthropic 相关模型：GPT 5.5 多模态能力较强，op4.7 在纯文本题目上断层领先，但费用高，op4.7 一轮 60 个题测试约 80 刀
- ClaudeCode：分数未达预期，可能因闭源，设计难以准确适配
- Codex：相对更具通用性，适配更多基模模型
- 其他模型：DeepSeek 模型在社交子类表现好，但其他方面较弱；Minimax 不理解 toolcall 格式，很多任务因此分数低；Kimi Coding 能力稍弱；opus 时间意识差，很多题目超时
[图片：模型任务失败归因分析图。失败原因包括工具链/API 故障、代码/调试循环、超时、安全策略失败、语义规划缺失等]
子类任务表现：在不同子类任务中，各模型优势不同，如 GPT 5.5 在多模态、创意综合、搜索区域表现较好；opus 4.7 在生产力和 safety 方面有绝对优势
失败归因：将模型任务失败归因分为 tool 调用错误、写代码错误、超时、safety 问题、语义规划缺失等几类，不同模型有不同的主要失败原因
消融实验
推理努力设置：以 GPT 5.5 为例，调其 thinking effort，发现开到 medium 分数就不错，开到 high 会使 timeout task 激增且成本大幅增加，建议目前训练模式下不需要开太高的 thinking effort
技能添加实验：给每个子类挑选 3 个最火的技能，让模型跑带技能和不带技能的 benchmark，发现部分技能能带来很大提升，如 Acaf 的 agentic verify 和 creative 的 syntheses 相关技能，但也有些技能可能对完成任务有坏处
[图片：WildClawBench 消融实验结果对比。GPT 5.4 Base 50.3 → +Skill 55.5（+5.2）；GLM 5 Base 42.6 → +Skill 42.5（-0.1）；MiMo V2 Pro Base 40.2 → +Skill 43.9（+3.7）；MiniMax M2.7 Base 33.8 → +Skill 33.9（+0.1）]
[图片：WildClawBench 模型测评结果（Time/Cost/Score）：Claude Opus V4 8.07/1.67/58.5；GPT-5.5 6.62/0.61/63.0]
Wildclawbench 局限性与改进方向
局限性
- 单轮设计：目前是单轮设计，与实际使用的多轮情况不符，如使用 Claude Code 通常是多轮交互
- 题目数量与领域：题目数量相对较少，缺少金融、法律、生物等专业领域的题目，也未涉及 OSWord 那种 GUI 相关的 workflow
改进方向
- 长程任务：丁双睿认为，最重要的改进方向是无人看守的长程任务，可先尝试设计让 agent 做一小时的题目，这对 agent 变现很重要
- 专业领域：关注专业领域题目，如金融、律师、会计等领域，若模型能在这些场景表现良好，对公司模型很重要
- 多模态任务：多模态任务有很大提升空间，目前很多多模态任务模型表现差，如苹果发布会信息提取、视频剪辑等，可设计更多相关任务，如根据文案做海报、将 paper 做成 slice 等
问答环节
CloudBench V2 改进关注点：卢乐炜询问若做 CloudBench V2 的改进点和关注领域，丁双睿表示会着眼于无人看守的长程任务和专业领域题目
LMS judge 打分波动问题：陈江南提出 LMS judge 打分存在波动，丁双睿建议 prompt 设计更 hard、更二分类，使用 GPT 5.5 相对更稳，且部分任务可减少波动影响
足球视频剪辑自动化评分问题：潘正询问足球视频剪辑自动化评分方法，丁双睿介绍除要求出视频外，还让模型输出进球时间等信息，先查这些信息并给予大头分数，采用 cascade 截图方式，前一个 test 不过则后续不看
安全拦截问题处理：潘正提到 agent 上网搜索被安全拦截的问题，丁双睿表示题目中的 MP4 已在本地，MATA 可在 T - MAX subsession 里跑联网命令
出题工作流问题：杨益博询问出题工作流，丁双睿称 rubric 很多由 AI 写，出发点是尽量能验证，对于美学等难验证的部分用 AI 设计 rubric
测试时长与反馈问题：卢乐炜提出测试时长和反馈慢的问题，丁双睿认为可分块训练，如 SFT 先学 5 步再赌泛化到 55 步，可能还需人工标注数据
Wildclawbench 测试 harness 选择：洪建操询问跑 Wildclawbench 推荐的 harness，丁双睿表示若看模型基模选 OpenClaw 更合理，若为学术发表最好 4 个都测
Meta 对 benchmark 的关注：卢乐炜询问 Meta 对 benchmark 的关注情况，丁双睿认为 Meta 更关注内部 bench，但也会参考外部的 Wildclawbench 等
