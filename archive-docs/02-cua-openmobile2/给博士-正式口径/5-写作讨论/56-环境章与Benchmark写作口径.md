## 1. 全文里这一块的位置

- 闫晨阳 lead 全文。篇幅草案：abs+intro 两页，MobileGYM++ 三页，轨迹/训练一页，结果和分析三页。

## 2. 环境章怎么切（三页）

| 小节 | 约 | 写什么 | 不写什么 |
|---|---|---|---|
| 环境本身 | ~1 页 | 扩 App、跨 App、规模、对比表 | 混合调用的长动机 |
| App-native tools | ~0.4 页 | 作为环境**特点**：动作空间、和 GUI 共用 Store、怎么暴露 | 为什么要 Hybrid；Hybrid 好不好 |
| **MobileGYM++ Bench** | **~1.5 页** | 精简版 benchmark paper：背景、动机、设计、质量 | 正式分数和现象分析（放实验章） |

**Intro 和这一章的分工**

- 混合调用「为什么值得做」：intro 讲清楚即可，环境章不再费笔墨写动机。
- Tools：环境章只写机制（和 click/type 并列、同一 Store、写完 GUI 能回读）。
- Bench：「为什么要做这张集、设计是什么、凭什么说质量好」属于这一章，要写完整。

## 3. Benchmark 核心动机（已拍板：前者）

**要：** 在稳定、可重置的模拟商业 App 上，评 agent 能不能把跨 App 的商业任务做完。动作空间同时支持 GUI-only 和 Hybrid。

**不要：** 「我们为混合调用场景专门做了一张 bench」。

原因：也希望别人在这张集上只测 GUI-only。GUI-only 是一等公民，不是 Hybrid 的对照附属。这和题规一致：**正式集里 GUI 路径必须存在；Hybrid 是同一世界的另一种走法，不是唯一解。**

对外可收成一句：

> 主动机是可控的模拟商业 App、跨 App、可验的商业任务；混合调用是重要特性，不是这张 bench 存在的唯一理由。

瞰之原句里的组合（商业 App + 完全可控状态 + 跨 App + 长程任务，现有 bench 给不了；Hybrid 是重要特性）方向对，下面三条写的时候要收口，否则正文兜不住。

---

## 4. 和真机 bench 怎么并列

必须写，放在 Bench 的背景缺口里，几句话 + 对比表。不要写成「我们比真机更真实」。

| | 真机 / 真 App bench | MobileGYM++ |
|---|---|---|
| 界面保真 | 强 | 弱一截，是 mock |
| 状态重置 | 弱 | 强：每次同一份初始状态 |
| 成功判定 | 常见 UI 树 / 截图 / 拼规则 | 读业务 Store |
| 混合调用 | 真 App 通常不给原生接口 | 同一状态上 GUI 和 tool 都能走 |

一句话：真机评「在真实皮肤上点得对不对」；我们评「在可重置的商业状态上，事情做完了没有」。

对外口径用 **mock 商业软件**（瞰之）。任务可以像真实商业流程（账单最值、未付款总价、跨 App 写回），**环境本身不是真机、真 App、真账号**。不要用「真实业务」暗示我们在跑真支付宝。

---

## 5. 写的时候三处不要写满

1. **多样数据状态**：多种子 / 多 profile 这版还没有，不当前核心动机。现在只说完全可控、可复现的初始状态。多状态可留期刊或 future work。
2. **「现有所有 bench 都给不了」**：太满。要说的是**这一组同时没有**：模拟商业 App + 业务状态可重置 + 终态可验 + 同一世界 GUI / Hybrid 都能跑。
3. **真实长程**：不要去抢 OSWorld 那种超长任务。对外写 **跨 App 商业流程**。难在信息分散、字段易混、换 App 写回，不是 300+ 步。

「真实业务需求」对外改成 **商业任务 / 用户目标终态**。

## 6. Bench 这一节写什么（精简 benchmark paper）

1. **缺口**：真机保真但状态不可控、终态难验、几乎只评纯 GUI；上一版 MobileGym 商业 App 和跨 App 不够。
2. **原则**（必须写死）
   - 一条题 = 初始数据 + 题面 + Tool + Verifier，指向同一份可重置状态
   - 正式集 GUI 路径必须存在；Hybrid 可选
   - 只验用户目标终态，不验「搜过没有、点过哪」
   - 从可运行单元里筛，不另起一套题
   - Verifier 点名的实体，屏幕上和接口里都要能见到
3. **质量**：reset / 固定时间可复现；Verifier 不认 Agent 自报完成；人工抽查与规则同向、误放为 0；对不齐的先改再进。
4. **价值**：评同一商业 App 世界上，GUI 和混合调用能不能把业务做完。数字和现象放实验章。

**369 条双跑成功率（GUI 57.2% / Hybrid 68.3%）不是正式 Benchmark 分数，周三也不要当主结果报。**
