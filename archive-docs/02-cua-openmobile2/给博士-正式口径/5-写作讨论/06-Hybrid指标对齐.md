# Hybrid 指标：和闫晨阳对齐后、框架里还缺的表

来源：群里讨论 + `83-Hybrid指标咨询`。作者口径如下。R8 原文只写到成功率，明天给博士时要把表补进「实验契约」。

## 为什么不能只报一个成功率

正式题必须有纯界面路径。工具是可选捷径。因此一个模型可以完全不调工具、只靠界面，Hybrid 成功率仍然不低。成功率回答「能不能把事做完」，不回答「会不会用工具」和「工具有没有省步数」。

MobileWorld 的一部分题把外部工具做成接近必要条件，不用工具就很难过，所以他们主榜只看成功率，不用工具会反映在 SR 里。我们不是那种造题法，不能照搬「只看 SR」。

## 辅表

| 模型 | 至少调用过工具的题占比 | 调用成功占比 | Hybrid 平均步数 | GUI-only 平均步数 |
|---|---|---|---|---|
| … | | | | |

- 调用率单独很好刷：乱调一次也算调用过。  
- 成功调用不等于用对了返回值。  
- 步数必须两侧都报。低成功率会早停，步数看起来也低。内部已经见过 Hybrid 步数反而更多：先无效调用，再退回界面。  
- 理想图像是成功率上去、步数下来。大约七十题的小集上见过；更大的集上不一定。

## 不做什么

不把成功率、调用率、步数加权合成主榜。权重没有理论，还会把「界面很强不用工具」和「工具很勤但常失败」混成一个数。MobileWorld、AndroidWorld、前作都没有这种主榜。ToolCUA 的复合式是训练奖励，而且他们按题标了「适不适合用工具」；我们可以跑完轨迹再分析子集，不在造题时预筛。

## 写进哪一章

环境章至少要用三句话声明：成功只看库；主比较是两个成功率；效率与调用放辅表并加早停注释。空表放环境章还是实验章，问博士。
