We introduce OpenMobile-2, a near-frontier mobile agent with fully open training environments and recipes. We make three key advances: (1) Diverse Environments with Simulated Commercial Apps: We build MobileGym++, featuring 35 realistic, functionally rich commercial-style apps with cross-app workflows, while preserving full controllability for reset and verification. Together with newly configured apps in Android emulators, we establish a diverse training playground spanning over 110 apps. (2) Open Training Data at Scale: Building on this foundation, we curate 12K mobile interaction trajectories for supervised fine-tuning and the largest open collection of verifiable RL training data for mobile agents, comprising over 2K executable tasks with automatic rewards. (3) Hybrid GUI and App-Native Tool Use: We explore an experimental mobile-use setting where apps expose selected functionalities as app-native tools alongside their GUIs, allowing agents to interleave GUI actions and tool calls within a task. We implement this setting in MobileGym++ with over 300 carefully scoped tools across 50 apps. Additionally, we introduce MobileGym++ Bench with realistic, long-horizon tasks over commercial-style apps, supporting both GUI-only and hybrid GUI–tool evaluation under a unified task suite. OpenMobile-2 achieves competitive performance on AndroidWorld (79.2), MobileWorld (48.3), and MobileGym++ (60.8), while showing promising transfer to real-device mobile use. 主题：第 (3) 条要不要做成「工具调用闭环」，还是只做环境/评测协议。

可转发原文：

> 摘要第 (3) 条想跟你对一下口径，避免后面实验和相关工作对不上。
>
> 最近 CUA-Universe（桌面 GUI+CLI）那篇，显著靠的是一条闭环：命令面定好 → 题从这些命令织出来 → Path-Steer 收过判定的 hybrid 轨迹 → 再训小模型。他们自己消融也写了，同一套 CLI 去掉 steering，增益就没了。强模型在他们那套命令上几乎不加分。所以涨分的是「训过这套工具」，不是「评测时开放了工具」。
>
> 我们这边现在更像：环境里有工具（大约 50 App / 300+，不少新复刻还是 search/list；不少题的写操作没有对应函数）、Bench 同一套题可以 GUI-only / hybrid 对照、Gemini 这种强模型在 hybrid 上已经有增益。但 9B 在同一张 215 上 hybrid 并不显著；12K / 2K 里有多少是按这些工具收齐、训过、再评同一套，我这边对不齐。马征也说了这轮不看纯 OOD（环境后补工具、权重还是旧的）。
>
> 想确认第 (3) 条这轮要立成哪一种：
>
> A. **闭环**：工具面、出题、hybrid 轨迹、训练、再评必须对齐。那 12K/2K 和 RL 要明确吃这些 app-native tools，摘要才能把 hybrid 写成和 (1)(2) 同级的 advance。工期和对 CUA-Universe 的关系也要按这个排。
>
> B. **试验床 / 协议**：同一套题、同一套判定，GUI 和 hybrid 并列可评；工具是 plus，不声称开源 9B 因调工具而起飞。那标题和 (3) 的措辞要压住，避免审稿人按 CUA-Universe 的体裁找「训完 hybrid 的表」。
>
