# 给闫晨阳：本环境一页

只谈这一块环境。画主图、写 intro 用。完整底稿：同夹 `84-主图运行逻辑-给闫晨阳.md`。机制摘录备份：`归档/85-0903周三审阅/08-环境工具判定摘录.md`。

## 是什么

浏览器里的手机模拟器。每个 App 有一份内存业务库：界面从这里画，工具改这里，判定读这里。Agent 只看截图和本轮函数表，看不到库。整机状态可以读成一份 JSON，也可以按这份 JSON 重置。时钟固定在 2026-07-12 09:00:00。

## 数字

可安装 64 个 App。新构造 35 个。约 52 个带工具定义。新构造商业客户端导航声明中位：37 条路由、175 个可交互动作、88 条跳转，深度中位 3。前作微信 100 / 265 / 深度 7。

任务按七个应用领域设计，规模约 200 条（约 116 单 App、84 真跨）。目前候选大约二百条，尚未正式锁定。

## 工具

不是外部地图或代码托管服务。每个 mock App 在自己的业务库上挂一组函数，和点击同一级。只推当前前台 App。正式题必须有一条纯界面路径；工具是捷径。支付键盘、选联系人留在界面。预填类调用不写入库，保存仍要点界面。日历是参考实现：搜索返回短候选，打开页再给新截图，预填日程后库里事件数组并不增加。

## 一局

同一套题、同一种初始化、同一套判定。开关只决定本轮有没有当前 App 的工具。每轮只执行一个调用。桌面或最近任务盖住时不给 App 工具。判定输入只有：开始前的库、结束后的库、可选的文字作答。成功看目标字段是否写对；干净看有没有改声明之外的路径。模型自报完成不算。

## 主图上建议能读出来的三件事

1. 世界 = 可重置的多 App 业务库 + 截图观测。  
2. 模型每步：手势，或当前前台的工具；两条路写同一份库。  
3. 停下来比两份 JSON，不比轨迹。
