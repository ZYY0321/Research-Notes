# 0815 Sonnet 4.6 出题管线，以及怎么接到现在的 Bench

2026-08-30。当时那批「每个 App 给真实底稿再让 4.6 出题」就在这里，没有丢。

**位置：** `docs/不要上传-修bug/0815tools实验/`  
**总说明：** `01-端到端实验管线.md`  
**设计原则：** `00-实验定位与工作方式.md`  
**对照实验（为什么要截图+结构事实）：** `04-Sonnet多模态任务生成对照实验.md`  
**产物：** `artifacts/task-generation/<App>/`（31 个新复刻 App）

它解决的是：**单 App 题怎样从真实 Store / 页面 / Tool 长出来，而不是凭品牌常识编。**  
现在 Bench 缺的是：**先按六个场景、再跨 App 组合。** 下面先复述完整流程，再写怎么接。

---

## 1. 当时实际喂给模型的，不是整份 defaults

你记得「完整底稿」方向对：题要落在真实商品、订单、国补地区上，不能瞎编 vivo / 白条。  
实现上 **没有把整个 App 源码和完整 defaults 塞进一次请求**（`00` / `04` 写明了，一次请求吞不下，也会串 App）。

每个 App 打成一份**压缩事实包 + 最多 12 张关键页截图**：

| 文件 | 从哪来 | 模型看到什么 |
|---|---|---|
| `navigation.json` / `navigation_simplified.json` | `navigation.declaration.ts` 分析图 | 页面、transition、可达性 |
| `state.compact.json` | `state.ts` / store 正则摘要 | 写动作名、观察到的字段、OS 调用 |
| `tools.compact.json` | `app_tools/apps/<id>/definitions.ts` | 真实 Tool 名、kind、声明摘录 |
| `candidates.compact.json` | `data/defaults.json` **抽样** | 每个集合：count + 最多 5 条样本（不是全表） |
| `screenshots-static/*.jpg` + 旁注 json | 模拟器关键页 | 入口、筛选、详情、结算等视觉 |
| `input-manifest.json` | 打包元数据 | 路由数、截图数、defaults 哈希、commit 可追溯 |

京东这份底稿的顶层 key 就是真实业务面：`items / cart / orders / guobuRegions / coupons / addresses`……样本里有店名、商品 id、白条额度。所以题能写成「河南国补 + vivo X300 + 白条 6 期」，而不是「买一个手机」。

脚本：

- 打事实包：`0815tools实验/scripts/build_all_fact_packs.py`
- 批量出题：`scripts/generate_all_with_sonnet.py`（`claude-sonnet-4-6`，temperature 0，一次一个 App）
- 大众点评试跑（更早、手写摘要）：`scripts/generate_tasks_with_sonnet.py`
- 自动门槛：`scripts/review_candidates.py`
- 落探索套件：`scripts/build_exploratory_suite.py`

`04` 里对照过：只给文本摘要容易写成测试用例；只给截图会编不存在的功能；**截图 + 精简 JSON** 最接近真实长链。正式批量走的是这一档（对照表里的 C），不是把全库倒进去。

## 2. 完整流程（当时 A → G）

```text
A 采集事实包（每 App 一份）
    → B Sonnet 4.6 出候选（public_instruction + private_design）
        → C 审查闸门（自动门槛 + 人工）
            → D 写成正式 spec / setup / verifier
                → E 冒烟（初态必须为负，正例能过）
                    → F 同初态双跑 hybrid / gui_only
                        → G 轨迹归因
```

生成和执行必须分开：没核实的创意不能跑；空数据、错 ID 不能算 Agent 失败；Verifier 不能看完轨迹再改。

### A. 采集

对 31 个新复刻 App 各建 `artifacts/task-generation/<App>/`。截图按功能域取入口和选择态（京东：首页、国补、分类、订单、购物车、搜索……），动态路由用真实种子 ID，空页 / not found 会丢掉。

### B. Sonnet 4.6 生成

- 一次只一个 App，避免京东数据和点评串线。
- 系统提示：只基于当前 mock 截图和结构事实，**不凭真实品牌常识补功能**。
- 最多约 8 条；证据不够就少出，不要凑数。
- 输出拆开：
  - `public_instruction`：只有用户目标和约束，禁止 Store / Tool / 检查 / 判分。
  - `private_design`：路径、所需事实、setup、终态、现有 Tool、风险。
- 原始回复存 `sonnet-raw.txt`，解析后存 `candidates.normalized.json`，不覆盖原文。

批量提示词的硬规则（现在 Bench 仍该留）：步骤必须服务**同一个用户目标**；禁止为了变长机械加笔记/微信；没有证据的功能不能写进题面；每条任务独立，不依赖上一条造的数据。

### C. 审查

自动门槛（`review_candidates.py`）：题面有没有 QA 词、长度、功能点是否在导航图里、搜索词/规格是否能在 candidates 里对上、是否独立 setup。结论 accept / rewrite / needs_fixture / reject。

人工再看：像不像人话、是不是该 App 特色、种子数据撑不撑得住、判定稳不稳。  
第一轮：260 条原始 → 224 条过结构证据门槛。自动曾误按每 App 截 4 条，已标 deprecated。

### D–E. 实现与冒烟

过审才写 setup、初态 fail-closed、终态 Verifier。117 条已有套件浏览器初态 117/117 过。当时 31 个里只有 11 个有 App Tool，其余还不能公平对照 Hybrid。

### F–G. 双跑和归因

同任务同初态跑 GUI-only 与 Hybrid。这批后来进了 369 里的 0815 explore 段。成功率当时明确 **不报**——语义 Verifier 没铺完。

## 3. 它和现在 Bench 骨架差在哪

| | 0815 管线 | 现在要的 Bench（58/59） |
|---|---|---|
| 入口 | **一个 App** | **一个业务场景**（职场 / 求职 / 出行…） |
| 题的形态 | 单 App 长链为主 | 真跨 App 为主，单 App 长链当少数/原子 |
| 底稿 | 该 App 的 nav + store 样本 + Tool + 截图 | 场景里 2–4 个 App 的底稿要一起看 |
| 收口 | 禁止机械加微信/笔记 | 微信/卡皮可以，但必须是第二个**业务**目的 |
| 难度 | 功能覆盖、多选项 | 信息不在第一屏；上限才是秘书题 |
| 产物 | 探索池、环境探针 | 正式集 25–35 条，四件套绑死 |

0815 不是废的：京东国补、猫眼选座、携程含早、BOSS 改期望，都是这条管线从真实样本里长出来的。缺的是 **A 之前没有「先定场景」**，B 没有「多 App 底稿一起喂」。

## 4. 融合后的一条管线（建议就用这个）

把 0815 整段嵌进 59 的「场景 → 结构 → 四件套」，不要另起炉灶。

```text
0. 定场景和一句真实吩咐          ← 现在 Bench（59 第一步）
1. 列出自然会打开的 2–4 个 App
2. 为这几个 App 各取 0815 事实包  ← 旧管线 A，可复用现成 artifacts
   跨 App 题：把 2–4 份 compact JSON + 各 4–8 张关键截图拼成一份「场景底稿」
3. Sonnet 出题                    ← 旧管线 B，提示词要改
   - 仍：只许用底稿里的实体/价格/Tool，禁止编造
   - 仍：public / private 拆开
   - 新：必须服务这一个场景目标；跨 App 必须有依赖，不许「查完发给陈静」
   - 新：GUI 路径必须存在；Tool 只写加速，不写「必须调用」
4. 审查                           ← 旧管线 C + 现在硬门槛
   像人话、三方能对齐、前提在 Store 里、不是假跨 App
5. 缺实体就补 defaults / 页面     ← 现在允许补素材（简历、行程中、张伟）
   补完更新事实包，再生成或改题，不要带着空世界出题
6. setup + 终态 Verifier + 冒烟   ← 旧管线 D/E
7. 同初态 GUI / Hybrid 双跑只作验收 ← 旧管线 F，不当正式分母
```

**单 App 长链**（猫眼、国补、携程填单）：几乎原样重跑 0815，只加一句「这条进哪个场景、是原子还是正式集」。  
**组合题**（秘书、S2 订酒店发给张伟、S9 投简历）：新做一个 `generate_scene_with_sonnet.py`，输入从「一个 App 文件夹」改成「一个场景文件夹」，里面是多份已经存在的 fact pack。

提示词从 0815 的「为 {app} 生成最多 8 条」改成：

> 场景：求职。用户吩咐：……  
> 下面是 BOSS / 邮件 / 文件 三份当前 mock 事实包和关键截图。  
> 只许用这些实体。产出 1–2 条跨 App 题。第二个 App 必须改变业务终态，不能只当信使。

这样真实性还是靠底稿，骨架则是场景而不是 App 目录。

---

## 5. 周三怎么一句话接上

> 出题分两层。底层沿用 0815：每个 App 的导航、抽样业务数据、Tool、关键截图喂给模型，题落在真实国补/场次/岗位上。上层按六个商业场景选 App、组合、补缺失素材。探索池里的单 App 长链当原子；正式集从场景组合里筛，不把 224 条整包当 Bench。
