## 2. 一条合格任务长什么样

四件套，指向 **同一份可重置 store**：

1. 初态（defaults / prepare，实体必须已在底稿里）
2. 公开题面：只写用户目标
3. GUI 路径必须存在；Tool 只是加速，**不能「必须调 Tool 才能过」**
4. Verifier 只验 **用户目标终态**，不验搜过没有、点过哪、调过哪个 Tool

题面语气（你刚点的）：统一成 **「我想……」** 第一人称用户目标。不要「你想」「请帮我检查」「用工具准备草稿」。不要出现 Store / Tool / Verifier / 截图 / 判分。

难度和真实性要能说出口：

- **像人会做的事**，不是开关、排序、切语言、改昵称
- 难在信息分散、约束多、换 App 写回，不在步数堆砌
- 跨 App 必须 **第二个 App 也有业务终态**（记一笔、建日程、分享详情、改地址并支付）。「查完发给陈静」= 假跨 App，不当覆盖
- 同骨只留一条（换商品名的加购支付不堆五条）

秘书题是质量上限，不是入门线。

## 3. 两轨分开，不要混

### 轨 A：已经双跑过的资产（只筛，不大改）

V6 + 0815 在 delivery-369 里 GUI / Hybrid 配对跑过的，是 **已验证资产**。

- 做：进 / 不进 / 同骨去重；题面统一「我想」；假跨 App、单步设置踢掉
- 不做：重写业务目标、换实体、换 verifier、为了「更好看」改约束
- 理由：大改等于新题，旧轨迹作废，你怕环境跑不了 / 验不了
- 4.6 分批看题面：表述、难度/真实性粗标、和跑分对照（GUI 挂且像环境/verifier 问题的标出来，不擅自改题）
- **进正式集前你仍会手点一遍**；轨 A 不代替手点

组合题（C02 这类）：题面是新的，骨架来自已跑过的源题。表里单独一列「组合自」。组合后必须再跑 GUI（和 Hybrid），不能只引用源题分数。

### 轨 B：新扩展（后台，完整管线，尽量不问你）

真跨 App 太少，靠组合 + 新出。出题必须走 0815 同款输入，**一次 2–4 个 App 的完整事实包**（navigation / state / tools / defaults 抽样 / 有则截图），禁止只丢一句「订完记卡皮」。

给 4.6 的自由度：

- 可以少出、可以不出
- 可以提问：这个实体在不在、这个写动作 GUI 能不能点完、缺什么 defaults
- 我查代码 / defaults 后回答，缺数据就补环境再出，不编造
- 4.6 出的题我自己对照事实包、必要时冒烟 / 预演 GUI；过不了的不进表

新题进表前至少要有：**题面 + 依据的实体在底稿里 + GUI 路径判断**。能跑的就跑 GUI，结果写进表。跑不通先记原因（缺页 / 缺数据 / verifier 写不了），不当成功条。

不编我们没有的 App（QQ、抖音、美团外卖、网易云）。空着就声明不收录，或等环境有了再补。
