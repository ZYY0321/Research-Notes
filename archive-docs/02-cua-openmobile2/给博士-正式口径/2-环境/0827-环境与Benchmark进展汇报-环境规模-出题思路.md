## 1. 四件事必须一起查

围绕环境和任务集，本周要先说清一件事：一条任务要能评，初始数据、题面、Tool、终态 Verifier 必须一起查，而且指向同一份可重置状态。双跑是用来验收这条绑定在真实轨迹上是否站得住。

| 查什么 | 必须成立 |

| 查什么 | 必须成立 |
|---|---|
| 初始数据 | 题面所说的实体和状态存在；开始时还不是目标态 |
| 题面 | 对象、约束、完成态写清楚，能唯一执行 |
| Tool | 读到的是同一份 Store、同一套字段含义；写完 GUI 能回读 |
| Verifier | expected 能从这份数据算出来；只认用户目标终态，不认 Agent 自报完成 |

分开查不够。数据对、题也对，但 Tool 扫的是另一张表，或 Verifier 写的是第三套数字，失败就分不清是 Agent 做错、环境没给、Tool 漏了，还是判分写错。成功率也就没有干净的分母。

这周在真实轨迹里看到的典型断裂：支付宝「订单」题，GUI 读到 4 笔 / 126 元，Tool 返回 5 笔 / 2552 元，Verifier 期望 12 笔 / 534.06 元，三个数对不上。滴滴题面写「行程中」，打开却是空闲。eBay 笔记标题和价格都对，却因 GUI 搜索状态为空整题失败。这类题先改齐再进正式集。

交付门槛：369 条四项都有、浏览器能启动、固定系统时间 55 个目标 × 2 个时间点共 110 次启动全部通过。这只证明可以评，不证明 Agent 都做对。

### 双跑结论，以及它对应后面什么工作

同一初始状态下，GUI-only 与 Hybrid 各跑 369 次，合计 738 次，基础设施错误 0。成功与否以规则 Verifier 读终态为准。

运行结论：GUI-only **211 / 369（57.2%）**，Hybrid **252 / 369（68.3%）**。Agent 宣布完成但终态未过 190 次，说明 Verifier 在拦自报完成。这两种成功率是当前可运行集的状态，不是正式 Benchmark 分数。

轨迹结论有两条。第一，多数任务四件事能跑通；失败里有一批是数据、Tool、Verifier 没对齐，或题面前提环境里没有，不能记成 Agent 能力。第二，抽 30 对轨迹做人工对照（见第 5 节）：与 Verifier 同向 52 / 60（86.7%），没有「没做完却判过」；不一致主要是判分过严或结构写错。

对应后续：先修对齐和 Verifier，再从修过的单元里出候选题，而不是先定一套筛选规则再往上套。正式集从这 369 条里筛，不另起一套题。

## 4. 任务：从轨迹看到什么，候选怎么出

原则：正式集里的题，GUI 路径必须存在。Hybrid 是同一世界上的另一条解法，不是唯一解法。难度放在信息结构上，不放在当前模型点不准、滑不动上。

这周没有先制定筛选规则，而是从轨迹里看哪些题已经是干净单元、哪些要改完再进。目前看到的几类，可以直接当候选或待修清单。

下面只谈已经跑通的单元：环境能走完、数据对齐、Verifier 和终态一致。失败的那一路如果有，是 Agent 没把该看的信息看全，或换页后把集合丢了——不是崩溃、不是前提缺失、不是三方数字对不上。那些是工程债，放在第 1、5 节，不当题目难度。

**可以保留的难度（屏幕上有、只是不在第一屏；至少一路已经成功）：**

- **跨 App 收口**：支付宝找出最大一笔支出，写进笔记。两路都过。
- **字段本身容易混**：未付款订单实付是 0，题要的是商品总价 6629.15。两路都过，都没有拿 0 交差。
- **列表里找最值**：最近 30 天最大三笔支出；附近咖啡馆按评分排第几；历史会议里预定最长的一场。Hybrid 都过。GUI 失败是因为只看到当前这一屏，答案在后面或要靠全表才能算。
- **做完换页再写回**：微信读书最长阅读日，加上 Spotify 今日已点赞的歌，发朋友圈。Hybrid 过；GUI 换到微信后只写出一首不在今日播放里的歌。

长链但每一步界面上都有的题（猫眼购票到改支付方式）两路都过，说明难度可以来自步骤多，不必来自环境坏掉。

**先改再进（不当难度讲，这里不展开）：** 题面前提环境里没有；数据 / Tool / Verifier 对不齐；成功条件写成了过程；Verifier 点名的实体当前数据里找不到。

### 和 OSWorld 2.0：题目上借鉴什么、不抄什么

他们要从 1.0「模型分高、任务其实没做完」走出来：任务更长更乱，约六成跨应用，答案可以藏在历史记录里的 ID，再加人造噪声邮件。评测不强制 GUI 或命令行，只要终态对。

借鉴：信息分散、跨 App、终态可验；「藏着」是第一屏看不到，不是屏幕上没有。  
不抄：1.6 小时、300–500 步、定时弹窗；现在就上多种子（可留后续扩展）。  
不做成：只有 Tool 算得出、界面上没有的题——和「GUI 路径必须存在」冲突。

列表排序 / 过滤这类题（GUI 能翻到但慢）要不要单独一层，会上问。

### 完整例子（可收起）

只收「至少一路 Verifier 通过、另一路若失败也不是环境坏掉」的题。

**两边都过：支付宝最大支出写笔记**

- 题面：查交易记录里支出最大的一笔，记到笔记并提醒控制开支。正确答案：转账给正中（刘沐辰）2500 元。
- GUI：12 步。账单里翻页，写出 2500 / 刘沐辰，两项通过。
- Hybrid：5 步。账单搜索拉回 44 条支出，自行找出最大值，写入同一结果。两项通过。
- 含义：难在「从一堆账单里取最值，再换 App 写回去」。两路都做完，数据一致。这是候选，不是环境债。

**两边都过：未付款订单不能拿实付当总价**

- 题面：ThinkBook 与 vivo X300 两笔订单的商品总价之差。题面写明 ThinkBook 未付款，已付为 0，不能当总价。正确答案：6629.15 − 4099 = 2530.15。
- GUI：13 步。进订单详情读到商品总价，不写 0。通过。
- Hybrid：7 步。订单摘要里同时有实付 0 和总价 6629.15，用后者。通过。
- 含义：实付和应付是两个字段，屏幕上和接口里都有。两路都没踩 0。这是业务上合理的混淆。

**两边都过：猫眼长链购票**

- 题面：功夫女足详情展开简介 → 明天、文悦国际、IMAX 2D → 推荐 2 人连座 → 加购双人餐 → 收银台改云闪付。
- GUI 17 步、Hybrid 16 步，三项都过。Hybrid 也没调候选 Tool，整段走界面。
- 含义：步骤多，但每一步界面上都有。难度来自链路，不是来自崩溃或缺失入口。

**Hybrid 过、GUI 败在没看全：附近咖啡馆排名**

- 题面：2 公里内最近的有评分咖啡馆，在同类评分里排第几。期望 21。
- GUI：27 步。视口里看到「潜渊咖啡馆」5 星，答 2。失败。
- Hybrid：3 步。一次取回 41 条，最近有评分的是麦咖啡（3 分），在有评分的里面排第 21。通过。
- 含义：排名必须对着完整列表。GUI 失败不是点错、也不是环境崩，是当前屏不够用。答案在地图数据里，只是不在第一屏。

**Hybrid 过、GUI 败在没看全：最近 30 天最大三笔**

- 题面：支付宝最近 30 天金额最大的 3 笔支出，发给黄勇，末尾加「我最近得省着点了」。期望含 520 / 浩杰、200 / 刘沐辰、美团 168。
- GUI：15 步。发出 200、美团 168、滴滴 42，漏掉 520。失败。
- Hybrid：6 步。44 条支出里取出正确三笔并发送。四项通过。
- 含义：三笔都在账单里。GUI 没翻到或看漏了最大的一笔。不是数据对不齐。

**Hybrid 过、GUI 败在没翻完：历史会议最长一场**

- 题面：腾讯会议历史里预定时长最长的一场，把名称和主持人发给陈静。期望「长时间研讨会」、主持人「组长」、180 分钟。
- GUI：点开前三场，把 90 分钟的「技术方案评审 / 李四」发出去。后面还有 180 分钟那场。失败。
- Hybrid：列出历史 10 条，按时长取最大，再取主持人。9 步通过。
- 含义：正确答案在列表更下面。失败是信息收集不完整，不是会议数据缺失。

**Hybrid 过、GUI 败在换页丢集合：读书时长加今日点赞歌发朋友圈**

- 题面：微信读书过去 7 天阅读最久的一天；Spotify 今天听过且已点赞的歌；朋友圈里两个栏目都要有。
- GUI：21 步。读书日对了（周二 226 分钟）。朋友圈「今天在听的歌」写成「悬溺 - 葛东琪」，这首不在今日 6 首播放里。失败。
- Hybrid：8 步。统计接口给出 226 分钟；最近播放带点赞标记，今日 6 首里 5 首点赞，完整列出。三项通过。
- 含义：难在换到微信之后还要带着上一屏的集合。GUI 不是环境没数据，是工作记忆丢了。

## 5. 验证：怎么判，人工对过没有，和 OSWorld 差在哪

当前做法：任务结束后读 App 状态，和 expected 做字段比较，主体是正则和数值匹配。不看 Agent 是否宣布完成。218 条近错扰动 470 次，错误通过 0；正例夹具 187 / 218，还有 31 条正例未绿。

### 5.1 人工审查：一致在哪，不一致在哪

抽 30 条任务、两种模式共 60 次判定，对照轨迹终态和 Verifier（本次先按人工审查计）。

| | 次数 |
|---|---:|
| 同向（人认为过、Verifier 也过；或人都认为没过） | **52 / 60（86.7%）** |
| 人认为做对了、Verifier 判失败（漏判） | 7 |
| 人认为没做完、Verifier 判通过（误放） | **0** |
| 看不准 | 1 |

闭环是否自洽：30 条里 19 条正确，9 条断裂，2 条看不准。断裂点主要在 Verifier 写法、初始数据、环境前提，不是「Agent 做完了却被放过去」。

一致的部分：终态对、字段对时两边都过；明显没做完（笔记空、短信没发出、选错实体）时两边都不过。误放为 0，说明当前规则在「不该过的不要过」上是紧的。

不一致几乎都是过严或结构写错：

- **标点当失败**：番茄 ToDo 周总结，内容语义对，只多一个句号，整项失败。
- **比较结构写错**：京东支付已到成功页，expected 是单个对象，actual 是订单数组，结构对不上就失败。
- **隐藏字段**：瑞幸下单规格和数量都对，因订单里没写出 `couponId` 失败。
- **过程捕获不稳**：Keep 两路做了同样的滑到第二页，一边记到 `[1]`，一边记成空数组。
- **expected 和可读数据不一致**：排障包两路都数出 14 个 ERROR，期望却是 23。

这些修完再冻正式分母。抽查规模还不够当对外金标，方向已经清楚：先消掉漏判和结构错误，再扩样本。

### 5.2 和 OSWorld 2.0：验证上借鉴什么、不抄什么

他们只看结束时的世界（中间打开过文件但没填，不算）；一道题很多检查点，按终态完成了几项给分，平均约 27 个；主体仍是函数 / 正则，视觉或格式多样时再用模型辅评。

借鉴：成功只看结束时的状态，不看走了界面还是 Tool；多项终态完成几项算几项。这两件事不对立——都在结束时看，只是不要 0 / 1 吃掉已经完成的项。  
不抄：为了像他们而给每题铺 27 个检查点。我们已有字段级检查，缺的是不要把过程字段和内容字段捆死。  
开放文本（评论、地址、措辞）再考虑少量模型辅助判断，主体仍用状态检查。

落到我们已有的题：eBay 找最便宜电风扇，笔记对了却因搜索状态为空整题失败——按他们，搜索是过程，不应进 success。腾讯会议建会、笔记、微信、短信四项里前三项已完成，短信未发出——按他们应是部分分，不应整题 0。

### 完整例子（可收起）

**过程当成成功条件：eBay 最便宜电风扇**

- 题面：搜电风扇，找最便宜的，标题和价格记到笔记。
- GUI：按「最低价 + 运费」排序，写入「Dyson 电风扇… 90.34」。搜索状态、笔记两项都过。
- Hybrid：商品搜索按总价升序，同一条写入笔记。笔记两项过；搜索状态 actual 为空，整题失败。
- 含义：用户目标是笔记里的商品和价格。搜索状态是路径，Tool 不会留下这条 GUI 记录。success 应只看笔记终态。

**二进制吃掉部分完成：腾讯会议四项**

- 题面：建会、记笔记、微信发陈静、短信发张三。
- 两路都在短信收件人上耗尽步数，前三项终态已对，整题记失败。
- 含义：字段检查已经有了，计分应按终态项给部分分。短信难处理，也不宜写成「必须 Tool」。

**标点漏判：番茄 ToDo 周总结**

- GUI 写入的心得语义正确，只比 expected 多一个句号，该项失败。
- Hybrid 未写入心得，失败与轨迹一致。
- 含义：开放文本用精确字符串会制造假失败。改子串或语义核对，不要整题捆死。

**结构写错：京东支付成功仍失败**

- Hybrid 已到支付成功页，流程走完。
- Verifier 用单个对象去比订单数组，类型对不上即失败。
- 含义：这是比较逻辑问题，不是 Agent 没付。expected 应能从实际结构里取出目标订单。

**过程捕获不稳：Keep 第二页**

- 两路都滑到 `p=1`。一项「查看第二页」一边记 `[1]` 通过，一边记空数组失败。
- 含义：访问记录若要当终态，写入必须稳定；不稳定就不要拿来判整题。

**数据与期望不一致：排障包 ERROR 数**

- 题面：统计 Download/排障包 里当前日志的 ERROR 次数，发给老板。
- 两路都读到 app.log 与 network.log，都发出 14；期望 23。
- 含义：要么还有文件没进目录，要么期望值写错。两边同一错法，先查数据，不记 Agent。
