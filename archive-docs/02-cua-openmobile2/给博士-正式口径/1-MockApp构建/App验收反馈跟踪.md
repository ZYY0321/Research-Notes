### 二、系统层接入检查（必做）

系统层已经具备支付、分享、相册、剪切板能力，但**只能调用 App 在** `manifest` **里主动声明、并走标准接口的功能**。如果你的 App 自己写了一套私有分享/复制逻辑，系统层扫描不到、无法介入，这个功能对评测就是"不存在"的——比如 agent 执行"复制快递单号"后，验证脚本读系统剪切板，永远是空的。所以：App 里只要有分享/复制/选图/支付的入口，就必须走标准接口，不能自己实现，也不能只显示"功能未开放"。


| 能力               | 标准调用方式                                                                    |
| ---------------- | ------------------------------------------------------------------------- |
| 跨 App 支付（微信/支付宝） | `window.__OS__.startActivityForResult('com.mobilegym.PAY', {...})`        |
| 系统分享             | `window.__OS__.startActivityForResult('com.mobilegym.SHARE', {...})`      |
| 系统相册/图片选择        | `window.__OS__.startActivityForResult('com.mobilegym.PICK_IMAGE', {...})` |
| 系统剪切板（复制）        | `window.__OS__.copyToClipboard(text)`                                     |


**检查提示词（把【App名】换成目录名，直接发给你的 AI）**：

```text
请检查 apps/【App名】中所有涉及以下四类能力的入口：分享、复制到剪切板、选择/保存图片（相册）、支付。
要求：
1. 全局搜索相关关键词（如 分享/share、复制/copy/剪切板、相册/图片/保存/download、支付/pay/收银），列出所有入口位置；
2. 逐个检查这些入口是否调用了 window.__OS__ 标准接口（com.mobilegym.SHARE / copyToClipboard / com.mobilegym.PICK_IMAGE / com.mobilegym.PAY），并在 manifest 中正确声明；
3. 凡是显示"功能未开放"、点了没反应、或用了自己写的私有逻辑的，一律改成对应的标准接口调用；
4. 做最小改动，不要重构、不要改其它 App。改完说明每个入口改前改后的调用方式。
```
