## 1. 环境

浏览器内可重置的手机模拟器。各应用维护一份业务状态：界面渲染、应用内函数、终态判定读写同一份对象。执行模型只观测截图与本轮允许的函数表，不能读取整机状态。每步至多执行一次界面动作或一次当前前台应用的函数。正式任务必须保留仅用界面即可完成的路径；函数是界面可达操作的子集。支付确认、密码与联系人选择不做成函数。预填类调用不产生业务写入。

时钟固定为 2026-07-12 09:00（周日）。相对日期、配送与倒计时必须走模拟时间服务，不能写死日历日。支付、分享、相册、剪贴板、通知走操作系统通道，不是某个应用的函数；相关任务须确认真正进入系统页。并行实例不共享状态；每个并行工人须自建浏览器页上的函数客户端。同一任务编号复跑时初态应一致；本版不做多种子对照。Python 层不得为了「执行函数」去改整机状态；函数实现以浏览器内 TypeScript 与已有业务动作为准。

## 4.1 安装与启动（不做会直接起不来）

要求 Node.js 22+、Python 3.11+、Playwright Chromium。在 `trial_apps/mobilegym` 下安装 npm 与 `bench_env/requirements.txt`，并 `playwright install chromium`。

必须另下约 1.4GB 资源包（主题、壁纸、部分合成数据）。根目录 `README.md` 第 3 节给出发布地址。解压后 `mobilegym-data/themes/manifest.json` 必须存在；缺包时模拟器往往仍能启动，桌面组件会加载失败，轨迹会脏。

人工查看用 `npm run dev`。跑模型必须用生产构建：`npm run build` 后 `npm run preview -- --host 0.0.0.0 --port 4173`，环境地址 `http://localhost:4173`。改环境后须重跑受影响任务，旧轨迹不能当新版本结论。

代理环境变量在本机请求模型或本地预览时经常把流量拐走；现有脚本会清掉 `HTTP_PROXY` / `HTTPS_PROXY`。并行评测默认若干工人、无头浏览器。

更细的入口：`trial_apps/mobilegym/README_zh.md`、`bench_env/README.md`、`bench_env/hybrid_benchmark/README.md`、`app_tools/TOOLS_DESIGN.md`。

## 4.2 两种会话 runtime（跟早期 README 会对不上）

根目录 README 里，`hybrid_benchmark` 的默认 runtime 是 `hybrid_xml`：每步重写 XML 系统词。另可选 `gpt_responses`、`kimi_k2_6`（独立适配，仍复用同一运行时与判定）。

**215 写死的是 `qwen35_session`：** 系统词与题面只发一次，服务端函数列表只有 `mobile_use`，只留最近 3 张图，应用函数写在进应用后的用户消息里。用默认 XML 跑 215，分数不可比。

对齐条件：同一 Git 提交、同一套件与任务编号、同一模型参数、同一模拟时钟；只改交互模式（仅界面 / 允许函数）与输出目录。

## 5. 评测协议（对齐 215 时不要改）

`run.sh` 固定：会话 runtime 为 `qwen35_session`；上下文只保留最近 3 步观测；思考过程开启；请求里的函数列表仅含界面总入口 `mobile_use`。进入前台应用后，该应用函数写在对话消息中，不进入该列表。

更改上下文步数、将应用函数挂入服务端函数列表、关闭思考，均视为新实验，不可与现有 215 对照直接合并。仅界面训练的 9B 在现行协议下往往不写出应用函数名，协议本身会放大这一差异。

奖励读终态判定的成功与否，不读模型自报完成。明细在结果目录的 `results.jsonl`：成功标志、子检查通过比例、是否改动声明外路径、判定自身是否报错、步数、应用函数调用列表、终态文件路径。监督数据只收成功且终态可追溯的样本。建议同时保留逐步轨迹与逐项断言，不要只留一个总分。
