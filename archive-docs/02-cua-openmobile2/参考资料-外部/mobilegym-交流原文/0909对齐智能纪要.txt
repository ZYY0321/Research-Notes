本次会议对齐 Open Mobile V2 项目的主实验进展、RL 训练、测试集建设、后续规划等事项，明确各环节落地要求，内容如下：
- 主实验与模型训练进展
  - SFT 模型更新与表现
- 已更新模型版本：已完成 3.5 27B MCP 模型、3.5 27B 金融 only 模型在目标 Word、目标 Gym 上的全量数据更新。
- 模型波动处理：27B 模型在 MobileWorld 上表现略低于 3.5 9B 模型，判定为偶发波动，后续补充多轮测试验证。
[图片]
    - 预期符合情况：27B 模型在 MobileGym+ 上表现符合预期，纯 GUI only 表现较高，混合模式无明显下滑，MCP 模式提升显著。
    - 历史bug处理：AndroidWorld 测试集的粘贴板 bug 已修复，涉及粘贴操作的任务需删除后重跑，音量类任务可先做人工校验。
    - MCP 测试进展：MobileWorld 场景的 MCP 测试仍在推进，当前存在工具额度限制、部分接口未调通的问题，暂未产出明确结论。
    - 阶段任务要求：SFT 阶段有空闲资源时优先完成剩余模型训练、补测工作，无需等待其他环节进度。
  - RL 训练推进安排
    - 当前迁移进展：已完成 RL 训练代码向天津集群的迁移，计划当晚启动 27B 模型训练，32 卡环境下单日可产出一版结果。
    - 历史问题修复：此前 9B 模型训练两次中断，经排查为学习率过高问题，已调低学习率，计划在马来集群重启 9B 训练。
    - 训练方案确定：RL 采用混合数据方案，整合混合场景数据与 MobileGym 提供的 160 条 Gym only 数据，无需拆分单独训练。
    - 结果预期要求：无需强制要求 RL 训练带来大幅指标提升，只要完成全流程实验、产出可验证的结果即可。
[图片]
- 测试集建设与结果分析
  - 基准测试结果统计
    - 基线模型得分：当前 9B 模型在安卓场景测试得分约 70 分，Gemini 在 215 题同设置测试集上整体通过率约 60%。
    - 测试集难度验证：当前 215 题测试集难度合理，主流大模型刷分难度较高，训练数据与测试集相似度正常，无过拟合风险。
  - 测试集问题修正规则
- 问题数量统计：215 题中明确存在错误的题目共 4-5 道，存在歧义、判定逻辑不合理的题目共十余道，无系统性问题。
- 修正执行方案：无需全部重跑现有测试结果，仅删除存在问题的题目即可，测试集版本后续冻结不再调整。
[图片]
  - 双模态效果对比分析
    - 整体表现结论：混合模态整体平均步数较纯 GUI 模式减少约 4 步，成功率更高，符合 Hybrid 范式的核心故事主线。
    - 场景差异观测：搜索类任务易出现工具重复调用导致步数激增，部分场景下纯 GUI 模式更稳定，需补充对应案例分析。
    - 补充分析要求：需补充控制变量对比验证 CUI 对交互步数的压缩率，同时整理纯 GUI 更优的场景案例，丰富 Hybrid 范式的论证维度。
- 后续实验与协作要求
  - 待开展实验规划
    - 非紧急消融实验：固定 5000 条训练数据，调整 APP 覆盖度测试性能变化，属于可选实验，有空闲资源时再推进。
    - 补充对比测试：待资源到位后测试 Opus 5、GPT-6 等主流大模型在测试集上的表现，如实呈现不同模型的能力差异。
    - 真机验证实验：启动模拟环境到真机的迁移效果验证实验，采购对应测试设备，产出结果支撑论文的泛化性论证。
  - 资源与协作要求
    - 训练资源协调：所有训练、测试所需的卡资源直接对接马征申请，优先保障投稿相关核心任务的资源供给。
    - 跨角色协作规则：测试相关数据同步给张荧滢、陈瀚开展后续评测，模态对比相关分析内容由张荧滢负责整理输出。
