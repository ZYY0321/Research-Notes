GUI-ClarityBench: 任务集构建方法与标准
1. 概述
GUI-ClarityBench是一个基于参数完整性的GUI智能体评估基准，专注于评估智能体处理不同清晰度用户指令的能力。本文档详细说明了任务集的构建方法、参数分类标准、清晰度计算方法以及任务收集流程。
2. 参数分类框架
2.1 参数重要性分级
参数根据对任务完成的影响程度分为三级：
重要性级别	数值编码	定义	识别标准	权重
核心参数	2	缺失会导致任务无法完成或结果严重偏离用户意图的参数	任务无法启动或完成；无可用默认值；用户必须提供才能继续	2.0
重要参数	1	影响任务结果质量但不会导致任务失败的参数	有合理默认值可用；影响用户体验但不阻碍完成；通常用户会主动提供	1.0
可选参数	0	对任务完成影响极小的参数	系统默认值通常可接受；用户经常不指定；缺失不影响核心功能	0.0
2.2 参数表达状态
参数的表达状态反映用户指令中参数信息的提供情况：
表达状态	数值编码	定义	评估标准	分数乘数
明确	2	用户提供了清晰无歧义的信息	信息完整且具体；无需推断或澄清；可直接映射到系统参数	1.0
模糊	1	用户提供了信息但存在歧义或不完整	信息需要推断、主观、范围、歧义等模糊表达；需要澄清但有初步信息	0.5
缺失	0	用户未提及该参数	指令中完全没有相关信息；需要系统提供默认值或询问	0.0

clarity_expression字段只允许三类取值："明确"、"模糊"、"缺失"

示例：
- "value": "42码", "clarity_expression": "明确"
- "value": "快点送来", "clarity_expression": "模糊"
- "value": null, "clarity_expression": "缺失"

3. 清晰度计算方法
3.1 清晰度分数计算公式
清晰度分数 = (核心参数得分 + 重要参数得分) / (核心参数总权重 + 重要参数总权重)
其中：
核心参数得分 = 核心参数权重 × (明确参数数 × 1.0 + 模糊参数数 × 0.5)
重要参数得分 = 重要参数权重 × (明确参数数 × 1.0 + 模糊参数数 × 0.5)
核心参数总权重 = 核心参数数 × 核心参数权重
重要参数总权重 = 重要参数数 × 重要参数权重
注意：可选参数不计入清晰度分数计算。
3.2 清晰度级别划分
清晰度级别	分数范围	描述
清晰 (Clear)	0.7 - 1.0	大多数核心和重要参数表达明确
半模糊 (Semi-ambiguous)	0.3 - 0.7	部分核心和重要参数表达明确或模糊
模糊 (Ambiguous)	0.0 - 0.3	大多数核心和重要参数缺失或模糊

【补充说明】
多目标+模糊约束+可量化条件
在任务集设计中，模糊和半模糊任务的核心应体现在“参数表达的模糊性、歧义性、主观性、范围性”，而不仅仅是参数的缺失。

- 推荐设计原则：每个任务应包含1-2个可量化参数（如数量、价格、时间、地点等）和1-2个模糊参数（如“比较火的”“有新意”“尽量多”“空闲率高”等），使任务既有可评估性，又能考察智能体的澄清与推理能力。
- 任务领域分布应均匀，涵盖购物、外卖、日历、社交、出行、信息检索等。

【各领域高质量模糊/半模糊任务举例】
- 购物：买5到6个比较火的黄油和面包单品，价格总共控制在500元以内（数量、价格明确，流行度模糊）
- 外卖：点三四样最近评价比较好的小吃，控制在50元以内（数量、价格明确，评价模糊）
- 日历：安排一场下周三下午的团队讨论，参与人数5-8人，主题不限，尽量选空闲率高的时间段（时间、人数明确，主题、时间段模糊）
- 社交：发一条朋友圈，内容和配图都要有点新意，点赞数尽量多，最好能@两位好友（@好友明确，内容/配图/点赞数模糊）
- 出行：查找3-4个最近评分较高的咖啡馆，步行距离不超过2公里，优先推荐环境安静的（数量、距离明确，评分、环境模糊）
- 信息检索：查找5篇最近比较热门的AI技术相关文章，内容要有深度，发布时间在近一个月内（主题、数量、时间明确，热门程度、深度模糊）

通过上述设计，既保证了任务的可评估性，也能真实反映智能体在多目标、模糊约束下的推理与澄清能力。

为此，建议在每个参数下增加clarity_expression字段，标注其表达清晰度：
- "clarity_expression": "明确" | "模糊" | "歧义" | "主观" | "范围" | "缺失"

示例：
- "value": "快点送来", "clarity_expression": "主观"
- "value": "鞋", "clarity_expression": "模糊"
- "value": "亮一点", "clarity_expression": "范围"
- "value": null, "clarity_expression": "缺失"

清晰度分数的计算应优先考虑参数的表达澄清程度，而不是仅仅统计参数数量。这样可以更真实地反映智能体在处理真实用户模糊指令时的澄清与推理能力。
4. 任务集构建流程
4.1 任务收集方法
4.1.1 方法一：从清晰任务退化
构建完整清晰任务
确定任务领域和应用场景（如订餐、日历管理、购物等）
定义完整参数空间，包括所有核心、重要和可选参数
创建包含所有必要参数且表达明确的用户指令
生成半模糊任务
从清晰任务中有选择地移除或模糊化40-60%的参数
优先移除重要参数，保留大部分核心参数
确保生成的指令清晰度分数在0.3-0.7范围内
生成模糊任务
进一步移除或模糊化参数，直到保留最少必要信息
确保至少保留一个核心参数（通常是任务类型）
确保生成的指令清晰度分数低于0.3
4.1.2 方法二：从真实用户指令增强
收集真实模糊指令
从用户日志、语音助手交互记录、公开数据集（如VoiceBench）收集真实模糊指令
筛选符合GUI交互场景的指令
分析参数空间
确定指令对应的任务类型
定义完整参数空间（核心、重要、可选参数）
标注现有指令中的参数表达状态
生成半模糊任务
向模糊指令有选择地添加30-60%的参数信息
优先添加核心参数，使指令可执行但仍需澄清
确保生成的指令清晰度分数在0.3-0.7范围内
生成清晰任务
进一步补充所有核心参数和大部分重要参数
确保指令包含足够信息可直接执行
确保生成的指令清晰度分数高于0.7

5.3 应用指定原则

为了确保任务的真实性和可执行性，所有搜索和信息查询类任务都需要明确指定应用，例如：
- 百度App：用于信息搜索类任务
- 微信：用于社交媒体类任务
- 京东App：用于电商购物类任务

这样做的目的是让智能体明确知道在哪个应用环境中执行任务，更符合真实用户使用场景，也便于评估智能体在不同应用间的适应性。

5.4 可选参数处理原则

在清晰度计算中，可选参数（importance_level=0）不计入分数计算，这是因为：
1. 可选参数通常有合理的默认值，缺失不影响任务核心功能完成
2. 不同任务的可选参数数量可能差异很大，将其计入会不当影响清晰度评分
3. 智能体应当优先关注核心和重要参数，而非可选参数

通过这种方式，我们确保清晰度评分真实反映任务的实际执行难度，而不受可选参数数量的影响。

6. 优化的任务构建方法

6.1 避免清晰任务步骤和难度增大问题

在实际构建任务集的过程中，我们面临一个挑战：如何在保持清晰任务参数完整性的同时，避免执行步骤过度复杂化。清晰任务应当包含完整的参数设定，这是评估智能体处理明确指令能力的重要方面，但同时也需要确保任务的执行难度与清晰度合理对应。

6.2 改进的任务构建原则

为解决这一问题，我们采用以下改进原则：

1. **保持参数完整性与步骤复杂度的平衡**：
   - 模糊任务：3-4步，仅包含极少数明确参数
   - 半模糊任务：4-5步，包含核心参数和部分重要参数
   - 清晰任务：6-7步，包含所有核心参数和大多数重要参数

2. **参数增减策略调整**：
   - 从模糊到清晰：逐步增加参数完整性，但控制步骤增长
   - 从清晰到模糊：有选择地移除参数，保持任务基本可执行性

3. **清晰任务设计原则**：
   - 清晰度分数应达到0.9左右，表示参数高度完整
   - 包含所有核心参数和大多数重要参数
   - 可以包含少量可选参数（不计入清晰度分数）
   - 参考SPA任务集中的完整指令设计

6.3 示例对比

**优化后的方法**：
- 模糊：买一双运动鞋（3步）
- 半模糊：在京东上买一双42码的运动鞋（4步）
- 清晰：在京东上购买一双42码的黑色耐克运动鞋，价格在800-1200元之间，送货上门，支付宝付款（6步）

这种方法确保了清晰任务包含完整的参数设定，同时步骤数量增加保持在合理范围内。

6.4 步骤数量与清晰度的平衡

在任务设计中，我们需要平衡以下因素：
1. 参数完整性（影响清晰度分数）
2. 执行步骤数量（影响任务难度）
3. 用户指令的自然性（符合真实场景）

理想的清晰任务应当是参数高度完整（清晰度≥0.9），步骤数量适当增加（比模糊任务多3-4步），且指令表述自然。这样的任务集能够准确评估智能体在不同清晰度指令下的实际表现，同时保持与SPA等现有任务集的一致性。
