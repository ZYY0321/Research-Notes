B. 澄清交互效果的指标集合（来自 RL 与信息论视角）
启发来源

建议（具体指标，容易落地）
把“交互评估”拆成三组可量化指标：
1. 交互成本类（Cost）
  - ClarifyCount：单任务澄清问题总数（越少越好）
  - ClarifyLatency：首次澄清所用步数或时间（越短越好）
2. 信息收益类（Gain）
  - ClarityDelta = C_after - C_before：交互前后清晰度提升（标准化到 [0,1]）

3. 交互质量类（Quality）
  - QuestionRelevance：澄清问题与缺失参数的对齐度（自动化方法：LLM judge 或人工/半自动评估）
  - InterruptionScore：衡量是否过度打断（基于用户/模拟用户满意度或固定阈值）
4. 综合效率指标
  - ClarifyEfficiency = ClarityDelta / ClarifyCount（单位澄清收益），便于比较不同策略的性价比（借鉴 RL 的 reward 设计）。

# 一、总体设计思路（一句话）

把 **任务清晰度** 从“人工分级”拓展为 **可量化的动态不确定性度量**（初始 (C_0) 和交互演化 (C_t)），并以此驱动**自适应澄清策略**与**诊断性评估指标**（澄清成本/收益、设想鸿沟率等），将 PCSM 作为任务语义骨架把这些指标系统化地计量与解释。

# 二、关键要素与可落地实现

## 1) 自动化清晰度（(C_0)） — 从“人工阈值”到“模型不确定性”

**要做什么**：把每个任务的初始清晰度 (C_0) 量化，且能复现与自动计算。

**怎么做（实现细节）**：

* **参数化输出**：对任务的每个核心参数 (p_i)（PCSM 中定义）让模型输出一个候选集合或概率分布（例如：top-K 候选值或 N 次采样的频率分布）。
* **不确定性度量（两种互补实现）**：

  1. **Prediction-set 大小（Conformal-style）**：对每个 (p_i) 生成含真值概率至少 (1-\alpha) 的候选集合 (S_{p_i})（借鉴 CICC 思路）。使用条款：若 (|S_{p_i}|) 大 -> 不确定性高 -> 低清晰度。
  2. **采样熵/分布宽度**：对同一提示/问题多次采样（temperature 多值或 nucleus sampling），统计参数候选的熵或标准差，作为不确定性数值。
* **合成 (C_0)**：用 PCSM 权重 (W(p_i)) 计算加权清晰度：
  [
  C_0 = 1 - \frac{\sum_i W(p_i)\cdot \text{Uncertainty}(p_i)}{\sum_i W(p_i)}
  ]
  其中 `Uncertainty(p_i)` 归一化到 [0,1]（1 表示完全不确定）。

**怎么验证**：

* 用人工标注的清晰度（多标注者，计算 Cohen’s κ）作为金标准，计算自动化 (C_0) 与人类评分的相关性（Pearson + Spearman）。目标：相关系数 > 0.8 说明可行。若低于 0.7，需调参（采样次数、α 值、权重学习）。

---

## 2) 动态清晰度序列 (C_t) 与日记式测量（借鉴 CHI25）

**要做什么**：记录每次澄清后清晰度变化，衡量澄清效果与效率。

**怎么做（实现细节）**：

* 在智能体与（真实或模拟）用户每次交互/澄清后，重新计算参数候选集合与对应不确定性，得到 (C_{t+1})。
* 记录序列 (C_0 \rightarrow C_1 \rightarrow \dots \rightarrow C_T)。
* 定义 `ClarityDelta_t = C_{t} - C_{t-1}`。

**怎么验证/指标**：

* `CumulativeClarityGain = C_T - C_0`（最终净收益）
* `TimeToSufficientClarity`：达到某阈值（例如 0.8）所需交互轮数/时间。
* 对比基线（无澄清 / 规则澄清 / adaptive-CICC）在同一任务集上的 `CumulativeClarityGain` 与 `TimeToSufficientClarity`。

---

## 3) 澄清策略与评价指标（可直接实现的指标集合）

**要做什么**：用明确指标评估“问得对不对、问得值不值”。

**指标（实现细节 + 解释）**：

* **ClarifyCount**：单任务澄清次数（直接计数）。
* **ClarifyLatency**：首次澄清前的操作步数或时间。
* **ClarityDelta**：每次交互带来的清晰度提升（见上）。
* **InformationGain**：用候选集大小减少百分比来衡量：
  [
  InfoGain = 1 - \frac{|S_{after}|}{|S_{before}|}
  ]
* **ClarifyEfficiency**（核心复合指标）：
  [
  ClarifyEfficiency = \frac{ClarityDelta}{ClarifyCount}
  ]
  （单次澄清平均带来的清晰度提升）
* **QuestionRelevance**：澄清问题是否针对缺失核心参数（自动化方法：用 LLM/judge 判定提问与参数缺失的对齐度，或人工标注）。
* **InterruptionCost**（用户感知）：模拟用户打分或真实用户实验衡量“过多澄清导致的厌烦度”。

**怎么验证**：

* 在 A/B 中比较三类策略（never ask / rule-based / adaptive-CICC+RL），以 `Success_Rate`, `ClarifyEfficiency`, `UserSatisfaction` 为主判据。期望 adaptive 策略在 `ClarifyEfficiency` 与 `Success_Rate` 上均优于 baselines。

## 4) 把 EMNLP 的“三大差距”映射进 PCSM（清晰度 ↔ 差距）

**要做什么**：把三类认知差距作为任务标签，便于诊断性分析。

**映射（直接可用）**：

* **指令差距** ↔ 低清晰度任务（自动化 (C_0 < 0.3)）
* **意向性差距** ↔ 中清晰度（(0.3 \le C_0 < 0.7)）
* **能力差距** ↔ 高清晰度但失败（(C_0 \ge 0.7) 且智能体失败）

**怎么做（实现细节）**：在任务元数据中加入 `gap_label`（可通过人工打标签，或用自动策略：基于 (C_0) + 成功/失败判定自动聚类）。

**怎么验证/用途**：

* 在结果分析中分别报告各 gap 的 `Success_Rate`、`EnvisioningGapFailureRate`（见下），以证明 RealEval 在诊断不同错位时的效用。

---

## 5) 设想鸿沟（Envisioning Gap）：如何构造与测量

**要做什么**：刻意包含“用户表达清楚但系统能力不足”的用例，并用指标区分“表达问题 vs 能力问题”。

**怎么做（实现细节）**：

* **任务分配**：把任务按 `EnvisioningGap` 标注为高/中/低（人工+自动混合），其中高鸿沟任务要求跨 APP、需复杂信息整合或 rare skill（例如：跨三 app 抓取并合并信息）。
* **指标**：

  * `EnvisioningGapFailureRate` = 高清晰度任务中失败比例（高值说明是系统能力问题而非表达问题）。
  * `ExpressedButMisunderstoodRate` = 人工确认的“用户表达清晰但结果与期望不符”的比例（需人工抽样验证）。

**怎么验证**：比较不同智能体在 3 类鸿沟级别上的表现，若模型在高清晰任务失败集中，则应标为能力差距问题。

# 四、实现注意事项与工程细节（便于落地）

1. **如何得到参数候选集（对 LLM 可行的实现）**：

   * 对每个参数用多次采样（N = 20–50）prompt 询问“这个任务中 X 的可能值是什么？按概率排序”。统计频率生成 top-k 候选。可并行化采样以节约时间。
   * 若能得到模型概率（部分 closed LLMs），可直接用概率阈值做 conformal-style selection。

2. **如何做 conformal prediction 风格的 prediction-set**：

   * 选取 calibration 集（若有历史数据），用 empirical quantile 方法设定 threshold α，使得 prediction-set 有覆盖保证；若无 calibration，可使用 bootstrap/多次采样近似。

3. **自动化 QuestionRelevance 的落地**：

   * 采用 LLM 作为 judge：给 judge 输入（提问文本、缺失参数列表），让它打分（0/1/soft）；抽样人工校验确保 judge 的质量。

4. **模拟用户的实现**：

   * 参数偏好库（频率分布）+响应策略（直接/模糊/矛盾）驱动自动回答。确保模拟用户与人工用户行为分布接近（可用你之前的日志做分布拟合）。

5. **计算资源/成本考虑**：

   * LLM 采样多次 + judge 评分会有较大 token 成本，论文中应报告每步平均 token 与美元估算（增强审稿可行性）。

3. **PCSM + 清晰度分级 能更好地诊断失败原因：能把失败分为“指令差距 / 意向性差距 / 能力差距”，并针对性展示模型在各类 gap 下的不同弱点**；
4. **引入 Envisioning Gap 使我们能区分“表达问题 vs 能力问题”，这对于后续改进（例如增强视觉模块 vs 设计更好的提示）具有直接指导意义**。

这些都是审稿人看重的“诊断性 + 可复现性 + 可操作性”贡献点。
