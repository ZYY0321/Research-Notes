## 1. PCSM（Parameter–Constraint–Space Model）形式化定义

**目标**：把“任务意图”从具体动作序列抽象为语义层级，使得“多路径”视为解空间内不同满足条件的解，而非单一黄金路径。

**定义**：一个任务表示为三元组
[
\text{PCSM} ;=; \langle P, R, S \rangle
]

* 参数层 (P={p_1, p_2, \dots, p_n})
  每个 (p_i) 是一个语义槽（slot），例如应用名、商品类别、数量、时间、目的地等。
* 约束层 (R={r_1,\dots,r_m})
  每个约束 (r_j) 是对参数间或系统状态的谓词（Predicate），可分为**硬约束**（必须满足，否则任务失败）和**软约束**（偏好类，可以影响质量性评分）。例如，“若选择外卖则必须有配送地址”是硬约束；“价格不超过1000元”可以是软约束。
* 解空间 (S)
  (S = { s \mid s \in V(p_1)\times V(p_2)\times \dots \times V(p_n), ;\forall r\in R_h: r(s)=\text{True}})，其中 (R_h) 为硬约束集合，(V(p_i)) 为参数 (p_i) 的值域。

**注**：PCSM 的作用是用于（A）任务生成（参数化生成多版本任务）和（B）成功判定/质量判定（用参数满足度而非动作序列严格匹配）。

## 2. 参数不确定性度量（两类实现）

我们需要对每个参数 (p_i) 给出一个不确定度度量 (U(p_i)\in[0,1])，越大表示越不确定。本文提供两种互补方法：

### 2.1 采样熵（Sampling Entropy）

**方法**：

* 用 LLM 对“缺失参数 (p_i)”进行多次采样（不同随机种子/temperature），得到候选集合 (V_{p_i}={v_1,\dots,v_k}) 与经验频率分布 (\hat{P}_{p_i}(v)).
* 计算 **信息熵（自然对数）**：
  [
  H(p_i) = -\sum_{v\in V_{p_i}} \hat{P}*{p_i}(v)\ln \hat{P}*{p_i}(v).
  ]
* 归一化（按候选集合大小的最大熵 (\ln |V_{p_i}|)）：
  [
  U_{\text{entropy}}(p_i) = \frac{H(p_i)}{\ln |V_{p_i}|} \in [0,1].
  ]

**性质**：

* 若分布集中（单一候选概率近1），则 (H\to 0)，不确定度低。
* 若分布均匀，则 (H\to\ln|V|)，不确定度高。

**实现注意**：

* 采样次数 (N)：建议 (N=20\sim50)（trade-off：更高 N 提高估计稳定性，但增加 token/cost）。
* 候选集截断：可取 top-K 最常见的候选（K 取5~10）。

### 2.2 Conformal-style prediction-set （覆盖保证）

**目的**：在统计上给出覆盖保证，即“预测集合 (S_{p_i}^{(\alpha)}) 包含真实值的概率 >= 1-\alpha（在 i.i.d. /近似假设下）”。

**split-conformal 实现（简述流程）**：

1. 从历史标注对（或 calibration 数据）中构建 nonconformity score（具体可用概率/置信度大小或逆频率等）。
2. 对新输入，按 calibration 的分位点 (\tau) 选出所有候选 whose nonconformity ≤ (\tau)，形成 prediction set (S_{p_i}^{(\alpha)})。
3. 设定 (\alpha)（例如 0.05），可保证覆盖率 (\ge 1-\alpha)。

**不确定度定义**：
[
U_{\text{set}}(p_i)=\frac{|S_{p_i}^{(\alpha)}|-1}{K-1}\in[0,1],
]
其中 (K) 为候选集最大长度（用于归一化）。

**优点/缺点**：

* 优点：有概率覆盖保证（在 calibration 假设下）。
* 缺点：需要 calibration 数据；若模型分布偏移，覆盖性可能失真。

## 3. 整体清晰度 (C) 的定义与性质

**定义**：给定参数权重 (W(p_i)>0)（反映核心/重要/可选），定义整体清晰度
[
C ;=; 1 - \frac{\sum_{i=1}^n W(p_i)\cdot U(p_i)}{\sum_{i=1}^n W(p_i)}.
]
其中 (U(p_i)) 取采样熵或 set-size 归一化度量（一致性要求：数值越大→越不确定）。

**解释**：

* 如果所有 (U(p_i)=0)（完全确定），则 (C=1)。
* 如果所有 (U(p_i)=1)（完全不确定），则 (C=0)。

**性质讨论**：

1. **线性可分性**：(C) 是参数不确定度的加权平均的线性映射（1 - weighted-average），便于解释。
2. **单调性**：若对某参数的不确定度降低（(U(p_j)) 下降），则 (C) 单调不减：严格地，如果其它不变，则 ( \partial C / \partial U(p_j) = - W(p_j)/\sum W <0)。
3. **可区分性**：可以用阈值 (\tau) 将任务分为低/中/高清晰度，例如 ([0,0.3), [0.3,0.7), [0.7,1])。阈值可基于 calibration（见后文）调整。

**进一步讨论（为何选这形式而非对数/非线性）**：
该线性加权形式便于解释和归一，且与多数诊断指标（如 ClarifyEfficiency）线性耦合；若需要，可用非线性变换 (f(C)) 以放大中段差异，但需在实验中验证。

## 4. 清晰度的动态更新与交互性指标

交互过程中产生一系列清晰度值：
[
C_0 \xrightarrow{\text{ask}_1} C_1 \xrightarrow{\text{ask}_2} \cdots \xrightarrow{\text{ask}_T} C_T.
]
**定义关键量**：

* (ClarityDelta_t = C_t - C_{t-1}).
* (CumulativeClarityGain = C_T - C_0).
* (TimeToThreshold(\tau) = \min {t \mid C_t \ge \tau})（若未达到，置为 (+\infty) 或 (T_{\max})）。
* (ClarifyCount = \sum_{t=1}^T \mathbb{1}[\text{ask}_t])（询问次数）。
* **单步澄清效率**：
  [
  ClarifyEfficiency = \frac{C_T - C_0}{ClarifyCount}.
  ]
  越大表示“少问多得”。

**指标的统计性质**：

* 需要计算均值与置信区间（bootstrap 推荐），特别是 ClarifyEfficiency 的分布往往偏斜（长尾），应使用非参数方法计算置信区间。

## 5. 澄清策略：MDP 建模与 Adaptive (CICC + RL) 细节

### 5.1 MDP 定义（用于 RL 策略学习）

* 状态 (s_t)：由当前参数候选集合特征构成。一个实用的向量化表征：
  [
  s_t = \left[ |S_{p_1}|,; U(p_1),; |S_{p_2}|,; U(p_2),; \dots,; C_t \right]
  ]
  （可加入历史 action summary、已问参数掩码等）
* 动作集合 (\mathcal{A})：对每个 (p_i) 的询问动作（ask (p_i)），以及“执行/停止询问并执行计划”动作。动作空间大小为 (n+1).
* 转移：若执行 ask (p_j)，则用户/模拟器返回回答，系统更新 (U(p_i)) 与 (C_{t+1})（基于新的候选分布）；若执行 execute，则进入终止/执行轨迹。
* 奖励函数（设计关键）：
  [
  r_t = \Delta \text{SR}_t - \lambda \cdot \text{CostAsk}_t - \mu \cdot \text{TimePenalty}
  ]
  其中 (\Delta \text{SR}_t) 为执行后成功率的增益估计（可用未来模拟估计或基于 heuristic 估计），(\text{CostAsk}_t) 为问一次的代价（以时间或用户烦扰为度量），(\lambda, \mu) 是权衡超参。实际 RL 实现中可用稀疏的最终奖励（任务成功/失败）并加上步惩罚以促进少问策略。

### 5.2 推荐训练算法

* 若能模拟用户：使用 PPO 或 A2C （离线/在线）训练策略；小 action space -> 无需大型策略网络，使用小 MLP 足够。
* 若训练样本有限：考虑基于启发式的 greedy 信息增益策略或用 imitation learning（用 oracle 策略生成演示后做行为克隆）作为 warm-start。

### 5.3 信息增益启发式（baseline）

* 对每个可能的询问 ask (p)，估计候选集大小减少比例 (InfoGain(p) = 1 - |S_{\text{after}}|/|S_{\text{before}}|)。选择单位成本下信息增益最大的询问（maximize (InfoGain/Cost)）。这是 RL 的良好启发式 baseline。

## 6. 评估 / 诊断指标（精确定义 + 置信区间估计）

### 6.1 成功性指标

* **Success Rate (SR)**：(SR = \frac{1}{N}\sum_{i=1}^N \mathbb{1}[\text{task}_i\text{ 成功}]).
  置信区间：使用 Wilson interval 或 bootstrap。对于比较（两策略/模型），使用 McNemar（配对）或二比例 z-test（独立）。

### 6.2 效率指标

* **Path Efficiency (PE)**：若任务理论最小步数为 (m^*)，实际步数为 (m)，则 (PE = m^*/m\in(0,1])。
* **Time/Cost**：任务平均耗时（秒）与 API/token 成本（美元）。

### 6.3 交互性指标

* **ClarifyCount**, **ClarityDelta**, **ClarifyEfficiency**, **InfoGain**（公式见上）。
* 交互质量可用 judge LLM 或人工标注得到 **QuestionRelevance**（0/1/soft）。

### 6.4 诊断指标（映射 URS 三类差距）

* 三类差距标签（指令差距 / 意向性差距 / 能力差距）用如下规则（可人工或半自动标注）：

  * **指令差距**：若 (C_0 < \tau_{\text{low}})（例如 0.3）且任务失败 -> 标为指令差距。
  * **意向性差距**：若 (\tau_{\text{low}} \le C_0 < \tau_{\text{high}})（例如 0.3–0.7）且失败 -> 标为意向性差距。
  * **能力差距**：若 (C_0 \ge \tau_{\text{high}})（≥0.7）且失败 -> 标为能力差距。
* **EnvisioningGapFailureRate**：在所有 (C_0\ge \tau_{\text{high}}) 的任务中失败比例。

### 6.5 置信区间与假设检验

* 对于连续指标（ClarifyEfficiency 等）用 bootstrap（推荐 percentile bootstrap）估计 95% CI。
* 对策略比较用配对 t-test（若分布近似正态）或 Wilcoxon signed-rank test（非参）。报告 p 值与 Cohen's d（效果大小）。
* 对 SR 差异在配对设计下优先使用 McNemar 检验（binary 成功/失败 paired data）。

## 7. Conformal prediction 实现细节与保证

### 7.1 split-conformal（步骤）

1. 将历史已标注数据划分为训练集 (D_{\text{train}})、calibration 集 (D_{\text{cal}})、测试集 (D_{\text{test}}).
2. 用训练集训练用于生成候选分布的模型或提示策略。
3. 在 calibration 集上计算 nonconformity score (s_i)（例如基于排名概率的逆数或 1 - p(true)）。
4. 选择分位点 (q_{1-\alpha}) 为 calibration scores 的 ((1-\alpha))-quantile。
5. 对新输入，根据 score ≤ (q_{1-\alpha}) 的候选形成 (S^{(\alpha)}).

### 7.2 理论保证（简述）

在独立同分布（i.i.d.）假设下，split-conformal 给出覆盖率保证：
[
\Pr{ y_{\text{true}} \in S^{(\alpha)} } \ge 1-\alpha.
]
（注：若 calibration 与 test 分布存在偏移，覆盖性受损）

### 7.3 实际工程注意

* 需要 calibration 数据集规模（推荐至少几十—上百样本）。
* 若无 calibration 数据，可使用 bootstrap / jackknife+ 方法，但代价更高。
* Conformal 建立后可以作为是否触发澄清的“保守度量”：当集合过大（(|S| > K_{\text{thresh}})）触发问询。

## 8. 候选集生成、采样策略与参数权重 (W(p))

### 8.1 候选集生成

常用方法：

* **Temperature sampling (N draws)**：在提示问法下多次调用 LLM，统计结果。优点：简单、捕获多模态分布；缺点：需要较多调用。
* **Beam search / top-k decoding**：生成概率最高的 K 候选（适用于有概率输出的模型）。优点：更稳定；缺点：可能缺乏多样性。
* **混合**：用 top-k + sampling 结合（先取 top-20 候选，再从中统计频率）。
  **推荐**：N = 20–50；K = 5–10（根据资源）。

### 8.2 参数权重 (W(p_i)) 的确定

两条路径：

1. **启发式**：核心=2，重要=1，可选=0（直观、易用）。
2. **数据驱动（学习）**：用历史任务与人类满意度/成功率训练线性模型，求解最能解释成功差异的权重。

   * 例如，目标变量 (y)（用户满意度或成功 0/1），特征可选为 ((1-U(p_i)))（即确定性度），拟合回归：
     [
     y \sim \beta_0 + \sum_i \beta_i \cdot (1-U(p_i)).
     ]
   * 将 (\beta_i) 归一化作为权重 (W(p_i))（再根据业务意义校正）。
     **注意**：学习权重需注意过拟合与可解释性，最好用 L1/L2 正则化并交叉验证。

## 9. 算法伪代码与复杂度 / 成本估算

### 9.1 伪代码：任务评估主流程

```
Input: task_description, PCSM(P,R), agent, strategy, N_samples, method
Output: success_flag, metrics

1. For each p in P: obtain candidate distribution by sampling N_samples -> compute U(p)
2. Compute C0 = 1 - sum(W[p]*U[p]) / sum(W[p])
3. t = 0
4. While not terminated and t < T_max:
    if strategy == NeverAsk: decide = execute_plan(candidates)
    elif strategy == RuleAsk: if any U[p] > thresh then ask param with highest U/p else execute
    elif strategy == Adaptive: action = RL_policy(state)
    if action == ask_p:
        ask question; get answer from user/simulator
        update candidates for p and recompute U(p), update C_{t+1}
        record ClarityDelta, ClarifyCount
    else:
        execute plan based on current candidates
        break
5. Run execution in environment, collect trajectory, evaluate success via automated pipeline
6. Compute metrics: SR, PE, ClarifyCount, ClarityDelta, ClarifyEfficiency, InfoGain...
```

### 9.2 计算复杂度与成本

* **LLM 调用次数**：约为 (m \times N)（m = 参数数目，N = 每参数采样次数），若每采样又调用 judge LLM 则更高。
* **时间复杂度（请求侧）**： (O(mN \cdot T_{LLM}))；其中 (T_{LLM}) 是一次 LLM 响应延迟（秒）。
* **Token 成本**：每次采样需要 prompt + response tokens，若 N=30，m=5，则 150 次 LLM 调用/任务。代价高昂，务必在论文中报告平均 token/美元成本估计。
* **建议优化**：并行化采样（多线程）、用小模型做初筛（弱模型廉价筛除），在可用时用 retrieval + closed vocab 映射减少 token。

## 10. 数值示例（逐步算例）

### 10.1 单参数熵示例

假设对参数 (p) 采样得到候选概率分布：
[
\hat{P}(v_1)=0.6,\quad \hat{P}(v_2)=0.3,\quad \hat{P}(v_3)=0.1,
]
则：

* 计算熵（自然对数）：
  [
  H = -[0.6\ln 0.6 + 0.3\ln 0.3 + 0.1\ln 0.1].
  ]
  逐步计算（自然对数）：

  * (\ln 0.6 = -0.5108256238). 乘以 0.6 → (0.6 \times -0.5108256238 = -0.3064953743).
  * (\ln 0.3 = -1.2039728043). 乘以 0.3 → (0.3 \times -1.2039728043 = -0.3611918413).
  * (\ln 0.1 = -2.3025850930). 乘以 0.1 → (0.1 \times -2.3025850930 = -0.2302585093).
  * 求和： (-0.3064953743 + (-0.3611918413) + (-0.2302585093) = -0.8979457249).
  * 所以熵 (H = -(-0.8979457249) = 0.8979457249)（单位：nats）。
* 归一化：(|V|=3), (\ln 3 = 1.0986122887).
  [
  U_{\text{entropy}} = \frac{0.8979457249}{1.0986122887} = 0.8170\ (\text{约}).
  ]
  逐步除法（近似）：(1.0986122887 \times 0.8170 = 0.89757)（接近上面熵），所以 (U \approx 0.817).

### 10.2 计算整体清晰度 C 的示例

假设任务有两个参数 (p_1,p_2)：

* (W(p_1)=2, U(p_1)=0.817)（如上）
* (W(p_2)=1, U(p_2)=0.20)（较确定）
  则
  [
  \sum W U = 2\cdot 0.817 + 1\cdot 0.2 = 1.634 + 0.2 = 1.834.
  ]
  [
  \sum W = 2 + 1 = 3.
  ]
  [
  C = 1 - \frac{1.834}{3} = 1 - 0.611333\ldots = 0.388666\ldots \approx 0.389.
  ]
  因此 (C\approx 0.389)（属于“半模糊”或偏模糊任务）。

## 11. 统计检验与样本量（power）计算（逐步示例）

### 11.1 比较两种策略 SR 差异（比例差异）样本量示例

目标：检测两策略（baseline, 改进）间 SR 差异从 0.50 提高到 0.60。
参数：显著性 (\alpha=0.05)（双边），检验力 (1-\beta=0.8)，即 (Z_{\alpha/2}=1.96), (Z_{\beta}=0.84)。

使用常见两独立比例样本量近似公式（保守）：
[
n = \frac{\big( Z_{\alpha/2}\sqrt{2\bar p (1-\bar p)} + Z_{\beta}\sqrt{p_1(1-p_1)+p_2(1-p_2)} \big)^2}{(p_2-p_1)^2},
]
其中 (\bar p = (p_1+p_2)/2).

代入 (p_1=0.5, p_2=0.6)：

* (\bar p = (0.5+0.6)/2 = 0.55).
* 计算第一项：

  * (2\bar p(1-\bar p) = 2\times 0.55\times 0.45 = 0.495).
  * (\sqrt{0.495}). 计算细节：0.703562（见前文推导，0.703562^2≈0.495）。
  * (Z_{\alpha/2}\sqrt{2\bar p(1-\bar p)} = 1.96 \times 0.703562 = 1.37898).
* 第二项：

  * (p_1(1-p_1)+p_2(1-p_2) = 0.5\times0.5 + 0.6\times0.4 = 0.25+0.24 = 0.49).
  * (\sqrt{0.49} = 0.7).
  * (Z_{\beta}\times 0.7 = 0.84\times0.7 = 0.588).
* Sum = (1.37898 + 0.588 = 1.96698).
* Square: (1.96698^2 =3.86899)（逐步可展成 ((1.96698)(1.96698)) -> 约 3.869）。
* ((p_2-p_1)^2 = 0.1^2 = 0.01).
* 最后 (n \approx 3.86899 / 0.01 = 386.899 \approx 387).

结论：若任务为独立分组测试（conservative），每组约需 387 个样本。如果采用配对设计（同一任务对比两策略），所需样本数会显著减少（McNemar 等）。这正好支持本文建议的“总任务数 400”作为合理规模。

### 11.2 相关性显著性样本量（C0 与人工清晰度达到 r=0.8）

检测样本 Pearson 相关显著性的估计（Fisher z 变换法）：

* Fisher z 变换： (z(r)=\frac{1}{2}\ln\frac{1+r}{1-r}). 对 (r=0.8):

  * (1+r)/(1-r) = 1.8/0.2 = 9.
  * (\ln 9 = 2.1972245773).
  * (z(r)=0.5\times 2.1972245773 = 1.0986122887).
* 标准误 (SE = 1/\sqrt{n-3}). 要求 (z(r)/SE \ge Z_{\alpha/2}=1.96),
  [
  n \ge \left(\frac{Z_{\alpha/2}}{z(r)}\right)^2 + 3.
  ]
* 代入： (Z_{\alpha/2}=1.96), (z(r)=1.0986122887).

  * 比值 (1.96/1.0986122887 \approx 1.78407)（逐步：见前文细致乘除演算）。
  * 平方约 (1.78407^2 \approx 3.183).
  * (n \approx 3.183 + 3 = 6.183 \Rightarrow) 四舍五入推荐最少 (n\ge 7).
    实际建议取更大样本（如 (n\ge 30)）以增强估计稳健性并支持更细粒度检验。该数学表明：若目标相关系数很大（0.8），统计上极易检测到，但为了泛化性应采集更多数据。

## 12. 故障模式、限制与缓解

### 12.1 模型偏差/偏移（distribution shift）

* Conformal 的覆盖性依赖 calibration 与 test 近似 i.i.d.；若 app 更新或 UI 改版，候选分布会剧烈变化。**缓解**：定期重校准 calibration 集、或在线更新 calibration。

### 12.2 LLM 幻觉（hallucination）

* LLM 可能“编造”不存在的参数值，导致候选集误导性高。**缓解**：对候选值做实体/词典校验（如 SKU、城市名校对）、或用检索/Retrieval 辅助验证。

### 12.3 采样成本过高

* N_samples*m 次 LLM 调用代价高昂。**缓解**：

  * 初期用小模型或规则过滤候选；
  * 并行化采样；
  * 对低不确定性参数减少采样（adaptive sampling）。

### 12.4 模拟用户与真实用户差异

* 模拟用户虽方便，但可能无法捕获真实用户的复杂反应。**缓解**：用小规模用户实验校准模拟器参数，并把实际用户评价作为最终验证。

## 13. 实验/消融建议（可直接落地）

必须包含以下消融/对照：

1. **C0 自动 vs 人工**：计算 Pearson/Spearman correlation、Bland–Altman plot、ICC/Cohen’s κ（若为分级）。
2. **策略对比**：NeverAsk / RuleAsk / Adaptive（CICC+RL） — 对 SR、ClarifyEfficiency、TokenCost 做成对比并做配对统计检验。
3. **Conformal vs Entropy**：用两种不确定度度量分别触发相同策略，比较结果差异与成本/稳定性。
4. **权重 W(p) 影响**：启发式 weights vs 学习 weights（回归训练）对 C 的解释力和下游策略效果比较。
5. **噪声鲁棒性**：在加广告/弹窗/动态加载场景下重复上面实验。

**每项实验都要报告**：均值、95% CI、p 值、Cohen’s d（或其他 effect size），并在附录给出每项的 raw counts/轨迹样本供复现。

## 最后几点建议（实践角度）

1. **先做小规模实验验证度量可用性**：先在 50–100 个任务上验证自动 (C_0) 与人类评分相关性与鲁棒性，再决定大规模部署参数。
