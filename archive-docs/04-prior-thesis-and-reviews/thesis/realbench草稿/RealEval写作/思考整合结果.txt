# GUI智能体清晰度分级任务评估框架

## 一、核心理论基础

### 1. 参数约束空间模型(PCSM)

我们的核心创新是提出参数约束空间模型(PCSM)，通过三层结构表达任务：
- **参数层**：表示任务所需参数及其清晰度状态
- **约束层**：表示参数间的约束关系及其强度
- **解空间层**：表示满足约束的可能解决方案集合

这种模型直接建模了参数清晰度和约束关系，而非传统的执行路径。

### 2. 信息论与贝叶斯方法

我们使用信息论量化参数清晰度：
```
清晰度(p) = 1 - H(P)/H_max
```

并使用贝叶斯推断评估智能体的参数理解：
```
P₁(v|p,e) = P(e|v,p) × P₀(v|p) / P(e|p)
```

### 3. 贝叶斯网络表示

任务约束通过贝叶斯网络表示：
- 参数节点表示参数变量
- 约束边表示参数间的条件依赖关系
- 联合概率分布表示解空间特征

## 二、评估框架结构

### 1. 多层次评估体系

我们设计了从顶层体验到底层指标的多层次评估体系：
- **顶层**：ClarityMOS = w1·系统质量 + w2·场景质量
- **中层**：系统质量和场景质量的具体维度
- **底层**：可直接测量的客观指标

### 2. 系统质量与场景质量分离

- **系统质量**：关注基础执行能力
  - 执行准确性
  - 执行效率
  - 系统稳定性

- **场景质量**：关注智能理解能力
  - 参数理解能力
  - 约束处理能力
  - 决策智能性

### 3. 参数驱动的检查点系统

我们设计了基于参数和约束的检查点系统：
- 参数理解检查点（明确/模糊/缺失参数）
- 约束处理检查点（显式/隐含/平衡约束）
- 决策智能性检查点（合理性/不确定性/解空间）

## 三、边界情况处理

边界情况（如商品售罄、网络错误）可以在PCSM模型中表示为：

1. **约束冲突**：
   - 用户要求特定商品(约束1)与商品售罄(约束2)冲突
   - 在PCSM中表现为约束集R中出现矛盾约束

2. **解空间变化**：
   - 边界情况导致解空间S发生变化
   - 智能体需要重新评估约束并调整解空间

3. **动态约束**：
   - 执行过程中出现新约束（如价格变动）
   - 需要更新约束集R并重新计算解空间

## 四、实际评估方法

### 1. 任务清晰度分级

根据参数清晰度计算任务整体清晰度：
```
任务清晰度 = Σ(清晰度(pi) × W(pi)) / Σ W(pi)
```

并据此分为：
- 清晰任务(0.7-1.0)
- 半模糊任务(0.3-0.7)
- 模糊任务(0.0-0.3)

### 2. 动态权重调整

根据任务清晰度动态调整评估权重：
- 模糊任务：系统质量(30%) + 场景质量(70%)
- 半模糊任务：系统质量(50%) + 场景质量(50%)
- 清晰任务：系统质量(70%) + 场景质量(30%)

### 3. 贝叶斯方法驱动的评估

使用贝叶斯方法评估智能体的参数理解和决策：
- 参数后验准确度：KL(P_agent || P_ref)
- 约束满足度：评估约束满足程度
- 解空间质量：P(智能体选择) / max(P(解))
