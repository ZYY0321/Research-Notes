明白了，我将调研当前移动端 GUI agent 或日常任务类 agent 在学术和工业界中是如何进行评估的，尤其关注 benchmark 构建策略。重点将包括：

* 任务完成度的评估标准（如是否仅为成功/失败，是否支持部分完成、路径质量等）
* 任务执行效率的衡量方式（例如路径最优性、多余操作判断等）
* benchmark 场景的构建（真实 vs 模拟，固定脚本 vs 用户行为驱动）
* 用户研究和用户指标（如满意度、易用性、认知负担）是否在评估中扮演角色
* 学术界和工业界已有的 benchmark 案例和最佳实践

我会尽快完成这项调研，并提出一套构建你自己的 benchmark 的关键要素建议。


# 移动端 GUI Agent 评估方法综述

## 任务完成度评估

大多数基准以任务**完成率**（成功/失败）作为主要指标，但不同研究对“成功”定义不尽相同。例如，有的工作仅要求智能体到达目标状态或输出结果与参考答案严格一致；也有工作要求完成全部子任务（multi-step subtasks）才算成功。此外，近年部分研究引入**部分成功**（partial success）概念，对未完全完成但部分达成目标的情况进行评分。例如，Zhang 等用指标区分完成部分子任务的程度；He 等通过 GPT-4V 判断轨迹完成度，其自动判定与人工评价一致率达85.3%。

为了更细致地评估行动流程，研究者还提出**中间步骤/连贯性**指标。例如，OS-Genesis 提出的“连贯性”（Coherence）指标评估动作序列是否符合逻辑、不包含冗余或无关步骤。这种评估关注过程合理性，帮助发现智能体是否存在多余操作或偏离目标路径的问题。总的来看，除了简单的成功率外，主流评估体系正逐渐采用多级成功标准、步骤级正确率、意图匹配等指标来全面刻画任务完成度。

## 代理效率评估

效率评估关注智能体完成任务的**速度和资源使用**。常用指标包括操作步数、执行时间等。例如，有基准设计了“效率得分”涵盖子指标：**时间成本**（Time Cost）衡量完成任务所用时间；**步骤成本**（Step Cost）衡量所需总步骤数；**资源成本**评估内存/CPU 资源消耗；**LLM 调用成本**评估模型调用的计算或金钱开销。这些指标可以量化智能体是否走最优路径、是否执行了多余操作。实际对比中，引入记忆或进化机制后，智能体所需步骤数和时间消耗显著下降，例如 AppAgentX 将平均步数从9.1步降至5.7步，执行时间从23秒降至16秒，同时成功率有所提升。这说明通过减少冗余点击和优化决策，效率指标得到了改善。总之，设计基准时应记录并比较智能体的平均步骤、平均耗时及资源消耗，以评估其操作路径的**最优性和简洁性**。

## 基准场景构建

基准任务的来源多样：**静态数据集**一般由研究者事先定义固定任务，适用于可复现评测。例如闭集静态任务有 RUSS（基于 DSL 的网页任务）、Mind2Web（扩充到2000个多样化任务）、MT-Mind2Web（多轮网页导航任务）、TURKINGBENCH（从众包获取的常见微任务）等。这些任务通常附带参考标签，便于计算准确率和中间步骤正确率。**开放世界静态数据集**则允许智能体访问真实网站，例如 WebVoyager（真实网站导航，多任务）、WebCanvas（动态网页任务，含**Mind2Web-Live**评测）等。

**交互式环境**通常通过模拟器或自建系统实时运行任务。典型例子如 MiniWoB、CompWoB（人工合成的网页微任务）、WebShop（模拟电商购物流程）、WebArena（跨领域自托管网站任务）、VisualWebArena（多模态网页任务）等。这些环境提供了可控的测试平台，能自动化评测多步导航能力。移动端基准如 **SPA-Bench** 提供340个涉及系统/第三方应用的任务。近期移动场景基准有 AppAgent Benchmark（50个任务，覆盖9款应用）、DroidTask（158个任务，13款应用）、AndroidWorld（116个任务，20款应用的真实场景）、Android Agent Arena (A3)（201个任务，20款常用应用）等，这些任务直接来自真实应用使用场景，提高了评测的真实性。桌面应用方面，**WorldGUI**基准覆盖10款常用桌面/Web应用（如PowerPoint、VSCode等），共611个任务，并对每个任务配备自然语言指令、演示视频和真实操作流程（GT计划），对不同初始界面状态进行了多种设置。综上看，优秀基准往往结合**真实应用操作**与**可控制脚本任务**：既包括众包或专家定义的人工任务，也利用模拟环境生成的连续轨迹。

## 用户体验与主观指标

迄今为止，GUI 智能体的评估多集中于客观指标，很少纳入大规模用户实验。一些研究意识到交互延迟对用户体验影响显著：当前智能体通常需要秒级推理时间，远超人类可接受（0.2秒）阈值，严重降低用户满意度。但真正将**用户满意度、可用性、认知负担、习惯学习**等主观指标纳入评测的工作并不多见。目前尚缺乏系统性用户研究来度量终端用户对不同智能体行为的偏好和感受。总体而言，现阶段大部分评测仍使用可自动计算的成功率、时间等指标，真正的人机协同式评估（如问卷、用户A/B测试）仅在极少数示例中出现。

## 现有评估体系与公开基准

学术界和工业界已经提出多种基准与评估框架：如面向网页导航的 **Mind2Web**（2000任务集）、移动设备自动化的 **AppAgent** 基准、跨域任务的 **WebArena** 环境、电商任务模拟的 **WebShop**、企业平台的 **WorkArena** 等；移动端还有 **AndroidWorld**、**AgentStudio** 等全功能仿真场景。商业系统方面，Adept.ai、Rabbit AI、Gorilla 等公司也推出了应用级自动化产品，部分团队公开了相关测试套件。总体而言，这些基准覆盖了不同平台（网页、桌面、移动）、不同任务类型（单步任务、多轮复杂任务）和不同数据来源（真实应用操作记录或研究者设计）。通过对比这些公开基准可以看出，它们通常提供清晰的评测指标和结果，以便客观比较不同智能体方案的性能。

## 通用基准构建要素与设计原则

综合现有研究经验，一个通用、可扩展、客观的 GUI 智能体基准应具备以下核心特征：

* **任务多样性**：包含跨平台（移动、桌面、Web）和跨领域（办公、社交、电商、测试等）任务，既有简单单步任务也有多步骤复杂工作流。任务应来源于真实使用场景，同时可通过脚本模拟生成，确保规模化。
* **丰富的反馈信息**：每个任务应提供详尽标注（如目标状态、过程演示、参考操作序列等），方便自动化评估。例如 WorldGUI为每任务配置指令、演示视频和GT操作流程。
* **多维评价指标**：结合**完成度**、**效率**及**安全/合规**等指标。既评测最终成功率，也可评测步骤层面的正确率、中间意图匹配、与最优路径的偏差（避免冗余步骤）。效率方面记录耗时、步数、资源消耗等。此外应考虑策略遵守度和潜在风险（如	ST-WebAgentBench 的“策略完成率”和“风险比率”指标）。
* **现实交互性**：基准设计应模拟真实动态环境，例如支持不同初始界面状态、多轮上下文切换等，以提高鲁棒性测试。例如 WorldGUI 强调不同起始态和上下文多样性来反映真实交互。
* **可重复与可扩展**：任务和环境应公开可复用，并提供统一评测脚本，使不同研究可在相同条件下比较。架构上建议模块化、可增量添加新任务或新平台，以适应未来更新。
* **用户体验关注**：尽管主要为自动化评测，也应考虑用户感知因素。如缩短响应延迟（以提高满意度）、评估智能体行为对用户认知负荷的影响等。可在设计中预留对用户主观评价的数据采集接口，为后续的人机协作研究提供基础。

总之，一个优秀的 GUI Agent 基准需综合考虑任务涵盖度、指标全面性与评价客观性，通过严格标注和多层次评分确保结果公平可对比，同时关注真实使用场景下的可靠性和用户体验。以上原则有助于构建一个通用、扩展性强且能真实反映图形界面操作能力的评测平台。
