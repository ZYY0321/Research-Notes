一、任务分级详述
（一）单应用任务分级
一级任务（L1）
难度特征：属于基础且简单的活动，通常涉及少于五个操作步骤。主要聚焦于应用的基本功能使用，对智能体的要求相对较低，例如在应用中进行简单的搜索、切换基础页面等操作。
举例：在音乐播放应用 “Spotify” 中，任务为 “播放周杰伦的歌曲”。智能体只需打开 Spotify 应用，进入搜索页面，输入 “周杰伦”，然后点击播放搜索结果中的歌曲即可完成任务。整个过程步骤清晰简单，不涉及复杂的 UI 元素处理或多步骤逻辑依赖。在文件管理应用中，“在文件夹 A 中创建一个名为‘新文档’的文件夹” 也属于此类任务。智能体找到文件管理应用并打开，定位到文件夹 A，执行创建新文件夹并命名的操作，一般不超过 5 步即可完成。
二级任务（L2）
难度特征：相较于一级任务，引入了更复杂的需求，例如处理复杂的 UI 元素，如滚动页面查找特定元素、处理弹出窗口、应对一些简单动画等，通常需要少于十个操作步骤。这类任务对智能体的 UI 理解和操作能力有更高要求。
举例：在电商应用 “Amazon” 中，任务为 “搜索并将价格在 50 - 100 美元之间的无线耳机添加到心愿单”。智能体需要打开 Amazon 应用，在搜索栏输入 “无线耳机”，然后在搜索结果页面中，通过滑动、筛选等操作，找到价格在指定区间的耳机，并点击添加到心愿单按钮。这一过程涉及到对搜索结果页面复杂 UI 元素的处理，包括价格信息的识别、筛选条件的设置等，步骤相对较多，但一般不超过 10 步。在视频编辑应用中，“在视频素材库中找到时长超过 3 分钟的视频，并将其添加到编辑项目中，设置初始播放速度为 1.2 倍” 也属于二级任务。智能体需要理解视频素材库的 UI 布局，识别视频时长信息，完成素材添加和播放速度设置等操作，复杂度高于一级任务。
三级任务（L3）
难度特征：是单应用任务中最复杂的级别，可能涉及多达十五个操作步骤，要求智能体处理更多步骤和复杂的逻辑依赖。这类任务往往需要智能体对应用的多个功能模块进行深度交互，处理复杂的业务流程。
举例：在旅行预订应用 “Expedia” 中，任务为 “预订从北京到纽约，出发日期为下个月 15 号，返程日期为下个月 25 号，经济舱，且包含免费早餐的往返机票，并选择可以免费取消的航班，同时预订纽约当地评分 4 星以上，价格每晚不超过 300 美元，距离市中心 5 公里以内的酒店”。智能体需要依次完成打开 Expedia 应用，设置出发地和目的地、选择出发和返程日期、筛选舱位类型、勾选免费早餐和可免费取消选项来预订机票；之后再切换到酒店预订页面，设置地点为纽约，筛选评分、价格和距离条件来预订酒店。整个流程步骤繁多，涉及多个功能模块的复杂操作以及严格的条件筛选，逻辑依赖关系复杂。在办公软件应用中，“在文档中查找所有出现‘重要事项’的段落，将这些段落字体设置为加粗、红色，字号调整为 14 号，并在文档末尾添加一个包含这些段落内容的总结表格，表格中每一行对应一个段落，且在表格旁边插入一个相关的图表（图表类型根据段落内容自动选择合适的）” 也是典型的三级任务。智能体需要在文档编辑功能中完成文本查找、格式设置、表格创建、内容填充以及图表生成等一系列复杂操作，对其理解能力和操作执行能力要求极高。
（二）跨应用任务分级
一级任务（L1）
难度特征：需要在两个应用之间进行切换来完成操作。虽然涉及应用间的交互，但步骤相对较少，应用间的逻辑关系相对简单，主要考验智能体在不同应用环境下的初步切换和协作能力。
举例：“使用浏览器（如 Chrome）搜索‘即将上映的电影’，然后将搜索到的第一部电影名称复制到笔记应用（如 Evernote）中创建一条新笔记”。智能体首先要打开 Chrome 浏览器，输入关键词进行搜索，找到第一部电影名称后，复制该名称；接着切换到 Evernote 应用，创建新笔记并粘贴电影名称完成任务。此过程涉及两个应用的基本操作以及信息在应用间的传递，难度适中。再如 “在地图应用（如百度地图）中查找‘附近的餐厅’，将排名第一的餐厅地址发送给微信好友”。智能体要在百度地图中完成搜索和地址获取操作，然后切换到微信，找到对应的好友并发送地址，体现了跨应用的简单交互。
二级任务（L2）
难度特征：要求在三个应用之间进行复杂的交互，涉及更多步骤以及跨应用间的依赖与协调。这类任务对智能体的多应用协同能力、上下文记忆以及逻辑推理能力有更高要求，因为在不同应用间切换时需要保持任务的连贯性和准确性。
举例：“在购物应用（如淘宝）中搜索一款运动背包，查看其商品详情页面获取价格信息；然后打开比价应用（如慢慢买），将该背包的名称和价格输入进行比价，找到价格最低的同款商品链接；最后将该链接发送到社交应用（如 QQ）给好友分享”。智能体需要在淘宝中完成商品搜索和价格信息提取，在慢慢买应用中完成信息输入和比价操作，再在 QQ 中完成链接分享，步骤较多且应用间的信息传递和操作依赖关系复杂。又如 “使用音乐应用（如网易云音乐）播放一首喜欢的歌曲，同时打开计步应用（如悦动圈）开始记录运动步数，当歌曲播放结束后，将计步应用中的步数数据截图，发送到钉钉工作群中汇报今日运动情况”。该任务涉及音乐播放、运动记录、截图以及社交软件中的信息分享，要求智能体在三个应用之间灵活切换，准确把握每个应用的操作时机和信息交互，难度较大。
二、评估指标详述
成功信号
评估方式：这是判断智能体是否成功完成任务的核心二进制指标。在单应用任务和跨应用任务中采用不同的混合检测方法。对于单应用任务，先通过粗检测，利用 OCR（如 PaddleOCR）提取截图中的文本信息，与人类注释的最终状态关键文本组件进行匹配。若粗检测通过，则进入细检测，使用如 GPT - 4o 等大模型评估器，结合任务描述、截图以及智能体执行的动作序列进行综合判断，以确定任务是否真正成功完成。在跨应用任务中，首先通过大模型将任务轨迹根据涉及的应用分割为多个子任务，然后对每个子任务依次进行验证。只有当所有子任务都成功完成时，才判定整个跨应用任务成功。
举例：在单应用任务 “在日历应用中创建一个明天上午 10 点的会议提醒，标题为‘重要会议’” 中，粗检测时，OCR 提取日历应用最终页面文本，若能检测到 “重要会议” 以及明天上午 10 点相关信息，则粗检测通过；细检测时，GPT - 4o 根据任务描述 “创建明天上午 10 点的会议提醒，标题为‘重要会议’”、最终截图以及智能体执行的创建步骤序列，判断操作是否符合预期，若符合则成功信号为真，即任务成功完成。在跨应用任务 “用浏览器搜索‘苹果发布会视频’，将播放量最高的视频链接复制到视频播放应用中播放” 中，大模型先将任务分割为浏览器搜索子任务和视频播放应用播放子任务。在浏览器搜索子任务中，判断是否成功搜索到相关视频并获取播放量最高的链接；在视频播放应用子任务中，判断是否成功使用获取的链接播放视频，只有两个子任务都成功，整个跨应用任务的成功信号才为真。
步骤比率
评估方式：在成功完成的任务中，计算智能体执行的步骤数量与人类预先定义的 “黄金步骤” 数量的比值。该指标用于衡量智能体完成任务的效率，比值越低，说明智能体的执行过程越高效，与最优的人类执行方式越接近，冗余操作越少。
举例：对于单应用任务 “在相册应用中选择最近拍摄的 5 张照片，并将它们打包成一个压缩文件”，人类执行的 “黄金步骤” 可能是打开相册应用，切换到最近拍摄相册，依次勾选 5 张照片，点击分享或导出选项，选择打包成压缩文件，假设共 6 步。若某智能体完成此任务执行了 8 步，那么该智能体在此任务上的步骤比率为 8÷6≈1.33。在跨应用任务 “在电商应用中购买一本书，然后在支付应用中完成支付” 中，人类 “黄金步骤” 可能是在电商应用中搜索书籍、选择书籍、加入购物车、结算，在支付应用中确认支付，假设共 5 步。若智能体完成该任务执行了 7 步，则步骤比率为 7÷5 = 1.4。较低的步骤比率表明智能体能够更高效地完成任务，减少不必要的操作流程。
终止原因
评估方式：记录任务结束的原因，主要分为三种情况。一是智能体自我报告完成任务，即智能体认为自己已经按照任务要求执行完毕；二是达到预先设定的最大步骤数，任务被迫终止，这表明智能体可能在执行过程中出现了问题，无法在合理步骤内完成任务；三是执行过程中发生错误，例如点击了错误的按钮、输入了无效信息等导致任务无法继续执行。通过分析终止原因，可以深入了解智能体在任务执行过程中的可靠性和稳定性。
举例：在单应用任务 “在邮件应用中撰写并发送一封邮件给指定联系人，主题为‘会议通知’，内容包含会议时间、地点等信息” 中，如果智能体成功撰写邮件并点击发送按钮后，报告任务完成，那么终止原因就是自我报告完成。若智能体在执行过程中，由于对邮件应用界面理解错误，一直无法找到发送按钮，达到了设定的最大步骤数（如 50 步），则终止原因是达到最大步骤。要是智能体在输入会议地点信息时，因格式错误导致系统提示无法继续，任务中断，此时终止原因就是执行错误。在跨应用任务 “在地图应用中规划从家到公司的路线，然后将路线分享到社交应用给同事” 中，若智能体成功完成路线规划并分享到社交应用后报告完成，属于自我报告完成；若在地图应用中规划路线时，由于定位错误或算法问题，始终无法生成正确路线，达到最大步骤数而终止，就是达到最大步骤终止；若在分享路线到社交应用时，因权限设置问题无法分享，导致任务失败，则是执行错误终止。
过早终止信号
评估方式：用于检测智能体在任务实际未成功完成的情况下，却误判自己已经完成任务并提前终止执行的情况。通过对比智能体的终止状态与任务的实际成功标准来判断是否出现过早终止信号。若智能体过早终止，可能导致任务未达到预期目标，影响其性能评估。
举例：在单应用任务 “在文档编辑应用中查找并替换所有‘apple’为‘苹果’，并保存文档” 中，智能体可能在查找替换了部分 “apple” 后，错误地认为已经完成全部替换，提前终止了任务。此时，通过检查文档中是否还存在未替换的 “apple”，即可判断智能体出现了过早终止信号。在跨应用任务 “在购物应用中添加商品到购物车，然后在支付应用中完成支付” 中，智能体在购物应用中添加商品到购物车后，错误地认为任务已完成，没有进入支付应用进行支付操作，这种情况也属于过早终止信号。过早终止信号反映了智能体对任务完成判断的不准确，需要进一步优化其成功检测机制。
逾期终止信号
评估方式：与过早终止信号相反，逾期终止信号用于判断智能体在任务已经成功完成的情况下，却未能及时识别任务完成，继续进行无效操作的情况。同样通过对比智能体的执行状态与任务成功标准，以及观察智能体在任务成功后的后续操作来确定是否存在逾期终止信号。逾期终止会浪费资源和时间，降低智能体的执行效率。
举例：在单应用任务 “在视频剪辑应用中对一段视频进行剪辑，添加特定字幕和音乐，导出视频” 中，当智能体成功完成视频剪辑、字幕添加、音乐添加并导出视频后，若还继续在应用中进行一些无意义的操作，如反复调整已确定的剪辑参数等，就产生了逾期终止信号。在跨应用任务 “在翻译应用中将一段中文文本翻译成英文，然后将翻译结果复制到文档应用中保存” 中，智能体完成翻译并复制结果到文档应用保存后，如果还在翻译应用中进行其他无关操作，没有停止任务执行，也属于逾期终止信号。避免逾期终止信号有助于提高智能体的执行效率，合理利用资源。
耗时
评估方式：记录智能体从开始执行任务到任务结束（无论成功或失败）所花费的总时间，单位为秒。该指标主要用于评估智能体的执行速度，对于需要快速响应的智能手机代理应用场景非常重要。耗时越短，说明智能体能够越快地完成用户指令，提升用户体验。
举例：在单应用任务 “在天气应用中查询明天的天气情况” 中，从智能体打开天气应用开始，到获取并显示明天天气信息的整个过程所花费的时间即为耗时。假设某智能体完成此任务耗时 3 秒，而另一个智能体耗时 5 秒，那么在这个任务上，前者的执行速度更快。在跨应用任务 “在新闻应用中找到一篇感兴趣的文章，将文章中的关键信息提取出来，发送到笔记应用中记录” 中，从智能体打开新闻应用搜索文章开始，到在笔记应用中完成信息记录结束，所经历的时间就是该任务的耗时。通过比较不同智能体在各类任务上的耗时，可以直观地了解它们的执行效率差异，为优化智能体性能提供时间维度的参考。
API 成本
评估方式：对于依赖专有大语言模型 API 的智能体，统计其在任务执行过程中调用 API 所产生的费用，单位为美元。API 成本反映了使用特定智能体完成任务的经济开销，尤其是对于需要频繁调用 API 的复杂任务，成本因素可能会影响智能体的实际应用和推广。通过计算 API 成本，可以评估不同智能体在资源消耗方面的经济性，帮助选择成本效益更高的智能体方案。
举例：某些智能体在执行任务时，每调用一次 GPT - 4o API 进行文本处理或图像识别等操作，会产生一定费用。在单应用任务 “在图像编辑应用中使用智能美化功能处理一张图片” 中，如果智能体调用 API 3 次，每次调用费用为 0.03 美元，那么该任务的 API 成本就是 3×0.03 = 0.09 美元。在跨应用任务 “在多个应用间进行复杂数据处理和交互，需要频繁调用大模型进行语义理解和决策” 中，若在整个任务执行过程中，智能体调用 API 共 10 次，每次费用 0.05 美元，则 API 成本为 10×0.05 = 0.5 美元。通过对 API 成本的评估，可以在实际应用中根据预算和任务需求，合理选择智能体，平衡性能和成本之间的关系 。
