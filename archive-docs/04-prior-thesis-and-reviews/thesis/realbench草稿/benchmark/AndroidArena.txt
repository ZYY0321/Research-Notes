摘要
大型语言模型（LLMs）已赋予智能体在领域特定软件
如浏览器和游戏内执行复杂任务的能力。然而，当应
用于通用软件系统如操作系统时，LLM 智能体面临三
个主要挑战。首先，动作空间庞大且动态变化，这使得
LLM 智能体难以保持最新理解并提供准确响应。其次，
现实世界任务通常需要跨应用协作，这要求 LLM 智
能体具备远见的规划能力。第三，智能体需要识别与
用户约束对齐的最优解决方案，例如安全问题和偏好。
这些挑战促使我们提出了 AndroidArena，一个用于
评估现代操作系统上 LLM 智能体的环境和基准。为了
解决人力成本高的问题，我们设计了一种可扩展且半
自动的方法来构建基准。在任务评估中，AndroidArena
包含了准确且自适应的指标，以解决非唯一解的问题。
我们的研究结果表明，即使是最先进的 LLM 智能体
在跨应用场景和遵守特定约束方面也存在困难。此外，
我们发现缺乏四项关键能力，即理解、推理、探索和反
思，是 LLM 智能体失败的主要原因。此外，我们对反思
失败进行了实证分析，并通过我们提出的探索策略将
成功率提高了 27%。这项工作首次提出了对 LLM 智能
体细粒度弱点的有价值见解，并为此领域的未来研究
提供了前进的道路。AndroidArena 的环境、基准和评
估代码已在https://github.com/AndroidArenaAgent/AndroidArena发
布。

1 引言
大型语言模型 (LLMs) 在理解人类隐含意图和常识推
理方面展现出了巨大潜力 [27]。这使得将 LLM 作为智
能体 [29, 32] 运用成为可能，即一个能够根据环境的
感知状态做出决策并执行动作的智能实体。一个例子
是 LLM 与 领域特定软件交互，例如数据库 [13]、游
戏 [28] 和浏览器 [40]，以完成任务。
最近，基于大语言模型的智能体出现，以与通用
软件系统交互，例如操作系统及其安装的应用程序，以
完成更复杂的开放领域任务 [35, 36]。这些任务从设置
提醒等简单操作到财务管理以及与亲人保持联系等更
复杂的活动。操作系统中的复杂场景通常表现出以下
特点：1）由于实时互联网数据交换、应用程序安装和
升级而导致的广泛且不断变化的动作空间；2）随着用
户任务变得更加相互关联和多样化，对跨应用程序协
作的需求不断增加；3）对个人兴趣和安全问题的更高
关注。
这些特性促使我们建立一个新的环境和全面的基
准，以研究大型语言模型智能体在复杂软件系统中的
能力边界。在本文中，我们介绍了 AndroidArena ，一
个基于安卓操作系统的环境，配有包含注释真实值动
作序列的评估基准。AndroidArena 支持实时互联网数
据交换和动态 APP 管理，并可在各种 APP 之间实现
无缝操作。这些特性有助于在广阔且动态的动作空间
和跨 APP 场景中评估大型语言模型智能体。此外，我
们提出了一种可扩展的方法，用于半自动构建指令基
准，确保对 APP 功能的全面覆盖。我们的开源基准，
基于上述特性，不仅评估单个 APP 内的任务，还评估
需要跨多个 APP 协作的复杂任务。它还考虑了受用户
偏好和安全考虑等约束的任务。
在复杂操作系统中评估任务并不简单 [14]，主要
是因为任务的可行动作序列通常不唯一。这在多步骤
决策场景中对精确评估智能体构成了重大挑战。为了
解决这个问题，我们设计了自适应指标以准确评估任
务完成情况。评估结果表明，所有最先进的 (SOTA) 大
型语言模型智能体在跨应用场景中表现不足，成功率
低于 60%，并且难以完全遵守特定约束。值得注意的

示了反思失败的原因，并在增强探索时实现了 27%
的改进。
2 背景
2.1 LLM 智能体框架
随着大语言模型的出现，大语言模型智能体的研究开
始蓬勃发展。早期的研究工作 [1, 11, 19] 通过环境观
察直接让大语言模型生成动作。ReAct [38] 是一项开
创性的工作，将推理和行动整合到大语言模型中以解
决一般任务。它首先根据历史上下文生成推理迹，随
后生成动作与环境交互。在此任务解决范式的基础上，
后续的智能体被提出以在各个维度上增强能力。Reflex￾ion [22] 总结环境中的文本反馈，然后将其作为额外上
下文纳入后续回合的 LLM 智能体中。自我反思的上下
文充当语义梯度信号，为智能体提供具体的改进方向，
并有助于从先前错误中学习以提高任务性能。本文专
注于评估大语言模型智能体的能力并理解其弱点。我
们采用 ReAct 作为基本智能体策略，Reflexion 作为评
估智能体自我反思能力的方法。
2.2 现有操作系统任务基准
操作系统 (OS) 是人类日常交互的重要环境，许多基准
测试已出现以评估智能体在 OS 中的性能。AITW [20]
作为一种静态图像数据集，提供了设备交互的人类演
示。然而，AITW 的静态特性使得智能体无法获得可重
复的环境。另一方面，AndroidEnv [26] 提供了对 APP
动态交互的支持。尽管如此，它仅支持每个环境实例
中单个 APP 的交互，这限制了其评估复杂和现实任务
的能力。WebArena [40] 创建了模拟网络浏览器中人类
行为的任务。然而，它也仅限于在单个网站上自动化
任务，这对其适用性构成了约束。虽然这些工作已经
带来了启发，但也突显了在 OS 上评估任务的重大挑
战。现实世界用户执行的任务通常更加复杂和具有挑
战性，需要多个 APP 的协作。此外，智能体还需要考
虑各种约束，如安全性和用户偏好。因此我们提出了
AndroidArena ，一个可重复的移动环境，允许跨 APP
访问。同时，我们引入了一个新数据集，该数据集包
含了指令的丰富性、难度和约束。与其他工作的详细
比较见表 1。
2.3 多步骤决策的现有指标
为了评估大语言模型智能体的性能，提出了多种指标。
SmartPlay [31] 和 LASER [16] 使用成功率和奖励来评
估任务完成情况。然而，这些指标无法反映单个任务
内的详细完成情况。TPTU [21] 和 Mind2Web [7] 采用
逐步动作对齐方法，提供了对任务完成情况更细致的
分析。然而，当应用于多步骤决策场景时，其中完成
任务的可行动作序列不唯一，这种逐步匹配方法可能
会引入不准确性。在本文中，我们提出了一种自适应
方法来准确评估任务完成情况，并提出了一组细粒度

3.2 广阔而动态的动作空间
与先验环境 [26, 40] 聚焦于单个 APP 并仅支持特定动
作不同，我们的动作空间是广阔且动态的。这归因于
一个典型的 APP 可能具有数百个可用于操作的 UI 元
素，这些 UI 组件由于实时互联网数据交换而表现出
变化性。当考虑 AndroidArena 中的所有 APP 时，广
阔和动态的特性进一步增强。我们设计的动作可以分
为四类：1) APP 级动作负责安装、启动和停止 APP；2)
组件级动作直接操作 UI 组件，如点击、输入、滑动等；
3) 系统级动作包括开启和关闭屏幕、调整音量、截屏
等；以及 4) 任务级动作是在智能体认为任务应完成时
发出的。完整的动作空间见 §B。

4.1 单任务与交叉 APP 任务构建
APP 功能提取。我们整合了 13 个预装的 Google 套件
测试 APP，这些 APP 专为与 Android OS 无缝协作并
提供基本服务而设计。完整的 APP 列表可在 §C中找
到。我们的目标是制定涵盖丰富且多样的 APP 功能的
任务指令，同时符合人类的真实使用行为。为了实现
这一目标，我们提出利用从互联网上关于 APP 的人类
讨论和共享经验中获得的见解。具体来说，我们首先
围绕特定 APP 的使用制定查询，并使用搜索引擎检索
相关网页。如图 3所示，构造的示例查询包括 “Gmail
和日历协作功能” 和 “如何将 Gmail 和日历一起用于
任务”。然后，我们构建一个向量数据库来存储包含
丰富功能且真正吸引和关注用户的大量网页。通过使
用 LLM 和特定提示符从数据库中检索 (§F.4)，我们可
以提取受限的 APP 功能。
指令生成与演化我们下一步是利用具有功能到指
令提示的 LLM (在 §F.5中提供) 来生成基于识别出的
APP 功能的初始任务指令。为了自动批量生成更多指
令，我们采用 Evol-Instruct [33] 策略来扩展原始指令。
在该策略的应用中，每次演化迭代都涉及使用 LLM 以
及两个提示，即深入演化和广度演化。深入演化提示
鼓励 LLM 通过使指令更复杂和更具挑战性来重写指
令，而广度演化提示旨在增强特征覆盖和整体数据集
多样性。通过多次演化的迭代执行，我们依次得出演
化数据集，从而扩展和优化任务指令池。
人工验证与标注为了构建基准，我们让熟悉操作
测试 APP 的标注者参与进来。他们首先被指导识别并
筛选出具有重复性、分歧或无法完成的任务。随后，他
们记录与手机的交互过程。考虑到完成任务可能有多
个可行的动作序列，他们被鼓励选择最简洁的动作方
案，即动作序列最短的方案。完成任务后，标注者会
使用回放脚本重新执行标注的动作序列，从而轻松验
证标注的动作序列的准确率。随后，整理好的任务指
令和动作演示被收集到基准数据集中。
4.2 受限任务构建
在现实世界移动任务的背景下，通常受到特定用户偏
好或安全考虑的限制，我们引入了一个受限任务集来
评估智能体理解用户定义约束的能力，并能够熟练地
做出决策以避免违反这些约束。具体而言，我们考虑
了三种类型的约束：APP 级、页面级和组件级约束。APP
级约束涉及使用特定 APP 的偏好，例如 “不 prefer 使
用即时通讯进行通信” 这样的约束。页面级约束限制
对特定页面的访问，如 “由于存在敏感信息，避免进
入 Gmail 的标签列表页面” 等场景。组件级约束将特
定的 UI 组件识别为敏感操作，e.g., “不要点击支付按
钮”。值得注意的是，这些受限任务是从单 APP 任务
集中精心挑选的，并且用自然语言约束手动标注了相
应的正确动作序列。

5.2 通过细粒度能力评估理解根本
原因
除了为复杂决策场景中的任务完成提供自适应和准确
的评估指标外，我们研究的另一个主要目标是探讨导
致智能体规划成功或失败的潜在根本原因。认识到强
化学习（RL）是解决 CMDP 问题的经典且有效的方
法 [9]，我们抽象了 RL 智能体中的基本元素和机制，并
提出了针对评估大语言模型智能体的细粒度能力。在
这里，我们使用 DQN [17] (算法 1)，最经典的强化学
习算法之一作为例子。我们将它分解为四个关键维度，
即理解, 推理, 探索, 和反思。
理解能力。理解能力 的方面涵盖了智能体在理解
观察内容以及遵循提示中指定的动作格式和空间方面
的熟练程度。与那些严格限制输出动作在预定义动作
空间内的强化学习智能体不同，大语言模型的输出空
间涵盖了整个词表。这给大语言模型智能体提出了很
高的要求，使其必须充分理解和遵守指定的动作格式
和空间。此外，由于手机屏幕大小的限制，诸如复选
框的简洁状态描述等关键信息，给大语言模型智能体
在理解重要但简短的观察细节方面带来了挑战。因此，
为了全面评估智能体的理解能力，我们制定了三个指
标：
• 格式无效。输出与提示中预定义格式偏离的动作比
例。
• 无效动作。在提示中指定的动作空间之外输出动作
的比例。
• 矿石挖掘。目标元素长度与整个观察值的比率，用
于评估智能体理解任务上下文和识别关键信息的能

7 增强大型语言模型智能体的未来
方向
通过 §6.3中的实验，我们观察到 LLaMA2 模型在所有
四个维度上都表现出弱点。即使是领先的模型 GPT-4，
仍然在探索和反思方面存在不足。在本节中，我们首
先分析了 Reflexion 的无效性，并对导致这一现象的因
素进行了实证分析。其次，我们提出了一种新颖的基
于提示的探索方法，揭示了明确鼓励智能体探索未知
动作可以提高性能。
7.1 反射失败分析

务，它本质上提供了额外尝试的机会，并具有性能提
升的潜力。因此，我们进行了比较评估，即在不经过

7.2 提升探索能力可提高性能
在阅读轨迹时，我们观察到即使对于 GPT-4，它仍然
表现出重复错误动作的明显倾向，如图 5(f)所示，这
表明其探索能力有限。此外，动作的重复会降低先前
轨迹的质量，使其不足以为反思提供有信息量的指导，
如 §7.1中所述。
本节中，我们为 LLM 智能体引入了一种基于提示
的探索策略。与之前的方法 [4] 不同，这些方法将 LLM
视为 RL 策略网络并采用来自 RL 的探索策略，我们的
策略通过包含一个指示先前访问观察次数 푀(s) 和已
执行动作次数 푁 (s, a) 的提示来引导 LLM 智能体的探
索。具体而言，我们在每个决策步骤嵌入一个提示，例
如 “你已经在这个状态停留了 M 次，执行动作 A 共 N
次”。这一概念受到上限置信度 (UCB) [2, 30] 的启发。
与 UCB 不同，我们没有设计显式的探索策略。相反，
我们将历史信息整合到提示中，利用 LLM 强大的决策
能力来平衡探索和利用。我们在 Camera APP 上进行
了实验，GPT-4 表现出最高的重复动作比率，以评估
探索策略的有效性。我们在 {5, 15, 25, 35, 45} 中改变了
最大步数限制，并在图 7 中展示了 SR 和重复动作比
率。结果表明，通过简单的基于计数的提示，SR 可以
提高 27%。此外，随着最大步数限制的增加，GPT-4 的
探索能力下降。相比之下，对于 GPT-4+Exploration，对
环境的有效探索持续存在，从而导致性能持续提升。
