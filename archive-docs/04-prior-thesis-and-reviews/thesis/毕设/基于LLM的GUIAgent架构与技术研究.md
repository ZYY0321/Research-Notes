选题的理论意义、实际意义、创新点
自现代计算机诞生以来，图形用户界面（GUI）始终是人机交互的基石。它用直观的视觉元素——窗口、图标、菜单与指针取代了晦涩难懂的命令，虽在一定程度上牺牲效率，却大幅降低了普通用户使用计算机的门槛，推动个人电脑走入千家万户。进入 GUI 时代后，出于安全、隐私、版权或商业利益等考量，大多数面向终端用户设计和开发的应用仅暴露GUI供用户操作，而不再提供 API 或 CLI 等可编程接口。在其他程序试图集成或复用其功能时，只能将 GUI 视为唯一的“黑盒”入口。
然而，GUI 的设计本质上围绕“人”而非“程序”展开，这种视觉取向使得GUI入口难以被外部程序接入。GUI的界面往往随软件迭代而持续变化，视觉元素缺乏稳定的语义标识，且往往采用事件驱动与异步机制。依赖屏幕坐标、图像特征或规则的自动化脚本难以适应这些变化，界面或流程稍有改动便可能失效。因此，传统的界面级测试与机器人流程自动化（RPA）往往脆弱且成本高昂——不仅需要大量人工编写与维护，还极易受上游应用变动影响，其综合投入远超命令行或 API 级别的自动化。
长期以来，GUI 自动化鲜有突破性进展，但随着大型语言模型（LLM）的崛起，这一局面正在被改写。自 ChatGPT 等模型问世以来，LLM 在自然语言理解、代码生成和任务泛化方面展现出卓越能力；视觉语言模型（VLM）和大型多模态模型（LMM）则进一步将这种能力拓展至视觉领域。以 LLM 与 VLM/LMM 为推理引擎的智能体能够“读懂” GUI 并像人类一样动态执行任务，有望彻底颠覆长期依赖人工脚本的 GUI 自动化范式。
这类智能体通常被称为 LLM-brained GUI Agent（简称 GUI Agent）。其正式定义是：在 GUI 环境中运行、以大型语言模型（或其衍生的多模态模型）为核心推理与认知引擎，能够灵活自适应地生成、规划并执行操作的智能体。GUI Agent 可实时解析屏幕界面元素，并基于对用户自然语言指令的理解，完成点击、输入、拖拽等操作。整个过程无需依赖预设脚本或固定工作流，即使在复杂、不可预测的场景下亦能保持高效与稳健，显著缓解了传统僵化且脆弱的 GUI 自动化方案的痛点问题。
在此背景下，“基于 LLM 的 GUI Agent 架构与技术研究”具有深远的理论与实践意义。其理论价值主要体现在以下方面：
软件自动化理论方面：传统 GUI 自动化依赖硬编码规则或脚本，局限于：① 事先掌握控件结构与坐标；② 难以适应任务变动与上下文差异；③ 仅能服务单一目标应用。LLM 驱动的 GUI Agent 将自然语言理解、视觉分割／识别与策略决策机制整合进统一框架，以非侵入方式操控现有软件，并具备跨应用的泛化与自适应能力，突破了“规则先行”的旧范式，重新界定了“通用交互层”的理论边界，为软件自动化开辟了新的研究路径。
LLM 智能体理论方面：作为 LLM Agent 体系的关键支柱，GUI Agent 为“智能体自我进化”与“多智能体协作”提供了可观测、可评估的实验场域。负责视觉解析、任务拆分与异常恢复的多个智能体需协同作业，持续积累操作轨迹与领域知识，构建可检索的长期记忆，并利用其持续改进后续决策与操作表现。围绕其展开的相关研究将进一步丰富 LLM Agent 在认知建模、任务分解与协同决策等方面的理论框架。
具身智能理论方面：GUI Agent 让用户通过对话式指令即可完成应用操作，为通用 AI 在真实桌面与移动环境中的落地形态提供了前瞻示范；同时也推动了人机交互与广义人工智能融合路径的理论探索，为具身智能研究注入新动力。
GUI Agent 有望在重塑未来的人机协作与生产力格局，其实践价值体现在以下方面：
降低用户操作门槛：用户只需用自然语言描述高层目标，GUI Agent 即可自动完成原本繁琐的 GUI 操作流程；这对非技术用户尤为友好，能够显著提升工作效率，减少软件学习与技术支持成本。
为封闭软件提供自动化路径：GUI 几乎是所有桌面与移动应用共享的外壳。GUI Agent 能绕过私有接口壁垒，在无需源码或官方 API 的前提下，实现企业遗留系统的自动化与跨系统集成，立竿见影。
提升生产效率，催生新型工作流：财务对账、网页数据录入、图像批量处理等重复劳动可交由 Agent 全天候运行，让人类聚焦于决策与创新；测试自动化、RPA 等领域也将由此迈入新阶段。
加速“操作系统级虚拟助手（AIOS）”落地：随着模型推理加速与视觉能力提升，类似《钢铁侠》中的 J.A.R.V.I.S. 正从科幻走向商用，既可能颠覆消费级体验，也将重塑企业级桌面与移动办公形态。
推动跨平台、跨生态的智能功能构建：GUI Agent 让大模型在无需应用源码或开发者配合的情况下即可调度各类应用，助力模型快速适应长尾场景，并为“万物可调用”的智能生态奠定基础。
综上所述，GUI Agent 研究有望在软件自动化、LLM 智能体协同与具身智能三大方向的交汇处开辟全新的研究范式，为操作系统级虚拟助手及“万物互联”智能生态的构建奠定坚实的理论与工程基础。本课题具有显著的创新性，其理论价值与应用前景均十分突出。
所要解决的主要问题及研究途径与方法（预期思路或技术路线）

工作1：Fairy: Interactive Mobile Assistant to Real-world Tasks via Multi-agent Evolution。该工作已完成并处于 ASE’25 审稿阶段，研究了一种能够在执行任务中逐步积累App知识而持续进化的交互式多智能体手机助手，经过广泛的实证测试，Fairy是迄今为止表现最好的移动端GUI智能体之一。
工作2：Fairy V2。针对工作1的缺陷进行进一步改进。包括：改进基座模型策略，不同模块使用不同的基座模型，针对部分模型进行微调；改进Self-Study相关模块，结合RPA相关思想，基于执行日志构建可复用的自适应自动化流程，从而大幅提升速度；改进可访问树的容错与补全策略，确保在结构信息缺失时依然能可靠定位界面元素。@孙家正 
工作3：RealMobile-Eval V2（真实场景移动智能体评测体系）。目前Mobile Agent领域缺乏真实世界场景下任务的统一评估方法、基线和指标，工作3将考虑研究并推进相关建设，包括构建主流真实世界App应用的Mock版本，设计全面、公平、不依赖人工评估的指标体系，以支持研究社区的量化评估与对比实验。@孙家正 
工作4：Mobile Agent Security（移动智能体安全评估与缓解）。聚焦移动智能体在权限管理、数据隐私与提示注入攻击等层面的安全风险，力求在不显著增加延迟的前提下，为智能体提供安全防护能力。
工作5：Web Hybrid Agent（API × GUI 协同网页智能体）。通过历史网络请求日志分析，累积页面私有 API 知识库，并在执行阶段采用 API Agent 与 GUI Agent 混合编排的策略：优先通过调用API接口的方式完成用户任务，在API接口不足以完成时利用GUI进行兜底。在保证操作精度的同时，大幅降低长链路任务的平均时延。@陆勇雍 
工作6：Fairy Web（与Fairy同架构的网页智能体）。在沿用 Fairy 主框架的基础上，将 DOM 结构、视觉特征与语义内容进行统一建模，并重新设计原子动作，以使得Fairy可以适应Web任务。此外，将进一步针对Web页面特点，优化关键信息抽取相关算法。@夏晨笑 
工作7：CDP Agent（基于 CDP 的网页调试与测试智能体）。计划将 Chrome DevTools Protocol 利用 MCP 协议接入 LLM ，并据此设计Web调试Agent，实现对前端组件行为、网络请求、JS代码执行逻辑的综合分析；与 Fairy-Web 协同，为前端开发与测试流程注入端到端的智能化支持。
