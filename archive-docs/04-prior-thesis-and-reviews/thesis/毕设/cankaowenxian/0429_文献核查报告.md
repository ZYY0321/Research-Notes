## A.1 MGA: Memory-Driven GUI Agent for Observation-Centric Interaction

> ⚠️ **arXiv 编号已更正**：原报告填写的 `2502.13923` 是错误编号（2502 开头说明是2025年2月，但该论文2025年10月才发布）。正确编号为 **arXiv:2510.24168**。

- **arXiv**: arXiv:2510.24168
- **链接**: https://arxiv.org/abs/2510.24168
- **时间**: 2025-10（v1 2025-10-28，v3 2026-04-14）
- **作者**: Weihua Cheng et al.（通讯作者待核实）
- **机构**: 待核实（GitHub 标注，已提交 ACM MM 2026）
- **会议**: arXiv preprint（已投 ACM MM 2026）
- **Motivation**: 现有 GUI Agent 框架将整个任务轨迹拼接入上下文，导致错误积累和推理偏见。Agent 需要一种从观测出发、再决策的轻量级框架，而不是依赖越来越长的历史。
- **Contribution**: 提出 MGA（Memory-Driven GUI Agent），核心是"先观测后决策"原则。设计了两个紧耦合机制：(1) Observer 模块作为无任务意图的屏幕状态阅读器；(2) Structured Memory 将每个交互步骤压缩为验证过的状态差量（state delta），构造轻量状态转移链。在 OSWorld 及真实桌面应用（Chrome/VSCode/VLC）上取得有竞争力的结果。
- **与GUI Agent的关联**: 直接工作。MGA 的结构化记忆思路与"GUI 状态记忆"课题高度相关，其以观测为中心的状态表征方式可直接启发 state representation 设计。
- **⭐特别关注**: GUI Agent 专用记忆，UI state representation

## A.2 A-MEM: Agentic Memory for LLM Agents

> ✅ **已核实**：arXiv:2502.12110，真实存在。  
> ⚠️ **描述更正**：原报告描述错误，将 CoALA 的工作/情景/语义/程序四层架构误归为 A-MEM 的贡献。A-MEM 的实际贡献是 Zettelkasten 式记忆网络，与 CoALA 无关。

- **arXiv**: arXiv:2502.12110
- **链接**: https://arxiv.org/abs/2502.12110
- **时间**: 2025-02
- **作者**: Siyu Yuan et al.（Yongfeng Zhang 通讯）
- **机构**: Rutgers University
- **会议**: arXiv preprint（被引用为 NeurIPS 2025，待核实会议版本）
- **Motivation**: 现有 Agent 记忆是扁平的日志列表，缺乏内部组织和演化机制。随着记忆增长，检索质量下降，且旧记忆无法随新信息的到来而自动更新。
- **Contribution**: 受卡片盒笔记法（Zettelkasten）启发，A-MEM 在每条新记忆写入时自动分析它与已有记忆的关联，生成双向链接，形成图状记忆网络。引入 Memory Evolution 机制：新记忆可反向更新旧记忆（如"Alice 结婚了"会将旧记忆"Alice 是单身"标为过时）。检索时沿 link 扩散返回整个"概念簇"。
- **与GUI Agent的关联**: 可迁移。A-MEM 的记忆演化和图状组织可以迁移到 GUI Agent：每次访问一个 UI 状态时，可以自动建立与历史等价状态的链接，支持跨任务的状态识别。
- **⭐特别关注**: GUI Agent 专用记忆（可迁移）

## A.3 Memory in the Age of AI Agents: A Survey

> ✅ **已核实**：arXiv:2512.13564，真实存在，2025 年 12 月发布。

- **arXiv**: arXiv:2512.13564
- **链接**: https://arxiv.org/abs/2512.13564
- **时间**: 2025-12
- **作者**: （以 H 开头，具体待核实，来自 Tsinghua/NUS/HIT/复旦/中科院自动化所等联合）
- **机构**: 清华大学、新加坡国立大学、哈尔滨工业大学、复旦大学、中科院自动化所等
- **会议**: arXiv preprint
- **Motivation**: Agent 记忆研究发展迅速但极度碎片化，术语不统一，传统"长期/短期记忆"分类已无法描述现代系统的多样性。需要一个统一的分析框架。

- **与GUI Agent的关联**: 为 GUI Agent 记忆研究提供完整的理论背景。可以借用该综述的三维分类框架来描述和对比不同 GUI memory 方案的设计。

## A.4 Memory-Augmented State Machine Prompting (MASMP)

> ✅ **已核实**：arXiv:2510.18395，真实存在，2025 年 10 月发布。  
> ⚠️ **机构警告**：来自国防科技大学（NUDT）和南开大学，不在顶级机构优先名单内。但论文内容对 GUI state representation 有参考价值。

- **arXiv**: arXiv:2510.18395
- **链接**: https://arxiv.org/abs/2510.18395
- **时间**: 2025-10
- **作者**: Runnan Qi, Yanan Ni et al.
- **机构**: 国防科技大学（NUDT）、南开大学
- **会议**: arXiv preprint
- **Motivation**: 在 StarCraft II 等实时策略游戏中，LLM Agent 因无法维护跨决策周期的战略一致性而失败。需要将非马尔可夫决策环境下的 LLM 决策结构化。
- **Contribution**: 提出 MASMP 框架，将宏观策略建模为有限状态机（FSM），并引入轻量级战略记忆模块，跨决策周期持久化关键战术变量（如当前战术、优先单位）。在 StarCraft II Lv7 AI 对抗中胜率达 60%（baseline 为 0%）。
- **与GUI Agent的关联**: 可迁移。FSM + Memory 思想可用于 GUI 任务建模——将"预订机票"等长流程任务的各阶段建模为状态机节点，记忆围绕这些状态节点组织，与 UI state abstraction 高度相关。
- **⭐特别关注**: UI state representation / state abstraction（可迁移）

## A.5 ActionEngine — arXiv:2602.20502 ✅ 🆕2026

- **arXiv**: arXiv:2602.20502
- **链接**: https://arxiv.org/abs/2602.20502
- **时间**: 2026-02-24
- **作者**: Hongbin Zhong 等
- **机构**: 待核实
- **会议**: arXiv preprint
- **Motivation**: 现有 GUI Agent 每步调用 VLM 推理截图→动作→新截图，成本随步数线性增长，且无跨页面持久记忆，导致重复操作效率极低。
- **Contribution**: 提出 ActionEngine，两 Agent 架构：(1) **Crawling Agent**——离线探索 GUI，构建可更新的状态机记忆图（节点=页面状态，边=动作）；(2) **Execution Agent**——在线基于记忆图合成完整 Python 程序，无需逐步 VLM 调用。执行失败时触发 vision-based re-grounding 修复并更新记忆图。WebArena Reddit 任务成功率 95%，平均仅 1 次 LLM 调用，成本降低 11.8×，延迟降低 2×。
- **与GUI Agent的关联**: 直接工作。State Machine Memory 是 GUI 专用持久化记忆的具体实现，与 AppAgentX 的 Chain Memory 形成对比——前者为状态图，后者为操作序列链。
- **⭐特别关注**: GUI Agent 状态机记忆，training-free

## A.6 HyMEM — arXiv:2603.10291 ✅ 🆕2026

- **arXiv**: arXiv:2603.10291
- **链接**: https://arxiv.org/abs/2603.10291
- **时间**: 2026-03-11
- **作者**: Sibo Zhu, Wenyi Wu, Kun Zhou, Stephen Wang, Biwei Huang
- **机构**: UC San Diego, Abel.ai
- **会议**: arXiv preprint
- **Motivation**: 现有 GUI Agent 外部记忆依赖平铺的向量检索，缺乏结构化组织；记忆不会随新经验演化，无法支持多跳推理。

- **⭐特别关注**: GUI Agent 图结构记忆，自进化

## B.2 Agent S2: A Compositional Generalist-Specialist Framework for Computer Use Agents

> ✅ **已核实**：arXiv:2504.00906，真实存在，2025 年 4 月发布。  
> ⚠️ **原报告描述完全错误**：原报告将其描述为"诊断-归因-修复"的自我提升框架，这是完全捏造的。真实内容是 Mixture-of-Grounding 技术 + Proactive Hierarchical Planning。

- **arXiv**: arXiv:2504.00906
- **链接**: https://arxiv.org/abs/2504.00906
- **时间**: 2025-04
- **作者**: Saaket Agashe, Kyle Wong, Vincent Tu et al.（Xin Eric Wang 通讯）
- **机构**: Simular AI，UC Santa Cruz

- **Motivation**: 当前 GUI Agent 依赖单一 generalist 模型，在精确 grounding 和长程规划上存在瓶颈，难以处理多样化界面中的复杂任务。

## D.4 GUITester — arXiv:2601.04500 ✅ 🆕2026

- **arXiv**: arXiv:2601.04500
- **链接**: https://arxiv.org/abs/2601.04500
- **时间**: 2026-01-08
- **作者**: ADaM-BJTU 团队
- **机构**: 北京交通大学（ADaM Lab）
- **会议**: arXiv preprint
- **Motivation**: GUI Agent 在任务导向导航中存在"目标导向遮蔽"（Goal-Oriented Masking）——Agent 专注于完成任务而自动忽略界面异常；同时存在"执行偏差归因"（Execution-Bias Attribution）——将系统缺陷误判为 Agent 自身操作错误。两个问题共同导致现有 Agent 无法自主发现 App 缺陷。
- **Contribution**: (1) **GUITestBench**：首个交互式探索性 GUI 缺陷发现 benchmark，12 个 Android App，26 种真实缺陷，143 个导航任务（缺陷描述对 Agent 不可见，需主动发现并上报）；(2) **GUITester**：双模块多 Agent 框架——**PEM（Planning-Execution Module）** 在子任务中嵌入测试意图主动探测潜在缺陷；**HRM（Hierarchical Reflection Module）** 通过交互历史分析解决归因歧义，确认是系统缺陷而非 Agent 操作失误。F1 = 48.90%（Pass@3），超过最强基线 33.35%（UI-TARS 等）。
- **与GUI Agent的关联**: 直接工作。GUITester 将 GUI Agent 与探索性软件测试结合，PEM 的"主动探测"机制与 Bug-oriented exploration 思路完全一致；HRM 的归因分析对 fault localization 有直接参考价值。
- **⭐特别关注**: GUI Agent + 探索性缺陷发现，GUI Testing Benchmark
