GUI长期以来一直是人机交互的核心，它提供了一种直观的、视觉驱动的方式来访问数字系统并与之交互。传统上，GUI交互自动化依赖于基于脚本或规则的方法，这些方法虽然对固定的工作流程有效，但缺乏动态、真实世界应用所需的灵活性和适应性。
大型语言模型（LLM），尤其是多模态模型的出现，开创了GUI自动化的新时代。它们在自然语言理解、代码生成、任务泛化和视觉处理方面表现出了非凡的能力。这为新一代 "具有 LLM 智能 "的GUI Agent铺平了道路。
它们能够解释复杂的GUI元素，并根据自然语言指令自主执行操作。这些Agent代表了一种模式的转变，使用户能够通过简单的对话指令执行复杂的多步骤任务。它们的应用横跨网络导航、移动应用程序交互和桌面自动化，提供了一种变革性的用户体验，彻底改变了个人与软件的交互方式。这一新兴领域发展迅速，在研究和产业方面都取得了重大进展。
为了提供对这一趋势的结构化理解，本文对基于 LLM 的GUI Agent进行了全面调查，探讨了它们的历史演变、核心组件和先进技术。我们探讨了一些关键的研究问题，如现有的GUI Agent框架、用于训练专门GUI Agent的数据的收集和利用、为GUI任务量身定制的大型行动模型的开发，以及评估其有效性所需的评估指标和基准。此外，我们还研究了由这些Agent驱动的新兴应用。
通过详细分析，本调查报告确定了关键的研究缺口，并勾勒出该领域未来发展的路线图。通过整合基础知识和最新发展成果，本研究旨在指导研究人员和从业人员克服挑战，充分挖掘具有 LLM 内核的GUI Agent的潜力。我们希望本调查报告既能作为构建 LLM 驱动的GUI Agent的实用食谱，也能作为推动这一快速发展领域研究的权威参考资料。
1 INTRODUCTION
GUI一直是人机交互的基石，从根本上改变了用户在数字系统中的导航和操作方式。GUI旨在使计算更加直观和易用，它以视觉驱动、用户友好的环境取代了命令行界面（CLI）。通过使用图标、按钮、窗口和菜单，GUI让更多用户能够通过点击、键入和手势等简单操作与计算机进行交互。这一转变实现了计算机使用的平民化，使非技术用户也能有效地使用复杂的系统。然而，GUI往往牺牲效率而换取可用性，尤其是在工作流程中需要重复或多步骤交互，而 CLI 可以保持更精简的操作。
虽然GUI彻底改变了可用性，但其主要针对人类视觉交互的设计却给自动化带来了巨大挑战。GUI布局的多样性、动态性和平台特定性使得开发能够适应各种环境的灵活、智能的自动化工具变得十分困难。早期的GUI交互自动化主要依赖于基于脚本或规则的方法。虽然这些方法对预定义的工作流程很有效，但其范围本身就很狭窄，主要集中在软件测试和机器人流程自动化（RPA）等任务上。这些方法过于僵化，需要经常手动更新，以适应新任务、GUI布局的变化或不断发展的工作流，从而限制了其可扩展性和多功能性。此外，这些方法缺乏支持动态、类人交互所需的复杂性，因此限制了它们在复杂或不可预测场景中的适用性。
大型语言模型（LLM）的兴起，尤其是那些增强了多模态功能的 LLMs，已经成为GUI自动化的变革者，重新定义了Agent与GUI交互的方式。从 ChatGPT 等模型开始，LLM 在自然语言理解、代码生成和不同任务的泛化方面表现出了非凡的能力。视觉语言模型（VLM）的集成进一步扩展了这些能力，使这些模型能够处理视觉数据，如GUI的复杂布局。这种演变弥补了语言理解和视觉理解之间的差距，使智能Agent能够以更像人类和自适应的方式与GUI进行交互。利用这些进步，LLMs 和 VLMs 提供了变革性的潜力，使Agent能够浏览复杂的数字环境，动态地执行任务，并彻底改变GUI自动化领域。
1.1 Motivation for LLM-Brained GUI agents 动机
以 LLM 为 "大脑"，由 LLM 驱动的GUI自动化引入了一类新的智能Agent，它们能够解释用户的自然语言请求，分析GUI屏幕及其元素，并自主执行适当的操作。重要的是，这些功能的实现无需依赖复杂的、特定于平台的脚本或预定义的工作流程。
这些Agent被称为 "LLM-brained GUI Agent"，可正式定义为：
在GUI环境中运行的智能Agent，利用 LLM 作为其核心推理和认知引擎，以灵活自适应的方式生成、规划和执行操作。  
这种范式代表了GUI自动化的变革性飞跃，可在不同平台上促进动态的、类似人类的交互。它能够创建智能、自适应的系统，使其能够实时推理、决策，并灵活应对不断变化的任务和环境。
[图片]
图 1 举例说明了这一高层次概念。传统的GUI自动化通常受到预定义规则的限制，或仅专注于特定任务，从而限制了其适应动态环境和多样化应用的能力。相比之下，由 LLM 驱动的GUI Agent将自然语言理解、视觉识别和决策整合到一个统一的框架中，从而带来了模式上的转变。这使它们能够在广泛的使用案例中通用，改变任务自动化，显著提高人机交互的直观性和效率。
此外，与基于纯应用程序接口（API）的新趋势不同，GUI Agent依赖的应用程序接口可能并不总是公开或可访问的。GUI提供了控制大多数软件应用程序的通用机制，使Agent能够以非侵入方式运行，而无需访问内部应用程序接口。这种能力不仅拓宽了GUI Agent的适用范围，还使外部开发人员能够在现有软件的基础上，跨不同平台和生态系统构建高级功能。这些创新共同将 GUI Agent定位为未来智能自动化的多功能变革性技术。
这种新模式使用户能够通过对话指令控制一般软件系统。通过减少多步骤GUI操作的认知负荷，LLM 驱动的Agent让非技术用户也能使用复杂的系统，并简化不同领域的工作流程。著名的例子包括用于网络导航的 SeeAct、用于移动交互的 AppAgent，以及用于 Windows 操作系统应用的 UFO。
这些Agent类似于《钢铁侠》中的 J.A.R.V.I.S.的 "虚拟助手"——一种直观、自适应的系统，能够理解用户目标并自主执行跨应用程序的操作。人工智能驱动的操作系统能够流畅、精确地执行跨应用程序任务，这一未来派概念正迅速成为现实。
由 LLM 驱动的GUI Agent在现实世界中的应用已经出现。例如：
- Microsoft Power Automate 利用 LLM 简化了低代码/无代码自动化，使用户能够以最少的专业技术知识设计跨 Microsoft 应用程序的工作流程。
- Microsoft Copilot等生产力软件中集成的人工智能助手正在缩小自然语言指令与应用程序操作之间的差距。
此外，由 LLM 驱动的Agent有望提高可访问性，通过将自然语言指令转换为可执行步骤，视障用户可以更有效地浏览GUI。这些发展彰显了由 LLM 驱动的GUI Agent在各种应用中的时效性和变革潜力。
LLM 与GUI自动化的融合解决了人机交互中长期存在的难题，并为智能GUI控制带来了新的机遇。这种融合促进了研究活动的激增，涉及应用框架[Application Frameworks]、数据收集[Data Collection]、模型优化[Model Optimization]和评估基准[Evaluation Benchmarks]。尽管取得了这些进展，但主要挑战和局限性依然存在，许多基础问题仍未得到探索。然而，对这一迅速发展的领域的系统性综述却明显缺乏，在理解方面留下了关键的空白。
1.2 Scope of the Survey 调查范围

3 BACKGROUND
基于 LLM 的GUI Agent的发展有三大进展：
1. 大型语言模型 (LLM)，它带来了自然语言理解和代码生成方面的先进能力，形成了这些Agent的核心智能；
2. 配套的Agent架构和工具，它们扩展了 LLM 的能力，弥合了语言模型和物理环境之间的差距，从而产生了切实的影响；以及 
3. GUI 自动化，它培养了一套强大的工具、模型和方法论，对 GUI Agent功能至关重要。
这些组成部分中的每一部分都在由 LLM 驱动的GUI Agent的出现过程中发挥了关键作用。在下面的小节中，我们将简要概述这些领域，为我们的讨论做好铺垫。
3.1 Large Language Models: Foundations and Capabilities
语言模型的研究历史悠久，从早期的统计语言模型和较小的神经网络架构开始。在这些基础概念的基础上，最近的进展集中在基于Transformer 的 LLM，如Generative Pre-trained Transformers（GPT）。这些模型在广泛的文本语料库上进行了预训练，模型规模大得多，验证了扩展规律，并在广泛的自然语言任务中展示了卓越的能力。除了规模大，这些 LLMs 还表现出更强的语言理解和生成能力，以及较小规模语言模型所不具备的新兴特性。
早期的神经语言模型基于递归神经网络（RNN）和长短期记忆网络（LSTM）等架构，在性能和泛化方面都有局限性。建立在注意力机制基础上的 Transformer 模型的引入，标志着一个变革性的里程碑，确立了现在几乎所有后续 LLM 的基本架构。
这一发展导致了模型结构的变化，包括纯编码器模型（如 BERT、RoBERTa、ALBERT）、纯解码器模型（如 GPT-1、GPT-2）和编码器-解码器模型（如 T5、BART）。
2022 年，基于 GPT-3.5 的 ChatGPT 作为开创性的 LLM 推出，从根本上改变了人们对语言模型所能达到的目标的看法。此后，又出现了许多先进的 LLM，包括 GPT-4 、LLaMA-3 和 Gemini，推动了该领域的快速发展。如今的 LLM 具有很强的通用性，其中很多都能处理多模态数据，执行从问题解答到代码生成等一系列任务，成为各种应用中不可或缺的工具。LLM 的出现还引入了重要的先进特性，为其应用注入了活力，使以前具有挑战性的任务（如自然语言驱动的GUI Agent）变得可行。这些进步包括：
1. 少量学习（Few-Shot Learning）：LLM 也被称为 "上下文学习"，它可以在推理过程中从提示中展示的一小部分示例中获取新任务，从而消除了重新训练的需要。这种能力对于GUI Agent以最小的代价在不同环境中进行泛化至关重要。
2. 指令跟踪：经过指令调整后，LLMs 在执行新任务时会表现出非凡的指令遵循能力，显示出强大的泛化技能。这使 LLMs 能够有效地理解用户向GUI Agent提出的要求，并准确地遵循预定的目标。  
3. 长期推理：LLM 具备规划和解决复杂任务的能力，可将任务分解为易于管理的步骤，通常采用思维链（CoT）推理等技术。这种能力对于GUI Agent至关重要，因为许多任务都需要多个步骤和强大的规划框架。
4. 代码生成和工具利用：LLM 擅长生成代码和利用各种工具，如 API。这一专长至关重要，因为代码和工具构成了GUI Agent与环境交互的基本工具包。 
5. 多模态理解：先进的 LLM 可以将图像等其他数据模式整合到其训练过程中，从而发展成为多模态模型。这种能力对于GUI Agent尤为重要，因为它们必须解释以图像形式呈现的GUI屏幕截图，才能有效发挥作用。
为了进一步提高GUI Agent LLM 的专业化程度，研究人员通常会利用特定领域的数据（如用户请求、GUI截图和操作序列）对这些模型进行微调，从而提高它们的定制化程度和有效性。在第 8 节中，我们将深入探讨这些为GUI Agent量身定制的高级模型，讨论它们在与图形界面交互时的独特适应性和改进能力。
3.2 LLM Agents: From Language to Action
传统的人工智能Agent通常侧重于增强特定能力，如符号推理或擅长围棋或国际象棋等特定任务。与此相反，LLM 的出现改变了人工智能Agent，它为Agent提供了自然语言界面，使Agent具有类似人类的决策能力，并使Agent能够在不同环境中执行各种任务和采取实际行动。
在 LLM Agent中，如果说 LLM 构成了GUI Agent的 "大脑"，那么它的配套组件则充当了它的 "眼睛和手"，使 LLM 能够感知环境状态，并将其文本输出转化为可操作的步骤，从而产生有形的效果。这些组件将 LLM 从被动的信息源转变为代表用户执行任务的交互式Agent，从而将 LLM 的角色从纯粹的文本生成模型重新定义为能够驱动行动并实现特定目标的系统。
在GUI Agent中，Agent通常通过屏幕截图和部件树来感知GUI的状态，然后在环境中执行模仿用户操作（如鼠标点击、键盘输入、手机触摸手势）的动作。由于任务可能是长期性的，因此往往需要有效的规划和任务分解，这就带来了独特的挑战。
因此，LLM 驱动的GUI Agent通常具备多模态能力、强大的规划系统、分析历史交互的记忆机制，以及与环境交互的专用工具包。我们将在第 5 节详细讨论这些为GUI Agent量身定制的设计。
3.3 GUI Automation: Tools, Techniques, and Challenges
自GUI应用于计算机领域之初，GUI自动化就一直是一个重要的研究和应用领域。GUI自动化最初是为了提高软件测试效率而开发的，其重点是在图形应用程序中模拟用户操作，如点击、文本输入和导航，以验证功能。早期的GUI自动化工具旨在执行静态界面上的重复测试用例。这些方法简化了质量保证流程，确保了一致性并减少了人工测试时间。随着数字解决方案需求的增长，GUI自动化已从测试扩展到其他应用，包括 RPA和人机交互(HCI)。RPA 利用GUI自动化来复制业务工作流程中的人工操作，使常规任务自动化，从而提高运营效率。
同样，人机交互研究也利用GUI自动化来模拟用户行为，从而进行可用性评估和交互研究。在这两种情况下，自动化都能最大限度地减少重复性任务，提高系统适应性，从而显著提高工作效率和用户体验。传统的GUI自动化方法主要依赖于脚本和基于规则的框架。
- 基于脚本的自动化利用 Python、Java 和 JavaScript 等语言以编程方式控制GUI元素。这些脚本模拟用户在界面上的操作，通常使用 Selenium 等工具实现基于网络的自动化（测试），或使用 AutoIt 和 SikuliX 等工具实现桌面应用程序的自动化（测试）。
- 而基于规则的方法则基于预定义的启发式方法，使用规则来检测特定的GUI元素，并根据位置、颜色和文本标签等属性与之交互。
这些方法虽然对可预测的静态工作流有效，但却难以适应现代GUI的多变性，动态内容、响应式布局和用户驱动的变化使得维持严格的、基于规则的自动化具有挑战性。
CV 对于解释GUI的视觉方面至关重要，即使布局和设计发生变化，自动化工具也能识别屏幕上的元素并与之交互。CV 技术允许GUI自动化系统通过分析屏幕截图和识别感兴趣的区域来检测和分类屏幕元素，如按钮、图标和文本字段。
光学字符识别 (OCR) 通过从图像中提取文本内容进一步增强了这一能力，使自动化系统能够准确解释标签、错误信息和表单说明。对象检测模型增加了鲁棒性，即使视觉布局发生变化，自动化Agent也能定位GUI元素。通过结合 CV，GUI自动化系统在动态环境中实现了更大的弹性和适应性。
尽管取得了进步，但传统的GUI自动化方法在处理当代界面的复杂性和多变性方面仍有不足。当今的应用程序通常具有动态、自适应的元素，仅靠僵化的脚本或基于规则的方法无法实现可靠的自动化。现代界面越来越需要上下文意识，例如处理屏幕上的文本、解释用户意图和识别视觉线索。这些需求揭示了现有自动化框架的局限性，需要更灵活的解决方案来进行实时调整并做出对上下文敏感的响应。
LLM 为应对这些挑战提供了一个前景广阔的解决方案。凭借理解自然语言、解释上下文和生成自适应脚本的能力，LLM 可以实现更智能、更多功能的GUI自动化。
LLMs 处理复杂指令并从上下文中学习的能力，使其能够弥补静态、基于规则的方法与当代GUI动态需求之间的差距。通过将 LLM 与GUI Agent集成，这些系统获得了根据界面当前状态即时生成脚本的能力，提供了传统方法无法达到的适应性和复杂性。LLM与GUI Agent的结合为先进的、以用户为中心的自动化范例铺平了道路，这种范例能够灵活响应用户请求，并与复杂、不断变化的界面进行无缝交互。
