## 2. 原因词表

| 标签 | 定义 | 次数 | 优先级 |
|---|---|---|---|
| `DEVICE_OFFLINE_OBS` | 设备掉线或截图不落盘，导致所有观测 ENOENT | 9 | **P0** |
| `APP_NOT_INSTALLED` | 目标包未安装，`open_app` 静默落回桌面 | 2（CM 段实际 11 条都受影响） | **P0** |
| `TASK_SELF_CONFLICT` | 任务卡内部指令互斥（如"按返回收键盘"与"禁止返回键"） | 1 | **P0**（系统性风险，需全量扫卡） |
| `REACHED_NO_REPORT` | 目标已到达，但未调用 report_result | 1 | **P0**（直接压低成功率，属假失败） |
| `EARLY_STOP_NO_REPORT` | 多步任务中途停止且未上报 | 1 | P1 |
| `RUNTIME_BACK_FATAL` | BACK 被拦截后直接终止 run，而不是返回可恢复错误 | 1（与冲突卡同条） | P1 |
| `REPORT_SCHEMA_REJECT` | report_result 参数校验失败（reason 过长或含特殊字符） | 1+ | P1 |
| `TASK_AMBIGUOUS_TARGET` | 目标元素判定标准模糊（如"普通微博"） | 1（weibo 诱因） | P2 |
| `STATS_OBSERVE_ZERO` | 日志中有 observe 调用，但统计 `observeSteps=0` | 全量 | P2（度量 bug） |

## 3. 统一整改

### Runtime
1. **无 report 兜底**：模型结束回合但未调用 report 时，追问 1 次。仍不上报则用 final 截图做到页判定，并单独标 `reached_no_report`。
2. **BACK 拦截改为非致命**：返回错误后让模型继续，不再结束 run。
3. **观测健康熔断**：截图或观测连续 2 次失败时，判 `env_device_offline` 并立即终止该条，同时暂停队列等待重连。
4. **`open_app` 显式失败**：包不存在时返回 `app_not_installed`，并终止该条。
5. **report 参数容错**：reason 自动截断（如 ≤500 字）并做转义。
6. 修复 `observeSteps` 统计。

### 任务卡
1. **全量扫描**：grep "返回键" 与 "禁止按返回键" 是否在同一张卡中共存。冲突卡统一改为"键盘弹出即视为到达"，或改用"点击空白处收起"。
2. 多步任务补一句**到达判据**，例如"进入 XX 页即可 report"。
3. 写清目标元素的判定标准，并给出备选方案（"首条不符合可下滑寻找"）。

### 环境前置
1. 每批开跑前：`hdc list targets` 非空、`snapshot_display` 正常、对任务集涉及的全部包名做 `bm dump` 校验。缺包的任务直接剔除，不排队。
2. 跑批过程中每 N 条做一次设备心跳。

### 先不测 / 范围外
- **开源样例应用一律不测**（用户 11-25 定）：CoolMall（CM*）、葡萄广场（GRAPE*）等。
- 已跑的 CM 不计入到页成功率；`1125g` GRAPE 续跑已停，不纳入分母。
