### 4. 短路径 ≥14/15 最小动作（本周，最多 5 条）

1. **统一截图通道**：harmony_ux_detect 从 uitest screenCap 切 snapshot_display，消掉截图反馈弹窗这一最大噪声源。
2. **截图 fail-fast**：0 字节/不可解码直接判用例失败并重试 1 次，堵住 step_4/7 那类假通过。
3. **钉钉登录态预置 + 跑前自检**：登录从用例里剥离，回归入口断言“已登录”，不满足直接拒绝启动整批。
4. **高德卡删“移到太平洋”**：nav-high 收敛为单 POI 最短路径，减少一条必挂。
5. **deep 只放 1 条进本周回归**：deep-min 跑通再扩，其余 2 条挂起，别用 0/3 拉低分母。

> 这 5 条做完，15 条里真正的不确定性只剩手势与网络等待两项，14/15 才具备可解释性。

### 特别判断四问（各 2 句）

**1. 0 字节 png 算用例失败还是环境失败？**
算环境失败，但必须让用例**红**——静默通过是在给后面埋债。处理方式是环境层重试 1 次，仍失败则标记 `ENV_BROKEN` 并从分母剔除，不算产品缺陷。

**2. 钉钉未登录要不要挡住整批回归？**
要挡。未登录下的 nav 用例失败信息全是噪声，会把真实缺陷比例稀释掉。建议入口硬门禁：登录自检不过就不启动，宁可当天 0 条也不出假数据。

**3. deep 0/3 是用例写错还是通道没通？**
优先当通道问题。3 条同时全败、且 observe 链路本身还在用另一套接口，几乎可判定是入口/参数层不通，而不是 3 条用例都写错——先跑通 1 条最短的来证伪。

**4. 为了 14/15 要不要放宽断言？**
不要。放宽断言换来的绿是假的，下周会以更贵的方式还回来。正确顺序是先砍 B1、C1、C2、C3 四个确定性问题，剩下的自然收敛。
