# GUIAgent 设计文档参考资料归档

归档日期：2026-09-13

本目录记录本设计说明书采用的公开参考资料。参考资料用于确定文档结构、需求表达方式和 HarmonyOS 设计语境，不把参考资料中的示例直接当作本项目事实。

## 软件工程文档模板

来源：[软件工程常用文档模板](https://github.com/cuizhenjie/software-engineering-document)

访问日期：2026-09-13

采用内容：可行性分析报告应说明技术、经济和社会可行性，并比较候选方案；概要设计应描述功能分配、模块划分、总体结构、输入输出、接口、运行设计、数据结构和出错处理。本项目据此设置“功能需求、非功能需求、可行性分析、总体架构、接口、异常处理和验收设计”等章节。

## 软件需求规格说明书模板

来源：[IEEE 软件需求规格说明书模板](https://srs.pub/specification/srs-template.html)

访问日期：2026-09-13

采用内容：需求应写到足以支持实现和验证的程度，并为每项需求指定验证方法。本项目为功能需求增加输入、处理规则、输出和验收证据，为非功能需求增加测量口径和统计方法。

## HarmonyOS 设计规范

来源：[HarmonyOS 设计规范和指南](https://developer.huawei.com/consumer/cn/design/)

访问日期：2026-09-13

采用内容：本项目的被测对象是 HarmonyOS 多设备应用，设计范围使用手机、平板、折叠屏、多折叠设备、横屏和多窗口等设备语境；具体验收问题仍以项目验收单和冻结测试集为准。

## 参考资料与本项目章节对应关系

| 参考资料 | 本项目对应章节 | 使用目的 |
|---|---|---|
| 软件工程常用文档模板 | 功能需求、可行性分析、总体架构、异常处理 | 确定概要设计文档的组成 |
| IEEE SRS 模板 | 功能需求、非功能需求、验收指标 | 将需求写成可验证条目 |
| HarmonyOS 设计规范 | 建设背景、验收范围、多设备执行 | 统一 HarmonyOS 多设备语境 |

参考资料未提供本项目测试集、模型接口、设备地址或准确率结果；这些内容必须来自项目材料和实际运行记录。
