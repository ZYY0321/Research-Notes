## 一、项目当前要解决的问题

项目目标是让 GUI Agent 在 HarmonyOS 手机、平板、折叠屏或多折叠设备上，根据任务指令进入指定页面，然后对该页面进行多设备 UX 问题检测。任务链路应当是：读取任务，连接并识别设备，启动或复位被测应用，执行点击/滑动/输入等动作，采集截图和 UI dump，确认已经到达目标页面，再以目标页面的单张截图进行 UX 检测，必要时使用布局树或受控滑动做辅助验证，最后保存逐任务证据并计算验收指标。

这里有两个不能混淆的阶段。探索阶段允许 Agent 浏览应用，用于发现页面、记录控件、收集轨迹和构建缺陷样本；验收阶段从冻结的高级指令或低级指令开始，要求 Agent 按指令复现目标页面。到达页面以后才进入 UX 检测。因而“点到商品卡片”和“判断商品卡片是否存在截断”是同一个任务的前后两个阶段，分别对应导航能力和 UX 检测能力。

## 二、原始验收要求

当前工作区没有找到一份单独命名为“验收单”的 Word/PDF，但发现了原始标注材料 `图片和附件/第一阶段数据标注规则.pdf`（5 页，2026-07-31 生成）。下面的页面导航和性能要求来自 2026-09-08 至 2026-09-14 对话中提供的验收文字；下面的缺陷标签和标注边界来自这份 PDF。两部分已经同步到 `docs/GUIAgent多设备UX检测系统验收设计说明书.md` 和 `docs/验收对齐清单-需向对方确认.md`。如果团队另有正式验收 Word/PDF，应以团队文件的版本号和统计口径为准，再在本文件补充链接。

原始业务范围是 `top225app` 场景，目标是支持复现 80% 以上的多设备 UX 问题，问题范围包括大图大字、页面截断、视频或图片拉伸、未适配横屏、避让异常等。覆盖设备包括折叠、双折叠、三折叠、平板等。每个任务包含高级指令和低级指令：高级指令是整个任务的自然语言目标，低级指令是每一步具体动作。任务要求先到达指定页面，再判断页面是否有 UX 问题，若有则进一步判断问题类型。

验收指标原文口径如下：

| 指标 | 要求 |
|---|---:|
| 低级指令正确到达目标页面 | ≥95% |
| 高级指令正确到达目标页面 | ≥80% |
| 成功到达检测页面后，正确发现 UX 问题 | ≥95% |
| 每个动作平均响应时间 | ≤3 秒 |
| 单步最大响应时间 | ≤5 秒 |
| 排除网络和资源等非模型因素后，三层界面 UX 检测端到端时间 | ≤10 秒 |

“三层界面”的准确含义尚未在本地材料中找到正式定义。当前设计按“从任务指令开始导航，确认目标页后完成一次检测”的端到端链路记录，同时把动作、截图/UI dump、模型、布局验证和滑动验证分别计时。需要团队确认“三层”究竟指三层页面、三个屏态，还是检测流程中的三个阶段。

### 原始 PDF 中的标注口径

原始标注规则把问题分为“截断、遮盖、溢出”。截断是对象的一部分在图片边缘、应用视口边缘或父容器边界处突然消失，只剩不完整的可见部分；不可见部分不能推测性补框。截断标签包括 `截断-文字`、`截断-图标`、`截断-图片` 和 `截断-组件`，每个截断框至少选择一个方向：`top`、`bottom`、`left` 或 `right`。轻微截断和艺术字是 `截断-文字` 的可选标志；图标被截断但主体是文字时增加“文字”标志。组件只标注可交互组件，并遵守最小组件标注原则。

遮盖是可见前景元素叠在目标对象上，导致目标对象的一部分无法辨认或使用。遮盖标签包括 `遮盖-文字`、`遮盖-图标`、`遮盖-图片` 和 `遮盖-组件`。系统弹窗、音量弹窗、消息弹窗、底部导航条和键盘造成的遮盖添加“系统”标志；应用内正常遮盖添加“应用内正常”；无法判断时添加“不确定”。遮盖框标目标对象，不标前景遮挡物，除非前景物自身另有独立异常。

溢出是文字超出其应在的父容器、控件或布局槽位后仍然可见，常伴随压到相邻区域、超出卡片/按钮、无法换行或控件尺寸失配。溢出框标产生溢出的内容或异常元素本身，不框整个父容器；同一容器内多个独立溢出分别标注。语义上不完整但像素和笔画完整的文字不标截断，正常设计的角标、浮层、弹窗和文字叠图不标遮盖。

这份 PDF 对本项目有两个直接影响。第一，模型输出的 `issue_type` 不能只使用笼统的“UX 问题”，至少要能映射到截断/遮盖/溢出及对象类型；第二，截断方向是对象相对正常区域的边界方向，不是 bbox 在整张图片中的方位。当前代码的截断验证器主要覆盖文字截断和误报过滤，遮盖/溢出标签的正式映射仍需与团队测试集字段对齐。

## 四、代码已经具备的能力

### 4.1 设备和观察链

`src/runner.ts` 能接收旧格式任务，也能通过 `TASK_SPEC` 接收结构化任务规格；结构化规格支持 `instructionLevel`、`highLevelInstruction`、`lowLevelInstructions`、`targetPage` 和 `plan` 等字段，并会写入轨迹。执行器通过 HarmonyOS HDC/uitest 完成打开应用、点击、滑动、输入、按键和截图/UI dump。

`src/ux-detect-runner.ts` 支持 `--mode=image|layout|slide`。`image` 只进行单截图检测；`layout` 在模型结果后运行布局验证；`slide` 对仍为 unknown 的候选执行主动滑动验证。每次运行会生成独立目录，通常包含 `snapshot.png`、`snapshot_window.json`、`snapshot_ui-tree.txt`、`model_result.json`、`layout_result.json`、`slide_result.json` 和 `snapshot_ux.json`。

设备识别和屏态逻辑位于 `.opencode/lib/device-profile.ts`、`.opencode/lib/emulator-fold.ts` 和相关模块。代码已覆盖普通手机/平板、双折叠、宽折叠和三折叠的配置，优先使用 DevEco Emulator CLI，失败时有 hidumper 回退路径。折叠切换后必须重新建立截图和 UI dump 的 snapshot，不能继续复用切换前的数据。

### 4.2 Agent 模块

`src/agent/planner.ts` 提供长程任务的步骤状态和最大尝试次数；`src/agent/page-oracle.ts` 根据 pagePath、requiredIds、requiredKeys、requiredTexts 和 forbiddenTexts 判断是否到达目标页面；`src/agent/page-graph.ts` 用页面节点和动作边记录探索得到的转移；`src/agent/recovery.ts` 对 no_change、wrong_page、wrong_target 等失败生成重新观察、回到安全起点或终止任务的策略；`src/agent/runtime.ts` 将计划、Oracle、反思和恢复状态组合起来。

这些模块已经可以被离线测试调用，但它们不是一个完全替代大模型的导航器。当前实现更准确的描述是“结构化编排和验证控制器”：大模型仍负责根据观察选择具体坐标和动作，计划器负责步骤进度，Oracle 负责机器可判定的目标页确认，恢复模块负责有限重试。页面图谱还没有被探索运行自动写入并在正式验收中冻结使用。

### 4.3 UX 检测和截断验证

模型检测器负责从最终页面截图提出候选问题和 bbox，原始模型响应单独保存。布局验证器负责解析 ArkUI UI dump、统一坐标、绑定 Text 节点、查找祖先裁剪边界、识别 Scroll/List/Swiper/Tabs 语义、过滤固定覆盖层和省略号误报，并输出 `true_truncation`、`not_truncation` 或 `unknown`。

主动滑动验证只处理布局阶段仍为 unknown 的候选。它根据截断方向滑动，再检查同一节点的前后 bounds/origBounds；现有实现增加了恢复失败记录和整体屏幕恢复检查。恢复失败、截图失败或页面跳转时，候选不会被静默删除。

针对“UI dump 中父级边界看起来没有相交，但最终渲染图片中上层卡片覆盖标题”的情况，`verifier.ts` 已增加受限视觉几何兜底：模型框绑定到 Text，且模型框明显越过 Text 可见边界、同时没有可恢复滚动或明确 owner 时，输出 `true_truncation/model_bbox_overhang_without_layout_owner`。该规则只根据截图候选框和布局节点几何关系判断，不把源码中的 `translate` 当运行时真值。

第二，缺陷 App 和测试环境的责任边界还没有落到文件和版本号。需要团队提供缺陷 App HAP/源码/下载地址、bundle/ability、构建说明、工具或“创意工坊”的准确名称、DevEco/云真机/真机类型、HDC 连接方式、设备系统版本、折叠状态和账号权限。

第三，Agent 的结构化模块尚未完全接入真实动作循环。`runner.ts` 已能把任务规格发给大脑并记录，但真实 MCP 工具输出到 `PageObservation` 的字段适配、Oracle 每轮触发、计划推进、恢复动作执行和 page graph 自动写入仍需在实际任务中验证。

第四，lemon `/detect` 与当前 DashScope 兼容接口不完全相同。lemon 接收 multipart 图片和 `X-API-Key`，返回 `pred_json`；当前 runner 使用 OpenAI-compatible `/chat/completions`。如果正式验收指定 lemon，需要增加接口适配、超时、错误码、模型版本和坐标空间记录。

第五，截断算法仍有边界风险。UI dump 可能没有真实渲染层的遮盖关系；布局 bounds 可能是逻辑布局而不是最终像素；开合屏或页面切换会改变截图；多候选滑动恢复不一定回到同一基线；WebView、Canvas、自绘文字可能没有可绑定 Text 节点。对于这些情况，必须保留 `unknown` 和证据，不能通过源码推断或强行归类来制造准确率。

第六，性能尚未达标。一次完整设置页链路记录约 12 秒以上，尚未证明动作平均≤3 秒、单步≤5 秒或端到端≤10 秒。下一步应把 HDC screenshot、UI dump、模型请求和结果写入分段计时，并在不改变“模型只看一张截图”约束的前提下优化。

第七，SI-001 缺少数据前置，SI-003 缺少固定模型复跑；因此 sample 工程“三个缺陷全部通过”目前不能写入报告。

## 八、新窗口建议的执行顺序
