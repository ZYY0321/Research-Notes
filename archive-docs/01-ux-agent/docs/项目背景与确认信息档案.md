## 一、验收要求（来自任务书原文）

- 任务：GUIAgent 应用于多设备 UX 问题的高效检测工具
- 评测集：TOP225 应用典型场景，设计基线 3000 条轨迹
- **页面到达率**：低级指令 ≥95%，高级指令 ≥80%
- **UX 问题发现准确率**：到达目标页面后 ≥95%
- **动作响应时间**：平均 ≤3 秒，单步最大 ≤5 秒
- **端到端时间（三层界面）**：≤10 秒。【已确认我方口径 2026-09-20】模型一次约 3 秒（验收自建模型），**其余算法必须 ≤7 秒**（截图 / dump / layout / 滑动恢复）。TokenHub 现场慢不进这 7 秒。支付宝「我的」分组后滑动约 **4.9 秒**（1 组），还在 7 秒内；两组会超。
- 覆盖 UX 问题类型（任务书）：大图大字、页面截断、视频/图片拉伸、未适配横屏、避让异常

## 十二、模型角色与训练数据【已确认，2026-09-14，来自 CUA 会议纪要和实验细节】

### 12.1 两类模型的分工

| 模型 | 功能 | 状态 |
|---|---|---|
| **导航 VLM**（Navigation Agent） | 理解任务指令 → 规划步骤 → 调用 MCP 工具完成页面导航 | 使用现成大模型（TokenHub/DashScope），无需本项目训练 |
| **UX 检测 VLM**（UX Detection） | 页面截图 → 识别截断/大字/拉伸等问题 → 返回 bbox 和置信度 | 截断检测模型已训练；其余类型用通用 VLM 或占位 |

### 12.2 导航轨迹 SFT（来自 OpenMobile/CUA 方法论）

SFT 训练的目的：提升小模型在 HarmonyOS GUI 操作上的泛化性，减少对大模型 API 的依赖。

**训练数据构建流程（CUA 数据合成方法论）：**
1. **环境探索**：用强模型（如 gpt-5.6-sol）在真机/模拟器上自动探索 App 页面，生成页面图+UI树
2. **任务生成**：基于探索到的页面，用 LLM 批量生成自然语言指令（含高级/低级两种粒度）
3. **轨迹采集**：将指令喂入 HarmonyArena benchmark runner，强模型自动完成任务，录制每步截图+动作
4. **质量过滤**：保留模型自判"已完成"的轨迹（`harmony_report_result` 返回 success）
5. **SFT 格式化**：将每条轨迹转为对话格式（system prompt + 多轮 user/tool/assistant），训练小模型

**session 格式（来自实验细节文档）：**
```
System: <gui-orchestrator 系统提示>
User (turn 1): 任务描述 + 初始截图
Assistant: <thinking> + 工具调用（harmony_open_app / harmony_tap ...）
Tool: 工具返回（截图 + UI树）
Assistant: <thinking> + 下一步工具调用
...
Assistant (final): harmony_report_result { success: true, reason: "..." }
```

### 12.3 截断检测模型（已完成训练）

- 架构：VLM + bbox 回归，针对文字截断场景微调
- 数据：第一阶段 Labelme 标注（截断/遮盖/溢出，200张左右，含 JSON bbox）
- 输出：候选截断 bbox 列表（norm1000 坐标 + confidence）
- 在 pipeline 中作为 image 阶段的检测器，后续由 layout/slide 阶段做二次验证

## 十三、TypeScript 编译错误分析【已确认，2026-09-14，来自代码审查】

`tsc --noEmit` 报出以下错误，均为**类型层面问题，不影响 npm run benchmark 运行时**：

| 文件 | 错误类型 | 本质 | 风险 |
|---|---|---|---|
| `.opencode/mcp/harmony_*.ts` | `TS2322`（Zod schema 类型不兼容）、`TS7006`（implicit any） | Zod 版本升级后类型推断发生 breaking change，但运行时逻辑不受影响 | 低（可忽略） |
| `.opencode/lib/ui-dump.ts:362` | `TS2367`（`true === false` 永假） | 某个 enabled 字段类型被推断为 `true`，导致 `=== false` 死代码，实际不影响逻辑 | 无 |
| `src/runner.ts` | `.status`、`.part`、`.info` 不存在于 union type | runner 通过 `as any` 或可选链使用这些字段，TS 类型定义不够精确，运行时取不到时安全降级 | 低（可选链保护） |

> **结论**：不必修复这些错误再跑轨迹，benchmark 直接用 `tsx`（无预编译）可绕过 tsc 检查。
