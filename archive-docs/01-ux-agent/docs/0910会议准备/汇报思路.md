## 2. 新算法：不靠文字，绑稳定 id

问题：模型只给框。字被切成一条缝时，dump 的 `text` 可能空、残、或和邻居一样，**不能当主键**。

新算法（`HarmonyArena-fdu_agent/src/text-trunc-verifier/id-binder.ts`）：

1. 只收树上有 **`id` 或 `key`** 的节点。不用 `text`，不用 `originalText`，不用 `accessibilityId` 当主键（滑动后会变）。
2. 系统栏 / session 这类 id 丢掉。
3. 对每个候选算：`bbox ∩ bounds`、`bbox ∩ origBounds`。字只露一点时，可见 bounds 几乎没面积，**origBounds 还在**，靠溢出条命中。
4. 最高分唯一且过阈值 → 绑上这个 id。两个 id 分差 <10% → 不猜，交给 unknown。
5. **滑动后再绑**：只认同一个 id 字符串，不认 `node_index` / `hashcode` / 文案。

会上就讲：**模型给框 → id-binder 找 `goods_list_title_830010` 这类稳定 id → layout 再判可滚还是真 Clip。** 空框救不了（模型没报就没有候选）。

**原版不能动。** `verifier.ts` 已恢复，15 个旧测试全过。新逻辑只在：

- `src/text-trunc-verifier/id-binder.ts`
- `src/text-trunc-verifier/verifier-with-id.ts`（sidecar，调用原 verifier，再附 id）
- 实验：`scripts/showcase/id_bind_experiment.py`

**已经跑过的数（真 dump，81 个带 id 的标题，文案不参与）：** `docs/0910会议准备/id-bind-experiment.json`

| 扰动 | hit | miss | abstain |
|---|---|---|---|
| 框=可见 bounds，不挪 | 81.5% | 0 | 18.5%（全是横滑限时购两卡靠太近，`box_covers_two_titles`） |
| 平移 ≤32px | 81.5% | 0 | 18.5% |
| 平移 64px | 33.3% | 10.2% | 56.5% |
| 框放大 2.2 倍 | 81.5% | 3.7% | 14.8% |

结论（能上台讲的）：框贴着一张卡、中心偏不超过大约 32 像素，比较稳，而且这时 **没有绑错**。并排限时购会主动放弃（18.5%），避免把左边记到右边。偏 64 像素会开始绑错邻居，不能说稳。例子和「模型自己打的框」见 `showcase/explain.html`。

## 3. 链路三（必须讲完，含恢复）

代码：`HarmonyArena-fdu_agent/.opencode/lib/slide-verify.ts`  
门槛：layout 已是 `true_truncation` / `not_truncation` → **整段跳过，不滑**。只有 `unknown` 或没有 layout 结果才滑。

对每一条要滑的框，固定做完这 11 步，缺恢复就不算讲清楚：

1. 记下当前屏 `snapshot_before`（模型那张）。
2. 定方向：校园模型给 `truncated_edges`（right/bottom…），没有 `slide_direction`。适配：`adapt_issue` 按框扁/竖补 `left`/`up`；再没有就用框相对屏幕中心。
3. 起点 = 框中心。靠边则挪出系统手势带；靠近中缝则偏开，避免触摸丢了。
4. `uitest uiInput swipe` 沿该方向滑 **100**（norm1000）。
5. 停 **1000ms**，等列表停住。
6. 再截一屏 `snapshot_after`。截失败 → `capture_failed`，框先留着，仍要走恢复。
7. 同一 bbox 裁成灰度，算平均像素差。
8. **>5%** → `scrollable`：字跟着跑了，是可滚，**丢掉这条误报**。
9. **≤5%** → `confirmed`：滑了画面几乎不变，**确认截断，留下**。
10. **必须恢复：** 同一起点，反向再滑 100，再等 1000ms。评测下一条之前，页面要回到滑前。不做这一步，后面的 case 全废。
11. 恢复后如需举证，可再截 `snapshot_restored`。重绑只用第 2 节的 id，不用文案。

方向反义：`up↔down`，`left↔right`。实现就在 `getReverseDirection` + `performSwipeOnDevice`。

**10 条完整故事里，凡是真的滑过的，都必须带：滑前图、滑后图、diff、已恢复。** 只滑不恢复，会上不能讲。

真 Clip（父级固定高度 + Clip）预期：滑完 diff≈0，confirmed，再反向滑回去。  
可滚底切（京东「帅电乔」、青商城横滑限时购）预期：layout 已定性，**根本不进这 11 步**。

**意外（防误报，讲义第 6 节写全）：** 布局已定性则不滑，这是主闸。仍说不清时：框打在空白却画面不变可能误确认；绑到邻居会滑错卡；框里有倒计时/轮播会假差；滑到头了会把可滚当成真切；截图失败不该硬留下；差在 5% 附近应放弃不硬判；恢复失败应中止本页。合成 80% 和旧 crop 不能当这些风险已经关掉。
