## 2. 三链路总图

翻到「三链路总图」。

左边，链路一。输入是整页截图。校园检测模型在它认为被切的地方画框，并标注类型：文字、组件或图标。这一级不读取组件树，也不判断父级是否可滚动。类型只决定后级绑定目标：文字框绑定 Text 节点，组件框绑定卡片或容器。不在链路一按标签丢弃。没有候选框，后两级没有输入。

中间，链路二。把候选框绑定到 dump 树上的节点，沿父链查找第一道裁切边界，读取 clip、scrollable、滚动轴与溢出方向，输出三种结论。出口 A：`true_truncation`，确认为截断缺陷。出口 B：`not_truncation`，从缺陷列表移除。出口 C：`unknown`，证据不足，必须进入链路三。出口 A 今天仍然进入链路三做滑动取证，不是定性后跳过。

右边，链路三。滑动方向由该节点的溢出方向决定：右侧被裁则向左滑，底边被裁则向上滑。操作为一次松手滑动，截滑后图，并对同一个 id 重新 dump。比较该节点的 `origBounds` 与 `bounds`。溢出方向上仍超出可见区，保留为缺陷。仅当同一 id 在该方向上不再溢出、该节点完整进入可见区时，才作为可恢复误报移除。横向切换到下一张卡片，不满足移除条件。框未绑定到文字或卡片时，只否决该框。滑完沿反方向恢复页面。

## 3. 链路一：模型打框

## 4. 链路二：绑 id

翻到「id 绑定算法」。这是上次点名要的新模块 `id-binder.ts`，不是对未改动的 `verifier.ts` 的重新解释。

绑定规则如下。只收带稳定 `id` 或 `key` 的节点，例如 `goods_list_title_830010`。不使用 `text`、`originalText`、`accessibilityId`。系统栏、session 等通用 id 丢弃。若 Text 自身无 id，沿父链取最近的带 id 祖先（例如商品卡外层 Row），记为继承绑定。

对每个候选计算两项位置分数：bbox 与可见 `bounds` 的交叉覆盖，以及 bbox 与 `origBounds` 的交叉覆盖。`bounds` 是当前屏幕上可见矩形；`origBounds` 是组件声明的完整布局矩形，被裁切时伸出可见区。字形只剩一条缝时，`bounds` 面积接近零，靠 `origBounds` 溢出部分命中，方法记为 `id_orig_overflow`。

确认绑定的条件：最高分 ≥ 0.12，且次高分不超过最高分的 85%。不满足则放弃，不猜测。若同一 bbox 同时覆盖两个文字节点各超过 40%（限时购并排卡片），拒绝绑定，输出 `abstain`，避免把左卡截断记到右卡 id。

滑动之后重新绑定：只匹配同一个 id 字符串，不使用 `node_index`、hashcode 或文案。找不到该 id，记为绑定失败。模型没有输出框时，绑定没有候选，不能凭空生成节点。

左边图：蓝框是 `bounds`，黄框是 `origBounds`。缝状蓝框不是整行标题。右边图：红框同时压住两行标题各超过 40%，算法 `abstain`。真 dump 81 个带稳定 id 的标题：框贴合或平移 ≤32px，hit 81.5%、miss 0、abstain 18.5%，放弃全部来自并排两卡。平移 64px：hit 33.3%，miss 10.2%。

## 5. 出口 A：确认截断并保留

翻到出口 A，下面两张局部图。

绑定到节点之后，从该节点沿父链查找第一道产生裁切的边界，并检查该边界所在方向上，是否存在滚动轴与溢出方向一致、且仍有滚动余量的连续滚动祖先（List / Grid / Scroll 等）。若不存在这样的祖先，被裁切的字形无法通过连续位移进入可见区，判定 `true_truncation`。

第一种，`text_self_glyph_clip` 或卡片内局部 clip：Text 或父级容器宽高写死并 clip，`origBounds` 在某一方向上超出 `bounds`。左边推荐列表局部：红框是 830010 / 830011，「限时直」被卡宽裁死。830009（Ultra）同样右侧溢出 2412px，这张图模型漏了。父级 Grid 可纵向滚动，滚动轴是纵向、溢出是横向，下滚只换下一件商品。裁切边界在卡片固定宽度。出口 A，保留。

第二种，`context_switch_cannot_reveal_same_glyph`：最近的可滑祖先是横向 List / Swiper，滑动切换的是另一张卡片，不是把同一 id 的剩余字形平移进可见区。右边限时购，id `flash_title_830001`。`bounds` 宽 420px，`origBounds` 宽 1470px，右侧 overflow 1050px。横滑后该 id 仍然溢出 1050px。上一版写成 `not_truncation` / 可恢复，是错的。今天按出口 A 保留。

不要把这两类说成「页面不能滑」。页面可以滑；滑动不能让**同一个 id** 在溢出方向上消除 overflow。

## 6. 出口 B：排除误报

翻到出口 B。链路二要把「视觉上像切、布局上不是缺陷」的候选移除，避免误报进入链路三。

`full_visible_glyph_no_partial_clipping`：各方向 overhang 小于约 1px，`origBounds` 与 `bounds` 重合，字形完整。短标题页「Xiaomi 15」「MIX Flip 2」属于这一类。不要拿该页最顶一张已经滚出顶的卡当例子。

`out_of_scope_ellipsis_candidate`：`text` 以「…」结尾，且 `origBounds` 与 `bounds` 无真实溢出。这是 `textOverflow=ellipsis` 的设计结果，三个点是完整字形，不是容器 clip。短标题页「徕卡光学…」属于这一类。

`continuous_scroll_glyph_clipping_recoverable`：父链存在与溢出方向一致的 List / Grid / Scroll，且 `scroll_capacity.toward_end=true`。同一节点还能沿该方向滚进可见区。购物车「你可能还喜欢」底部那行只露出上半截，列表还能上滚，走这一支。限时购**不属于**这一类：父级可横滑，但滚动结果是换卡，同一 id 的 overflow 不消失。设置页「存储」只当口头负例，主屏不放图。

`fixed_overlay_background_occlusion_out_of_scope`：遮挡来自 TabBar、状态栏等固定浮层，目标节点在内容层。购物车推荐区被底栏切开时，TabBar 会进候选；本例因列表还能上滚，走的是可滚，不要把这张图讲成 overlay。

## 7. 出口 C，和同屏那棵树

出口 C 是 `unknown`。两种实现过的子类型：`no_matching_component`，框覆盖区域内找不到带稳定 id/key 的文字节点（打在 Image、空白、价签上），无法做父链分析；`ambiguous_clipping_owner`，父链上同时存在多种可能的 clip 来源（例如横向 clip 与纵向 List），方向关系冲突，不能确定裁切制造者。这两类必须进入链路三。

下面组件树是同一屏两处出口 A，裁切边界不同。上层：横向 List，`ListItem` 固定卡宽约 420px，`flash_title_830001` 的 `bounds` 宽 420px、`origBounds` 宽 1470px，右侧 overflow 1050px。下层：纵向 Grid，`goods_list_title_830009` 的 `bounds` 宽 738px，`origBounds` 宽 3150px，右侧 overflow 2412px。两处父级都 `scrollable=true`，但滚动轴都救不了横向溢出。两处都保留。

## 8. 链路三：怎么滑

翻到链路三。核心 1、核心 2 在解决范围内：文字框或组件框提出问题，布局定为真截断后，仍做滑动取证。

现场怎么滑，按实现说清楚。

不是按住不动再截图，也不是滑完再让模型重新打框。设备上执行 `uitest uiInput swipe`：从绑定框中心沿溢出反方向滑一段（规范坐标位移 100，约屏幕的十分之一），手指松开。等待约 1000ms，列表惯性停住，形成松手后的稳态。然后截一张滑后图，并对**同一个 id** 再 dump 一次。比较该节点滑后的 `bounds` 与 `origBounds`。不重新调用检测模型。

结案：溢出方向上 `origBounds` 仍超出 `bounds`，该文字或该张卡没有完整进入可见区，保留缺陷。仅当同一 id 在该方向上 overflow 消失、节点完整进入可见区时，才移除。换卡不算。框打在 Image 上未绑到文字或卡片，只否这个框。最后反向同样幅度滑回、松手、等停住。

若有人问「有的滑动必须按住才有效果」：判定用的是松手之后的稳态，不是按住时的瞬时画面。必须按住才能看到完整内容、一松手就弹回，稳态 dump 上 overflow 仍在，按真截断保留——用户正常浏览也不会一直按着看。不另立「按住才有效就一定有问题」的单独规则，和 overflow 是否消失是同一套结案。

## 12. 判定边界（被追问再展开）

被追问时说判定边界，不讲实现漏洞。

结案看同一 id 松手后的 overflow，不看框内画面变了多少。换卡、图跟着横条走，都可以画面大变而节点仍溢出，保留。

溢出在右侧就向左滑，在底边就向上滑，文字和组件同一套。父级滚动轴对不上时，overflow 不会消失，保留。

必须按住才露出完整内容的，看松手后的 dump：仍溢出则保留。

框内有倒计时、轮播，标 uncertain。恢复失败则中止本页。

## 13. 实验结果（有人要数字再翻）

翻表，不要把每一格念完。

构造 31 条，负例 10/10 干净，模型可以报文字也可以报组件，组件框也是有效输入。标准框交给布局规则，31/31 和预期一致，规则不依赖模型。

真商城去掉骨架页，7 条溢出标题命中 3 条。不要报 15/31，那串含 tb_ 骨架。合成滑动 80% 也不是实机，不当主数字。

绑 id：81 个标题，贴合和偏 32 像素以内，81.5% 命中、0 绑错。

现场滑动：核心 1、2 保留为缺陷；核心 3 将 Image 上的框从候选中移除。

一键：工程里 `npm run showcase` 跑 31 条，`npm run showcase:real` 跑真页。
