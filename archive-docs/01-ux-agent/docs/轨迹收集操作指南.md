# 轨迹收集操作指南

本文说明如何在本机鸿蒙模拟器上安装「HMOS代码工坊」，并用 HarmonyArena benchmark runner 自动收集 GUI Agent 轨迹。

## 1. 测试应用安装

测试应用源码目录：`/Users/zhangyingying/sample_in_harmonyos/`

包名：`com.huawei.hmos.sample`  
入口 Ability：`EntryAbility`

安装步骤：

1. 打开 **DevEco Studio**，选择 Open，打开 `/Users/zhangyingying/sample_in_harmonyos/`。
2. 等待工程 Sync 完成。
3. 将运行入口改为 **phone**（手机 / 折叠屏 / 平板）。
4. 连接本机鸿蒙模拟器，按提示完成签名。
5. 菜单选择 **Build → Build HAP/APP**，编译完成后安装到模拟器。
6. 也可直接点击运行，等待编译并部署到模拟器。

安装后可用下面命令确认包已在设备上：

```bash
hdc list targets
hdc shell bm dump -a | grep com.huawei.hmos.sample
```

## 2. 运行 benchmark 收轨迹

```bash
cd /Users/zhangyingying/UX-Agent/HarmonyArena-fdu_agent
npm install
npm run benchmark -- --tasks benchmarks/hmos-codeworkshop-tasks.json --name hmos-ux-run1
```

前置条件：

- Node.js 20+
- `PATH` 中已有 `hdc` 和 `opencode`
- 模拟器已启动且 `hdc list targets` 能看到设备
- `opencode.json` 中的视觉模型可用，并已配置 `DASHSCOPE_API_KEY`

任务文件 `benchmarks/hmos-codeworkshop-tasks.json` 共 28 条，覆盖组件、样例、实践、我的四个模块；高级指令与低级指令各 14 条。

## 3. 轨迹输出位置

一次运行会在项目根目录下生成：

```
results/hmos-ux-run1-<timestamp>/
  benchmark-results.jsonl
  summary.txt
  <task-id>-<startedAt>/
    artifacts/          # 每步截图与页面观察
    <task-id>.json     # 该任务的动作序列
    runner.log
```

对应关系：

- 运行目录：`results/hmos-ux-run1-<timestamp>/`
- 单任务产物：`<task-id>-<startedAt>/artifacts/`
- 每步截图：`step_N.png`（另有 `step_N_agent.jpg`、`step_N_window.json`、`step_N_ui-tree.txt`）
- 动作记录：任务目录下的 `<task-id>.json`（工具步骤列表，JSON Lines 语义上等价于动作轨迹）

## 4. 轨迹数据格式

一条轨迹 = 一条自然语言指令 + Agent 完成任务的每步操作（截图 + 动作）。

动作文件示例（`<task-id>.json` 中的一步；也可按行拆成 `actions.jsonl`）：

```json
{
  "step_id": 2,
  "tool": "harmony_tap",
  "input": {
    "x": 180,
    "y": 960,
    "reason": "点击底部组件页签"
  },
  "screenshot": "step_2.png"
}
```

完整任务动作文件结构如下：

```json
{
  "id": "hmos-button-detail-low",
  "task": "打开 HMOS代码工坊，点击底部「组件」页签，再点击「Button」，进入按钮组件详情页。",
  "steps": [
    {
      "step_id": 1,
      "tool": "harmony_open_app",
      "input": {
        "app_name": "HMOS代码工坊",
        "reason": "启动被测应用"
      }
    },
    {
      "step_id": 2,
      "tool": "harmony_tap",
      "input": {
        "x": 180,
        "y": 960,
        "reason": "点击底部组件页签"
      }
    },
    {
      "step_id": 3,
      "tool": "harmony_tap",
      "input": {
        "x": 500,
        "y": 420,
        "reason": "点击 Button 卡片"
      }
    },
    {
      "step_id": 4,
      "tool": "harmony_report_result",
      "input": {
        "success": true,
        "reason": "已到达 Button 组件详情页，可见预览区和属性调整区"
      }
    }
  ]
}
```

坐标使用 0–1000 屏幕空间。`harmony_tap`、`harmony_swipe`、`harmony_type_text`、`harmony_press_key`、`harmony_open_app` 均会写入动作列表，并在对应步骤目录留下截图。

## 5. 常见问题

### 模拟器未连接

现象：`hdc list targets` 为空，或 benchmark 报设备不可达。

处理：

1. 确认 DevEco Studio / 模拟器管理器中模拟器已启动。
2. 再次执行 `hdc list targets`。
3. 若有多个设备，可指定目标：

```bash
export HDC_TARGET=<device-id>
```

### App 未安装

现象：Agent 调用 `harmony_open_app` 后焦点不在 `com.huawei.hmos.sample`，或 `bm dump` 找不到该包名。

处理：

1. 按第 1 节重新编译并安装 phone HAP。
2. 确认运行入口是 **phone**，不要误装 wearable / tv。
3. 安装后再跑：

```bash
hdc shell aa start -b com.huawei.hmos.sample -a EntryAbility
```

### 模型 API key 缺失

现象：OpenCode / UX 检测报鉴权失败，或提示需要 `DASHSCOPE_API_KEY`。

处理：

1. 在运行环境中设置：

```bash
export DASHSCOPE_API_KEY=sk-your-key-here
```

2. 确认 `HarmonyArena-fdu_agent/opencode.json` 使用 `{env:DASHSCOPE_API_KEY}`，且默认模型为带视觉能力的 `dashscope/qwen3.6-plus`。
3. 重新执行第 2 节的 benchmark 命令。
