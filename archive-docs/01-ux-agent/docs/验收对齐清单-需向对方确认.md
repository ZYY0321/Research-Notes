# 明日验收对齐清单（会议版）

更新时间：2026-09-14  
用途：和测试集、缺陷 App、设备及模型服务负责人一次性锁定输入；不是验收结果。

## 会议目标

明天结束前至少拿到一份可安装 App、两条低级任务、两条高级任务、一个目标页面规则、一个正例和一个负例真值截图、一台已解锁设备。正式数据规模按 3000 条轨迹作为设计基线；拿到最小集即可先跑“任务 → 页面 → 截图 → 模型 → 结果”冒烟，避免等全量数据到位后才发现接口不一致。

## P0：不确认就不能正式跑

| 项目 | 必须确认的字段 | 对方负责人 | 会议结果 |
|---|---|---|---|
| 缺陷 App | HAP/源码地址、bundle、ability、版本、安装方式、是否需要登录/预置数据 | 待指定 | ☐ |
| 设备环境 | 真机/模拟器型号、系统版本、分辨率、HDC ID、解锁状态、调试权限 | 待指定 | ☐ |
| 屏态范围 | single、dual、triple、half-fold、横屏哪些是必测；每条任务对应哪些屏态 | 待指定 | ☐ |
| 正式测试集 | 文件路径、任务总数（设计基线 3000 条轨迹）、版本号、冻结日期、是否包含高/低级指令 | 待指定 | ☐ |
| 页面真值 | pagePath/id/key/text 规则；截图人工确认方式；相似页面如何排除 | 待指定 | ☐ |
| UX 真值 | 截断/遮盖/溢出/拉伸/避让等标签、bbox 格式、标注人、真值版本 | 待指定 | ☐ |
| 模型服务 | URL、模型名/版本、鉴权、请求格式、坐标空间、超时、fallback 是否允许 | 待指定 | ☐ |
| 三层界面 | 三层页面、三种屏态还是“模型/布局/滑动”三个阶段 | 待指定 | ☐ |

## P1：不确认会影响统计或复现

| 项目 | 需要确认 | 当前建议 |
|---|---|---|
| unknown | 是否单独报告、是否进入 UX 分母、是否允许主动滑动 | 保留 unknown，单独报告，不静默算 TN |
| 重试 | 模型/设备/导航失败各重试几次，重试是否算新任务 | 每次重试新 runId，原失败保留 |
| 环境失败 | 锁屏、网络、资源不足、数据缺失如何归类 | 单独记环境失败，不写成模型漏报 |
| 复位 | 清数据、回 Home、关输入法、恢复屏态的操作和责任 | 默认 relaunch + 回 Home |
| 性能 | 动作、观察、模型和端到端的起止点；网络/资源如何排除 | 全部分段记录，排除项不删除 |
| 轨迹微调 | 回放、提示词优化、检索、行为克隆、grounding 训练还是 LoRA；qwen3.6 endpoint 是否支持微调 | 默认先采集/清洗/回放；训练作为条件性增强 |
| 轨迹数据 | 3000 条是否全部盲测；若拆分，Train/Validation/Test 比例及按应用/页面去重规则 | 默认 2400/300/300，需对方确认 |
| 数据责任 | 谁提供、谁标注、谁批准冻结，最晚交付日期 | 会议现场写 owner 和日期 |

## 可直接发送的消息

您好，我正在整理 9 月 15 日设计文档和 9 月 30 日验收材料。为避免设计口径和正式测试集不一致，请统一提供：缺陷 App 安装包/仓库及版本、bundle/ability 和构建说明；实际使用的平台/工具名称、入口和权限；真机/模拟器型号、系统版本、折叠状态和 HDC 连接方式；测试集文件及高级/低级指令、目标页面规则；UX 问题人工标注、bbox 和 unknown 规则；模型服务地址/版本、鉴权和坐标空间；页面到达率、UX 准确率、响应时间的统计口径，尤其是 unknown、重试、环境失败和网络耗时如何处理。若完整测试集暂时未准备好，请先提供两条高/低级任务和一台已解锁设备，我们先跑通接口和证据归档。

## 补充 P0：当前版本遗漏的关键问题

> 以下条目在原有清单中未覆盖，但不确认则无法独立搭建环境、完成算法或收集轨迹。

| 项目 | 必须确认的字段 | 对方负责人 | 会议结果 |
|---|---|---|---|
| 独立搭环境 | DevEco Studio 版本号、模拟器镜像版本（ROM）、HDC 工具版本、推荐的 SDK API Level；能否脱离测试同学那台机单独跑通 | 待指定 | ☐ |
| 缺陷 App 来源 | App 是人工注入缺陷还是真实采集？HAP 包放在哪个仓库？是否需要特定系统版本才能复现缺陷？ | 待指定 | ☐ |
| 导航模型服务 | 高级指令模式用的是哪个 VLM / API？URL、鉴权方式、坐标返回格式；我方是否有独立调用权限还是必须走测试侧 | 待指定 | ☐ |
| UX 识别模型服务 | 检测大图大字/截断/拉伸用的模型是否与导航模型相同？输入格式（截图 base64 还是 URL）、输出 schema | 待指定 | ☐ |
| 轨迹收集责任方 | 3000 条轨迹谁来收？测试侧还是我方？若我方需收，现有收集工具是什么？是强模型跑还是人工录制？ | 待指定 | ☐ |
| 轨迹数据格式 | 单条轨迹包含哪些字段（task_id / instruction / steps[]：screenshot+action+state / page_result / ux_result）？有无格式示例或 schema 文件？ | 待指定 | ☐ |
| 真值标注方式 | UX 问题真值是预先人工标注（随 App 一起交付）还是验收时现场比对？标注文件在哪？格式是 JSON/CSV？ | 待指定 | ☐ |
| 算法参考资料 | 视觉+结构融合检测、避让判定、跨屏态比对等算法有无内部文档、相关论文、或可参考的已有实现？ | 待指定 | ☐ |
| 轨迹微调数据用途 | 收集的轨迹是用于 SFT 训练导航模型还是仅用于构建评测集？若用于训练，Train/Test 切分规则是？ | 待指定 | ☐ |
| 验收报告提交格式 | 验收报告是 JSON/Markdown/Excel？需要提交哪个系统/平台？截图命名规范？ | 待指定 | ☐ |
