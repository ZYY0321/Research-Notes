# 我们在干什么

在 HarmonyOS 真机上自动检测 App 有没有文字 / 组件 / 图标截断。  
人负责：把 App 点到和参考图同一类页面，说一声"好了"。  
程序负责：截图、读布局树、滑一下、告诉你这页有没有截断。

目前只测**截断**这一类（文字 / 组件 / 图标）。拉伸、横屏、大字这些还没做。

**2026-09-21：没有 XML 的 case 不跑端到端（不连真机滑、不 dump）。只测测试集里带 `.xml` 的；没有 XML 的交给模型判断。** 说明：[有XML才端到端.md](有XML才端到端.md)。

---

## 你要干的三件事

**1. 把设备连上**  
USB 直接插，或按下面的表远程连茶思屋。连上之后跑 `hdc list targets` 能看到设备 id 就行。折叠屏用手折好，不要用命令切内外屏。

**2. 把 App 点到和参考图（GT）同一类页面**  
程序会告诉你去哪个 App、大概什么页。点到差不多就说"好了"。字可以不一样（账号不同、feed 内容会变），只要是同一类截断就行。  
如果页面差太多（弹出了分享弹窗、账号完全不对），说"作废"，跳下一条，不算算法的锅。

**3. 说"好了"之后等结果，记进 run-log**  
程序跑完会告诉你这页过了还是没过，以及用了多少秒。  
**过了写短的即可。挂了或 unknown 不能只写过/不过：** 要写清是模型、layout、滑动还是回滑的问题，什么情况，后面怎么改，并把 dump、滑后图、恢复图路径写上。模板见 [失败要写清问题和证据.md](失败要写清问题和证据.md)。  
测之前先 `git pull`，保证是最新算法。

## 设备怎么连

| 屏 | 前缀 | 在哪 | 连法 |
|---|---|---|---|
| 双折叠（Mate X5） | `bifold_*` | USB 手头 | 直接插 |
| 平板 | `tablet_*` | USB 手头 | 直接插 |
| 直屏 | `phone_*` | 茶思屋 | 远程桌面 → HDC |
| 三折叠 | `trifold_*` | 茶思屋 | 远程桌面 → HDC |
| 阔折叠（Pura X Max） | `widefold_*` | 茶思屋 | 远程桌面 → HDC |

茶思屋在新江湾莱蒙国际中心 B 座 15F，设备已经插在那台 Windows 上。**用 ToDesk 连，不要再找 VPN。** 设备码、临时密码、锁屏 PIN、解开后点哪：见 [茶思屋ToDesk连接.md](茶思屋ToDesk连接.md)（截图 [远程设备连接方法.png](远程设备连接方法.png)）。

多台设备同时插时：
```bash
hdc list targets           # 看有几台
export HDC_TARGET=<id>     # 指定用哪台
```

折叠屏不要用 `hidumper` 命令切屏，直接用手折就行。

## 跑检测

在 `HarmonyArena-fdu_agent` 目录里：

```bash
set -a && source .env && set +a
npm run ux-detect -- --mode=slide
```

如果有多台设备：先 `export HDC_TARGET=<id>` 再跑。

有校园网（10.176.44.15 能通）时走官方检测接口，大约 3 秒出结果。没校园网时走 `.env` 里配的备用接口，会慢一些，慢的部分不算进验收的 10 秒。

校园网接口直接用 Python 测：
```python
import requests
response = requests.post(
    "http://10.176.44.15:8000/detect",
    headers={"X-API-Key": "4a4b88cd2cde994f5d41dace91205d23727a2c15b636cd7e8ecf9a9bb7bfcf87"},
    files={"image": open("test.jpg", "rb")},
    timeout=600,
)
print(response.json()["pred_json"])
```

## 什么叫"过"

**页级过** = 这一屏没有「滑了也看不到的截断」。

- 列表底部被切掉，滑一下就露出来 → **过**（可以恢复的不算缺陷）
- 文字被裁掉、滑了还是看不完整 → **不过**
- 弹窗后面的字被挡住，不是字本身截断 → **不算截断，过**
- 省略号（...）→ **不算截断**

## 参考图（GT）在哪

只用 `测试集/整理`，这是最新版带标注的（9月19日更新，有 Labelme JSON）。  
`整理 2` 和 `整理_older` 是旧包，没有 JSON，不要用。

判定标准：同名 `.json` 的 `正常图=true` 且无框 = 负例；有框 = 正例。  
文件夹名和 json 有时会打架，以 json 为准。

## run-log 怎么记（两个人都维护这一个文件）

文件：`docs/20260919-测试集存档/case-run-log.md`  
GitHub 上共享，**每次写之前先 `git pull`**，写完就 `git push`，避免撞车。

每测一条追加到文件末尾，格式：

```
### BF-美团-G03-S2（或你自己的简称）
- GT：测试集/整理/bifold_image_truncated/meituan/g03/...jpg
- 现场图：HarmonyArena-fdu_agent/ux-detect-output/<时间戳>/snapshot.png
- 页级：ok / bad / unknown / 作废
- 人眼：写一句为什么（例如：和GT同类底切，算法可滚消解通过；例如：环境不对弹了分享窗作废）
- 算法秒数：（写数字，没跑就写"未跑"）
```

只追加自己的段落，不要改别人已经写的那些。挂了按 [失败要写清问题和证据.md](失败要写清问题和证据.md) 把证据路径写全。

## 改代码的底线（合作期间）

- 筛查阶段不要改代码，只记录
- 要改算法时先说一声，确认不会打掉已过的 case（支付宝 g01–g03、番茄 g02/g03、小红书 g01、B 站 g01–g03、美团 g01–g02）
- 截图必须用 `snapshot_display` PNG，不要用 jpeg 或系统截屏（美团会弹分享窗）
- 改完用一句话说清改了什么，加进 run-log 的"算法改动"段落，并 **push**，让对方测到最新代码
