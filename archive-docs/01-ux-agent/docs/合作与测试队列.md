## 怎么合作（结论）

**先筛查，再真机测，改代码最后。**

第一阶段：合作方先做**筛查**，不用连设备。看每条 case 的 GT 图，把预判（大概会过 / 会挂 / 不确定）记进 `case-run-log.md`（格式见 `docs/给AI.md`）。筛完之后再决定哪些 case 优先上真机。

第二阶段：两人按设备并行测。双折叠 USB 和平板 USB 不冲突，茶思屋的三台远程机先在队列里占坑再连。

**不要两人同时改同一段判定代码。** 判定、滑动、串起来只有三份核心文件，合并时很容易打掉已过的 case。有失败单了再开 `fix/<短名>` 分支。

必须同步远端：每次改了文档或算法就 push，测之前先 pull。合作方筛查/真机不只记过不过，要能看出算法哪有问题、什么情况、证据在哪。
