# CoolMallArkTS 复杂验收任务集设计说明

本任务集以 `apps/CoolMallArkTS` 的实际源码和仓库中已经移植的淘宝迁移测试页为依据，模型调用配置为 `qwen3.6-flash`。任务输入同时保留高级指令、低级指令、可执行 journey 和 target_rules，执行器可以据此区分“要完成什么”和“每一步怎样到达页面”。所有任务的真值字段只表示构造来源或待标注状态，不把模型一次运行结果当作事实标签。

任务集前半部分覆盖商城真实业务页面：搜索页支持输入、搜索历史和推荐词，分类页支持价格区间、分类筛选、综合、价格和销量排序以及网格/列表布局切换，商品详情页支持评论、服务、富图、优惠券和规格选择弹层。路径刻意加入回退、失败后恢复、重复打开模态、键盘焦点、长列表上下滑动和多候选文本消歧，使目标页到达与单截图检测同时受到考验。折叠设备任务保留 `needs_preflight`，因为大屏左右布局需要在目标模拟器上确认后才可纳入统计。

任务集后半部分进入 `TbHomePage` 的“切开样例”页面。页面源码明确提供十种不同裁切机制，包括父容器右切、固定行高切字、窄列横切、半宽店名、按钮文案、两行末行、嵌套弹层标题、价格挤压、图标后剩余宽度和卡片底切价格，并提供系统省略号与完整短标题两个负例。每个机制既有直接单屏判定任务，也有滚动复核、候选消歧或控件语义区分任务；负例标记为 `source_expected`，真实缺陷标记为 `constructed`，复合场景标记为 `needs_annotation`，这样可以在不把预期当作模型准确率的前提下进行统计。

2026-09-16 在同一页追加 8 个边界样例（任务 CM051–CM058）：正常两行换行、相邻双标题消歧、大字压住购买按钮、大字被矮槽切掉、占位图拉伸、假键盘挡住提交、无 clip 溢出、角标遮盖标题。用来把截断、溢出、遮盖、大图大字、拉伸、避让拆开，不能把它们都打成截断。新样例需重新编译 CoolMall 后才能在模拟器上看到。

任务 DSL 仅使用 `launch`、按可见文本或 key 定位的 `click`、中部 `scroll`、`back`、`input`、`observe` 和少量归一化 `click_xy`。淘宝迁移首页的左上 Logo 是进入 `TbHomePage` 的源码入口，切开样例使用 `tb_tab_fault` key；未在源码中实现的结算提交、虚构商品详情和外部网络功能没有写入任务集。完整机器可读任务保存在 `HarmonyArena-fdu_agent/benchmarks/complex50/tasks.json`，其中包含 50 条任务、难度原因、目标规则、变体和真值来源。

推荐验收时先运行前三十条真实商城任务，确认模型能够在搜索、筛选、详情、弹层和回退链路中稳定到达目标页，再运行后 20 条截断场景中的单截图判定。正式统计应分开报告页面到达率、单截图缺陷发现率、负例误报率、恢复成功率和每步时延；`qwen3.6-flash` 的响应内容只能作为预测结果，必须和源码构造标签或人工复核结果分别保存。
