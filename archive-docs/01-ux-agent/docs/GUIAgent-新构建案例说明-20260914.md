# GUIAgent 页面找寻与缺陷检测

## 新构建案例说明（V01–V16）

日期：2026-09-14  
版本：local-ux-lab-v2  
适用范围：页面找寻后的 UX 缺陷检测逻辑验证、案例复现与验收输入对齐

## 1. 交付结论

本阶段新增 16 个独立案例，覆盖方向性裁切、控件文本、弹窗、键盘层、横滑同组件、固定遮挡、图片文字、正常换行、组件歧义、折叠态重排、WebView/Canvas 以及滑动恢复失败等场景。

| 统计范围 | 结果 | 成功率 | 统计定义 |
|---|---:|---:|---|
| V01–V16 新构建复现集 | 16 / 16 | 100% | 最终 verdict 与案例期望一致 |
| 真实页面探索集 | 17 / 33 | 51.5% | 正例命中或负例保持干净 |
| 页面找寻复杂任务预检 | 29 / 50 | 58.0% | 目标页面 Oracle 到达 |

三类结果不得合并为单一“模型准确率”：第一项验证后验检测逻辑，第二项反映真实页面识别能力，第三项反映导航链路到达能力。

## 2. 处理链路

1. **页面确认**：导航执行后重新采集页面状态，使用关键文本、稳定 id/key 和页面结构确认目标页已到达。
2. **视觉候选**：qwen3.6-flash 对截图提出缺陷候选框，候选框使用 norm1000 坐标。
3. **布局绑定**：将候选框映射到布局树节点，仅使用稳定 id/key 作为组件身份；比较 visible bounds 与 origBounds，判断是否为自身内容裁切。
4. **滑动复核**：仅当布局证据不足时进入滑动；对滑动前后同一 id/key 做对比，记录 diff、动作方向、距离和 restore_ok。
5. **结论输出**：输出 `true_truncation`、`not_truncation` 或 `unknown`，并保留 subtype、evidence 和恢复结果。

## 3. 逐个案例说明

### V01｜右边界裁切

- **问题**：文本可见区域右侧少一段，截图中只剩半个词或半个字。
- **底层信号**：节点 visible bounds 的 right 小于 origBounds 的 right；候选框落在右边界附近。
- **处理**：先按稳定 id/key 绑定到 Text 节点，再比较横向 bounds 差值，方向归类为 `right`。
- **结果**：`true_truncation`；通过。

### V02｜左边界裁切

- **问题**：文本左侧被父容器或自身边界截去。
- **底层信号**：visible bounds 的 left 大于 origBounds 的 left。
- **处理**：沿 left 方向检查 hidden extent，排除候选框误落到相邻节点的情况。
- **结果**：`true_truncation`；通过。

### V03｜顶边裁切

- **问题**：文本上半部分不可见，常见于固定高度容器或布局上移。
- **底层信号**：visible bounds 的 top 大于 origBounds 的 top，且候选框接近上边界。
- **处理**：使用纵向 bounds 差值判断，不以“文本是否仍可读”作为排除条件。
- **结果**：`true_truncation`；通过。

### V04｜底边裁切

- **问题**：文本下半部分被裁，视觉上容易与底部导航遮挡混淆。
- **底层信号**：visible bounds 的 bottom 小于 origBounds 的 bottom。
- **处理**：先确认文本 owner，再判断裁切是否发生在组件自身；与 fixed overlay 分开归类。
- **结果**：`true_truncation`；通过。

### V05｜Button 文案越界

- **问题**：按钮文字超出按钮自身宽度，不能只依赖 Text 节点类型。
- **底层信号**：Button 节点存在稳定 id，origBounds 宽度大于 visible bounds，且节点设置 clip。
- **处理**：将 Button 纳入可绑定组件类型；绑定后沿按钮内容区域做同样的 bounds 对比。
- **结果**：`true_truncation`；通过。

### V06｜Dialog 标题自身裁切

- **问题**：弹窗标题在弹窗内部被截断，容易被误判为弹窗边界或背景遮挡。
- **底层信号**：Dialog 为候选 owner，标题子节点 visible bounds 小于 origBounds。
- **处理**：先向上解析 dialog owner，再对标题子节点执行 glyph clip 判断；不把整个 Dialog 当成文本节点。
- **结果**：`true_truncation`；通过。

### V07｜键盘层导致 action bar 不确定

- **问题**：键盘出现后，页面底部 action bar 位置变化，截图看起来像被裁。
- **底层信号**：页面层、键盘层和 action bar 的布局证据不完整，无法证明是组件自身裁切。
- **处理**：对键盘层和页面层分层；缺少完整布局证据时不升级为真缺陷。
- **结果**：`unknown`；通过（保守判定）。

### V08｜横滑换卡但同 id 仍溢出

- **问题**：横向滑动后卡片内容变化，但同一组件 id 的标题仍超出边界。
- **底层信号**：滑动前后可重新绑定同一 id/key，origBounds 与 visible bounds 的差异持续存在。
- **处理**：滑动只用于复核，不作为自动排除条件；对同一 id 做前后对比。
- **结果**：`true_truncation`；通过。

### V09｜固定底栏遮挡

- **问题**：固定底栏覆盖了内容区域，视觉上与文本底部裁切相似。
- **底层信号**：候选区域与 TabBar/BottomBar 的空间相交，但文本节点自身 bounds 未缩短。
- **处理**：输出独立的 `bottom_occlusion` 关联问题，不并入 `text_truncation`。
- **结果**：`not_truncation`；通过。

### V10｜图片内嵌文字

- **问题**：图片中的文字看似被截，但布局树中没有对应文本节点。
- **底层信号**：候选框命中 Image/Canvas 区域，无法找到可绑定文本 owner。
- **处理**：不从像素猜测组件身份；保留视觉候选，最终返回 `unknown`。
- **结果**：`unknown`；通过（证据不足不猜测）。

### V11｜正常两行换行

- **问题**：正常换行被误报为截断。
- **底层信号**：visible bounds 与 origBounds 一致，文本节点完整存在。
- **处理**：检查 bounds 差异和裁切标记；正常换行、正常省略号不进入真裁切分支。
- **结果**：`not_truncation`；通过。

### V12｜候选框无对应组件

- **问题**：模型框落在空白区域或跨越布局树不存在的节点。
- **底层信号**：空间查询无稳定 id/key 可绑定，query coverage 不足。
- **处理**：拒绝以最近邻文本替代真实 owner，返回 `unknown` 并保留候选证据。
- **结果**：`unknown`；通过。

### V13｜候选框覆盖两个 owner

- **问题**：一个候选框同时覆盖两个相邻文本或卡片 owner，强行绑定可能造成错报。
- **底层信号**：多个节点均满足空间相交条件，owner 不唯一。
- **处理**：执行 ambiguity 检查；无法唯一确定 owner 时直接 abstain。
- **结果**：`unknown`；通过（避免错绑）。

### V14｜折叠态重排但内容完整

- **问题**：折叠态或窗口尺寸变化导致布局重排，视觉位置变化被误认为裁切。
- **底层信号**：前后页面状态中 id/key 保持一致，visible bounds 与 origBounds 均完整。
- **处理**：比较内容完整性而非绝对坐标；状态切换本身不生成缺陷。
- **结果**：`not_truncation`；通过。

### V15｜WebView/Canvas 文字

- **问题**：WebView 或 Canvas 内存在文字，但原生布局树没有可用文本节点。
- **底层信号**：截图存在视觉内容，布局查询返回 Image/WebView/Canvas 容器，无法获得文本 bounds。
- **处理**：保留候选并标记证据缺口；不把图像像素直接升级为原生文本缺陷。
- **结果**：`unknown`；通过。

### V16｜滑动后恢复失败

- **问题**：滑动复核后无法恢复到初始页面状态。
- **底层信号**：`restore_ok=false`，前后页面状态无法形成可靠闭环。
- **处理**：恢复失败时禁止从 `unknown` 升级为 `true_truncation`；将恢复失败作为独立证据项。
- **结果**：`unknown`；通过（不输出未经闭环验证的结论）。

## 5. 真实页面与页面找寻结果

真实页面探索集共 33 条唯一案例，统计结果为正例命中 15 条、负例干净 2 条，即 17/33（51.5%）。页面找寻复杂任务预检共 50 条，目标页 Oracle 到达 29 条（58.0%）；未到达任务主要涉及测试数据、搜索/筛选控件、页面重置和恢复路径，不能直接归因于缺陷识别模型。

识别基线使用 qwen3.6-flash；页面动作由 Agent + HDC/uitest 执行。后续正式验收需要在固定应用版本、设备、任务集、truth、模型版本和坐标系后重新计算统一分母。

## 6. 交付边界与后续输入

正式验收前需确认：

1. 被测应用包名、HAP/版本和启动入口；
2. HDC target、分辨率、横竖屏及折叠状态；
3. 任务列表、前置状态、页面到达条件和重置方式；
4. 缺陷 truth、bbox、标签定义和 unknown 处理规则；
5. qwen3.6 endpoint、模型版本、提示词版本和坐标系；
6. `bottom_occlusion`、WebView/Canvas、键盘层是否纳入验收；
7. 页面找寻、识别和恢复三个环节的分母及失败归因。
