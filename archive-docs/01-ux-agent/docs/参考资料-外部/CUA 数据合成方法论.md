# CUA 数据合成方法论



第一部分是判断依据（为什么这样做），第二部分是六个关键步骤（每步做什么、收集什么、桌面上怎么改），第三部分点明从手机迁到桌面真正的难点。



---



## 一、判断依据



Agent 训练数据需要考虑三种重要的情况，所有取舍都在应对其中之一：



- **覆盖不足**：某类功能或组合从没出现过，模型学不到。表现是题不少，但都挤在应用主路径上。

- **分布错配**：训练时的状态和推理时的状态不是一回事。最典型是专家示范里全是「正确状态 → 正确动作」，模型上线后进入**错误状态**——训练分布里没有，于是不会自我纠正。

- **长程任务**：

五条原理由此展开：



|\#|原理|一句话理由|违反时的现象|理想处理|
|---|---|---|---|---|
|1|合成任务的复杂度上界 = **出题时可见环境的广度**|出不来跨功能难题是信息缺口，不是模型能力缺口。只给一条探索路径，它只能组合这条路上见过的界面|题多但简单、彼此雷同|尽量全的环境信息：截图信息、截图间的可达性|
|2|**状态由弱模型产生，标签由专家产生**|要同时拿到「见过错误」和「知道正确」，两者必须来自不同来源|模型一旦点错就一路错到底|有能意识到处于错误状态并纠错的关键步|
|3|错误检测放在**任务进展层**，不是动作层|GUI 多解，动作不一致往往两个都对，不是错误信号|接管频繁、轨迹被切碎||
|4|跨阶段引用必须有**显式外键**|探索、出题、采集在时间上分离，却必须指向同一环境状态|大量轨迹开局即失败|环境可以复现|
|5|质量用**功能覆盖**度量，不是「像不像好题」|覆盖率与下游成功率同向，且可优化；题面相似度不是|数据加倍但成绩不动||



两条记账原则：**环境故障不是模型失败**（崩溃、卡死、权限弹窗单独归类，不能当负样本）；**成功不等于干净**（步数远超同类中位数的多半是绕路，降权而非当示范）。

## 二、六个关键步骤



|步骤|目的|Mobile 实现|CUA 迁移要点|
|---|---|---|---|
|1 环境与初态|让同一状态可重复还原|模拟器快照 \+ 逐应用初始化脚本|虚拟机/容器快照 \+ 文件级 seed；粒度更粗、成本更高|
|2 探索|拿到界面、功能、可达关系|随机点无障碍树元素|**不能随机**，改为受控 \+ 人工覆盖式演示|
|3 环境表征|把碎片织成可查询的功能地图|界面去重 \+ 真实跳转邻接 \+ 功能描述|增加窗口维度与文件维度|
|4 出题|产出可执行、可判定的 query|记忆增强合成 \+ 三层过滤|路径/窗口/产物名必须写死|
|5 采集|拿到含纠错的轨迹|弱模型开局，偏离后专家接管|检测器必须看活动窗口与文件变化|
|6 判定入库|只留可信样本|查数据库/设置|查文件内容与校验和，判定脚本更贵|



下面逐步说明。**为什么重要**决定了这一步不能省；**收集什么**是交付物清单。



### 步骤 1：环境与初态



**为什么重要。** 三个阶段在不同时间跑，只有初态能把它们对齐。这一步没做好，后面所有产出都不可复现。



**Mobile 做法。** 每轮探索前恢复应用快照，用初始化脚本写入种子数据，固定设备时间与语言。给这套初始化一个 id。



**要收集的信息。**



- 初始化 id（后续 query 的外键）

- 种子、写入的数据、设备时间

- 屏幕规格（分辨率、缩放、DPI）

- 应用版本

**自检。** 用同一个 id 初始化两次，环境数据应完全一致。做不到就先修这里，不要加大出题量。



**CUA 迁移。** 桌面状态散落在文件系统、配置目录、账号里，没有「逐应用一键还原」。改为两层：**镜像层**（虚拟机/容器快照，含系统与已装软件，版本必须固定）\+ **工作区层**（预置文件，记路径、大小、校验和）。恢复更慢、体积更大，这直接决定了采集成本，也是后面要提高良品率的原因。



### 步骤 2：探索



**为什么重要。** 出题的复杂度上界由这一步决定。探索没走到的功能，出题时看不见，也就永远不会出现在数据里。



**Mobile 做法。** 每轮从无障碍树里随机选可交互元素，点击或输入，走若干步；无效元素进黑名单；轮次之间恢复快照。随机就够用——因为有快照兜底，最坏结果是回滚。



**要收集的信息（这是交付物）。**



- 每一步的前后截图

- 状态转移三元组：`(当前界面, 动作, 下一界面)`

- 本轮对应的初始化 id

- 被操作元素的文本与位置

- 界面是否真的发生变化

**CUA 迁移：手段要换，目标不变。** 桌面上随机点不可行——很多操作有副作用且不可逆（删文件、覆盖保存、发出内容、改系统设置、触发付费流程），而快照恢复又比手机贵得多。但我们要的东西没变：**界面、功能、可达关系**。所以把「随机采样」换成「按成本分层获取」：



|优先级|手段|说明|
|---|---|---|
|1|**直接枚举，不用点**|菜单树、设置项、文件系统目录。能读出来的结构不要靠点击去发现，这是桌面上最高效的部分——尤其是文件清单，只点界面根本看不到目录里有什么|
|2|**只读动作自动遍历**|展开菜单、切换标签、滚动、打开只读视图。先定义**只读白名单**，白名单内才允许自动走|
|3|**人工覆盖式演示**|写操作、不可逆操作、需要多步配置的流程，由负责人手动走一遍|



第 3 项是关键，也最容易做成一团散沙。它不是「随便点点」，而是**覆盖式演示**：负责人拿到一份功能清单，把每个菜单、每个对话框、每条主要流程走一遍，目标是把界面覆盖到，而不是把任务做完。要统一交付规范，否则每人风格不同、数据无法合并：



- 每个不同界面一张截图（同一界面不同窗口尺寸算同一个）

- 从桌面到该界面的路径（例如：文件 → 导出 → 选择格式）

- 该界面能做什么（人写要点，或截图交模型补全描述）

- **可逆性标注**：这里的操作是只读、可撤销、还是不可逆

- 涉及哪些文件或配置项

**可逆性标注是桌面独有、且必须有的一项。** 它决定了哪些功能可以出题（可逆或可通过快照恢复）、哪些只能作为背景知识而不出题（不可逆、影响宿主、需要联网提交）。手机上有快照兜底，不需要这一栏。



### 步骤 3：环境表征



**为什么重要。** 探索结果是碎的，多轮会反复走到同一界面。不先合并，出题时模型每次只能看见一条路径上的几张图，题仍然局部。



**Mobile 做法。** 相似界面合并为代表界面；邻接只认**真实发生过的跳转**（不是「看起来像」）；每个界面用几句话写清「在哪一层、对数据或设备做什么」；按应用建语义索引，供出题时召回「这次没走到但相关」的功能。



**要收集的信息。**



- 去重后的界面集合及代表截图

- 邻接关系（谁能走到谁）

- 每个界面的功能条目，区分**应用能力**与**用户数据**

- 按应用的检索索引

**CUA 迁移。** 加两个维度：



- **窗口维度**：跳转要区分「同一窗口内换页」和「切换到另一个窗口」。出题时默认只用前者串流程，否则模型会把「切到无关窗口」当成正常步骤。

- **文件维度**：功能描述里写清这个操作会改哪个文件、是否需要焦点、菜单路径是什么。

另外，同一界面在不同窗口尺寸下要能合并，否则表征会膨胀。



### 步骤 4：出题



**为什么重要（原理 1、4、5）。** 这一步同时决定覆盖率和可执行性。题不合格，后面的算力全浪费。



**Mobile 做法。** 对每个候选界面，给生成模型三块材料：这个界面、能走进/走出的邻居界面、**同应用里语义相关但本次没走到的功能**。第三块是出跨功能组合题的关键。产出后三层过滤：规则预筛 → 打分（清晰度、合理性不达标丢弃，复杂度只用于排序）→ 去重与按应用封顶。



**要收集的信息（每条题）。**



- query 文本与 id（改文案就换新 id）

- 应用、初始化 id、种子、起点（默认桌面）

- 屏幕规格

- 打分结果、用到了哪些记忆（便于抽检是不是凭空编的）

**验收（人工 20 条，四问全过才放量）。** 写得具体吗？对象在这份初态里吗？从桌面能做吗？做完能自动验吗？



query 文本、初始化、判定脚本必须引用**同一份结构化字段**。三处各写一遍，整条轨迹的监督都是错的。



**CUA 迁移。** 桌面上没有唯一指代，「那个表格」「刚才那个」无法还原，所以必须写死：



```Plain Text
打开 ~/data/sales_q3.xlsx，把 sheet「华东」按销售额降序排序，
另存为 ~/output/east_q3_sorted.xlsx，不要修改其他 sheet。
```



规则：点名应用或窗口；路径与产物名写死；说明不要动别的文件（既降低误伤，也让判定好写）；query 里出现的文件、菜单、快捷键必须在初态清单或探索见过的范围内。还要**只在可逆功能上出题**——这是步骤 2 那份可逆性标注的用途。



### 步骤 5：采集



**为什么重要。** 这一步决定数据能不能修分布错配。



**Mobile 做法。** 先用初始化 id 还原环境（不是从出题时那张界面开始），把 query 当作目标。弱模型开局并真的犯错；检测器只判断「是否偏离目标」，不出动作；偏离后专家接管，并把偏离理由一并交给它。限制接管次数、要求专家接手后连续做若干步、不允许弱模型独自宣布完成。（弱模型先执行、强模型检测弱模型每一步判断是否接管）



**要收集的信息（每一步）。**



- 执行前后的观察（截图 \+ 界面结构）

- 界面是否发生变化

- 动作：类型、目标、像素坐标与归一化坐标**都要**

- 执行者是弱模型还是专家

- 检测器输出与是否触发接管

**CUA 迁移。** 可以与mobile同



### 步骤 6：判定与入库



**为什么重要。** 标签错了，前面全部白做。



**Mobile 做法。** 目前是模型自我判断是否完成 \+ vllm\-as\-a\-judge。



**要收集的信息。**



- 成败、判定来源、失败原因

- 步数、接管次数

- 本批用的模型与阈值（换配置就新开一批，不覆盖旧数据）



**CUA 迁移。** 规模化的话目前还是觉得同mobile：模型自我判断\+vllm\-as\-a\-judge更为划算

## 三、从 Mobile 迁到 CUA 



### 核心难点

方法论五条不变，变的是**获取环境信息的成本**和**还原环境的能力**。



**1\. 探索不能随机。** 手机上有快照兜底，随机点最坏就是回滚。桌面上大量操作不可逆或有外部副作用，随机点既危险又低效。这不是调参能解决的，必须换手段：能枚举的直接枚举（菜单、设置、文件系统），只读动作自动遍历，写操作由负责人覆盖式演示，并逐条标注可逆性。



**2\. 初态还原从「细粒度」退化为「粗粒度」。** 手机上能逐应用恢复；桌面上通常只能整机快照 \+ 文件 seed，慢且大。直接后果是每条数据更贵，**良品率比产量更重要**。



**3\. 观测可能不可靠。** 手机有无障碍树，元素结构化。桌面上不少应用（自绘界面、跨平台框架、专业软件）的可访问性信息缺失或残缺，只能靠像素。这会同时影响探索（拿不到可交互元素列表）、动作（只能给坐标）、检测（判不出界面是否真的变了）。补偿办法是把**窗口元数据和文件变化**当作一等观测，而不是只依赖截图。



**4\. 状态空间从「单屏」变成「多窗口 \+ 文件系统」。** 新增的失败模式是手机上没有的：点到了另一个窗口、焦点丢失导致输入进错地方、文件被覆盖、快捷键被系统截走。表征要带窗口维度，检测器要看焦点，判定要看文件。



**5\. 任务更长、判定更贵。** 桌面任务步数更多、等待更久（导出、加载、渲染），环境异常也更多（未响应、保存对话框卡住、权限弹窗）。这些必须严格归入环境故障，不能混进负样本，否则评估会被噪声带偏。



一条务实的迁移顺序：用枚举 \+ 人工演示拿到界面与功能，出一批路径写死的题；确认还原稳定后再开弱强切换采集；再加第二个应用才允许跨应用题。

mobile端都在一个虚拟环境中，computer则由多个负责人搜集，但一般来讲可以通过统一截图池也可以让模型生成跨app的任务

## 四、按现象排障



|现象|大概率原因|查哪一步|
|---|---|---|
|题很多但简单、雷同|出题时只看见局部|步骤 3/4：有没有给「没走到但相关」的功能|
|一旦点错就一路错到底|训练集没有错误状态|步骤 5：纠错片段占比|
|接管频繁、轨迹碎|在动作层判错|步骤 5：抽查接管点是否真的偏离|
|大量轨迹开局即失败|环境与题对不上|步骤 1：同 id 初始化两次是否一致|
|数据加倍但成绩不动|在重复生成|步骤 4：覆盖的功能种类数有没有跟着涨|
|桌面上成功率远低于手机|多为焦点/窗口问题，不是能力问题|步骤 5：检测器有没有看活动窗口|

## 附录：参考参数



一组mobile场景已验证可用的取值。换环境时按原理调整。



**探索**：每轮约 30 步；无效元素进黑名单；轮次间恢复快照；不联网、不登录。  

**表征**：相似界面按感知哈希合并（阈值约 0\.95）；邻接只认真实跳转；按应用建语义索引。  

**出题上下文**：当前界面 \+ 1 个前驱 \+ 最多 3 个后继 \+ 约 30 条同应用相关功能（彼此去近义）；每个界面产出 1–3 条。  

**过滤**：规则预筛 → 打分（清晰度/合理性不达标丢弃）→ 相似度去重 → 每应用封顶 → 人工抽 20 条四问。  

**采集**：每条最多接管 2 次；专家接手后至少连续做 3 步；弱模型不得独自宣布完成。  

**判定**：模型自我判定 \> 模型裁判（须抽检）。
