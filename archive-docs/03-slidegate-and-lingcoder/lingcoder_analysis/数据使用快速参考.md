## 四、常见问题快速解答

### Q1: 为什么不能用rStarCoder？它是Microsoft官方数据啊！

**A**: 
- ✅ rStarCoder是高质量算法数据
- ❌ 但算法占比99.9%，比algorithm_python（73.1%）更极端
- ❌ algorithm_python已经造成fullstackbench -7.83的损害
- ❌ rStarCoder预计损害更严重（-8~-10）
- ✅ **解决方案**：用algorithm_go替代（几乎不损害fullstackbench）

### Q2: 我需要算法能力，怎么办？

**A**:
```
✅ 正确做法：
使用algorithm_go + 保持base数据>80%

❌ 错误做法：
使用rStarCoder或algorithm_python
```

### Q3: 为什么Go语言算法数据比Python好？

**A**:
- algorithm_go: fullstackbench -0.06（几乎无影响）
- algorithm_python: fullstackbench -7.83（严重损害）
- **差异7.77个百分点！**
- 可能原因：Go语言本身包含更多工程实践内容

### Q4: base数据比例至少要多少？

**A**:
- fullstackbench优先：≥90%
- 平衡多任务：≥80%
- 深度学习优先：≥70%
- **绝对底线：不低于60%**

### Q5: 如何快速配置一个安全的方案？

**A**:
```
默认配置（闭着眼睛用）：
400k base + 50k algorithm_go + 30k database + 20k nonpython_ds
```

这是验证过的最安全平衡方案。

### Q6: 我可以混合多个数据集吗？

**A**:
```
✅ 可以混合的：
base + algorithm_go + database + nonpython_ds

⚠️ 谨慎混合的：
上述 + base_epicoder_func + sft_code_mix（少量）

❌ 绝对不混合的：
任何包含rStarCoder/Nemotron/algorithm_python的组合
```

### Q7: 验证结果只有LingCoder，其他数据能用吗？

**A**:
```
已验证可用：
├── algorithm_go（LingCoder子集）
├── database（LingCoder子集）
└── nonpython_ds（LingCoder子集）

未验证但风险可控：
├── base_epicoder_func（算法占比47%，相对安全）
└── sft_code_mix（算法占比67%，中等风险）

已验证高风险/预估极高风险：
├── algorithm_python（已验证：-7.83）
├── rStarCoder系列（预估：-8~-10）
└── Nemotron（预估：-8~-10）
```
