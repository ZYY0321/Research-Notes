## 三、重要发现

### ✅ 正面发现

1. **nonpython_ds数据最有效**
   - 在DS1000上提升7.13分（所有子集中最高）
   - 是唯一在HumanEval plus上超过基线的lingcoder子集
   - 说明跨语言的数据科学知识有助于提升模型能力

2. **database数据表现均衡**
   - 在多个任务上都有提升
   - 多语言能力下降最小（-0.51分）
   - 在数据库相关任务上表现突出

3. **专业化数据有效**
   - algorithm_python在数据科学和科学计算任务上有帮助
   - 说明针对性数据对特定领域有提升

### ⚠️ 需要注意的问题

1. **Python专用数据可能影响多语言能力**
   - algorithm_python和python_ds在HumanEval X上下降明显（-2.05和-1.97）
   - 如果模型需要支持多语言，需要谨慎使用

2. **software_engineering数据质量存疑**
   - 几乎所有任务都表现不佳
   - 总分仅提升0.76分（最差）
   - HumanEval plus下降3.12分（最差）
   - 建议深入分析数据质量或重新筛选

3. **python_ds不如nonpython_ds**
   - 虽然都是数据科学相关，但nonpython_ds表现更好
   - 说明数据多样性比单一语言更重要

## 四、最终建议

### 4.1 数据使用策略

**✅ 强烈推荐使用**：
- **nonpython_ds**（非Python数据科学）
- **database**（数据库相关）

**✅ 有条件推荐**：
- **algorithm_python**（如果主要关注Python任务，且不强调多语言能力）

**❌ 不推荐使用**：
- **software_engineering**（效果不佳，建议重新评估数据质量）

**⚠️ 谨慎使用**：
- **python_ds**（表现不如nonpython_ds）

### 4.2 数据组合建议

**推荐方案1（平衡型）**：
- 400k base + 50k nonpython_ds + 30k database + 20k algorithm_python

**推荐方案2（专注数据科学）**：
- 400k base + 100k nonpython_ds
