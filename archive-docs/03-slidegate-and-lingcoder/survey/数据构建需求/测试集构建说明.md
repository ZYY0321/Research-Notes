# 测试集（Query）构建说明

**主表**：`query-test.csv`，**173 条**（不含表头）。**1–48** 为 **48 题**；**49–173** 为 **刘波侧**样本。评测以 **`prompt_rewritten`** 为准。

**合并后类型/场景分布**：见同目录 `输入类型与使用场景分布.md`。

---

## 变成 `query-test.csv` 要做什么

1. **48 题**：命题宽表字段直接进 CSV；附件只在本地 `48ti附件汇总/`，无下载 URL。  
2. **刘波无文件**：来自 `prompt_gen` 的 JSON（`metadata` + `prompts[]`），有 `id`/`variant_id`、`prompt`、`prompt_rewritten`、`topic` 等，**没有** `ppt_scene_data`。合并时 **补**「使用场景」「页数」、把评测用 **「输入类型」** 映射成五分法（多为「一句话」/「详细要求」等）。  
3. **刘波有文件**：来自 `xhx_prompt_extractor` 最终 classified JSON，条内有 `session_id`、`file_*`、`prompt_rewritten`（常带 `<FILE/>`）、**`ppt_scene_data`**（含 `scene`/页数类 `duration`）、以及 LLM 分的 **`category`**（多源文档整合 / 模板应用 / 迭代修改 → 对应 CSV「文档与要求」「模板与资料」「已有PPT与资料」等）。**`scene` 长尾**需归并进评测枚举。  
4. 与 48 题按序号拼成一张宽表；若需溯源可在表里加 `session_id` / `variant_id` 列（当前未必有）。

---

## `query_dataset`（带附件文件夹）

- **脚本**：仓库根目录 `build_query_dataset.py`。  
- **48 题**：从 `48ti附件汇总/` 按文件名/前缀/别名等规则复制（细则见脚本内注释）。  
- **刘波**：按「附件下载 URL」拉取（内网环境常需 IP + Host）。  
- **输出目录示例**：`/mnt/afs/zhangyingying/ppt/query_dataset`（`{序号}-{48ti|return-data}-…/` + `query.json`）。

### 原数据长什么样、怎么接到本表

| 线 | 原数据形态 | 怎么变成「我这样可以」 |
|----|------------|-------------------------|
| **无文件** | `demo_output_with_statistics.json`：`metadata.statistics` 做分布；`prompts[]` 每条含 `prompt`、`prompt_rewritten`（可选 LLM 改写）、`id`（如 S1_*）、`topic` 等 | 抽样/筛选进合并表 → **补**「使用场景」「页数」「输入类型」→ 写入 `query-test` 对应列 |
| **有文件** | `prompt_ppt_classified_with_file_*_with_statistics.json`：`metadata` + `prompts[]`；每条含 `file_id`/`file_url`/`file_name`、`prompt_rewritten`、`ppt_scene_data`、`category`/`id`（S4/S7/S8）等 | 抽样/筛选 → **映射** `category`→「输入类型」、`scene`（及长尾）→「使用场景」、`duration`→「页数」→ 附件列用 `;` 拼多文件 → 写入 `query-test` |

**管线逻辑（便于对照代码）**：无文件侧为 **模板随机 + 可选 GPT 改写**（`ppt_prompt_generator.py`）；有文件侧为 **plan 回流抽 session → GPT 清洗/topic → GPT 三分类并拼 `<FILE/>`**（`1_get_examples.py` → `2_process_prompts.py` → `3_classify_scenarios.py`）。
