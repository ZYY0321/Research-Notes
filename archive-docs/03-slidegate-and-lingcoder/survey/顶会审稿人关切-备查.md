# 顶会审稿人关切备查

> 供框架设计和论文写作阶段随时对照检查，每条都需要有对应的实验或声明来回应。

---

## 必须回应（否则大概率被拒）

### R1：LLM-judge 悖论
- **问题**：论文核心 motivation 是"LLM judge 在视觉结构判断上系统性失效（accuracy≈15%）"，但 Track A/C 仍依赖 LLM judge 评估。
- **需要**：Track A/C 中用到 LLM judge 的每个维度，必须报告与人类标注的 Spearman/Kendall τ 相关系数（即使只有 100 条样本），证明该维度的 LLM judge 是可信的。

### R2：IAA（标注一致性）缺失
- **问题**：12,798 条分页标注的客观性主张未经验证；"有语义影响的遮挡（非创意设计）"等定义本身主观。
- **需要**：对 Track B 的每个标注类型报告 Cohen's κ 或 Krippendorff's α（至少 2 名标注员，至少 300 页交叉标注）；目标 κ>0.7 才能主张"客观二元"。

### R3：为什么是 PPT，而不是通用文档生成
- **问题**：审稿人会问是否已有工作覆盖（Design2Code、DocVQA、VideoScore）。
- **需要**：明确 PPT 的三个不可替代的特有挑战：
  1. 多页视觉×内容联合约束（页内独立约束 + 页间叙事连贯）
  2. 用户约束异构性（硬约束：页数/语言；软约束：受众/风格，同时存在）
  3. 渲染失败模式特殊性（代码渲染导致的越界/遮挡，图像任务中不存在）

## 应当回应（影响论文完整性）

### R4：873 条 query 的代表性
- **问题**：领域分布、复杂度分布是否有偏；来源是否多样。
- **需要**：报告 query 的场景分布表（学术/商业/教学/产品等各占比）；约束复杂度分布（单约束/多约束）。

### R5：Benchmark 饱和度
- **问题**：人类上限 vs 当前最好 agent 之间是否有足够 gap。
- **需要**：至少报告一个"人类基准分"，哪怕只是 20-30 条人工写的"理想 PPT"在各 track 上的得分，与当前 agent 形成对比。

### R6：多轨道如何聚合为最终排名
- **问题**：三个 track 分别出结论，但论文最终需要回答"谁更好"。
- **需要**：明确立场——推荐参考 HELM 的做法：各维度独立排名 + Borda count 综合排名，核心论点是"不同 agent 的能力 profile 不同"，这种差异只有分解排名才能揭示。
