模型认为"极简=专业=好"，同时也认为"色彩丰富=有设计感=好"，两者在 1-5 量尺上根本没有区分机制。
- 4分：43.3%，5分：34.7%，合计 78%
- 1-2分合计仅 6.9%
- 各 agent 均值范围：3.63（claude-minimax）~ 4.36（kimi），极差仅 0.73 分
用 1-5 分量尺来区分 7 个 agent，实际有效量程只有 0.73，几乎没有区分力。而 aes_high 占 page_score 25% 的权重（page×0.35 = overall 的 8.75%），但实际只能在 agent 间产生不到 0.06 的 overall 分差
改进：
1. 配参考锚点 Gallery：每个分数档配 2-3 张标定图，写进 prompt。如"以下是2分的典型样例：内容稀少、留白过多……"
2. 或改用相对比较评分：不问"这张给几分"，而是问"这两张哪张更好"（pairwise），自动构建排名。这样消除绝对打分的参考系问题。（暂时考虑）
3. 拆分维度而非综合打分：分为 information_density（信息密度，可客观判断）+ visual_polish（精致感）两个维度分别打分，避免两种优秀设计哲学互相抵消。（后续可插入，前置提取约束？）

真实性
问题一：输入分类太粗。报告类型决定了真实性的基准，关键是"我们期望这个 agent 对 report 做什么"。
目前 input_type 分为"文档与要求/一句话/详细要求"，但这个分类没有捕捉到重要的区别 ： 
style-gemini 的 0.947 是因为它做的就是排版工作，truthfulness 就会是 1.0 。而anygen 生成了大量报告里没有的细节（虚构文献、假设性数据），这可能才是我们想检测出的问题。

问题二：计算/总结类内容无法用"是否在报告里找到依据"来评判
报告给了原始数据，PPT 做了计算总结，这类声明既不能说"有依据"（报告没有直接写这个结论），也不能说"无依据"（计算是合理的）。当前 prompt 没有处理这种情况。
改进：
1. 增加 report 类型标签（新的 input_type 子类）：区分"逐页脚本型"与"数据报告型"
2. 对"逐页脚本型" report，truthfulness 可降权或直接跳过（结果必然是满分，没有信息量）？
3. 对"数据报告型"，truthfulness prompt 增加处理规则："若 PPT 中某条陈述是对报告数据的合理计算/总结，标记为 derived，不算 unsupported"？
