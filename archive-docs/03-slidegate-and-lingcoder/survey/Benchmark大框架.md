## 参考：现有 PPT Benchmark 的数据规模与实验

| 论文 | Query/实例规模 | 生成结果规模 | 标注类型与规模 | 主要实验 |
|------|----------------|-------------|----------------|----------|
| PresentBench | 238 实例，5 领域 | 8 个系统 × 238 | 每实例 ~54 项 binary checklist（MLLM 执行）；人类偏好排名 24 实例 | 系统排名；人类对齐 Spearman；消融（各维度贡献）；跨领域分析 |
| SlidesGen-Bench | 187 topic，7 场景，9 产品 | — | 1326 条人类排序记录 | 内容 QuizBank；美学公式；与人类排序一致性 |
| LecEval | 56 门课 | — | 2097 个 slide-text 对，四维度 1–5 分，3 名标注员；测试集 420 | 与人类评分 σ/ρ/τ；对比 5 种参考指标 + 4 种 LLM |
| PPTC | 279 多轮 session | 3 闭源 + 6 开源 LLM | 基于 API 序列/预测文件的 PPTX-Match | 单轮准确率；session 准确率；错误原因分析 |
| PPTArena | — | 2125 张幻灯片 | 800+ 编辑案例，IF/VQ 各 0–5 分 | 编辑任务上的指令遵循与视觉质量 |
| DECKBench | paper-slide 对 | 多 agent | 有参考 + 无参考指标；多轮编辑指令 | 幻灯片级/集级/多轮级指标 |
| PPTBench | HF 数据集 | — | 元素级 JSON GT；人类评分 Spearman 0.86–0.89 | Detection/Understanding/Modification/Generation 四任务 |

**共性**：都有明确「实例/query 规模 + 生成或标注规模」；主实验多为「系统排名 + 人类对齐验证 + 维度/场景分析」。

## 零、论文定位与初版边界

### 0.1 一句话定位
- [ ] 论文主叙事统一为：`面向复杂多约束 PPT 生成的可靠评测 benchmark`
- [ ] 不将论文主线表述为“判断 PPT 美不美”，而是强调“哪些自动评测信号能稳定反映真实生成质量”

### 0.2 初版核心问题
- [ ] 内容质量：生成结果是否覆盖并正确使用用户输入材料
- [ ] 硬性视觉错误：是否存在越界、遮挡、内容缺失等用户不可接受的失败
- [ ] 约束遵循：是否满足页数、语言、受众、场景、模板/图片使用等明确要求

### 0.3 初版暂不主打
- [ ] 纯美学总分：可作为补充分析，不作为主指标
- [ ] 页间连贯性：保留为扩展方向，初版不作为主结果
- [ ] 生成-修复闭环：保留为后续任务，不纳入初版必做范围

### 0.4 核心 claim
- [ ] Benchmark 的价值是提供可靠、可解释、可分解的优化信号，而不是给 PPT 一个单一总分
- [ ] 相比粗粒度 LLM-as-a-judge，分层评测更利于发现系统真实短板
- [ ] 场景/受众/输入类型会改变“好 PPT”的标准，因此 query 设计必须显式建模这些约束

### 2.4 标注标准设计（怎么做）

| 步骤 | 内容 | 完成情况 |
|------|------|----------|
| 1. 确定两层 | Hard Check：二元，有明确定义（越界/遮挡/内容缺失）；Aesthetic：pairwise 或 0/1/2，与 10 类分页对齐 | |
| 2. 写标注指南 | 每类 Hard Check 的判断规则 + 正负例；美观的对比说明（若用 pairwise） | |
| 3. 标注员与 IAA | 建议每份至少 2–3 人；Hard Check 目标 κ>0.8；pairwise 目标 agreement rate；整体分目标 α 或 κ | |
| 4. 试标与校准 | 先标 50–100 条，算 IAA，修订指南后再铺量 | |
| 5. 与整体/分页的衔接 | 明确：分页 Hard Check 如何汇总为 deck 级失败率；偏好层是否只作为补充分析 | |

## 三、评估管线

### 3.1 内容质量
- [ ] 确认输入格式（HTML/PPTX/截图）
- [ ] 页数、完整性、真实性（修复真实性标准）
- [ ] 区分可直接落地项（页数、完整性）与待改进项（真实性）
**现有**：页数可用；完整性基本可用；真实性不可用。初版主打页数 + 完整性，真实性作为补充探索。

### 3.2 硬性视觉错误
- [ ] Hard Check：zero-shot 或训练 Hard Filter
- [ ] 输出页级错误标签与 deck 级硬错误率
**现有**：zero-shot 准确率低；但 Hard Check 是用户强相关、可解释的关键信号，需单独建模和验证。

### 3.3 指令遵循
- [ ] 页数/语言等规则
- [ ] 风格/受众类约束的评估方式
- [ ] 是否利用输入文档/图片/模板等外部信息
**现有**：规则型约束更容易先落地；风格/受众类约束需先补标注协议。

### 3.4 偏好层与页间连贯性（扩展）
- [ ] 偏好层：pairwise 或 ranker，仅作为增强分析
- [ ] 页间连贯性：LLM / PPL 方法保留，不纳入初版主结果

## 四、实验与统计（需要提前想好）

| 实验 | 目的 | 需要的数据/标注 | 需要产出的统计 | 完成情况 |
|------|------|-----------------|----------------|----------|
| 系统排名 | 各 agent 在各维度上的表现 | 所有 query×agent 的生成结果 + 自动评估 | 各 agent 的维度得分表；排名表 | |
| 人类对齐验证 | 证明自动评估可信 | 子集上的 deck 维度分、页级 Hard Check、约束遵循标注 | 内容/约束遵循用 Spearman 或 κ；Hard Check 用 Precision/Recall/F1；偏好层用 Pairwise Acc | |
| 消融 | 各维度对排名/对齐的贡献 | 同上的多维度打分 | 去掉某维度后的相关性变化 | |
| 跨场景/跨类型分析 | 不同场景下 agent 差异 | query 场景/类型标签 | 按场景或类型的得分表、排名 | |
| Hard Filter 评估 | 硬性错误检测能力 | 有 GT 的 Hard Check 标注（val/test） | 每类 F1/Precision/Recall | |
| 约束遵循分析 | 证明 benchmark 能评估真实用户需求满足度 | 带场景/受众/页数/语言等标签的 query 子集 | 分约束类型的准确率或一致率 | |
| Reranking（可选） | 证明综合分具有优化信号 | 同一 query 多 agent + 人类偏好子集 | 用综合分选出的 top-1 与人类偏好一致率 | |
| 生成-修复（后续） | Refinability | 编辑指令数据 + 修复前后 deck | 修复率、回归率、Refinability | |

### 4.1 初版最小 human alignment 闭环

| 模块 | 最小验证集建议 | 标注形式 | 首选统计 |
|------|---------------|---------|---------|
| 内容质量 | 100–150 deck | deck 级维度分或 checklist 聚合 | Spearman / Kendall's τ |
| 硬性视觉错误 | 500–1000 页 | 页级多标签 Hard Check | Precision / Recall / F1；必要时报告 κ |
| 约束遵循 | 100–200 deck | deck 级规则/约束满足标注 | Accuracy / Macro-F1 / κ |
| 偏好层（可选） | 100–200 对 | pairwise 偏好 | Pairwise Acc |
