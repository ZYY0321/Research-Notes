5.针对多agent 协作轨迹难归属的问题，新增子代理身份自报：每个子代理收尾时首句自报身份标签，让"规划-配图-写页-自检"各环节在轨迹里清晰可追溯，便于定位是哪一步出的问题（也利于后续作训练数据的质检）。身份通过prompt 注入到 sub 的 goal 中。

4. Benchmark 点数对比（原生9B，训练9b， opus）
【重点】原始9b有个问题……现在static的管线是  orch-subagent 架构的，没有训练过的 9b base success rate 几乎为 0
Qwen 3.5-9b baseline 失败的原因：扒了一条base 失败deck（剧本杀那题）的编排器轨迹：base 9b 会规划（计划很合理：封面/主张/论据/反例/对比/结论），但不会按多 agent 流程委派，它试图自己一把梭直接写整套HTML(write_file)，结果：
- 撞上 skil l约束中的 "编排器禁写slides/"的硬限制（轨迹里："路径被限制了，让我重新写入文件")
- 于是写到别处/格式不对→产不出slides/结构→"没有产出任何slide"→判失败。
结论：base 失败不是不会做PPT，是不会用 agentic 委派流程（plan→delegate_task 给子agent 逐页写）。它不知道这套多 agent 协议，就自己硬写、撞墙。
但这也正是训练要教会的东西：上周末 trained 模型的测试，完成率比base高很多，约 74%，就证明蒸馏让模型学会了"编排器规划+委派子agent"这个agentic pattern
