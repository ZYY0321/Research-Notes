# 0708 机器打分可靠性排查 · 内容分虚高 bug 修复 · 全量重判

> 2026-07-08。起因：mentor / 用户发现「Flash-lite step3k DPO 模板模式 64.6，低于无 DPO 版」，
> 让排查 DPO 是不是退化了。排查下去发现是**判分侧的一个静默 bug 导致内容分虚高**，牵出全 board 口径不一致。
> 本文档记录：根因、修复、重判、结论、待办。周会汇报可直接用。

---

## 一、结论先行（TL;DR）

1. **DPO 没有退化**。64.6「低于无 DPO」是**假象**——无 DPO 基线的内容分被系统性**虚高**了，两者不是同一口径。干净重判后两者基本持平（overall 差 −0.01，噪声级）。
2. **根因是判分侧一个静默降级 bug**：动态内容检查项（dynamic checklist）生成/解析失败时，代码把「失败」当成「0 条正常」继续打分，内容分只由易过的通用项（core）决定 → 虚高，且**全程不报错**。
3. **影响面**：老批 6 个模型 30~49% 的 case 中招（内容分虚高）；新批 3 个模型（用 TokenHub Claude 判分）0 中招。混在一张 board 上 → 新模型被系统性压低。
4. **已修**：判分代码加「快速重试 + 失败抛错」，不再静默降级；三值忠实度 prompt 加强制 JSON 约束。**已全量重判** 6 个老模型统一口径。
5. **dashboard 已改**：分数详细展示（主分+细分+deck子分），内容分不稳定的 case 打 ⚠ 标注。

## 二、根因链条（判分侧）

`benchmark/evaluators/content_evaluator.py` 内容评测三步：①生成动态检查项 → ②Checklist L0/L1/L2 评估 → ③三值忠实度。

**静默降级发生在①**（②③同理）：
```
model.call() 判分网关失败 → 底层返回 {"content":"", "error":"无候选回复"}
  → call() 只取 content（空串），error 被丢弃，不抛异常
  → _extract_json("") 返回 {} → dynamic_checklist = []
  → try/except 没触发（无异常），日志平静打印「生成了 0 条动态检查项」
  → 只判 core 6 项（都是易过的通用项）→ 内容分虚高
  → aggregator 照常写入，content_eval_dynamic_items=0，全程无报错
```

**为什么老批中招、新批没有**：老批判分走的是旧 Gemini 网关（不稳/部分已禁用，见 `benchmark-judge-gateway-tokenhub` 记录），大量请求返回空候选；新批已切 TokenHub Claude sonnet-4-6，稳定返回。

**判据**：`content_eval_dynamic_items == 0` 即该 case 内容分不可靠（正常应有 6~10 条动态项）。

## 五、修复内容

**代码**（`benchmark/evaluators/content_evaluator.py`）：
- 新增 `_call_json_with_retry()`，统一收口 生成/checklist评估/三值 三处判分调用。
- 逻辑：call → 校验空返回/解析必需字段 → 失败**快速重试**（默认 5 次 × 0.5s，env `CONTENT_CHECKLIST_GEN_RETRIES` / `_RETRY_SLEEP` 可调）→ 重试仍失败则 **raise RuntimeError 中断**。
- 原则：假设 API 可用，偶发抖动重试兜底；真打不出分 = 环境异常，暴露而非静默降级。**绝不交付缺内容分 / 内容分虚高的残次结果**。
- 未改底层 `call()`（保持最小改动）。

**prompt**（`benchmark/evaluators/prompts/content_claim_3val_prompt.md`）：
- 加强制约束：「只输出 JSON、第一个字符必须是 `{`、禁止在 JSON 外输出逐条演算」。
- 解决大数据表 case 模型「话痨失控」（见失败 case 分析）。

**dashboard**（`results_dashboard/server.py`）：
- `_load_scores` 增读 `content_eval_dynamic_items`、`deck_subscores`。
- `scoreRow` 详细化：主分（总分/页面/全套/内容）+ 细分（硬性/美观细/美观高/清单/忠实）+ deck 子分（结构完整/跨页一致/内容质量）。
- 内容分不稳定（dyn=0）的 case：⚠ 标注 + 黄框 + 提示文案；overall 徽章也附 ⚠。

## 七、失败 case 根因（q1495，周会可讲）

- **case**：flash3k_tpl q1495，「2025 考勤总结 PPT」，附件是 xlsx 考勤大表（15 人明细）。
- **现象**：三值忠实度阶段，6 次快速重试全部失败并抛错（修复行为正确 —— 暴露而非静默）。
- **真因**：源材料 22364 字 + 21 页图 → 模型「话痨失控」，输出 25502 字**全是逐人逐条自然语言演算**（"张林洁=99 > 王星=62 → unsupported"），**从头到尾没输出 JSON**（响应里 `{` 出现 0 次）。非网关/密钥问题，是**超大数据表触发模型格式失控**。
- **对策**：已改三值 prompt 强制 JSON；待重判验证是否解决。
- **教训**：三值忠实度对「大数据表 + 多页」case 脆弱；`_extract_json` 对纯文本无 JSON 返回空 dict。
