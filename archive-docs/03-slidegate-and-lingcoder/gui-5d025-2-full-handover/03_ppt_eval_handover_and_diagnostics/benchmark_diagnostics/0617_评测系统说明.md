## 二、题库

题库位于 `data/` 下，当前可用：

| 题库 | 路径 | 题数 | 说明 |
|------|------|------|------|
| min40 | `data/0427_minset_40_tasks/` | 40 | 精选 40 题，覆盖 4 种输入类型 |
| ms215_full170 | `data/ms215_full170_20260425/` | 170 | 全量大题集 |

### 2.1 题库结构

```
data/0427_minset_40_tasks/
    index.json               ← 40 题索引（数组，每项包含 seq/modality/场景等）
    seq_0007/
        query.json           ← 题目完整定义
    seq_0115/
        query.json
    ...
```

### 2.2 附件（有源材料的题）

```
data/0427_attachments/
    _manifest.json           ← 40 题附件清单（哪些题有附件、文件名、大小）
    seq_1030/
        01_xxx.pdf
        02_xxx.docx
    seq_1622/
        01_xxx.docx
    ...
```

只有带附件的题才会跑三值忠实度评估（faithfulness）。无附件时 content_score = checklist_score。

### 2.3 query.json 字段

```json
{
  "id": "S1_complex_direct",
  "prompt": "制作一个关于并购财务尽调的PPT，学术报告风格，紫色系配色",
  "prompt_rewritten": "制作一份《并购财务尽职调查》主题PPT...",
  "category": "一句话生成",
  "input_type": "纯文本",
  "complexity": "复杂",
  "topic": {...},
  "expected_capabilities": ["复杂需求理解", "结构化规划", ...],
  "observation_points": ["是否主动询问细节", ...]
}
```

### 2.4 如何新增题目

1. 在题库目录下新建 `seq_XXXX/query.json`
2. 如有附件，在 `data/0427_attachments/seq_XXXX/` 下放对应文件
3. 更新 `index.json` 和 `_manifest.json`

## 三、评测数据组织（Agent 产出）

评测入口是一个根目录（`input_root`），每个子文件夹 = 一个 agent 对一道题的产出。

### 3.1 目录结构

```
data/<input_root>/
    <agent_name>_<dataset>-<date>-<query_id>/
        images/              或 *.pptx 或 code/*.html
        attachments/         ← 从题库复制的附件
        query_info.txt       ← 题目描述
```

### 3.2 三种输入格式

代码自动检测并转换，只需提供其中一种：

| 格式 | 文件 | 转换链 | 系统依赖 |
|------|------|--------|----------|
| A. PNG 截图（推荐） | `images/*.png` | 无需转换 | 无 |
| B. PPTX | 根目录 `*.pptx` | LibreOffice→PDF→pdftoppm→PNG | `libreoffice` |
| C. HTML 多页 | `code/page_01.html ...` | Playwright→PNG | `playwright` |

转换结果缓存到 `images/`，不会重复转换。

### 3.3 query_info.txt

```
Query序号: 7
来源: min40
输入类型: 详细要求
使用场景: 商业提案
页数: 10-15页
Prompt: 制作一份关于并购财务尽调的PPT，学术报告风格，紫色系配色
附件文件名: 01_尽调报告模板.pdf
附件下载URL:
```

| 字段 | 必填 | 说明 |
|------|------|------|
| Prompt | ✅ | 用户需求描述 |
| Query序号 | 建议 | 用于 skip_done 去重 |
| 附件文件名 | 有附件时 | `attachments/` 下的文件名，多个用 `;` 分隔 |
| 输入类型 / 使用场景 / 页数 | 可选 | 元数据 |

### 3.4 文件夹命名规则

`{agent_name}_{任意唯一后缀}`

代码从文件夹名提取 agent_name（匹配 `_test40` 或 `_val48` 之前的部分；无匹配时取整个名称）。

### 3.5 完整示例：为新 agent "myagent" 组织一道题的数据

```bash
# 假设题目是 seq_0007，agent 产出了 PPTX
mkdir -p data/my_eval/myagent_exp1-20260617-seq_0007/

# 放入 agent 产出（三选一）
cp /path/to/output.pptx data/my_eval/myagent_exp1-20260617-seq_0007/
# 或者已有截图：
# cp /path/to/images/*.png data/my_eval/myagent_exp1-20260617-seq_0007/images/

# 放入题目信息
cp data/0430_test40_eval/kimi_test40-20260430-seq_0007/query_info.txt \
   data/my_eval/myagent_exp1-20260617-seq_0007/

# 有附件时复制
cp -r data/0427_attachments/seq_0007 \
   data/my_eval/myagent_exp1-20260617-seq_0007/attachments
```

## 四、配置文件（YAML）

```yaml
run_name: "my_run"                      # 结果文件前缀
description: ""

input:
  input_root: "data/my_eval"            # 相对于 benchmark/
  agents: []                            # 空=全部；填 ["myagent"] 只跑指定

output:
  results_dir: "results"

run:
  workers: 8              # 并发题数
  heartbeat_seconds: 12
  skip_done: true         # 断点续跑
  no_repair: true         # 关闭修复闭环
  debug: true             # 保存原始 prompt/response

model:
  eval_model: "gemini-3.1-pro-preview"  # 裁判模型

v2:
  enabled: true
  agentic_hard_check: false
  constraint_llm: false
  substantiveness_eval: false

pairwise:
  enabled: false

pairwise_visual:
  enabled: false
```

## 五、评测管线

每个 (agent, query) 依次经过 3 步（提示词全文见 [`0724_评测维度与提示词说明.md`](0724_评测维度与提示词说明.md)）：

**Step 1: 逐页视觉评测**
- Hard Check 4 项 + 美观 6 项 + 高层次视觉 3 项

**Step 2: 全套评测（采样页）**
- 结构完整性、跨页视觉一致性、内容质量

**Step 3: 内容评测（全部图片）**
- 固定 Core + 场景动态 Checklist（L0/L1/L2）；有源材料时再做三值忠实度

## 六、评分公式

```
page_score = 0.35 × hard_check + 0.40 × aesthetic_fine + 0.25 × aesthetic_high

deck_score = 0.40 × structure + 0.35 × consistency + 0.25 × content_quality

checklist_score = 0.20 × L0 + 0.35 × L1 + 0.45 × L2
content_score   = 0.60 × checklist + 0.40 × faithfulness  （有源材料）
content_score   = checklist_score                          （无源材料）

overall_score = 0.30 × page + 0.35 × deck + 0.35 × content
```

完整公式说明与全部提示词原文：[`0724_评测维度与提示词说明.md`](0724_评测维度与提示词说明.md)。

## 七、输出

```
results/
    <run_name>.jsonl              ← 每题一行 JSON
    <run_name>_debug/             ← 原始 prompt/response
```

### JSONL 字段

| 字段 | 说明 |
|------|------|
| `agent_name` | Agent 名称 |
| `overall_score` | 综合分（0~1） |
| `page_score` | 单页视觉质量 |
| `deck_score` | 全套结构一致性 |
| `content_score` | 内容质量 |
| `hard_check_score` | Hard Check 通过率 |
| `aesthetic_fine_score` | 美学 6 维均值 |
| `aesthetic_high_score` | 高层次美学归一化 |
| `content_checklist_score` | Checklist 得分 |
| `content_faithfulness_score` | 忠实度（无源材料为 null） |
| `pages_with_hard_fail` | Hard Check 失败页码 |
| `query_meta` | 题目元数据 |

## 九、常用操作

| 场景 | 做法 |
|------|------|
| 断点续跑 | 重跑相同命令（skip_done 自动跳过） |
| 只看数据不调 API | 加 `--dry-run` |
| 只跑某个 agent | YAML 里 `agents: ["agent_name"]` |
| 补跑 faithfulness 缺失 | YAML 里加 `skip_done_strict_content: true` |
| 新 agent 加入 | 按第三节组织数据，写新 YAML，跑 |
| 新增题目 | 按第二节 2.4 加题，重新收集 agent 产出 |
