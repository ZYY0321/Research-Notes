## E · 新训练特征 feature 频率专项（按需 · 训练侧要求时必做）

**触发条件**：当训练团队（王博/张荧滢等）**明确指出**本轮新数据主打某个 feature（如 `<file_action>` 播报、`<report>` 结构、`<subtask>` 拆分等），必须做频率专项分析并落文档，供训练侧判断"feature 是否学到、格式是否稳定、是否可迁移"。

**产出位置**：`评测任务文档/0708_生成失败showcase_模型侧.md` **末尾追加一节**（编号往后顺延，如 §13）。文档头 §0 的"变更日志"也追加一行指向新节。

**必做四项对比（每列都做）**：

| 指标 | 定义 | 用法 |
|---|---|---|
| **覆盖率** | 该 feature 在多少 case 里至少出现 1 次 / 全部 case 数 | 判断"是否学到" |
| **消息占比** | fa 消息数 / 该批全部 assistant_output 消息数 | 判断"使用密度" |
| **ok 次数** | 该 feature 后**紧跟真正 tool_call** 的次数（说明播报被真正落地） | 判断"正确使用" |
| **畸形率** | ok / (ok+bad) 里的 bad% | 判断"格式稳定性"（畸形=末轮吐 feature 后无 tool_call） |

**对比矩阵**：至少包含**上一版无该 feature 的对照** + **本版本** + **中间过渡版（如 CSFT/CSFT+DPO）**，8 批全铺开更好。让训练侧看到"没学过 → 部分学到 → 稳定学到"的完整趋势。

**脚本模板**（在 xhx_agent_v3 根目录跑）：
```bash
python3 -c "
import json, os, glob
BATCHES = {
    '<label>': '<output/testset_v2_...>',
    # ...
}
FEATURE = '<file_action>'   # 换成本次要分析的 feature 标签
def scan(d):
    n=asst=fa=ok=bad=0; cases=set()
    for cd in sorted(glob.glob(f'{d}/*/')):
        n += 1; cid = os.path.basename(cd.rstrip('/'))
        # 主 agent (result.jsonl 的 message_records)
        rj = os.path.join(cd,'result.jsonl')
        if os.path.isfile(rj):
            try: rec = json.loads(open(rj).read())
            except: rec = None
            if rec:
                msgs = ((rec.get('result') or {}).get('state') or {}).get('message_records') or []
                for i,m in enumerate(msgs):
                    if m.get('type')!='assistant_output': continue
                    asst += 1
                    if FEATURE in (m.get('text') or ''):
                        fa += 1; cases.add(cid)
                        nxt = msgs[i+1] if i+1<len(msgs) else None
                        if nxt and nxt.get('type')=='tool_call': ok += 1
                        else: bad += 1
        # 每个 subtask (subtask_*.json 的 messages) —— 必扫，大部分 feature 使用在这里
        for sf in sorted(glob.glob(f'{cd}subtask_*.json')):
            try: dj = json.load(open(sf))
            except: continue
            sm = dj.get('messages') or []
            for i,m in enumerate(sm):
                if m.get('role')!='assistant': continue
                asst += 1
                c = m.get('content')
                text = c if isinstance(c,str) else json.dumps(c)
                if FEATURE not in text: continue
                fa += 1; cases.add(cid)
                has_tool = isinstance(c,list) and any(b.get('type')=='tool_use' for b in c)
                if has_tool or (i+1<len(sm) and sm[i+1].get('role')=='tool'):
                    ok += 1
                else:
                    bad += 1
    return n, asst, fa, ok, bad, len(cases)
for L, d in BATCHES.items():
    if not os.path.isdir(d): continue
    n,asst,fa,ok,bad,cvr = scan(d)
    print(f'{L:<18} cases={n} asst={asst} fa={fa} ok={ok} bad={bad} bad%={bad/max(1,fa)*100:.1f}% pct={fa/max(1,asst)*100:.2f}% cvr={cvr}/{n}')
"
```

⚠️ **必须扫 subtask**：主 agent `message_records` 里 assistant_output 只覆盖主循环产出；**大部分 feature 使用发生在 subtask 里**（PPT 生成的多阶段 subtask 结构）。漏扫 subtask 会严重低估 feature 频率 —— 曾把 dpov2 的 fa 漏成 0（实际 3042 条 assistant 只有 1 条畸形）、csftv2 的密度算成 9%（实际 6~8% 但覆盖 100%）。判断 ok/bad 时：subtask 里 assistant 消息如果 `content` 是 list 且含 `type=tool_use` block，或紧跟的下一条 `role=tool`，就算 ok；否则 bad。

**结论段建议写清 4 件事**：
1. **是否学到**（覆盖率对比）
2. **使用密度**（消息占比对比）
3. **格式稳定性**（畸形率对比 + 特别标注 DPO 阶段是否消除畸形）
4. **副作用**（与 §6 分析文档中 content/deck/aes_high 变化对齐——feature 密度上升是否伴随其他维度回退，供 v3 训练取舍参考）
