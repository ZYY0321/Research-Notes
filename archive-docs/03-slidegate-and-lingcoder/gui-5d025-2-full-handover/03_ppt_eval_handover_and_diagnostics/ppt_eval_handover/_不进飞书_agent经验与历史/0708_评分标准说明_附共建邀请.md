# PPT 评测评分标准说明（附共建邀请）

> 目的：说明这套自动评测的**打分口径与依据**，供模型侧核对。标准全部成文、可审计——每个维度都有明确 rubric（判分 prompt），且与《人工标注指南》对齐，**不是黑盒/拍脑袋打分**。
> 若对任一维度的定义、权重、判定口径有异议，欢迎直接提，我们一起校准（见文末「共建」）。

---

## 一、总分构成（权重明确）

```
overall = page(单页) × 0.30  +  deck(全套) × 0.35  +  content(内容) × 0.35
```

三大块各自的细分：

| 大块 | 权重 | 细分维度（含权重） |
|---|---|---|
| **page 单页** | 0.30 | Hard Check 硬性质检 ×0.35 + 美学6维 ×0.40 + 高层次视觉 ×0.25 |
| **deck 全套** | 0.35 | 结构完整性 + 跨页一致性（1–5 分归一化） |
| **content 内容** | 0.35 | Checklist(L0×0.20 + L1×0.35 + L2×0.45) + 忠实度(三值) |

权重与打分逻辑均在代码里固定（`run_from_config.py`），每条 case 的打分明细（各维度分值 + evidence）都落盘在结果 jsonl，可逐条复查。

## 二、各维度评分依据（rubric 来源）

每个维度对应 `benchmark/evaluators/prompts/` 下一份 prompt，即**给判分模型的评分细则**。要点摘录：

### 1. 单页 · Hard Check（硬性质检，4 项，只判「有无问题」不评美观）
`page_eval_prompt.md`（含判定优先级 + 易混项速查表）：
- **boundary_crop** 边界与裁切：元素超出页面/容器或被异常裁切
- **occlusion_overlap** 遮挡与重叠：字压图/图压字且影响阅读
- **content_integrity** 内容完整性：空白因未填内容、图表缺图例/轴/标题、未替换占位符
- **image_quality** 图片质量：图/图表模糊、拉伸、失真、锯齿

> rubric 明确了**判定优先级**避免重复扣分，例如："空白因内容未填 → 标 content_integrity，不要再标间距失衡""图表缺图例/轴 → 属内容完整性而非排版""标题页允许设计性留白"。

### 2. 单页 · 美学 6 维（0/1/2 三档）
布局 3 项：layout_alignment 对齐 / layout_spacing_balance 间距留白均衡 / component_style_consistency 组件风格一致；
排版 3 项：text_legibility 文字可读 / font_hierarchy 字号层级 / line_spacing_typesetting 行距排版。

### 3. 单页 · 高层次视觉
整体卷面观感（1–10），子维含 layout_hierarchy_path 布局层次、visual_language_polish 视觉语言精致度、overall_visual_impression 整体印象。

### 4. 全套 deck
- **结构完整性** structural_completeness：封面/目录/正文/结尾等结构件是否齐备
- **跨页一致性** visual_consistency：整套 PPT 风格/配色/版式统一度

### 5. 内容 · Checklist（三层，`content_checklist_gen/eval_prompt.md`）
固定核心维度（准确性/相关性/完整性/适量性/一致性/可理解性）+ 6–10 条**场景动态特化项**（按 query/场景/受众生成）。每条分三层打分：
- **L0 存在性**（×0.20）：该信息模块是否出现
- **L1 具体性**（×0.35）：是否给出具体内容而非泛泛而谈
- **L2 适切性**（×0.45）：是否匹配该场景的合理专业期待（注：**L2 不是越深越好，而是是否匹配场景**）

### 6. 内容 · 忠实度（三值，`content_claim_3val_prompt.md`，有源材料的题才评）
逐条提取事实性声明，与源材料比对分三类：
- **supported**：源材料中有直接依据
- **derived**：基于源材料的合理计算/推断（**推导可追溯即算对，非错误**）
- **unsupported**：无依据也非合理推导（幻觉/编造/过度推断）

> 明确区分了 derived 与 unsupported（"给了各季度销售额→写全年增长率且算对=derived；只有 2023 数据→写预计 2025 增长=unsupported"），并豁免首页占位符/尾页结束语。

## 三、判分模型与可靠性

- 判分网关：TokenHub Claude sonnet（统一口径，同一套 prompt）。
- 近期修复了一个**内容分静默 bug**（判分网关偶发空返回被当成「0 条检查项」→ 内容分虚高），已加重试+失败即报错，不再静默降级；本轮所有数据均为修复后的干净口径（动态检查项缺失率为 0）。因此**同一模型修复前后分数会有变化**，请以最新重判结果为准。
- 每条 case 打分明细（各维度值 + evidence 短评）均可导出逐条核对。

## 四、共建邀请

这套标准是为了**客观可比**，不是终审判决。如果模型侧对以下任一点有异议，欢迎提出，我们一起校准：

1. **权重**：page/deck/content 的 0.30/0.35/0.35，或单页内 Hard/美学/高层视觉的 0.35/0.40/0.25 是否合理？
2. **维度定义**：某个维度的判定口径是否过严/过宽、是否有歧义（尤其易混项）？
3. **场景适配**：Checklist 的场景动态项是否覆盖了你们关注的能力点？
4. **缺失维度**：有没有你们认为重要、但当前没评的能力（比如某类交互/图表/特定版式）？

我们可以把有争议的维度拉出来，用具体 case 对齐一次口径；也欢迎模型侧提出希望新增的评测维度。
