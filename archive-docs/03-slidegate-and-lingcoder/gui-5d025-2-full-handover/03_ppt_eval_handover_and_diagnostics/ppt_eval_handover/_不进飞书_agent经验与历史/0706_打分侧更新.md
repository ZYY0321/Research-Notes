## 1. 三个修复 / 勘误（重点）

### ① content 评测 JSON 解析 bug（会静默丢分）
- **现象**：跑完后一批 case 的 `content_score` 是 null（上轮 269 条丢了 71 条）。
- **根因**：评测 LLM 输出的 JSON，string 值里嵌了**未转义的英文双引号**（中文写 `"..."专业、高效"..."`），
  `json.loads` 崩溃 → checklist 生成/评估解析成空 → content 分丢失。内容其实都在 raw_response 里。
- **修复**：`benchmark/evaluators/content_evaluator.py` 的 `_extract_json()` 末尾加了 `json_repair` 兜底，
  并删掉了有害的 `s.replace("'",'"')` fixer。**已修，新跑的不会再丢。**

### ② Claude 网关图片格式 bug（换 tokenhub 后必踩）
- **现象**：打分请求（要发页面图给 claude）全部 `400 Input tag 'image_url' ... does not match`。
- **根因**：`models/gemini_model.py:_chat_anthropic_native` 把 OpenAI 风格 `{"type":"image_url"}`
  直接发给 Anthropic 原生 `/v1/messages`（tokenhub），它只认 `{"type":"image","source":{base64}}`。
  （老的 34.96 网关是 one-api 类会自动转，换 tokenhub 后不转就崩。）
- **修复**：加了 `_to_anthropic_message()` 统一转换，两种网关都兼容。**已修。**

### ③ content 补齐后必须重算 overall（0703 文档漏了这步）
- overall = `0.30×page + 0.35×deck + 0.35×content`（见 `config.py` PAGE/DECK/CONTENT_WEIGHT）。
- content 缺失时聚合器走 no_content 归一化（page/deck 重新分权）；**content 补上后 overall 会变**。
- 所以补分 / 修分之后**必须重算**：
  ```
  cd ~/zyy/benchmark && conda activate ppt-eval
  python -m benchmark.recompute_overall_jsonl --jsonl results/<run>.jsonl --in-place
  # 再重生成 summary：
  python -c "import sys;sys.path.insert(0,'/home/gui-5d025-2/zyy');\
from benchmark.aggregator import BenchmarkAggregator;\
BenchmarkAggregator(results_dir='results').generate_summary(run_name='<run>')"
  ```
  （`recompute` 会自动备份 `.bak`。dashboard 靠 scores_jsonl 的 mtime 自动重建，重算后自动刷新。）

### 补充脚本：`benchmark/scripts/fix_content_missing.py`
- 若某次跑分后仍有 content=null（如老数据、或中途网关抖动），用它补：
  - 自动分两类：eval-only 失败 → 离线重解析（不调 LLM）；gen 失败 → 重跑（调 LLM）。
  - 支持 `--workers 8` 并发（**串行极慢，务必并发**）、`--dry-run`、`--offline-only`、`--limit N`。
  - 每条即时原子写回，中途挂不丢进度。

## 2. 完整「打分 + 上板」流程（照这个走）

前提：deck 已生成在 `xhx_agent_v3/output/`（或 imported）。打分在 `~/zyy/benchmark` 做。

```bash
cd /home/gui-5d025-2/zyy/benchmark && conda activate ppt-eval
```

### Step 1 — deck 转成 benchmark 输入
```bash
python scripts/build_benchmark_eval.py   # 见脚本头注释，把 <run> deck 转成 code/*.html+query_info.txt+attachments
# 产物落 /data/gui-5d025-2/benchmark_eval/<集名>/<version>_test40-<date>-<seqid>/
# agent_name = version（folder_loader 用 _test40 分隔切出）
```

### Step 2 — 跑分（务必带这串 env，否则网关不对 / 无限重试挂住）
```bash
WANGBO_CLAUDE_BASE=https://tokenhub.sensetime.com \
WANGBO_CLAUDE_KEY="$(python3 -c 'from config import TOKENHUB_API_KEY;print(TOKENHUB_API_KEY)')" \
GEMINI_MAX_RETRIES=3 GEMINI_REQUEST_TIMEOUT=120 GEMINI3_EVAL_MAX_RETRIES=3 \
python -u run_from_config.py configs/<你的>.yaml 2>&1 | tee results/<run>.log
```
- config 参考 `configs/industry_v2_all.yaml`（eval_model=claude-sonnet-4-6，workers=16，skip_done=true）。
- 判分模型是**固定的 claude-sonnet-4-6**（走 tokenhub），**不是被测模型** → 被测模型有无多模态不影响打分。
- 产物：`results/<run>.jsonl`（每行一个 agent×query）。

### Step 3 — 检查 content 覆盖，必要时补 + 重算 overall
```bash
# 看有没有 content=null：
python3 -c "import json;r=[json.loads(l) for l in open('results/<run>.jsonl') if l.strip()];\
print('content缺失:',sum(1 for x in r if x.get('content_score') is None),'/',len(r))"
# 若 >0：并发补
WANGBO_CLAUDE_BASE=... WANGBO_CLAUDE_KEY=... python scripts/fix_content_missing.py --workers 8
# 补完（或任何改分后）重算 overall + summary（见 §1③）
```

### Step 4 — 上板
编辑 `xhx_agent_v3/results_dashboard/runs.json`，给对应 run 加：
```json
"scores_jsonl": "/home/gui-5d025-2/zyy/benchmark/results/<run>.jsonl",
"scores_agent": "<该版本在jsonl里的agent_name，默认=run id>"
```
- runs.json 改动**不用重启**服务（`_watch_signature` 监视 mtime 自动重建）。
- 只改了 `server.py` 代码才需 `systemctl --user restart ppt-dashboard`。
- 看板：http://10.151.196.17:8770/

## 3. 被测模型「无多模态」的影响（本轮新模型的疑问）

**结论：不影响打分，基本不影响生成。**
- 打分侧：判分用固定的 claude-sonnet-4-6，与被测模型无关。
- 生成侧：config 里 `llm` 块=被测模型（只做文字→HTML），看图的活（stage6 视觉复核 / VQA）走**独立的 `vlm` 块**（gemini-3-flash-preview）。被测模型不看图，所以无多模态不卡生成。
