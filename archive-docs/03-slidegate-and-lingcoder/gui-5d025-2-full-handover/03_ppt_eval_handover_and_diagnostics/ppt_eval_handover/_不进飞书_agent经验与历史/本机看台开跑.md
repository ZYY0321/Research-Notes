给人看的摘要在上一级 `[260911]评测交接（人读）.md`。本文给 agent 填表和监控。

## 地址

- 对比看板：http://10.151.196.17:8770/
- 开跑（经 8770 反代）：http://10.151.196.17:8770/automation
- 开跑直连：http://10.151.196.17:8877/ （`automation/server.py`，默认端口 8877）

## 填表

| 字段 | 怎么填 |
|---|---|
| tag | 英文数字下划线，如 `flash284b_opd` |
| label | 看板展示名，**对方原文**；同一模型 notpl/tpl 必须相同 |
| 主端点 | 办公网 `10.210.9.14:端口`，不必写 `http://` 和 `/v1` |
| model | `/v1/models` 返回的 **id**，不是口头简称（有的必须带 `vllm-` 前缀） |
| protocol | `openai` 或 `anthropic` |
| api_key | 内网端点常可留空；TokenHub 等外网必须有，只放环境/表单，不写 Git |
| concurrency | 默认 4 |
| 沙箱 | 办公网主端点用腾讯云 `http://62.234.119.98:3000`；不要把办公网端点配内网沙箱 |
| HTML 端点/模型 | 可空=主模型 |
| thinking | 默认开；reasoning_effort 默认 `xhigh`（只进 `extra_body.chat_template_kwargs`） |
| review | 见下方「Review 模型配置」 |

先探活，再开跑。会同时起 notpl + tpl，≥20 题有 HTML 时早打分，整批结束后终打分，并登记 8770。

## Review 模型配置

无模板模式生成后有「截图视觉 review」步骤，review 模型**必须支持多模态**（看图能力）。根据主模型是否支持多模态分两种情况：

**情况 A：主模型支持多模态（自家 SenseNova 系列）**  
→ review 用**主模型自身**，看台 review 相关字段留空即可（脚本默认回退到主模型端点）。

**情况 B：主模型不支持多模态（DeepSeek、GLM、Qwen 等纯文本模型）**  
→ 必须单独给 review 配一个多模态模型，当前标准选项：

| 字段 | 值 |
|---|---|
| `PPT_HTML_REVIEW_BASE_URL` | `http://10.120.4.82:8787`（内网，沙箱可直连）|
| `PPT_HTML_REVIEW_MODEL` | `qwen3.7-plus`（近期实验部分也用 `qwen3.8-max-a`）|
| `PPT_HTML_REVIEW_API_KEY` | 见 skills 目录下 `_html_llm_direct.py` 中 `DEFAULT_REVIEW_API_KEY`（不写进文档）|
| `PPT_HTML_REVIEW_PROTOCOL` | `openai` |

> 看台表单里的 review 字段直接填 `qwen3.7-plus` 即可，端点和 key 会从 skills 脚本默认值读取。  
> 不要把 `10.210.9.14`（办公网主模型端点）填进 review 字段，那些端点普遍不支持图文混排。

**忘配的后果**：不支持多模态的主端点收到带图片的 review 请求会 400/500，脚本捕获后触发 `PPT_SKIP_HTML_REVIEW` 静默跳过 review 步骤，生成页面不经视觉修正直接交付，分数可能偏低。

## 开跑后 agent 必须做

1. 另开窗口持续 monitor，按手册 §0.1。
2. 看 `automation/tasks/<tag>/` 与对应 `output/testset_v2_*` 的 `events.jsonl`，不要只信看台徽章。
3. 异常当轮写可转发反馈：先分模型 / serving / 管线 / 沙箱。
4. `--resume` 只捡 `infra_failed`/被杀；不要新开 OUT 覆盖已成功题。
