## 步骤 ① 探活端点（省得白跑一批）

新模型给的是一个端点地址 + 一个 served model 名（`/v1/models` 里的 `id`，**未必等于模型代号**，如 checkpoint-2200）。

```bash
M=<served模型名>      # curl 端点/v1/models 拿到的 id
EP=http://<ip>:<port>
curl -s $EP/v1/models                       # 看 served 名、max_model_len
# 字符串 content（基线，必须 200）
curl -s -o /dev/null -w "%{http_code}\n" $EP/v1/messages -H 'content-type: application/json' -H 'anthropic-version: 2023-06-01' -H 'x-api-key: dummy' -d "{\"model\":\"$M\",\"max_tokens\":16,\"messages\":[{\"role\":\"user\",\"content\":\"hi\"}]}"
# 数组 content（agent 实际会发这种；必须 200，否则见端点坑文档，要模型侧修）
curl -s -o /dev/null -w "%{http_code}\n" $EP/v1/messages -H 'content-type: application/json' -H 'anthropic-version: 2023-06-01' -H 'x-api-key: dummy' -d "{\"model\":\"$M\",\"max_tokens\":16,\"messages\":[{\"role\":\"user\",\"content\":[{\"type\":\"text\",\"text\":\"hi\"}]}]}"
```
- 数组 content 若 500/400 → 端点没实现 block 数组，**必须先让模型侧修**（复现见 `0706_checkpoint2200_端点报错复现.md`），否则 agent 每次调用必崩。
- `tool_choice:{"type":"none"}` 若 400 → 已知坑，但只在极端 case 触发、不阻断，可以先跑。
- 首次 curl 偶发超时(000) 属冷启动，复测两次确认。

⚠️ **max-turns 用 20**（batch_run_test.sh 默认写死 8，重题不够用会截断成 done_no_html）。⚠️ **用独立新 OUT 目录**（sandbox 是历史混放，防复用旧 deck 报假 done）。

```bash

nohup uv run python scripts/run_batch_and_export.py \
  --input data/added/ppt_testset_industry_balanced_v2.jsonl \
  --output "$OUT" --config conf_v3_zh_<标志>_$(date +%Y%m%d).yaml \
  --concurrency 4 --max-turns 20 --seed 42 \

  --disable-skills deep-research > "$OUT.log" 2>&1 &

```

## 已知坑清单（都踩过）

| 现象 | 根因 | 对策 |
|---|---|---|
| 3.6s "done"、0 png、deck 是旧的 | sandbox 混放，复用了历史 deck | 用独立新 OUT 目录 |
| done_no_html / 被截断在准备阶段 | max-turns 8 不够 | max-turns=20 |
| 大量 render_suspect、轨迹里 `｜DSML｜` 乱码 | **模型自身**工具调用能力弱，吐畸形 tool call | 非流程 bug，是评测结论（这版模型不达标） |
| 数组 content → 500/400 | 端点没实现 block 数组 | 模型侧修端点 |
| tool_choice=none → 400 | 端点没实现该参数 | 极端 case 才触发，可先跑；一并报模型侧 |
| **html 是 1 字节空壳但仍进打分** | 转换脚本 scan_pages 只数文件、不查空 | 见下「待修」 |
| png 全 0 | 生成侧本就不出 png，打分侧 folder_loader 渲染 html→png | 正常，不是问题 |

## 待修（转换脚本漏洞，2026-07-07 发现）

`build_benchmark_eval.py` 的 `scan_pages` 只判断 `page_*.html` 文件存在，**不检查文件是否为空**。若模型产出 5 个 1 字节空壳 html（如 step2k 的 seq_0206），会被当成 5 页收进打分、给出污染性低分（overall 0.17）。应加：过滤掉大小近 0（如 <100 字节）的空壳页；全空则该 case 跳过（按失败计，不进打分）。
