## 1. 评分展示对齐：重叠 / 冲突 /「以前的分好像变了」

**问题**
- 看板上分数与 case 的对应方式需要彻底厘清：是否会错挂、重叠、旧分污染新批。
- 有人反馈「以前的结果评分好像变了」——需区分：**真重判**、**展示错挂**、**jsonl 残留旧行**、**overall 公式重算**。

**已知事实（本周踩过）**
- Dashboard 用 `_seq_key` 把 `query_id`（如 `gpt56sol_tpl_q7`）与 case id（`seq_0007` / `prod_adda7bc8`）按**数字序号**对齐；短序号易冲突（`_q7` 与 `prod_*7*` 同键）。
- 正式 `scores_jsonl` 路径由 VERSION 固定；`auto_pipeline` 打分 `skip_done: true`，旧 jsonl 不挪走则**不会被全量覆盖** → 看板挂陈旧分（例：卉辛 59.5 混进正式 `gpt56sol_tpl`）。
- 手册已补「分数文件隔离」：`0708_评测复现完整手册.md` §4 / §8。

**建议动作**
1. 写清并贴在看板：分数 join 规则（`dashboard_case_id` / `_seq_key` / `scores_agent`）。
2. 评估是否改为 **case_id 精确匹配**（或强制 `dashboard_case_id`），避免短数字碰撞。
3. 对「分变了」做可追溯清单：该 jsonl 的 mtime、是否 rejudge / recompute_overall、是否换过 judge / checklist。
4. 正式批挂 pipeline 前检查：对应 `industry_v2_<id>.jsonl` 为空或不存在。

## 2. Trace 展不开部分 subagent（xhx 管线 id 落盘）

**问题**
- 逐套 Trace 里，有的 subagent 记录展示不出来；与跑批时 **subtask id / 文件名** 记录有关，需改 **xhx 管线**（非仅 dashboard）。
- 改动时**维护好 git 分支**，后续可能要上传 / 合入。

**是否有过记录：有**
- `benchmark/docs/0717_周报_0714至0717.md`（7/16）：seq_0216 少展开一段 subagent，根因 `agents/agentv3/agent_v3.py` ≈1627 `_enqueue_delegate_tasks` 的 **`subtask_counter`**：两次 `create_subtask` 都写成 `subtask_0`，第二次覆盖第一次。
- 当时结论：**dashboard 展示逻辑正确**，是 agent 侧落盘 bug；dashboard 侧 7/15 已支持按 `parent_tool_call_id` 挂 `subtask_*.json`（见 `0715_交接文档.md` §2.2）。

**建议动作**
1. 在独立分支修 `subtask_counter` / 落盘命名（如 `subtask_{n}` 单调递增、禁止覆盖），附复现 case。
2. 修完后用「同 case 多 subtask」回归：磁盘文件数 = create_subtask 次数，Trace 全部可展开。
3. 分支命名建议：`fix/subtask-counter-id`（或团队约定前缀），commit 写清复现与影响面。

## 3. 顶部模型标签：两栏布局

**问题**：顶部标签横向堆叠难看。  
**建议**：分成两栏——**左：模板模式 / 右：无模板模式**（同模型上下或左右对齐，减少一长串混排）。

---

## 4. 逐套面板：质量分布 vs「vs 基准」拆开

**问题**：质量分布是独立模块，不应与「vs 基准」分数挤在同一块。  
**建议**：所有 **vs 基准** 相关控件/数字归一组；**质量分布**单独成块，视觉上分开。

---

## 5. 面板标注总分计算与维度关系

**问题**：总分怎么算、各维度（page / deck / content / hard_check / aesthetic…）权重与关系不直观。  
**建议**：在面板固定位置加简短说明（或「?」浮层）：公式 + 各维含义 + 与 overall 的关系；与 `recompute_overall` / 手册口径一致，避免口头口径漂移。

---

## 6. 后置产物是否已更新到最新版本

**问题**：面板依赖的后置产物（如 `model_analysis.json`、summary、人评标签、生成侧 dashboard 静态页等）是否都已跟到**当前 runs / 最新批**。  
**建议**：做一次清单核对（runs ↔ analysis 卡 ↔ scores jsonl ↔ OUT 目录）；缺的补齐或在 UI 标「产物过期 / 缺失」。

---

## 7. 按需导出评分结果

**问题**：需要导出能力——例如勾选若干模型，导出其评分结果（jsonl / csv / 汇总表，口径待定）。  
**建议**：8770 增加「选择 runs → 导出」；导出字段至少含 case_id、query、overall 与各维、timestamp、scores 来源路径，便于周会/对外贴表。
