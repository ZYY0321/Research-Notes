## 二、关键发现（按重要性排序）

### 发现 1：判分侧存在系统性口径漂移，且是"看起来分差"的主要噪声源
**证据**：prod_1eaed984（宝马 M4）CSFT 视觉明明更好、人眼判断领先，overall 分却低 DPO v2 −0.12。根因是 `dynamic_checklist` 每次现生成，同 query 不同模型抽到不同 checklist——CSFT 抽到"图文搭配"L0 硬约束把它拉低 −0.31。

**修完后的口径变化**：全量 4 模型重跑，CSFT vs DPO v2 相对排名从"打平 (Δ 0.003)"变成 "**CSFT 领先 0.024**"，与人眼判断对齐。

**方法层教训**：判分侧任何"每次现生成"的中间产物都是漂移风险源。dynamic checklist、prompt 里的临时指令、判分 rubric 的自由文本项都需要审视是否应该固化到基线。

**文档需要完善**：
- `评测任务文档/0708_评测管线问题与现状.md` 需要新增 §"dynamic_checklist 口径漂移" 章节，把 case + 修复 + 效果写清楚
- `评测任务文档/0708_评分标准说明_附共建邀请.md` 需要明确说明"我们现在用**固定 checklist 基线**（预生成 + LLM 合并 + 缓存）"

### 发现 2：DPO 训练对"工具调用格式稳定性"有明确正向作用，是隐藏收益
**证据**：
- CSFT_notpl 3/47 挂在畸形 XML（`<file_action>...</summary></invoke>`）
- CSFT+DPO_notpl **47/47 全 done**（自家版本第一次达到 100%）
- DPO v1/v2 系历史失败共 9 例，**无一例是畸形语法**
- OTTO 无 DPO：44/47 挂在 XML，怎么改 prompt 都压不住（移除 `<file_action>` 后立刻被 `<invoke>` 取代）

**结论**：**DPO 阶段用偏好信号对"结构化 tool call vs XML tool call"做了有效约束**，这是纯 SFT 学不出来的。overall 分数上 DPO 阶段不加分（CSFT+DPO 反而略低于 CSFT），但**生成可靠性 100% 是产线级别的红利**。

**方法层教训**：evaluate 时不能只看 overall，**"生成成功率" + "重试鲁棒性" 是产线必须的独立维度**，评测管线现在只报 done/failed 比例，没独立打分。

**文档需要完善**：
- `评测任务文档/0708_模型特点与缺陷分析.md` §7 已加"CSFT+DPO 是推荐路线"（本周已完成）
- **评测管线需要新增维度**："生成成功率" 应该独立报出来（现在藏在失败 case 里，只有 dashboard `terminal_class` 分布能看）
- 后置产出清单应该强制填"生成成功率" 一栏

### 发现 3：CSFT 走观感路线、但存在人评能看到而机评看不到的短板
**证据**（人评 0714 vs 机评对比）：
| 维度 | 机评 | 人评 |
|---|---|---|
| **观感/字体/间距** | CSFT_notpl 领先（aes_high 0.905, spacing 0.881） | 一致，CSFT 视觉更精致 |
| **图表能力** | 未捕捉 | **CSFT 明显弱于 DPO v2**（短稿几乎没图、图表种类少） |
| **跨风格适配** | 未捕捉 | **CSFT 差**（游戏/生日会/品牌类没"那味儿"） |
| **装饰疲劳** | 未捕捉 | **CSFT tpl 装饰重复堆砌**（"▶▶▶"/星星/散点重复用） |
| **overall 结论** | notpl CSFT 领先 0.024 / tpl 打平 | **DPO v2 更好**（无论 notpl 还是 tpl） |

**结论**：机评在**观感的细粒度维度**（对齐、间距、字号）分辨力强，但**在"图表多样性、跨风格适配、装饰疲劳"这类"内容-呈现匹配度"维度上失明**。机评的 aes_high（1-10 整数打分）+ aes_fine（0/1/2）都是**对页面本身**的评价，没评价**"页面内容与题目类型匹配度"**。

**方法层教训**：机评需要补一个 **"内容-呈现匹配度" 维度**，这是当前判分空白。

**文档需要完善**：
- `评测任务文档/0708_评分标准说明_附共建邀请.md` 需要新增"当前空白维度"章节，把这 4 项写清楚，作为下一步扩展 rubric 的输入
- 详见本次同步产出的 `benchmark/docs/0715_评测标准评价与rubric建议.md`

### 发现 4：模板模式全员塌方，训练侧当前解决不了
**证据**：CSFT_tpl (0.654) ≈ DPO v2_tpl (0.654) ≈ CSFT+DPO_tpl (0.652)——**三条不同训练路线在模板模式下打平**（Δ < 0.003）。CSFT_notpl 的 aes_high 0.905 在 tpl 下塌到 0.698（−0.207）。连 Opus 4.7 模板模式也塌方（0.827→0.726）。

**根因**：套模板后"占位区不填→大面积空白→重心失衡"是共性瓶颈，训练路线在这一层被抹平了。

**方法层教训**：**模板任务的挑战主要在 skill/prompt/管线层，不在模型层**。基模团队的训练调优不应该重点看模板模式分数，重点看无模板模式。

**文档需要完善**：
- `评测任务文档/0708_模型特点与缺陷分析.md` §7 已强调"模板模式先修链路再谈模型"（本周已强化）
- 后续产出报告时要标注这一点，避免误导训练团队去优化模板任务而没修 skill

### 发现 5：Otto agent v1.1 step5700 是纯模型侧问题
**证据**：44/47 失败，模型 thinking 完全正常（`reasoning` 字段有完整 CoT），但输出的**每个复杂 tool call 都退化成 XML**。移除 `<file_action>` 规则重跑，`<file_action>` 消失但立刻被 `<invoke>` XML 取代——**同 SFT 学到多套 XML tool call 模板，prompt 层修不了**。分裂点在"参数是否嵌大段结构化载荷"：`read_file`/`execute_shell_command` 简单调用正确、`write_file`/`create_subtask` 复杂调用退化。

**方法层教训**：接入外部模型需要 smoke test 阶段就跑完整 agent loop（不是单轮），能提早发现这类"简单 tool call 对但复杂的错"的问题。

**文档需要完善**：
- `评测任务文档/0707_新模型接入评测_端到端总纲.md` 需要加"接入前 smoke test 检查清单"：至少跑 3 个包含 `write_file`/`create_subtask` 的 case 验证复杂 tool call 稳定性
- 深度分析 + 复现工具集已经在 `评测任务文档/0714_otto_prod_1eaed984_失败trace分析.md` + `0714_otto_repro/`

### 发现 6：Dashboard 之前不显示 subagent，评估遗漏严重
**证据**：Dashboard 之前 trace 视图只显示 main agent，subtask 完全隐藏。修复后每个 case 主 agent 里 `create_subtask` 的 tool_result 下面能看到嵌套子任务对话（3-4 个 subtask × 6-8 turns，是评估质量的关键数据）。

**方法层教训**：评测的"可观测性"决定了能否 debug 到根因。之前找不到失败根因，很多时候不是模型问题而是 dashboard 没显示到位。

**文档需要完善**：
