## 〇、概况

- **现在日常用的评测**：每套 PPT 打三块分——单页视觉、整套结构、内容质量，加权成一个总分，结果在看板上看。评分模型一直是 Claude Sonnet 4.6。
- **它的主要不足**：内容分偏向"写得多、写得满"；一些人看得出的问题（页面下半截空、图表没画完、字太小）在总分上体现不明显；产品提的评测维度里，"有没有按用户要求做"这一项还没有。
- **新版评测（半成品）**：新增"指令遵循"，内容里新增"必要要点覆盖率"，三个维度分开出分。各维度做过一轮稳定性和人工一致性检查，有些地方一致性还不高。**代码没有接入日常管线，也没有统一入口。**
- **需要后续决定的**：日常总分以后怎么算（要不要加新维度、权重怎么定）、严重问题（裁切遮挡、明确要求没做到）要不要单独标出来、维度内部的权重要不要重新校准。

### 1.1 看板上能看到什么

| 页签 | 看什么 | 配图 |
|---|---|---|

| 跨版本对比 | 选一道题，左模板 / 右无模板，多个版本并排看产物 | `02_看板_跨版本对比.png` |
| 导出评分 | 勾选版本导出表格 | `03_看板_导出评分.png` |
| 模型分析 | 页顶"指标速查"解释每个分数；下面每个模型一张卡：优点 / 典型缺陷 / 分维分数 | `04_看板_模型分析.png`、`06_看板_模型卡分维分数.png`、`07_看板_模型卡分维分数_续.png` |

> 贴图建议：`01` 说明"一行一个版本、看均分"；`06`+`07` 说明"一个模型有哪些分维分数"。

看板上的分数含义：

| 看板字段 | 含义 |
|---|---|
| `overall` | 总分，0–1 |
| `page_score` | 单页综合：硬伤 + 细节美观 + 整体美观，取全部页的平均 |
| `hard_check` | 硬伤：文字/图片被裁切、内容遮挡、内容残缺、图片质量差 |
| `aesthetic_fine` / `aes_high` | 细节美观（对齐、间距、字号层级、配色…）/ 整体美观 |
| `deck_score` | 整套：结构是否完整、页与页风格是否一致、内容是否完整 |
| `content_score` | 内容：要点有没有、具不具体、重点对不对；有附件时再看内容是否忠于附件 |

### 1.2 公式

```
overall    = 0.30 × page + 0.35 × deck + 0.35 × content       （有内容分时；缺项按剩余权重归一）
overall    = 0.40 × page + 0.60 × deck                        （仅 query、无内容分时）

page       = 0.35 × 硬伤 + 0.40 × 细节美观 + 0.25 × 整体美观
deck       = 0.40 × 结构 + 0.35 × 一致性 + 0.25 × 完整度（有报告）/ 内容质量（仅 query）
清单分     = 0.20 × L0 + 0.35 × L1 + 0.45 × L2
content    = 0.60 × 清单分 + 0.40 × 忠实度                      （有可读附件）
content    = 清单分                                             （无附件）
```

L0：要点有没有；L1：是否具体；L2：重点、逻辑、受众是否合适。每道题的内容清单是固定的，在 `$BENCH/checklist_lib/industry_v2/`。

## 二、日常评测的不足

### 2.1 和产品要的评测维度对比

产品给过一张端到端评测维度表：[飞书：[260727]产品端到端评测维度：测试反馈](https://sensetime.feishu.cn/wiki/MhiXw7sFciYjYIk85wVcBLownzc)。我们逐项看了每一维能不能评、评得稳不稳、能不能拉开差距：

- **能不能评**：只看渲染后的页面截图 + 用户要求 + 附件，能不能判。
- **评得稳不稳**：同一模型重跑、换个模型、故意造错，结论是否一致。
- **能不能拉开差距**：不同系统之间的分数能不能区分开。

逐项结论见 `$BENCH/handoff/[260824]产品维度逐项对齐_实验与纳入结论.md`。

| # | 产品维度 | 日常管线现状 | 新版处理 |
|---|---|---|---|
| 1 | 指令遵循 | **没有** | 新增为独立维度 |
| 2 | 内容准确性与事实性 | 有附件时有忠实度 | 同左；无附件时判不了 |
| 3 | 内容完整性 | 清单 L0/L1/L2 | 新增"必要要点覆盖率" |
| 4 | 结构与叙事 | 整套结构分 | 试过单独打分，大多数稿子都接近满分、拉不开，只做参考 |
| 5 | 单页信息组织 | 隐含在单页美观里 | 试过单独打分，实际量到的是文字密度和留白，和视觉重叠，只做参考 |
| 6 | 排版与设计 | 单页视觉 | 同左 |
| 7 | 图表与图像质量 | 图片清晰度在硬伤里 | 图片清晰度、图表缺零件（只有色块没坐标轴、空框）在视觉里检查；**图表数字对不对得上，只在有附件时作为页面上的数字陈述去和附件比对**，没有专门的图表核对，无附件时不做 |
| 8 | 交付物能否打开 | 不评 | 截图看不出，归工程 |
| 9 | 可编辑性 | 不评 | 截图看不出，归工程 |
| 10 | 场景与受众适配 | 在内容 L2 里 | 明确写出的受众要求进指令维度 |
| 11 | 交付效率 | 看板有耗时统计 | 归工程 |
| 12 | 安全与合规 | 不评 | 没有可复核的依据，归工程 |

### 2.2 看稿子时发现的问题

下面是对照看板分数和实际页面时整理的观察（摘自给模型侧的分析）。**这些是人工看稿的印象，不是系统性结论**；哪些分数能反映、哪些反映不明显，写的是当时的观察。

**（1）内容分偏向"写得多"**

- 内容清单里 L1（是否具体）和 L2 权重最大，写得越满越容易拿分；但写得满的页面往往更挤。
- 有过数据参考：旧内容清单分和人评系统排名的相关只有 0.455（不显著），是当时几个自动指标里最低的（来源：`$BENCH/handoff/[260824]实验总账_设置结果与Benchmark影响.md` H3）。
- 看稿时也有过这种情况：某个版本总分领先，主要靠内容清单多命中；但忠实度更低，人看反而觉得另一个版本更好（`step3kdpocsftv2_tpl` vs `step3kdpov2_tpl`，记在 `测试结果文档汇总/[260708-0817]机评模型特点与缺陷分析.md`）。

**（2）人工看稿常见的四类问题**

| 类别 | 现象 | 分数上的体现 |
|---|---|---|
| 布局 | 页没填满，字堆在卡片上半截，下半页大面积空白 | "间距均衡"是单页美观里扣分最多的一项，能反映一部分 |
| 图表 | 图表只有色块、没有坐标轴和图例；示意图/流程图没画出来，页上剩一个空框 | 硬伤里的"内容残缺"会扣，但 4 项硬伤取平均，单页出问题对总分影响较小 |
| 整套结构 | 缺目录；目录和正文对不上；目录写到的页最后没有 | 结构分会降，但"目录和正文是否一一对应"没有单独检查 |
| 细节美观 | 同页卡片高低不齐、标签颜色不统一、字太小看不清 | 只在组件一致和行距上扣一点；**字太小评分模型通常认为没问题** |

另外，模板模式经常看到"页被砍掉（十几页变成六七页）+ 大片留白"，以及占位符（`XX`、`YYYY-MM`、"【待填】"）没替换。

**（3）看板模型卡和人工看稿的关系**

看板模型卡是 agent 根据分数和页面自动写的，人工看稿时有几次判断不一样，主要在"整体观感""和场景是否搭""某一页是不是空的"这类需要整套看下来的地方。两边的差距目前没有系统地比较过。人工看稿的记录可参考：

| 记录 | 位置 |
|---|---|
| 给模型侧的群消息分析（上面四类问题的出处） | `$BENCH/handoff/群消息模型分析.txt` |
| 外包人评的评价（孙继业，0708–0714） | `$ROOT/评测任务文档/人评0730.md` |
| 肉眼对比工作笔记 | `$ROOT/评测任务文档/0727_flashv39_肉眼对比工作笔记.md` |
| agent 写的模型卡源稿 | 本包 `测试结果文档汇总/[260708-0817]机评模型特点与缺陷分析.md` |

> 建议：后续改进与其继续在日常总分上微调，不如放在新增维度上迭代（指令遵循、要点覆盖，以及下面第四节提到的严重问题标记），因为这几类问题本身更明确、更好验证。

### 2.3 评分模型

- 日常一直用 **Claude Sonnet 4.6**。所有历史分数、看板、总分表都是这把尺子。
- 试过 GPT-5.6 也能用，但兼顾效率，一直沿用 Sonnet。
- 如果要换模型，注意不同模型对"细节视觉缺陷"和"整体美观"的敏感程度不一样。7 月做过一次 GPT-5.6 和 Sonnet 4.6 的对比（360 例）：
  - 单页分整体接近（相关约 0.83）。
  - GPT 对溢出、重叠、底部留白这类硬伤更严；整体美观也更严，Sonnet 更爱给满档。
  - 整套和内容分 GPT 系统性偏低，但模型之间的相对顺序大体不变。
  - 来源：`$ROOT/评测任务文档/0717_GPT5.6terra_vs_sonnet46_judge对比.md`、`0717_GPT5.6terra_视觉判分详细分析.md`。
- 换了评分模型，对照基线都要用新模型重打一遍，不能和 Sonnet 的历史分直接比。

## 三、新版评测（半成品）

### 3.1 一道题怎么评

配图 `20_新版_一道题怎么评.png`（建议放在这一节开头）：

1. 根据用户要求和附件，先生成这道题的检查清单并冻结（同一题对所有被测系统用同一份）。
2. **指令**：逐条检查用户明确提出的要求。
3. **内容**：逐条检查必要要点有没有覆盖；有附件时，页面上的数字和说法逐条和附件比对。
4. **视觉**：每一页检查裁切、遮挡、内容残缺、图片质量，再打设计分。
5. 三个维度分别出分，不合成总分；严重问题单独标出。

### 3.2 三个维度

| 维度 | 和日常管线比 | 怎么打 | 公式 |
|---|---|---|---|
| **指令遵循** | 全新 | 从用户要求里抽出明确要求（页数、语言、版式、必须包含的内容、保留模板、增改），每题三份草稿合并后冻结。每条判通过 / 部分 / 失败 / 不可判；页数等能数的由代码直接判。分硬要求（必须做到）和软要求（偏好），只有硬要求算分 | 硬要求通过率 = (通过 + 0.5×部分) / (通过 + 部分 + 失败) |
| **内容** | 加了要点覆盖率 | 每题冻结一份必要要点清单，逐条判覆盖 / 部分 / 缺失（配图 `21_新版_内容覆盖打分示例.png`）；保留日常管线的 L0/L1/L2；有附件时算忠实度（页面上的说法有附件支撑的比例） | 深度 `D = .20 L0 + .35 L1 + .45 L2`；`B = .70 D + .30 覆盖率`；有附件 `内容 = .60 B + .40 忠实度`，否则 `内容 = B` |
| **视觉** | 公式同日常 | 4 项硬伤 + 6 项设计 + 3 项美观 | `page = .35 硬伤 + .40 设计 + .25 美观`，整套取页均值 |

严重问题（明确要求没做到、必要内容缺失、页面裁切/遮挡）的例子见配图 `22_新版_三类严重问题示例.png`。

### 3.3 关键结论

- **三个维度互相不能替代**：两份稿子之间，视觉说 A 好、内容说 B 好的情况占 40%–49%，接近随机。配图 `23_新版_三维方向冲突.png`。
- **合成总分很敏感**：三维权重每 0.1 取一组，共 66 组权重，得到 22 种不同排名。所以新版没有给总分。
- **稳定性好**：同一评分模型重跑，指令逐条一致 97.8%，内容 97.3%；指令换一个评分模型重判，一致 94.1%。
- **能抓到故意造的错**：人为制造违规后，指令 10/10 检出，内容 9/10，视觉 8/10。
- **和人的一致性分维度差别大**：视觉排名和人评较一致；内容深度（L0–L2）和人基本一致；**忠实度和单页的裁切、内容残缺判断，和人对不齐**（详见 3.5）。
- **对流程改进敏感的是指令和内容**：同一底座模型，多阶段生成比直接生成，指令和内容明显提升，视觉变化不显著。

### 3.4 测试集的局限

- 新版是在 **test40**（40 题，`$BENCH/data/0427_minset_40.jsonl`）上做的，被测对象主要是 **4 月份 6 家商业产品**（AnyGen、Kimi、Doubao、Skywork、MiniMax、Manus）的产物，外加我们自己同一底座的两种流程。题型示例见配图 `30_新版_测试集题型示例.png`。
- 用到我们自己模型迭代上，可能的问题：
  - **题集不同**：日常用的是 47 题行业集（industry_v2），新版的指令清单和要点清单是按 test40 冻结的，换题集要重新生成和冻结。
  - **问题分布不同**：商业产品很少出现大片空白页、占位符没替换、页数被砍半；我们自己模型这些问题更多。新版的清单和阈值是在商业产品上调的，对这类问题的敏感度没有专门验证。
  - **模板模式覆盖少**：test40 里带模板的题很少，日常的模板模式评测基本没覆盖到。
  - **样本量小**：6 个系统、40 题，系统级排名的相关性检验在 6 个点上很难显著。

### 3.5 验证情况和不确定的地方

| 维度 | 验证了什么 | 结果 | 还不确定的地方 |
|---|---|---|---|
| 指令 | 同模型重跑 30 份 | 逐条一致 97.8% | 只说明稳定，不说明判得对 |
| 指令 | 换评分模型 | 一致 94.1% | 同上 |
| 指令 | 页数、宽高比用代码判 vs 模型判 | 45/46 一致 | 能用代码判的只有 46 条，占比很小 |
| 指令 | 人造违规 | 10/10 检出 | 人造的违规比真实的明显 |
| 指令 | 人工核对清单和判定 | **没做**（标注包建好了，没人标） | 清单是否漏了要求、是否把可选当必须，没有人工确认；软要求不算分，是否合理没讨论 |
| 内容 | 同模型重跑 | 97.3%，系统排名基本不变 | — |
| 内容 | 人造缺失 | 9/10 检出 | 同上，人造的比真实的明显 |
| 内容 | L0–L2 和两位标注员比 | 一致 80.7% / 85.6% | **两位标注员之间一致性很低**，说明"具体不具体、重点对不对"这类标准本身就模糊 |
| 内容 | 要点覆盖的方向（两份稿谁覆盖得更好） | 一位标注员、10 题，有明确倾向的 28 对里 20 对一致 | 只有一个人、样本少，是试点 |
| 内容 | 要点清单本身是否合理（每条是不是真该必须有） | 两位标注员已标完 | **还没分析**，所以清单是否合理还不能下结论 |
| 内容 | 机评判"缺失"的要点，人是否认同 | 两位标注员已标完（Manus、Doubao 各 10 题） | **还没分析** |
| 内容 | 忠实度和人比 | 一致 50% / 60%；两位标注员之间只有 35% | **目前最不可靠**：没有标准答案，人和人都对不齐 |
| 视觉 | 系统排名和人评排名 | 10 个系统时相关 0.855；只算 6 家商业产品时 0.829，但 6 个点统计上不显著 | 只在系统级成立，不代表单页、单套判得准 |
| 视觉 | 两份稿谁更好看，和人比 | 约 70% 一致 | 后来几批标注里我们自己的系统固定在同一侧，一致率降到 51%–62%，有位置偏差，不能合并看 |

| 权重 | 维度内部权重（.20/.35/.45、.70/.30、.60/.40、.35/.40/.25） | **没做** | 都是沿用或经验设定，没有用人评校准过 |

## 四、需要后续决定的问题

| 优先级 | 问题 |
|---|---|
| P0 | **日常总分以后怎么算**：现在是 页面 / 整套 / 内容 = 0.30 / 0.35 / 0.35。要不要加入指令遵循和要点覆盖？加的话权重怎么定（新版试过，权重一变排名就变）？还是像新版一样分维度出分、不合成总分？无论哪种，都要考虑和历史分数怎么衔接。 |
| P0 | **严重问题要不要单独标出来**：比如页面裁切/遮挡、用户明确要求的页数没做到、必须有的内容缺了。现在这些被平均进分数里，单页出问题对总分影响很小。是否在看板上单独列出、是否影响总分，需要决定。 |
| P1 | **维度内部权重要不要重新定**：L0/L1/L2、深度 vs 覆盖、清单 vs 忠实度、单页三项，都是沿用或经验值，没有校准过。 |
| P1 | **新版里还没确认的地方**：要点清单是否合理、机评判"缺失"的要点人是否认同——这两项人工标注已经做完，还没分析；忠实度和人对不齐，需要想办法（比如先只看数字类陈述）。 |
| P1 | **新版接入日常**：整理统一入口；在 47 题行业集上重新生成并冻结清单；先作为看板上的独立分列试跑，不改总分。 |
| P2 | **具体改进思路**（供参考，未验证）：内容 L2 加"简洁、重点突出"的判据，缓解偏向写得多；单页可读性加字号判断（提示词或直接从 HTML 量最小字号）；图表加"坐标轴/图例是否齐全"的检查；整套加"目录和正文是否对应"的检查。 |
| P2 | **换评分模型**：先用同一批稿子做 Sonnet 和新模型的对照，重点看硬伤和整体美观两项，再决定是否全量重打。 |
