## 1. 系统边界和模型角色

### 1.1 三个模型不是一个配置项

| 角色 | 初版示例模型字符串 | 运行位置与协议 | 输入 | 输出与作用 |
|---|---|---|---|---|
| 主 Agent | `vllm-sensenova-flash-320b-V16-20260901-step500-0pd-step160` | 主机上的 `BaseLLM`，LiteLLM/OpenAI 兼容协议 | 系统提示、消息记录、工具 schema、工具结果 | 结构化工具调用、阶段安排、最终回答 |
| HTML 生成/重写 | 默认同主模型；可通过 `html_model` 独立指定 | **沙盒内** `_html_llm_direct.py` 直接 HTTP | 页级输入 JSON、完整生成提示词、模板 HTML、可选修改意见 | 单页 HTML 源码 |
| 生成过程 review | **`qwen3.7-plus`**，不是随意把用户显示名 `qwen3.7plus` 原样当 API ID | 沙盒内独立 review HTTP，OpenAI `/v1/chat/completions` | 单页截图与 review 提示词 | 是否重写、问题列表、建议；不产生最终排行榜分数 |
| 最终裁判 | **`claude-sonnet-4-6`**，对应 Sonnet 4.6 | benchmark 主机，Anthropic 原生 `/v1/messages` | 页面截图、整套页面、query、附件正文等 | 页面、整套、内容分数及证据 |

主 Agent 与直接 HTML 调用属于两个客户端。只改 YAML 的 `llm.model`，不会自动改沙盒脚本里的 HTML 模型；只改主模型 key，也不会自动替换 review 和裁判 key。最终裁判同样不会自动采用 review 模型。

当前自动化基类的 review 默认根地址是 `https://tokenhub.sensetime.com`，裁判根地址也是这个域名，但两者使用不同凭据、协议和请求体。**地址相同不代表路由权限相同。** 后续必须按这两个准确的模型 ID 分别验证，不能用其他模型的成功请求代替。

### 1.2 端点和 thinking 的真实约定

- YAML 主模型 `base_url` 通常为 `http://HOST:PORT/v1`，`provider: openai`。
- HTML/review helper 的 `DEFAULT_BASE_URL` / `DEFAULT_REVIEW_BASE_URL` 使用**不带 `/v1` 的根地址**，helper 自己追加协议路径。
- 最终裁判使用 `WANGBO_CLAUDE_BASE` 与 `WANGBO_CLAUDE_KEY`；Sonnet 路由为根地址加 `/v1/messages`，包含 `anthropic-version: 2023-06-01` 和代码使用的 Bearer 授权头。
- OpenAI 生成端 thinking 放在 `extra_body.chat_template_kwargs`；关键字段为 `thinking`、`enable_thinking`、`reasoning_effort`。不能把另一个服务商的 Anthropic 参数照搬到 vLLM 请求。
- `automation/pipeline.py` 接受 `xhigh/high/medium/low/max`，但“控制器接受”不等于“模型服务接受”。应以合法 effort 成功、非法哨兵值被服务拒绝等证据确认参数没有被静默忽略。
- 当前 `_patch_thinking_into_html_script()` 对 `thinking=true` 的 OpenAI 配置做强制覆盖；`thinking=false` 不完整清理基类里原有 thinking 默认值。因此 UI 关掉 thinking 后，仍要检查实际复制出的 helper 和真实请求。文末配置脚本显式把两个路径都设成 false，作为保守复现基线；需要开启时应重新 doctor/smoke 并冻结有效配置。

这不是一个由 Python 逐项调用所有 stage 的固定 DAG。**阶段顺序主要由技能提示词指导 Agent 执行**，子任务实际执行仍经过模型决策；Python preflight、slice、lint、verify 只强制其各自覆盖的约束。因此“阶段文档写了必须执行”与“运行证据证明执行了”要分开审计。

`case_id` 是数据集身份；`conversation_id` 是某次尝试的会话身份；`session_id` 是沙盒/运行身份；`ppt_id` 是 deck 身份；`query_id` 是评测器身份。它们不能互换。重跑同一 case 会产生新 conversation；只能用当前尝试对应的 deck，不能通配匹配同题的历史成功产物。

## 3. Agent 运行时的实现

### 3.1 配置构建与预算

入口读取 YAML 后构建模型客户端、工具 registry、语言提示词、技能注册和 sandbox 配置，再创建 MainAgent、SubtaskAgent、ReflectionAgent。当前基类有以下预算：

| 字段 | 当前值/含义 | 容易混淆之处 |
|---|---|---|
| `runtime.max_loops` | 200，主运行时循环上限 | 不是生成 200 页 |
| `runtime.subtask_max_loops` | 20，委派 Agent 循环上限 | 不是 batch 的 `--max-turns` |
| `runtime.max_context_tokens` | 200000，上下文预算 | 不是一次输出上限 |
| 主 LLM `max_tokens` | 配置生成器写 128000 | 服务端仍可能有更小限制 |
| `--max-turns` | 20，外层 ask_user 后的 resume 次数上限 | 每次 resume 内还能有很多 LLM/tool 循环 |
| `delegate_parallelism` | 未覆写时默认 4 | 与逐页生成并发、题目并发分别相乘 |

技能配置位于 **`runtime.skill_registry`**，不是顶层 `skill_registry`。关键字段：`skills_dir`、`skills_sandbox_dir`、`allowlist`、`extra_dirs`。本机 allowlist 包括 PPT 入口和两种模式，额外上传 `templates`。批跑用 `--disable-skills deep-research` 删除深度研究技能，不能只禁用 web_search 就认为研究技能也被禁用。

### 3.2 单次 run_single_case 生命周期

```text
run_single_case(case, components)
  prepare_session(case)
    确定 conversation_id 与 runtime_session_id
    深拷贝配置，注入本次身份与工具限制
    创建沙盒；压缩/上传 allowlisted skills 和 extra_dirs
    恢复此 conversation 的工作区文件（不覆盖新上传的 skill）
    创建 Agent 与本线程工具上下文
  启动检索上下文预取和沙盒 keepalive
  prepare_runtime_state(case.agent_state, resume_answers)
  agent.run(state)
    循环调用当前活跃节点，执行工具/委派/恢复/终结
  发布会话快照；finalize_session_result
  finally
    停止并等待 keepalive 线程退出
    回收工作区；删除远程 session
```

清理线程的 timeout 是告警阈值，不是允许后台继续触碰已删除 session 的许可。实际流程等待 keepalive 完成再释放，以免释放后心跳制造竞态。

### 3.3 消息记录与 LLM 消息分离

主 Agent 的可信状态是 `message_records`，而非某次请求临时拼出的 messages。典型 state 包含：

```json
{
  "state_version": "由源码管理",
  "conversation_id": "batch_case_abcdef",
  "message_records": [],
  "asset_index": {"files": {}, "parsed_artifacts": {}},
  "runtime_control": {
    "conversation_status": "idle",
    "supports_ask_user": true
  },
  "session_metadata": {},
  "projections": {}
}
```

上例只展示组织结构，完整字段/默认值以 `src/conversation_state_v3.py` 为准。重建实现需要：记录用户轮次、assistant 内容、tool call 与 tool result；保持 tool_call_id 的配对；在编译为模型 messages 时按顺序投影；把文件上下文与有效摘要插入正确位置；保留运行控制状态以便 ask_user 恢复。

上下文压缩不是简单截去最旧字符。`apply_summary_offload...` 负责归档与摘要投影，保留当前目标、工具关系和恢复所需信息。预算策略含 recent rounds 预算比例、summary/user 比例与上限。对子任务，运行时维护独立的 messages-only 状态，而不是把父 Agent 全部消息原样复制进去。

### 3.4 BaseNode 的一轮调用

1. 从记录投影重建 messages，规范化工具消息。
2. 使用 BaseLLM 发起 completion，请求中附工具 schema。
3. 处理传输错误、空响应、工具参数错误，按有限重试策略恢复。
4. 返回文本和 tool_calls 都为空时判为空响应；只有 thinking 文本不算完成答复。
5. 对真实 structured tool_calls 做 schema 校验，校验通过才执行工具。
6. assistant/tool call/tool result 写入记录，更新循环数和运行控制。
7. 遇到 ask_user 进入 waiting/checkpoint，本轮后续工具可能被跳过，等待 resume。
8. 遇到 create_subtask 交给 coordinator；遇到终结条件进入 FinalizeNode 输出最终答复。

非法参数不会先执行再报错。兼容处理仅将 `create_subtask.todo` 的纯字符串数组转成换行字符串，不应泛化成“所有参数格式错误都自动修”。日志诊断应记录字段路径，避免输出可能含敏感值的整份参数。

当空响应前存在工具历史，节点可通过 nudge 和合适的 `tool_choice` 引导重试；在没有可用工具但仍有工具历史时，BaseLLM 会提供 dummy tool 与 `tool_choice=none` 处理供应商协议兼容。文本中看似工具的 DSML 标签不是 structured tool_calls，不能直接执行。

### 3.5 委派并发和结果回填

`tools/subtask/create_subtask_tool.py` 接受字符串字段：必填 `title/goal/todo`，可选 `relevant_files/criteria/skill/addition`。工具返回 XML 描述，由 runtime 解析并建立子任务。**当前 `skill` 参数被接受但未实际用于自动选择或执行技能**；必须在任务内容中明确告诉子 Agent 读取哪个技能/阶段文件。

coordinator 为每个子任务建立独立状态、工具上下文与消息列表；可用 ThreadPoolExecutor 并发执行，worker 数不超过任务数和 delegate_parallelism。完成后按提交顺序处理结果，将子任务最终内容回填父任务原 `create_subtask` 的 tool_call_id，父 Agent 因而能接着消费结果。

委派预算有预留逻辑，避免没有足够预算时仍启动一批任务。当前合并 `global_loops` 使用 max 语义，**不是所有并行子任务循环数求和**。不能拿它当总模型调用数或账单 token 数；计费/效率分析要统计实际请求日志。

### 3.6 调用可观测性

主模型日志记录 request_id、case/conversation、调用来源、模型/地址来源、消息/工具数量、延迟、正文长度、reasoning 与 structured tool call 数。直接 HTML helper 不经过 BaseLLM，因此需要同时收集其日志和逐页产物。

一个题目“日志一直增长”只能证明某些动作持续发生，不能证明生成前进。可靠进展是新有效 HTML、阶段 JSON 更新、请求获得有效响应、当前 case 的终态转为有效完成。文件 mtime、历史成功响应、心跳都不能单独代表新模型在正常工作。

### 3.7 检索上下文、历史和长期记忆

`context_pipeline.py` 负责日期/历史信息、预加载上下文、检索结果的过滤和可选 LLM 摘要，再投影进实际 prompt。检索预取可以异步启动，但是否等待、怎样过滤分数、超时如何降级都有单独配置。不能把“异步检索已提交”理解为本次模型请求必然见到了检索正文。

长期事实记忆与会话文件恢复是两个机制：前者可使用 mem0，后者依赖 message_records/checkpoint/workspace snapshot。history 按 memory_user_id 保存 session JSONL 与日期摘要，sandbox_sync 可把历史同步到 `/mnt/data/history`；身份设置决定是否按登录用户隔离或走匿名共享池。`memory_update.py` 还实现受限工具集的记忆更新、按租户/用户串行更新日期摘要；该锁是进程内锁，多进程部署仍需要队列/数据库协调。

当前基类的 **memory.enabled=false**，虽然下级 history/summary/jobs 内存在 enabled=true，不能越过总开关就断言它们全在运行。评测基线应保持总开关与上下文配置一致；若启用记忆/检索，必须冻结用户身份、历史快照和辅助模型，否则相同 query 可能因历史不同得到不同上下文。记忆任务完成不能作为 PPT 或评分完成证据。

## 4. 沙盒与文件生命周期

### 4.1 RPC 合同

| HTTP | 路径 | 主要请求字段/响应目的 |
|---|---|---|
| GET | `/v1/ping` | 基础可达性 |
| POST | `/sessions/create_session` | `language`, `timeout`, `cpu_mem_limit_mb`, `cpu_core_limit`, `request_session_id`；创建隔离会话 |
| POST | `/sessions/{id}/execute_command` | `session_id`, `command`；运行 shell |
| POST | `/sessions/{id}/run_code` | `session_id`, `code`, `libraries`；执行代码 |
| POST | `/sessions/{id}/upload_files` | `session_id`, `files:[{content_base64,dest}]`；上传文件 |
| GET | `/sessions/{id}/download_files` | 客户端使用 JSON body 包含 session 和文件路径；此处不要擅自改为 POST |
| GET | `/sessions/{id}/get_session_status` | 心跳/状态 |
| DELETE | `/sessions/{id}/delete_session` | 删除远程会话 |

实现时应直接对照仓库 SDK 与服务端请求模型，不能仅凭上表猜出所有可选字段。服务侧有 FastAPI、容器/Jupyter 执行等依赖；主机能 ping 沙盒不代表沙盒能访问内网模型。doctor 至少要覆盖：主机→主模型、沙盒→HTML 模型、沙盒→review、评测主机→裁判。

### 4.2 上传、持久化与回收

每题独立 session，技能被压缩后上传到 `/mnt/data/skill`。PPT 工作区通常在 `/mnt/data` 下用唯一 ppt_id 初始化。session 结束时，`release_workspace` 枚举需要保留的文件，排除技能等目录，下载并按目录层级写入本机 `retrieve_path/<conversation_id>/`。

会话恢复依赖此前持久化文件与 agent_state；只传对话文字无法恢复实际 deck。批跑固定禁用列表随每次恢复继续生效。会话隔离和目录身份检验避免另一题/另一轮的文件污染当前题。

keepalive 间隔由 timeout 派生，约束在至少 1 秒、最多 30 秒内。它保护 session TTL，不会修复模型连接失败。现有回收逻辑在下载失败时仍可能进入删除 session 的 finally，因此必须审计回收错误；不能看到远端生成成功就认为本地已保存。

### 4.3 两套渲染器

生成过程 review 的渲染经 `_tool_call` 对接远程 `html_to_png`；最终 benchmark 使用 FolderLoader/Playwright 在评测主机渲染。它们是不同组件，字体、资源加载、浏览器环境差异可能导致截图不同。正式复现必须保留最终渲染器、字体和浏览器版本；review 的成功不能代替最终渲染成功。

## 5. PPT 技能与数据契约

### 5.1 工作区初始化与公共输入

PPT 入口先收集需求，再调用初始化脚本建立 `pptid_<uuid>` 工作区。`task_pack.json` 是需求与约束，`info_pack.json` 是来源材料、证据和缺口。后续 stage 引用同一 deck_dir，不能各自创建新 deck。

`task_pack` 应表达主题、目标读者、语言、页数、模式、模板选择、内容与视觉约束、文件引用和交付要求。`info_pack` 应区分原始资料事实、提炼信息、引用位置和未解决缺口。**完整原始字段合同在附录原文保留**，不以这里的概念性概括替代 schema。

评测禁用搜索/生图时，资产计划仍须存在；没有可用图片应显式记录，而不是捏造外部来源或把链接写成已下载路径。

### 5.2 两条阶段链

| 阶段 | 无模板 | 模板 |
|---|---|---|
| 入口 | task_pack + info_pack + workspace | 相同 |
| Stage 2 | `style_spec.json`，确定视觉 tokens | `template_map.json`，检查模板、分配参考页、补全元信息 |
| Stage 3 | `outline.json`，逐页结构与内容预算 | `outline.json`，受模板槽位/容量约束 |
| Stage 4 | `asset_map.json`，内容补充与图片映射 | 相同，但服从模板可替换槽位 |
| Stage 5 | slice → 逐页生成 → lint/一次修正 | slice → 参考模板生成 → 模板 lint/一次修正 |
| Stage 6/7 | 逐页截图 review → 有问题页重写；技能要求合并为一次子任务 | 当前技能没有对应 review/rewrite 阶段 |
| 完成 | verify 页数、文件与结果交付 | 检查模板生成结果与页文件 |

这里的 Stage 编号来自技能文件，不是 benchmark 的 stage1/stage2；benchmark stage1 是逐套评分，stage2 是可选 pairwise。

### 5.3 style_spec 与 outline 的约束

`style_spec` 提供统一 palette、字体库、typography、motif、页面变体和图表/列表规则。颜色采用角色化 token；背景装饰与内容装饰分开，通过稳定 motif key 引用，避免逐页任意换风格。

无模板 `outline.json` 的 `schema_version` 为 `ppt_no_template_outline_v1`；包含 `deck_dir/ppt_id/language/title/total_pages/pages/unresolved`。`pages` 按 1 起始连续编号：

```json
{
  "page_id": "page_001",
  "page_number": 1,
  "page_number_label": "第1页，共12页",
  "page_type": "title",
  "title": "示例标题",
  "layout": {"category": "按原始枚举选择", "custom_description": ""},
  "content": {},
  "background_picture": "",
  "unresolved": [],
  "page_type_variant_id": "来自 style_spec 的变体",
  "page_goal": "本页要传达的结论",
  "content_budget": {
    "max_content_blocks": 4,
    "require_chart_or_table": false,
    "require_image": false
  }
}
```

此例用于解释层级，不是可以绕过枚举校验的完整输入。`content` 只使用 `sub_point1/sub_point2/...` 结构。sub_point 具有 icon/sub_point_name/text、table/chart/picture、picture_source_ref、sub_sub_points、block_type 等字段；同一块的 table/chart/picture 最多一个非空。图片编号全 deck 统一 `picture-NNN`。单页内容预算的 max_content_blocks 不超过 6；它是生成布局的重要约束，不是只供展示的备注。

### 5.4 asset_map、template_map 与预检

asset_map 包含 schema、deck 和 pages；每页至少有 page_id/page_number、`content_supplements` 数组和 `image_assets` 数组。image asset 描述 asset_id、slot_id、asset_kind、caption、source、local_path、reason。当前标准基类禁止内容补充，content_supplements 必须始终是空数组；source 只允许 user_provided，不能临时新增生成/搜索来源。

template_map 把最终页对应到模板 HTML，并记录可替换槽位、容量和选择理由。`preflight.py` 验证文件与映射，`enrich_template_map.py` 补 `template_page_type/layout_category/constraints`。模板相关参考图和 user 目录由切片脚本按需复制；复制不是生成新的模板。

无模板 `outline_preflight.py` 检查 outline 的关键结构。切片脚本检查页码集合一致性，但不是完整语义验证器：outline 写错事实，或 style token 不合理，不能指望 slice 发现。

### 5.5 Stage 5 的页级输入

slice 为每页生成 `htmls/page_NNN.input.json`，避免每个 HTML 请求携带整套多页内容。无模板主要结构：

```json
{
  "schema_version": 1,
  "deck_dir": "/mnt/data/pptid_EXAMPLE",
  "page_number": 1,
  "page_id": "page_001",
  "output_html_path": "/mnt/data/pptid_EXAMPLE/htmls/page_001.html",
  "task_pack_path": "/mnt/data/pptid_EXAMPLE/task_pack.json",
  "style_spec": {},
  "outline_page": {},
  "asset_map_page": {}
}
```

模板输入另含 `template_html_path` 与 `template_map_page`，生成器读取模板文件正文拼入 prompt。`task_pack_path` 等是文件层面的上下文定位，不意味着所有字段都会进入模型请求：helper 的 `_page_data` 会选取约定字段。重建时必须复制这个筛选逻辑，防止误以为模型见到了完整 task_pack。

## 6. HTML 生成、review 与重写

### 6.1 直接调用生成器

实际标准基类中的 `html_page_generate_batch.py` 导入 `direct_gen_html`。历史 `_tool_call` 生成接口仍可能作为回滚代码存在，但默认生成路径是**直接请求模型**，不是统一的远程 html_page_generate 服务。

单页算法：

```text
读取 page_NNN.input.json
读取本模式完整生成 prompt
拼接筛选后的 page data；模板模式另拼完整参考 HTML
调用 direct_gen_html（HTTP 层最多 3 次尝试，单次 timeout 600 秒）
清理最外层 Markdown code fence，写入目标 HTML
执行本模式 deterministic lint
若失败：携带 lint 原因重新生成一次，覆盖该页，再 lint
返回本页成功/失败与原因
```

batch 默认页并发 4，可用 `--pages` 仅处理指定页。HTTP 重试与 lint 重生成是两层预算，不能认为“一页最多请求两次”。stdout 的总 `status=ok` 和进程 exit 0 不保证每页成功，必须读 `failed_pages` 与单页结果。

### 6.2 HTML 输出合同与 lint

无模板页面以 1280×720 的 `.wrapper` 为画布，`#bg` 与 `#ct` 分离背景和内容，display item 用稳定 `data-display-id` 连接到 outline。motif 属性把装饰元素与 style_spec 绑定。图像使用预期 picture wrapper 和相对资源路径，避免随意在 img 上放本应属于父容器的 picture ID。

无模板 lint 覆盖：HTML 结构、尺寸、重复/缺失/未知 display id、隐藏内容、空装饰、重复文本、孤立行、未使用素材、图片 wrapper、motif key、失败图片占位、未标记可见文本、背景声明位置、禁止的 CSS 特效及表格/布局限制。它不等于浏览器视觉判断，也不验证所有事实。

模板 lint 关注：保留参考模板固定图片 src，清除占位内容，闭合 HTML、最小内容长度、背景与样式重复、不新增脚本、表格跨行跨列和嵌套等限制。模板模式不是“把原模板当截图贴上去”，模型仍生成可渲染 HTML，只是结构和资产受参考约束。

### 6.3 Qwen review 的准确输入与解析

1. 读取最终 HTML，把支持的本地图片/CSS 资源引用内联，交给远程 `html_to_png`。
2. 从响应取 png_base64；过大图像按 helper 限制缩放/转码。
3. 构造 OpenAI 多模态 message：`image_url` data URL + review 文本提示。
4. 向独立的 `DEFAULT_REVIEW_BASE_URL`、`DEFAULT_REVIEW_MODEL=qwen3.7-plus` 发请求，使用独立 key；当前常规参数 temperature=1、max_tokens=8192。
5. 解析模型 JSON：先标准 JSON，再尝试提取大括号区域，最后兼容字段正则；全部失败标记 parse_ok=false/review_failed。
6. 保存 `page_NNN.review.md` 和批次汇总；只有 `needs_rewrite` 且 `issues` 非空的页进入重写集合。

字段包括 `is_ok/score/needs_rewrite/issues/suggestion`，parse_ok 是内部解析诊断。它不是严格 JSON Schema：部分字段缺失时存在默认值，所以 parse_ok=true 不等于内容合同已完整满足。审计时要检查问题列表、改写决策和渲染结果，而非只看 is_ok。

当前 helper 对大图存在转 JPEG 后仍沿用 PNG MIME 标签的兼容风险。重建实现应令 MIME 与实际编码一致；这属于当前实现的已知边界，不应写成已修复。

### 6.4 重写闭环的实际范围

重写请求输入原 HTML、review issues、页数据和生成提示词，调用的是**HTML 生成模型**。Qwen 提供意见，不负责生成替换 HTML。重写后覆盖文件并 lint；当前流程不是一直 review→rewrite 直到通过的无限闭环，也没有保证对每次重写再次截图复审。

review 脚本自身默认并发为 1，可被 `PPT_HTML_REVIEW_CONCURRENCY` 改变，但 stage 的显式 `--concurrency 4` 会覆盖环境默认值。调并发必须检查实际命令。`PPT_SKIP_HTML_REVIEW=1` 会返回带 skipped 说明的伪通过记录；正式结果必须标注 skip，不能混入正常 review 口径。

根 `skills/` 较新的某些 review 实现带 deterministic lint 合并，当前 `BASE_SKILLS_DIR` 复制的版本没有同样行为。对代码树改动的评估要以本任务冻结的实际技能为准。

## 7. 跑批、事件与断点恢复

### 7.1 输入与自动答疑

两份行业平衡 v2 数据集各 47 题：

- `data/added/ppt_testset_industry_balanced_v2.jsonl`
- `data/added/ppt_testset_industry_balanced_v2_template.jsonl`

每行以 id/query/files 为主体，mode 决定无模板或具体模板。两份数据的行序可能不同，比较必须按 case ID，不能 zip 第 N 行。runner 拼接模式后缀和 autonomous 指令，并设置 `supports_ask_user=true`、`persist_sandbox_state=true`，循环运行和恢复。

自动答疑优先读取显式答案，todolist 反馈可自动批准，PPT 模式问题尽量选与输入一致的选项；其他封闭选项用固定 seed 派生随机选择，无选项的开放问题可能报 `open_ended_question_in_flow`。**当前 proceed_opts 的后续选择可能覆盖之前 pinned mode 的结果**，不能把模式锁定视为完全硬约束；smoke 应检查实际 task_pack/mode。

### 7.2 事件合同

```jsonl
{"event":"case_start","id":"case_001","conv_id":"batch_case_001_a1b2c3","ts":"示意时间"}
{"event":"case_done","id":"case_001","terminal_class":"done","success":true,"error":"","duration_s":123.0,"turns":2,"deck_html_pages":12,"deck_png_pages":0}
```

上例展示字段语义；`case_done` 当前没有 conversation_id 和 ts，不能只解析终态行寻找产物。必须按文件顺序，把它与此 case 最近一次 case_start 配对。新的 case_start 会使旧终态失效，直到本次有新的终态。还存在 case_error、batch_start、batch_done。

batch_summary.json 可能只记录本次 resume pass，不能无条件当累计真相。转换器通过 summary/events mtime 选择来源；这是当前策略，不是严格事务版本号。需要稳定归档时，应冻结事件文件、审核每题当前尝试，再生成全量快照。

### 7.3 terminal_class 的优先级

| 类别 | 当前分类依据 | 对本次 PPT 任务的处理 |
|---|---|---|
| `infra_failed` | error/response 命中连接、沙盒、限流等基础设施特征，优先判断 | 排除正在运行后可恢复重试 |
| `other_error` | LLM 重试耗尽、参数校验耗尽或其他错误 | 先诊断，再有针对性重排 |
| `done` | success=true 且发现非空 HTML 页 | 还需页数、连续性、当前会话、可渲染校验 |
| `done_no_html` | success=true，未找到 deck 和页面 | 通用 runner 允许文字交付；PPT 评测不算有效完成 |
| `render_suspect` | success=true，找到 deck 但无有效页 | 查输出、回收和渲染问题 |
| `content_incomplete` | max_turns_exceeded 或开放问答卡住 | 查自动答疑/流程，不是无限同参数重试 |
| killed/inflight | 有 start 无当前终态的派生状态 | 先查存活进程，禁止与活任务重复运行 |

`done` 不等于“预期 12 页都齐了”。当前生成质量检测比较宽松，完整验收必须额外核对 outline.total_pages 与连续 HTML 页码及最终截图。

### 7.4 resume 的真实行为

`--resume` 跳过 done、done_no_html、render_suspect、content_incomplete、other_error，只重跑 infra_failed 与未完成 start。它不是“重试所有非 done”。另一个边界是 `_scan_event_ids` 在 case_start 时没有清除旧 terminal_class：如果某题曾成功、后被人为重排、最新尝试又中断，原生 resume 可能仍按旧成功跳过。此时必须用最新 start/terminal 配对生成明确 remain 输入，不依赖该旧终态扫描。`--resume-skip-started` 甚至跳过所有开始过的题，不能用于补齐失败题。

可恢复错误续跑应保持 input、output、配置、版本标识不变。对于经诊断需要重跑的 triage 类，先生成仅含那些 ID 的 remain JSONL，再对同一 output 跑这份输入；不要加会把它们再次跳过的 --resume。remain 必须排除当前有效成功题和活跃题。不要通过扫描历史任何 quota 字符串把已成功题重新标为失败，也不要手写假的 batch_done 骗过监控。

## 8. 评测输入转换与渲染

### 8.1 build_benchmark_eval 的具体算法

输入：原始 JSONL、run_dir、sandbox_root、version、固定 date。

1. 加载当前结果；summary 足够新时使用 summary，否则按 events 计算各题最新尝试。
2. 用本次 conversation_id 确定回收目录，不能跨会话通配回退。
3. 递归找 `htmls/page*.html`，丢弃小于 100 字节页面；多 deck 候选取有效页数最多者。
4. 为每题建立 `<VERSION>_test40-<YYYYMMDD>-<case_id>` 文件夹。
5. 重建 `code/` 并复制 HTML；按存在情况复制 assets、user、htmls_png 与原始附件。
6. 写 `query_info.txt`，供评测器解析 query 序号、Prompt、场景/输入类型与附件。

目录名中的 test40 是历史兼容标记，不意味着这次只有 40 题。固定 date 是运行身份的一部分：跨日续跑不能随日期新增另一份同题目录。当前自动 `_score_mode` 用当天日期，这是需要防范的现有问题；文末严格手工评分路径使用固定日期。

### 8.2 两个必须补上的审计条件

**转换器不只导出 done。** 当前只要某题最新终态关联到有页的 deck，就可能导出，包括部分失败题。用于正式评分时，应先把转换输入限制在“当前有效成功集合”，而不是默认接受所有有页目录。

**覆盖 HTML 不自动失效截图。** FolderLoader 优先读取已有 `images`，再考虑 PPTX/PDF/HTML 渲染。转换器改了 code 后不会自动清 images，所以同一评测目录可能继续使用旧图。修复了页面的题需要备份并失效其 images 缓存，同时从分数里移出该题旧行后重评；不能只改 HTML 然后依赖 skip_done。

### 8.3 query_id 与原 case_id 的映射

FolderLoader 从目录名前缀识别 agent_name，从 query_info 的 `Query序号` 生成 `<agent_name>_q<seq>`。转换器的序号来自 case_id 中数字片段，存在不同 case 映射到相同数字的风险。正式对齐应结合 case_id、query_info Prompt 和 score.query_meta.query；无法唯一映射时报告歧义，不按数量猜测。

定义：G=当前有效生成 case 集合，S=能唯一回溯的已评分 case 集合。必须分别报告 `G∩S`、`G−S`、`S−G`。有 40 条分数和 40 个有效 deck，不代表这 40 个 ID 相同。

### 8.4 最终截图和附件

HTML 由本地浏览器渲染，按页面画布截图，并检查明显空白/单色等异常。截图的浏览器依赖、字体、图片文件和相对路径必须可用。`htmls_png` 参考图不等于最终的 `images` 截图。

附件由 FolderLoader 解析为可供裁判使用的文本；无法解析的错误标记应剔除，不能当参考正文。评测能运行但没有参考正文时，faithfulness 可能缺失；必须在结果中记录内容评估适用范围。

## 9. 裁判实现与评分公式

### 9.1 run_from_config 与 GeminiModel

`../benchmark/run_from_config.py` 在导入评估组件之前设置 V2 环境变量，然后创建 FolderLoader、模型适配器、聚合器，按套 ThreadPool 并行执行。类名 `GeminiModel` 是历史名称，不代表实际调用 Gemini：当模型名为 Claude 时会进入 anthropic_native 路由。

Sonnet 原生请求将 OpenAI 风格图片 data URL 转成 Anthropic image block，将 system 独立提取，使用 `/v1/messages`。响应取 text block，不把 thinking 当评分 JSON。常规 max_tokens 为 16384，重试/timeout 受环境和具体 evaluator 覆写影响，不应把某一个 timeout 变量解释成全链路统一截止时间。

每套评测内部还有逐页并发，套并发 4 不等于只有 4 个 HTTP 请求；常见逐页池为 4，可能达到约 16 个并发页面任务，再叠加其他调用。当前自动化评分把套并发固定为 4，且加全局评分锁，避免多任务叠加压垮裁判路由。

### 9.2 页面评分 P

页面 evaluator 分三个组：

| 组 | 维度 | 原始量纲与归一化 |
|---|---|---|
| Hard H | boundary_crop、occlusion_overlap、content_integrity、image_quality | 每页是否通过；各维度页面通过率再平均，范围 0..1 |
| Fine F | layout_alignment、layout_spacing_balance、component_style_consistency、text_legibility、font_hierarchy、line_spacing_typesetting | 每项 0/1/2，除以 2 后聚合 |
| High A | layout_hierarchy_path、visual_language_polish、overall_visual_impression | **新版每项 0..3，三项和除以 9** |

`P = 0.35 × H + 0.40 × F + 0.25 × A`。

旧版 high-level 1..5、1..10 的兼容字段仍可能存在，不能拿旧显示量纲再次归一化新版 A。当前解析对部分缺字段有默认值，例如 hard 的默认通过、fine 的中间值、某些汇总缺项的 0.5；所以“有分数”不足以证明裁判完整返回。复核应抽查 `_page_results` 原始维度与模型解析告警。

### 9.3 整套评分 D

DeckEvaluator 从整套截图、query 和可用报告信息评价结构、视觉一致性与完整性/内容质量。结构、视觉一致性、无报告时的内容质量原始维度是 1..N，当前默认 N=5，用 `(raw−1)/(N−1)` 归一化；有报告时 completeness 已为 0..1，直接使用。

`D = 0.40 × structure + 0.35 × visual_consistency + 0.25 × completeness_or_content_quality`。

有提取出的报告 key facts/topics 时走报告相关完整性分支；仅 query 时走内容质量分支。长 deck 的送模页面可能按 evaluator 策略抽样；因此逐页评价和整套评价的可见信息不完全相同，精确抽样策略要随源码版本冻结。

### 9.4 内容评分 C

ContentEvaluator 即使没有报告也可以根据 query 做 checklist，所以**没有附件不等于 content_score=None**。

- 核心 checklist 加动态 checklist：固定核心为 6 维 × 3 层，动态通常为 6–10 条 × 3 层；动态条目由 query、场景、受众、输入类型和页数提示等生成，并写入独立缓存。
- 层级分数：`C_check = 0.20 × L0 + 0.35 × L1 + 0.45 × L2`。
- 有可用源材料时，裁判把事实声明标为 supported / derived / unsupported，并返回 statistics.faithfulness。
- 当前 Python 直接取裁判返回的 faithfulness 数值，并没有从所有 claim 标签重新计算。因此复现要保留提示词定义和原始统计；不能在文档里另造一个权重公式替换它。
- 有 faithfulness：`C = 0.60 × C_check + 0.40 × faithfulness`。
- 无 faithfulness：`C = C_check`。

动态 checklist 不是逐次任意生成：缓存键与 query/元数据有关。需要沿用同一个 checklist cache 比较模型；若换规则或缓存，必须标注评测口径变更。生成失败会重试并报错，不应把空 checklist 当全通过。

### 9.5 Overall 与 V2 字段

当 content_score 有值时：

`Overall = 0.30 × P + 0.35 × D + 0.35 × C`。

当 content_score 为 None 时：

`Overall = 0.40 × P + 0.60 × D`。

实际实现对 overall 的缺失组成项重新归一化剩余权重；页面 P 内部对单个缺失组填 0.5，不能把两种行为混淆。若新版 ContentEvaluator 未返回有效 content，aggregator 还存在旧版回退：真实性与 completeness 各占 0.5，缺一项时以 0.5 填充。关键分支依据是 **content_score 是否存在**，不是输入是否有附件。

V2 会另写 v2_page/v2_aesthetic/defect_density/substantiveness/v2_overall 等诊断字段，其 v2_overall_score 组合使用 page/deck/content/substantiveness 四路，权重分别为 .30/.35/.15/.20；defect_density 是诊断字段，不是这里的第三路。substantiveness 缺失时重新归一化。`v2.enabled=true` 不会把主 overall 自动替换成 v2_overall。当前标准配置关闭 agentic_hard_check、constraint_llm、substantiveness_eval，也关闭 pairwise 与 pairwise_visual。

### 9.6 结果、重算与跳过

单题 JSONL 包括 query_id、agent_name、timestamp、eval_protocol_version、deck 量纲标识、overall/page/deck/content、hard/fine/high、维度详情、checklist/faithfulness、query_meta，以及 `_page_results/_deck_detail/_content_eval_detail` 等证据。

`skip_done=true` 主要按 agent_name+query_id 是否已有行跳过，不证明该行对应当前 HTML、当前截图、当前裁判或完整维度。部分 strict_content 模式会增加附件忠实度检查，但不能代替版本审计。

`recompute_overall_jsonl --in-place` 备份后按现有子分数重算总分；它不重新询问裁判，也不能补齐漏题。旧 deck 分值与新版 normalized 字段有兼容逻辑，不能对已经 0..1 的分数再除以 10。summary 从 JSONL 聚合，正式操作前必须核对唯一 query_id；线程锁只保护同进程 append，不会防住两个 scorer 进程同时写同一文件。

run_from_config 对单题异常可能记录失败后继续，进程退出码 0 不等于全部题成功；最终验收要看唯一映射和分数内容。

## 10. 自动化控制器、看板和交互产品

### 10.1 当前控制器的状态和执行

`start_task` 依次 gen_config、gen_skills_dir、launch_batch、register_dashboard、save_state、ensure_monitor。两种模式各一个 runner，`Popen(start_new_session=True)` 保存真实 pid；不要额外套 setsid 让父进程提前退出，造成假中断。

state.json 通过临时文件 replace 保存，包含 task_id、params、conf_path、launch_info、status、created_at，以及监控追加的 progress、known_issues、last_check 等。**原 start_task 会把 params 整体保存，若包含 key 就会落入 state。** 文末配置步骤将凭据移入私有配置/文件，保存的监控 params 不含明文 key。

`gen_skills_dir` 会删除同名目标目录再复制，不适合对运行中任务调用。新实验用唯一 task_id；续跑使用已经冻结的配置和技能，不能重新准备覆盖。

### 10.2 监控不是自动治愈所有错误

monitor_loop 大约每 120 秒刷新：

1. 读取双模式当前事件和存活进程。
2. 某模式有效生成达到 20 套时早评分。
3. 早评分后新增至少 3 个未评分成功 case 时增量评分。
4. 当前 batch_done 时终评分。
5. 评分线程异步运行，监控线程继续更新，不被长裁判请求阻塞。
6. 最终要求当前生成 G 至少 40 且 G−S 为空才认可该模式的 scoring 完成。

**40 是控制器最低阈值，正式完整数据集是每模式 47。** 控制器可能标 done 同时仍有缺题告警，不能直接宣布 47/47。监控可识别错误、进程消失和覆盖问题，但它不是完整的基础设施重启/失败重排器；恢复需要第 12 节的有界操作。

监控线程是 daemon，必须由长期存活的 server/driver 持有。运行一行 `start_task()` 后让 Python 退出，会留下 runner 却失去该进程里的监控。`_MONITORS` 只在进程内去重，不能让两个独立监控进程同时负责同一任务。

### 10.3 评分锁和凭据注入

评分使用全局 `_global_scoring.lock` 和任务/模式锁，避免两套评测同时争抢资源或向同一结果追加。`_score_mode_unlocked` 执行转换 → 写 benchmark YAML → conda scorer → 重算 → summary → dashboard reload。

本次工作区已有 `_task_eval_env`：优先从任务 params 的 `eval_api_key_file` 读取裁判 key，空文件/缺文件直接失败；`eval_api_base` 控制根地址；未指定的旧任务仍走历史 benchmark key 回退。新任务应显式设置文件引用，避免静默使用别人的 key。相关 5 个测试通过；常驻服务器未重启时尚未加载新 Python 代码，不能以磁盘已修改推断旧进程已生效。

### 10.4 看板如何关联结果

8770 服务加载 `results_dashboard/runs.json`。每模式一行，核心字段为 id、label、model、mode、run_dir、sandbox_root、scores_jsonl；label 保留用户模型名称，两模式靠 mode 区分。注册已存在 ID 时不会完整替换所有路径，所以新 run 不应复用旧 ID 指望自动换目录。

看板从 run_dir 取得生成进度与页产物，从 scores_jsonl 取得分数，通过 query/序号关联；`/api/reload` 刷新数据。注册一行不等于已完成评分，看到平均分也不等于覆盖一致。模型分析卡、best/worst 分析和交付链接是后置产出，不应假定注册动作会自动完成所有分析文章。

8770 是结果看板，8877 是自动化管理服务。它们和交互式 Agent 的 FastAPI/React 前后端是不同进程。

### 10.5 交互后端和前端如何复用运行时

`backend/server.py` 提供 query、status、conversation resume/stop、消息、文件、重放等 API；配置来自 `AGENT_CONFIG_PATH` 或 `CONFIG_PATH`，默认服务端口 8000。后端也调用相同的 Agent/session 组件，但增加用户身份、持久化和推送。

SQLite 表包括 users、conversations、messages、message_records、conversation_events、workspace_snapshots、conversation_checkpoints、conversation_assets、sessions。实现时区分：消息文本用于展示，message_records 用于恢复模型上下文，checkpoint 记录控制状态，workspace_snapshot 记录对应文件状态。重放某个用户轮次或子任务要从匹配 checkpoint/file snapshot 分叉，不能用当前文件配旧消息。

React/Vite 前端消费后端状态和流式记录更新，展示工具执行、答疑、文件与预览。stop 是取消运行流程，不是删除产物；文件接口需要路径边界和身份校验。离线 batch/scorer 不依赖前端运行，也不需要通过前端点击发起每题。

### 10.6 不要混用旧 auto_pipeline.sh

旧 shell 流水线与当前 Python 控制器存在差异：历史 batch_done 检测、全局 pgrep、较高 scoring workers、硬编码凭据来源、输入集默认值、缺少相同的锁与完整错误传播。不能一边开 Python 监控评分，一边为同一模式再开旧 shell scorer。本文主路径使用显式生成命令与有锁的评分步骤，并单独说明如何启用现有自动控制器。

### 12.3 已有分数但输入变化时的定向重评

不能只删除 score，也不能只清 images。必须在同一个评分锁内完成：

1. 记录目标 case_id 与唯一 query_id 的映射，保存旧 HTML/图片/分数/输入指纹作为证据。
2. 将该题评测目录整体移到归档目录，保留旧图片和相对资源；从当前结果 JSONL 移出且仅移出对应 query_id 的行。
3. 从该 version 的 inputs.json 中移出对应 case_id；清除失效的 score.ok/full.complete 标记。
4. 重新 snapshot、导出该题和未变题，score_once 用 skip_done 仅对缺失的目标题重评。
5. 重算 summary，核对 G/S，再 reload 看板，并在交付记录注明重评原因与日期。

该操作依赖你已确认的精确 ID 映射，不能写一个按模糊 query 子串批量删除的通用脚本。若缺少唯一映射，先修索引，不动原分数文件。不要对整个 results 目录清空重跑。

### 12.4 交付前统计命令

以下从当前两份正式 JSONL 读取均值、中位数、缺失项和 best/worst 候选，不自动写主观分析结论。best/worst 需要结合页面截图核验，不能仅按 overall 推导训练建议。

```bash

for mode in ('notpl','tpl'):
    p=bench/'results'/f'industry_v2_{task}_{mode}.jsonl'
    rows=[json.loads(x) for x in p.read_text().splitlines() if x.strip()]
    assert len({r['query_id'] for r in rows})==len(rows)
    keys=['overall_score','page_score','deck_score','content_score','hard_check_score',
          'aesthetic_fine_score','aesthetic_high_score']
    item={'n':len(rows)}
    for k in keys:
        values=[r[k] for r in rows if isinstance(r.get(k),(int,float))]
        item[k]={'mean':statistics.mean(values) if values else None,'n':len(values)}
    overall=[r['overall_score'] for r in rows if isinstance(r.get('overall_score'),(int,float))]
    item['overall_median']=statistics.median(overall) if overall else None
    item['content_none']=sum(r.get('content_score') is None for r in rows)
    item['dynamic_zero']=sum(r.get('content_eval_dynamic_items')==0 for r in rows)
```

| ModelClient | completion(messages, tools, generation_options) → normalized assistant | 结构化 tool_calls 与 text 分开；保留 tool_call_id；有限重试 |
| ToolRegistry | schema(name)、execute(name,args,context) | 执行前验证；上下文携带 session/conversation；禁用表不可绕过 |
| ConversationState | append_record、compile_messages、checkpoint、resume | 记录为真相；工具消息配对；文件与 checkpoint 同一版本 |
| AgentCoordinator | run(main_state, delegates, runtime_control) | waiting 可恢复；委派独立上下文；预算与停止可观测 |
| SandboxClient | create/upload/execute/download/delete | session 隔离；keepalive 和释放不竞态；回收可审计 |
| SkillRegistry | allowlist、extra_dirs、load/publish | 冻结实际技能和模板，不能依赖工作区同名另一版本 |
| PPT Stage | 输入文件路径 → 输出约定 JSON/HTML | schema、页 ID、页码、素材路径、模式一致 |
| BatchRunner | JSONL + config + output + resume policy | 当前 attempt 身份；append events；成功任务不可重复 |
| Converter | 当前结果快照 + 源 query → folder dataset | 不跨会话捡旧 deck；资源与 query/ID 可追溯 |
| Evaluator | folder → Page/Deck/Content details → score row | 同一裁判口径；量纲统一；缺失可诊断 |
| Orchestrator | gate → generate → score → reconcile → publish | 单一所有者、全局锁、固定身份、按集合验收 |
| Dashboard | runs registry + scores + artifact resolver | 不把注册/行数当成功；路径与模型 ID 对齐 |

### 13.2 分阶段实现和可验证结果

1. **先打通无模型的文件与事件通路。** 使用固定夹具创建一个 case、session、deck 和两页 HTML，验证回收、事件最新尝试解析、转换目录和 query_id 映射。特别覆盖“旧成功后新 start 未完成”，确保不会读到旧 deck。
2. **实现模型与工具协议适配。** 用本地假客户端测试空 text + 有 tool_calls、只有 thinking、非法 arguments、同轮 ask_user 后还有工具、工具历史但当前无 tools。这里的测试比“mock 一次函数返回”更有价值。
3. **实现 Agent coordinator。** 先单子任务，再多子任务；验证返回顺序与 tool_call_id 回填，父子上下文隔离，预算不足和取消。
4. **按附录合同实现公共 task/info 和无模板 stage。** 固定 JSON schema，再写 preflight/slice/lint/verify；提示词不能只留下标题，必须保留字段语义、禁止项、工具命令和交付要求。
5. **加模板流程。** 构建 template map，固定图片/槽位，补元数据，测试资源复制与相对路径；不要把无模板 review 自动套上模板并宣称同口径。
6. **加独立 review。** 确认 image payload/MIME、JSON 解析、issues→rewrite 条件、失败/跳过标记；重写由主 HTML 模型完成。
7. **实现 FolderLoader 与三个 evaluator。** 先固定 HTML 截图，再测试原生 Sonnet 图像请求；用已知原始分数验证公式、缺失处理和新旧量纲兼容。
8. **实现持久化评分和恢复。** 一个 key 对应一行、同进程锁+跨进程锁、固定 input fingerprint、skip_done；输入变化必须显式重评。
9. **接控制器与看板。** 先完成一题端到端，再各模式 smoke，最后 47+47。加入覆盖差集、定时报告和后置交付流程。
10. **最后接交互产品。** backend 的 checkpoint/stream/files 与同一 runtime 共用状态语义，React 只做交互和呈现，不另写一套生成算法。

### 13.3 提示词和资产也是程序的一部分

这套项目的部分控制逻辑写在系统提示词和技能 stage 中：什么时候创建 subtask、读取哪些文件、是否进行 review、如何映射页面元素。因此“同样的 Python 类 + 换一段概括 prompt”不等价于复现原项目。

必须冻结：主 system_prompt、PPT SKILL/stage/prompt 全文、静态模板及图片、数据集 JSONL 与附件、有效 YAML 参数、直接 helper、模型精确 ID/协议、沙盒和最终浏览器环境、benchmark prompt/checklist/评分配置。附录保留核心结构契约，源码指纹索引用于定位其余实现；模型有采样和服务端版本差异时，应区分功能复现与逐字节相同输出。

````markdown
# 无模板 PPT 单页 HTML 生成指令

你是资深网页工程师，按下面规则把「本页数据（JSON）」渲染成**一页** 1280×720 的 PPT HTML。你是 renderer，不是内容补写器：只渲染 `outline_page` 已有的内容，**不得**新增、改写或遗漏任何文字/数据。最终**只返回完整 HTML 本体**，不要解释、不要 markdown 代码块。

## 画布与骨架
- 整页固定 1280×720，禁止滚动条、禁止跳转、禁止交互控件（tab/button/input/切换）。
- 骨架：`<body>` 内只允许两个顶层业务层 `#bg`（背景）和 `#ct`（内容），先写 `#bg` 后写 `#ct`；两者都 `position:absolute`、尺寸 1280×720。`#footer`（页码）必须放在 `#ct` 内，不作为第三个顶层层。
- 外层用 `.wrapper` 承载缩放：等价于 `max-width:1280px;max-height:720px;aspect-ratio:16/9`。缩放只写在容器层级，不写在内容元素上。
- 布局用 flexbox / CSS grid；**禁止** `position:absolute + transform:translate(...)` 给流式内容定位，**禁止** `mt-auto`/`flex-grow`/`flex:1` 伪造间距，禁止 TailwindCSS。

## 视觉系统（全部来自 `style_spec`）
- 字体严格用 `style_spec.typography.title_strategy.font_family_css`（标题）与 `body_strategy.font_family_css`（正文），不得用未声明字体。**禁止任何远程字体链接**（`fonts.googleapis.com` / `fonts.gstatic.com` / `@import url(...)`），只依赖 `font_family_css` 字符串本身的系统兜底。
- 颜色严格用 `style_spec.color_palette[].hex`，不写死未声明颜色。
- 背景声明硬约束：所有 `background`/`background-color`/`background-image` **只能**挂在 `#bg` 及其后代；`<body>`/`.wrapper`/`.page`/`.slide`/`.container`/`#ct`/`#footer` 一律不得带 background。
- 装饰层：遍历 `style_spec.decorative_elements.global_background_layer`，把每条 `html_template` 原样嵌入 `#bg`，外层挂 `data-layer="bg-motif"` + `data-motif-key="<key>"`；`local_decorations` 中 `target_page_types` 含当前 `page_type` 的嵌入 `#ct`，挂 `data-layer="fg-motif"` + `data-motif-key`。当前 page_type variant 的 `background_motif_recipe`/`foreground_motif_recipe.motif_keys` 列出的 key **必须**都在 HTML 中以 `data-motif-key` 出现。正文/内容页至少要有一个大面积或跨边缘的背景 motif。

## 图片渲染单元（硬约束）
- 只渲染 `asset_map_page.image_assets` 里 `local_path` 非空且真实存在的图；每一条都必须被渲染，不得有图不用。
- **所有图片**用「外层 div + 内层 `<img>`」结构，禁止裸 `<img>`、禁止用 CSS `background-image:url('../assets/...')` 引真实资产：
  - 内容图（`asset_kind=illustration`）：`<div id="picture-NNN" class="picture" style="width:100%;height:100%;"><img src="../assets/<asset_id>.<ext>"></div>`
  - 背景图（`asset_kind=background_image`）：在 `#bg` 内再套 `<div id="picture-NNN" class="picture" style="width:100%;height:100%;"><img ...></div>`。
- 外层 div：`id` 等于该 asset 的 `slot_id`（形如 `picture-001`，连字符+三位数字）、`class="picture"`、内联 `style` 必须同时含 `width` 和 `height`（标准 `width:100%;height:100%;`）——下游靠这三样提取图片，缺一会丢图。内层 `<img>` **不带 id**。
- `<img src>` 用相对路径 `../assets/<asset_id>.<ext>`（HTML 在 `htmls/`、图在 `assets/`），禁止绝对路径/远程 URL。
- **无图槽位**：`outline` 里某 `sub_point.picture`/`background_picture` 声明了 `picture-NNN` 但 `asset_map_page.image_assets` 没有对应条目 = 该槽位没有可复用的既有图（本流程无配图获取能力），按无图处理：保留文字/图表或重排布局，**不要**插占位块、空 `<img>`、emoji/SVG/色块/虚线框冒充图。图片区域若占前景不到 20% 就别放图，用文字/图表替代。

## 图表（ECharts）
- 甘特/雷达/折线/饼/柱状等一律用 ECharts，不用 Chart.js；`<head>` 引 `<script src="https://cdn.jsdelivr.net/npm/echarts@5.4.3/dist/echarts.min.js"></script>`。
- 图表容器是 `<div id="chart_1" style="width:100%;height:100%;">`（不是 `<canvas>`），`echarts.init(document.getElementById('chart_1')).setOption({...})`。
- option 必须是严格 JSON：禁止 `.map()/filter()/reduce()/new/function/=>` 等任何计算，数组写成最终值。系列配色用 `style_spec.ui_components.charts.color_sequence`，title/axis/legend 沿用 `echarts_options`。禁止在图表上用 flex/transform/scale。

## 元素命名与内容忠实度
- 每个文本/图表/表格元素有唯一 id（`text_1`/`chart_1`/`table_1`），页脚固定 `id="footer"`；class 含类型描述（`text`/`chart`/`table`/`picture`/`footer`）。
- 内容块与 `data-display-id` 一一对应：`outline_page.content` 的**每个 sub_point** 渲染为一个内容块，块的最外层挂 `data-display-id="<该 sub_point 的 key>"`（如 `data-display-id="sub_point1"`；`sub_sub_points` 渲染在父块内部，**不**单独挂）。页面主标题块挂 `data-display-id="title"`；若标题文字已由某个 sub_point 承载（封面类页常见），就不再单独渲染 title 块，避免重复文字。HTML 里出现的 `data-display-id` 值**只能**是 `title` 或本页 content 真实存在的 sub_point key；每个有可见内容的 sub_point key 都必须被兑现。禁止隐藏挂了 `data-display-id` 的元素（`display:none`/`visibility:hidden`/`opacity:0`/0 尺寸等），禁止同一值重复挂两处。
- 页面任何 ≥4 中文字符（或 ≥8 英文字符）的可见文字，其本身或祖先必须挂 `data-display-id`；找不到来源的文字不得出现（豁免：`#footer` 页码、与 `title`/`page_goal` 同源的 2-3 词英文 kicker）。
- 禁止同一内容既用结构化组件又用自然语言段落复述；禁止 outline 之外的新文字/新数据/新图例。
- 页码用 `<div id="footer" class="footer">`，`position:absolute;right:40px;bottom:20px;`，文案取 `outline_page.page_number_label`；右下 160×60px 是安全区只放页码。
- CSS 装饰脚手架（grid 槽位、`.card`/`.signal-card`/`.feature-grid` 等承载内容语义的容器）每个槽位都要有真实内容，填不满就删掉脚手架，不留空槽/占位文字。`#ct` 内无文字无图表、尺寸≥120×120 的纯装饰空框必须挂 `data-layer="fg-motif"`+`data-motif-key`，否则删掉。
- 标题做孤字防护：避免末行只剩 1-2 字，必要时调 `font-size`/`max-width`/显式 `<br>`。
- 禁止 SVG 绘图、禁止 Font Awesome、禁止远程字体。

## 静态解析器硬约束（文本 / 形状 / 布局 / 表格）

最终 HTML 会交给一个**静态 DOM 测量解析器**转换为可编辑 PPT 元素——它**不执行 JavaScript、不加载外部 CSS**。除 ECharts 图表外（见下方豁免），页面必须在不跑 JS、不加载外链的前提下完整可见可测量。以下为硬约束：

- **文本**
  - 每段可编辑文字必须放在**独立、可测量**的块级 / inline-block / flex / inline-flex 元素里，不要把多段语义不同的文字塞进同一个裸节点。
  - **禁止「装饰空元素 + 裸文本」结构**：当一个容器同时有装饰元素（小圆点 / 竖条 / 图标位等）和文字时，文字必须用 `<span>` 或 `<div>` 包住。禁止写成 `<div><span class="dot"></span>裸文本</div>`，必须写成 `<div><span class="dot"></span><span>文本</span></div>`。
  - 文本只依赖 `font-size` / `color` / `font-family` / `font-weight` / `line-height` / `text-align` / `opacity` 这几样属性表达。
  - **禁止用 `background-clip:text` + `color:transparent`（含 `-webkit-` 前缀）制作渐变文字**——解析器读不到这种文字，会丢字。需要强调就用实色 `color`。
  - 不同颜色 / 字号 / 语义的文字**拆成独立元素**，不要靠复杂行内富文本混排；可用 `<br>` / `<strong>` / `<b>` 和简单 `<ul>` / `<ol>` / `<li>`，但不要在其中嵌复杂布局。
- **形状**
  - 形状用纯色 / 渐变背景、`border`、`border-radius`、`box-shadow` 实现。
  - **禁止 `clip-path` / `mask`（含 `-webkit-mask`）/ `filter` / `backdrop-filter` / `mix-blend-mode` / 3D 变换 / 旋转**（`rotate` / `skew` / `matrix` / `perspective` / `translate3d` 等）——这些解析器无法还原。
  - 伪元素（`::before` / `::after`）**不得承载关键信息**；如仅作装饰，必须显式设置 `content` / `width` / `height`。
- **布局**
  - 关键尺寸和定位一律用 `px`，**禁止 `calc()` / 视口单位（`vw` / `vh` / `vmin` / `vmax`）/ 容器查询（`@container` / `cqw` 等）/ CSS 动画（`@keyframes` / `animation`）**。
  - 子元素全部 `position:absolute` 的容器，必须自身显式设置 `width`/`height` 或 `inset:0`，不得零宽零高。
- **表格**
  - 只用标准 `table` / `tr` / `th` / `td`，推荐显式 `thead` / `tbody`；每行列数一致。
  - **禁止 `rowspan` / `colspan` / 嵌套表格 / 复杂单元格布局**。
- **图表豁免**：上述「无 JS 可见」约束**不适用于 ECharts 图表**——图表仍按前文「图表（ECharts）」一节用 `<script>` + `echarts.init` 生成，由下游单独处理。但图表 `option` 之外的页面 CSS 仍须遵守本节形状 / 布局禁用项。
````

````markdown
# 模板 PPT 单页 HTML 生成指令（照模板生成）

你是资深网页工程师。下面给你「参考模板 HTML」和「本页数据（JSON：`outline_page` + `template_map_page` + `asset_map_page`）」。你的任务是**照着参考模板的布局、配色、字号体系、分区结构和装饰，生成本页最终 HTML**——最终页面在视觉上必须可辨认为该模板的同一套设计。**只返回完整 HTML 本体**，不要解释、不要 markdown 代码块。

幻灯片是单页静态展示：整页 1280×720，不能有滚动条/跳转，不含 tab/button/输入框等交互组件。

## 一、模板是布局与样式的唯一依据（最高优先级）

- **复用模板**：整体版式、主列/侧栏/分区的**数量、相对宽度、间距**、配色、字体族、**各槽位的字号体系**、以及模板自带的 SVG / 装饰 / motif 元素——都照模板来，生成结果是模板的「内容替换版」，不是另起炉灶的新设计。
- **结构**：`<body>` 内只有两个 div：背景层 `#bg` 和内容层 `#ct`；二者都 `1280×720`、`position:absolute`，**先写 `#bg` 后写 `#ct`**（`#ct` 覆盖在上）。装饰性元素放 `#bg`，正文/标题/图表放 `#ct`。
- **背景**：背景色 / 背景图声明**只能在 `#bg` 及其后代**，数值照模板、不改不增；模板若把 background 误写在外层 `.page`/`<body>`，搬进 `#bg` 内等价子元素，不照抄到外层。
- **不要新增**模板没有的：全屏背景图、外部库 / `<link>` / `<script>`（模板没有 `<script>` 就不输出）、模板里不存在的 SVG / 图标 / 装饰。
- **禁用** font-awesome、tailwind；不要用 `position:absolute + transform:translate` 来填空隙，不要用 `mt-auto` / `flex-grow` 填空隙。

## 二、字号与尺寸纪律（**严格遵守，这是常见崩点**）

- **字号跟随模板对应槽位**：标题、正文、标签的 `font-size` 一律沿用模板该槽位的字号，**严禁自己发明超大字号**（如把标题写成 100px）导致溢出。
- **任何元素不得超出 1280×720 或其父容器**：文字过长时**压缩改写**到 `template_constraints.available_text_subpoint_character_number` 字符上限内，**绝不**靠放大字号、撑宽容器、绝对定位往外溢来容纳原文。
- 表格 / 图表区域高度与其内容一致，无滚动条，数据图形完整可见。
- 给页码留出页边距。

## 三、文字填充（用 `layout_slots` + `outline_page.content`）

- 按 `template_map_page.layout_slots[]`（含 `slot_id` / `slot_role` / `capacity_hint`）把 `outline_page.content.sub_pointN` 的文字填进对应槽位：标题 / 标签槽用 `sub_point_name`，正文槽用 `text`。`<title>` 与页面主标题用 `outline_page.title`。
- **文字不增、不删、不改原意**；唯一允许的改写是「超长压缩到字符上限内」。
- **可浮动槽位数量**由 `template_constraints.available_text_subpoint_range = [min,max]` 控制：识别模板中并排的「重复槽」（同父、同 class、同结构的兄弟，按序 T1..Tk），设 outline 的 sub_point 数为 N——
  - N==k：逐个替换；
  - N<k：保留 T1..TN，**删除** T(N+1)..Tk 整棵 DOM；
  - N>k 且 N≤max：以 T1 克隆 (N−k) 份再填（复用原 class/样式，不新增 `<style>`）；
  - N>max：前 max 个正常渲染，其余以「｜」并入最后一个槽（不超字符上限）。
- **占位文字严禁残留**：模板里的傻瓜占位（`内容内容内容…` / `小标题` / `流程描述` / `Lorem ipsum` / 孤立年份 `2016`-`2025` / 孤立序号 `01` `02` / `第x页，共xx页`）——命中的换成真值，未命中的固定槽位**清空**。页码槽强制替换为 `outline_page.page_number_label`。
- **章节号 / 段落号**（"第一章" / "Part One" 等）只按大纲内容写；大纲不涉及章节号但模板有，则**删掉模板里的章节字样**，避免编号对不上。

## 四、图片填充（picture-NNN ↔ 模板布局槽 ↔ fallback.png）

模板里 `<img src="../htmls_png/fallback.png">` 是留给内容图的**可填充占位**（不是装饰图）。三个 id 不在同一命名空间，必须经 outline 桥接，**逐条** `asset_map_page.image_assets` 处理：

1. 取 image_asset 的 `slot_id`（`picture-NNN`，如 `picture-001`）→ 在 `outline_page.content` 找 `picture == 该值` 的 sub_point → 读它的 `slot_id`（**模板布局槽名**，如 `hero_image` / `left_image`）→ 在模板 HTML 中**定位该布局槽承载 `fallback.png` 的那个 `<img>`**。
2. 把该 `<img src="../htmls_png/fallback.png">` **整体替换**为：
   `<div id="picture-001" class="picture" style="width:100%;height:100%;"><img src="../assets/<asset_id>.<ext>"></div>`
   （外层 div 的 `id` 取该 asset 的 `slot_id`(picture-NNN)，只挂 `id` + `class="picture"` + `style="width:100%;height:100%;"`，**不复制**原 `<img>` 的 class/style；内层 `<img>` 不带 id；`src` 用 `../assets/<asset_id>.<ext>`。）

**硬规则（必守，否则破版或 lint 失败）：**

- **图必须填进它 `slot_id` 指向的那个布局槽**——**严禁**把图塞进标题 / 正文 / 标签 / 演讲人 / 页脚等任何**文字槽**或装饰位。找不到对应布局槽就按下条丢弃，绝不硬塞。
- **不得超过本页 `template_constraints.image_num` 张图**：asset 给的图多于 `image_num`、或某 `picture-NNN` 在模板里找不到对应 `fallback.png` 槽 → **丢弃多余/无槽的图**（宁可少图，不破版）。`image_num==0` 的页（如封面以固定背景图为主视觉）→ **一张内容图都不放**。
- `template_constraints.has_background_image==false` 的页：即便 asset 给了 background_image 也**不插**。
- 没有任何 image_asset 覆盖的 `fallback.png` 槽：把该 `<img>`（必要时连其图容器）按「无图槽位」**删掉**，**绝不**把 `fallback.png` 原样留在输出里。
- **严禁假图**：禁裸 `<img>`、禁把 `id` 挂在 `<img>` 上、禁漏 `class="picture"`、禁漏 `style` 的 width/height、禁用 CSS `background-image` 引真实资产、禁去 `assets/` 捞未索引的候选图、**禁用灰底 / 虚线框 / emoji / 渐变块 / 纯色块 / 远程 URL / data-URI 冒充图**。
- 模板自带的固定图（非 `fallback.png` 的 `<img src>`，如 `../htmls_png/*`、`../user/*`）**原样保留**，不改源、不删。

## 五、图表（仅当本页有图表数据时）

- 用 **ECharts**（不用 Chart.js）：容器是 `<div>`（不是 `<canvas>`），`style="width:100%;height:100%;"`，`echarts.init(document.getElementById('chart_x'))`。
- `option` 必须是**严格 JSON 字面量**：禁 `.map()` / `.filter()` / `reduce` / `function` / `=>` / `new`，所有数组写成最终值；含 `title` / `legend` / `grid` / 至少一组 `xAxis|yAxis` / 至少一个 `series`。
- 图表外层 div 高宽由父容器控制；某图表规划占前景比例不足 20% 则不画。不要遗漏大纲里的图表。

## 六、文字与配色

- 文字颜色与背景形成对比（深底浅字、浅底深字），在此前提下尽量跟随模板配色；**不要随意发挥填充颜色**。
- 禁止因内容少而新增大纲里没有的部分；**大纲没提到的数据，禁止编造**。

## 七、静态解析器硬约束（文本 / 形状 / 布局 / 表格）

最终 HTML 会交给一个**静态 DOM 测量解析器**转换为可编辑 PPT 元素——它**不执行 JavaScript、不加载外部 CSS**。在「照模板生成」的前提下，若模板本身已合规就照搬；一旦模板出现下列写法，**改写成等效的合规写法**（保持视觉，不破版）：

- **文本**
  - 每段可编辑文字放在**独立、可测量**的块级 / inline-block / flex / inline-flex 元素里。
  - **禁止「装饰空元素 + 裸文本」结构**：容器内既有装饰元素（小圆点 / 竖条 / 图标位）又有文字时，文字必须用 `<span>`/`<div>` 包住，不能写成 `<div><span class="dot"></span>裸文本</div>`。
  - 文本只依赖 `font-size`/`color`/`font-family`/`font-weight`/`line-height`/`text-align`/`opacity`。
  - **禁止 `background-clip:text` + `color:transparent`（含 `-webkit-`）渐变文字**——解析器读不到会丢字，模板若这样写就改实色 `color`。
  - 不同颜色 / 字号 / 语义的文字拆成独立元素，不用复杂行内富文本；`<br>`/`<strong>`/`<b>`/简单 `<ul>`/`<ol>`/`<li>` 可用。
- **形状**
  - 形状用纯色 / 渐变背景、`border`、`border-radius`、`box-shadow`。
  - **禁止 `clip-path`/`mask`（含 `-webkit-mask`）/`filter`/`backdrop-filter`/`mix-blend-mode`/3D 变换 / 旋转**（`rotate`/`skew`/`matrix`/`perspective`/`translate3d` 等）；模板里这类装饰若非关键信息就删，关键内容改用合规形状承载。
  - 伪元素不得承载关键信息；仅装饰时必须显式 `content`/`width`/`height`。
- **布局**
  - 关键尺寸用 `px`，**禁止 `calc()`/视口单位（`vw`/`vh`/`vmin`/`vmax`）/容器查询 /CSS 动画（`@keyframes`/`animation`）**。
  - 子元素全 `position:absolute` 的容器必须自身显式 `width`/`height` 或 `inset:0`。
- **表格**：只用标准 `table`/`tr`/`th`/`td` + `thead`/`tbody`，每行列数一致；**禁止 `rowspan`/`colspan`/嵌套表格**。
- **图表豁免**：上述「无 JS 可见」约束**不适用于 ECharts 图表**（见第五节），图表仍用 `<script>`+`echarts.init`，由下游单独处理；但图表 `option` 之外的页面 CSS 仍须遵守本节禁用项。
````
