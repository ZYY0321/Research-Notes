
## 四、脱敏逻辑（两步走）

### 4.1 思路说明

**脱敏策略是"丢弃"而非"替换"**——不是把手机号改成 `***`，而是把整条包含敏感信息的 query 从训练集里 drop 掉。这是主动选择，原因是：query 里的敏感信息往往在上下文里，单独脱敏字段后 query 也失去了真实性，不如直接剔除。

### 4.2 第一步：规则扫描（快速统计，不修改数据）

代码：`/data/xhx_return_data_2607/meta/scan_query_pii.py`

用正则扫描以下类型，**只记录命中数量，不输出匹配文本**：
- `phone`：手机号（1[3-9]xx）
- `email`：邮箱
- `id_card`：18 位身份证（含校验位验证）
- `bank_card`：银行卡号（Luhn 算法验证）
- `person_titled`：带称谓的人名（汇报人/教授/经理等 + 2-4 汉字）
- `org`：机构名（大学/医院/有限公司等后缀）
- `high_risk_kw`：高风险关键词（病历/工资明细/身份证复印件等）

1-6 月全量扫描结果（`pii_scan_counts_20260831.json`）：
- 49,636 条中 9,698 条（约 19.5%）命中任意一项
- 命中最多的是 `org`（7,050）和 `person_titled`（4,400）

**注意**：规则扫描有较高误报（公司名不一定是隐私），这步主要是给模型打标提供参考，不直接 drop。

### 4.3 第二步：模型逐条判断（实际 drop 决策）

代码：`/data/xhx_return_data_2607/meta/pii_model_label/full_label.py`  
调用内网 LLM，对每条 query 给出是否 drop + 原因类型。

**1-6 月已跑完**（截至 2026-09-15）：

| 指标 | 数值 |
|------|------|
| 总条数 | 47,554 |
| 标记 drop | 2,611（drop rate **5.49%**）|
| real_person | 597 |
| real_org | 1,145 |
| combo（多类组合）| 362 |
| payroll（工资/薪资）| 101 |
| id_account（证件/账号）| 130 |
| roster_minor（名册含未成年）| 94 |
| 其他（地点/生物/医疗/学生名单）| 共 182 |

**7 月**：模型打标**未跑**（`full_label.py` 没有针对 7 月数据的版本）。

### 4.4 脱敏现在的问题

1. **drop 结果没有和 AOSS 数据对齐**：`preds.jsonl` 里的 drop 结论还没有用来从 AOSS 里实际删除或标记这些 query。现在 AOSS 里的 1-6 月数据是"带着应该 drop 的 query"的原始版本。
2. **7 月脱敏未做**：7 月数据只有规则扫描（且只扫了部分），模型判断步骤未跑。
3. **模型打标质量未人工抽检**：drop 决策全靠内网 LLM，没有系统人工复核样本（`审阅包_敏感条_20260906.md` 里有部分，见 `pii_model_label/` 目录，但不是全量验证）。
