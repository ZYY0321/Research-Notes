# 第一部分：OpenMobile 论文解读

## 基本信息

| 项目 | 内容 |
|------|------|
| **论文标题** | OpenMobile: Building Open Mobile Agents with Task and Trajectory Synthesis |
| **arXiv** | 2604.15093 |
| **提交日期** | 2026年4月16日（work in progress） |
| **作者** | Kanzhi Cheng, Zehao Li, Zheng Ma 等（南京大学、商汤科技、南洋理工大学、上海AI实验室） |
| **开源** | GitHub代码 + HuggingFace模型(OpenMobile-8B) + 数据集(OpenMobile-Data) |

## 核心问题

闭源移动端agent（GPT-4o/Gemini）在AndroidWorld上达~70%成功率，而开源方案仅~30%。**瓶颈在于缺乏高质量训练数据**——包括多样化任务指令和包含错误恢复模式的轨迹数据。

## 技术方法

### 阶段一：可扩展的任务合成

核心创新：**将探索与指令生成解耦**

1. **环境探索**：每次session随机探索10步，生成屏幕-动作转换序列
2. **全局环境记忆构建**：
   - 感知哈希（pHash）聚类视觉相似屏幕
   - VLM提取每个UI元素功能描述
   - 建立邻接关系图 + 语义embedding索引
3. **记忆增强的任务合成**：从三个互补来源构建上下文——焦点屏幕、短期记忆（相邻屏幕）、长期记忆（语义相关远距功能），鼓励**跨功能组合**

### 阶段二：策略切换的轨迹采集

交替使用学习者模型和专家模型：
- 监控器（Gemini-3.1-Pro-Preview）检测学习者偏离时，专家介入纠正
- 捕获标准模仿学习中缺失的**错误恢复信号**
- 消融实验：每条轨迹平均1.56次错误恢复 vs 纯专家蒸馏仅0.42次

## 数据集与结果

数据规模：2,800条指令 / 34,000个动作步骤 / 20个Android应用

| 模型 | AndroidWorld | AndroidLab | MobileWorld |
|------|-------------|------------|-------------|
| Qwen3-VL-8B + OpenMobile | **64.7%** | **51.5%** | **17.7%** |
| ScaleCUA (开源baseline) | 27.2% | - | - |

三个benchmark均大幅超越现有开源方法，接近闭源商用系统。

## 局限性

1. 监控器依赖 Gemini 闭源模型
2. 仅覆盖20个Android应用
3. 2,800条指令规模有限
4. Random walk可能无法覆盖深层功能
5. 标注"work in progress"，部分代码coming soon

## 作者研究脉络

| 时间 | 工作 | 贡献 |
|------|------|------|
| 2024 | SeeClick (ACL 2024) | 纯视觉GUI grounding，ScreenSpot benchmark |
| 2024 | OS-Atlas (ICLR 2025 Spotlight) | 最大跨平台grounding语料库（1300万+元素） |
| 2024 | OS-Genesis (ACL 2025) | 逆向轨迹收集：先交互后回溯生成任务 |
| 2025 | OS-Sentinel (ACL 2026) | Mobile GUI agent安全性框架 |
| 2025 | GUI-Actor (NeurIPS 2025) | 坐标自由的视觉定位 |
| 2026 | OpenMobile | 全流程开源数据合成框架 |

# 第二部分：领域现状

## 关键Agent系统

### 基于提示的方法
- **AppAgent**：人类演示/自主探索学习（ICLR 2024 WS）
- **Mobile-Agent v1/v2**：视觉感知 → 三智能体架构
- **UFO**（Microsoft）：Windows双agent框架

### 视觉基础模型

- **SeeClick/GUI-Actor**：视觉定位专家
- **Ferret-UI**（Apple）：移动UI理解
- **ShowUI**：2B轻量模型，256K训练样本

### 强化学习 / 在线学习
- **DigiRL**：1.3B VLM从SFT 17.7% → RL **67.2%**
- **UI-TARS**（字节）：10+基准SOTA
- **AutoGLM**（清华/智谱）：中文app 89.7%

| 方法 | 成本 | 质量 | 平台 | 错误恢复 |

| 人工标注(AITW) | 极高 | 高 | 移动 | 无 |
| AgentTrek (ICLR 2025) | 低($0.55/条) | 中高 | **Web** | 无 |
| OS-Genesis (ACL 2025) | 中 | 中高 | 多平台 | 无 |
| DigiRL/UI-TARS | 高(计算) | 高 | 移动 | 有(RL) |

| Apple | Ferret-UI（端上UI理解） |

# 第四部分：UX Testing 横向如何支撑研究方向

## 横向与研究的关系

UX Testing 横向项目用 GUI Agent 做自动化界面测试——这与 OpenMobile 数据合成方向有**天然的双向支撑关系**：

### 4.1 横向为研究提供的支撑

| 支撑点 | 说明 |
|--------|------|
| **真实app交互数据** | UX Testing过程中产生的agent轨迹可作为数据合成的种子数据或验证集 |
| **多样化的app覆盖** | 横向项目接触大量真实商业app（不限于OpenMobile的20个），天然扩展数据多样性 |
| **错误模式积累** | UX Testing的核心就是发现bug和异常——这些错误模式正是数据合成中错误恢复信号的来源 |
| **工程基础复用** | Android模拟器环境、app安装部署、轨迹记录等基础设施，横向和研究共用 |
| **真实需求驱动选题** | 从实际UX Testing中发现agent的具体弱点，反过来指导数据合成的优化方向 |

### 4.2 研究反哺横向

- 更好的数据合成方法 → 训练出更强的GUI Agent → UX Testing效果提升
- 跨App任务合成能力 → 支撑跨App的端到端测试场景
- 安全感知数据 → agent在测试中不会执行破坏性操作

### 4.3 向导师说明的逻辑

> "横向的UX Testing项目和我的研究方向是互相支撑的。UX Testing让我有机会接触大量真实app和真实错误模式，这些是数据合成研究中最缺的资源。同时研究产出的更好的agent能力直接提升横向交付质量。这不是两件独立的事，而是一个正循环。"

## 4.4 UX Testing可能衍生的新研究方向

### 方向F1：面向软件测试的GUI Agent数据合成

**思路**：现有数据合成（包括OpenMobile）的任务目标都是"完成用户需求"（如发邮件、订餐）。但UX Testing的目标不同——是**主动寻找界面bug和异常**。这需要完全不同类型的探索策略和任务合成逻辑。

**创新点**：
- 将数据合成从"任务完成型"扩展到"缺陷发现型"
- 设计面向bug发现的探索策略（boundary testing, 异常输入, 边缘路径等）
- 合成包含"正常操作→异常触发→bug报告"完整链路的训练数据

**可行性**：⭐⭐⭐ — 组内有UX Testing横向的真实数据和场景，彭鑫老师的软件工程背景天然匹配

### 方向F2：GUI Agent在软件测试中的能力评估

**思路**：现有benchmark（AndroidWorld等）只评估"用户任务完成"，完全没有评估agent在软件测试场景下的表现——如能否发现UI bug、能否生成有效测试用例、能否覆盖更多UI状态。

**创新点**：构建首个面向"GUI agent做软件测试"的评估框架

**可行性**：⭐⭐⭐ — benchmark型工作适合新生，与彭鑫组的软件测试方向完美契合

# 第五部分：具体可做的后续方向（排序）

## 推荐排序

| 排序 | 方向 | 创新性 | 可行性 | 组内匹配 | 合作者 |
|------|------|--------|--------|---------|--------|
| 1 | **E1：跨App复杂任务合成** | ⭐⭐⭐ | ⭐⭐ | ⭐⭐ | 程瞰之 |
| 2 | **F1：面向UX Testing的数据合成** | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ | 组内 + 程瞰之 |
| 3 | **E3：安全感知数据合成** | ⭐⭐⭐ | ⭐⭐ | ⭐⭐ | 程瞰之(OS-Sentinel) |
| 4 | **F2：测试场景agent评估** | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ | 组内 |
| 5 | **E2：去闭源依赖+数据效率** | ⭐⭐ | ⭐⭐⭐ | ⭐⭐ | 孙秋实(PRM) |

## 推荐策略

**最佳路线**：E1 或 F1 作为主线，E3 作为备选
- E1（跨App）：纯学术创新最强，但需要更多设计工作
- F1（UX Testing数据合成）：**最独特的差异化优势**——别人没有UX Testing的真实场景和数据，组内匹配度最高
- E3（安全）：与OS-Sentinel结合自然，审稿人认可度高

**F1的特别优势**：如果走"面向UX Testing的数据合成"方向，这在GUI agent领域是**完全无人做的交叉方向**。别的组做不了——他们没有软件测试的背景和真实项目数据。这恰好是彭鑫组的独特优势。
