# 附件二：标准模式 Query 合成管线技术说明

**整理时间**：2026-06-12  **负责人**：张荧滢

---

## 一、背景与目标

标准模式的原始数据是「回流 PPT 解析结果」，只有结构化内容（大纲+要点），缺少视觉设计描述，无法直接作为 gpt-image-2 的生图 prompt。

**目标**：将内容侧（回流数据）和设计侧（L3 prompt 库）合并，产出可以直接送给 gpt-image-2 的完整生图 prompt，进而生成带内容的 PPT 页面图片。

---

## 二、数据来源

### 内容侧（Content）
- **文件**：`data/standard_mode/std_mode_full.jsonl`
- **来源**：标准模式 PPT 回流数据全量解析，共 **36,573 页 / 2,807 套 PPT**
- **字段**：`ppt_title`（PPT 主题）、`page_title`（页面类型，如「图表页」「章节标题页」）、`content_json`（结构化内容：标题、要点列表、数据等）

### 设计侧（Design）
- **文件**：`manual_content_design_handwritten_current.jsonl`
- **来源**：孙继业人工采集并精拆，300 条，来自 2slides、canghe 等设计网站
- **字段**：`content`（内容说明，入管线时忽略）、`design`（纯设计描述：配色/布局/字体/元素）、`asset_type`（类型，如 infographic / ppt_slide / poster）、`id`（来源标识）

## 三、管线流程

```
std_mode_full.jsonl
      │
      ▼ [1] 采样（按页面类型覆盖均衡）
  30 条页面
      │
      ▼ [2] 内容提取
  content_text = PPT主题 + 页面类型 + 要点列表
      │
      ▼ [3] Design 选取（LLM 择优）
  从全部 300 条 design 中随机抽 5 个候选
      │
      ▼  Claude Sonnet API
  LLM 输出：chosen_idx（1-5）+ 选择理由 + 合成 prompt
      │
      ▼ [4] gpt-image-2 生图（并行，10 workers）
  1536×864 PNG，quality=medium
      │
      ▼ [5] 输出
  synthesized_queries.jsonl + images/ + gallery.html
```

### 步骤说明

**[1] 采样策略**：按 `page_title` 分组，尽量每种类型各取 1 条，保证 30 条覆盖 30 种不同页面类型。若不足则随机补全。

**[2] 内容提取**（`extract_content_text` 函数）：
- 提取 `ppt_title`（PPT 整体主题）
- 提取 `page_title`（当前页面功能分类）
- 遍历 `content_json.content` 字典，拼接各要点的 `sub_point_name` 和 `text`
- 输出：中文纯文本，约 100-300 字

**[3] Design 选取**（核心改进点）：
- 从全部 300 条 design 中随机抽 5 个候选（保证每批内不重复 source）
- 将 content_text + 5 个候选 design 全文送给 Claude Sonnet
- LLM 输出 JSON：`{"chosen_idx": 2, "reason": "...", "synthesized_prompt": "..."}`
- 相比旧版「固定类型映射表」的优势：语义对齐（LLM 判断内容与设计的匹配度），无需维护映射规则，新页面类型自动兼容

**[4] 生图**：
- 模型：`gpt-image-2`（tokenhub 代理，`https://tokenhub.sensetime.com/v1`）
- 尺寸：`1536×864`（16:9），quality=medium
- 并发：ThreadPoolExecutor，10 workers
- 重试：最多 8 次，遇 429 限流等待 10s，遇 400/safety 跳过

### 4.2 合成 Prompt 示例

```
PPT主题：差旅费用超支分析报告
页面类型：不足分析-柱状图
```

## 五、两种路径对比

| 维度 | 创意模式 | 标准模式（本管线） |
|------|---------|-----------------|
| 内容来源 | PPT 原始 image_prompt（有设计意图） | 回流数据结构化内容（无设计） |
| 设计来源 | 无（image_prompt 已包含） | L3 人工精拆 design prompt |
| LLM 介入 | G6 分类（规则+LLM） | Design 选取 + Prompt 合成 |
| 单张成本 | ~$0.04（生图） + ~$0.003（分类） | ~$0.04（生图）+ ~$0.005（合成） |
| 适合场景 | 大量快速生产，质量稳定 | 覆盖结构化 PPT 内容，多样化风格 |

## 六、已知问题与改进方向

| 问题 | 影响 | 改进方案 |
|------|------|---------|
| Design 来源多样性不足（canghe 占 43%） | 生图风格偏集中 | 补充 Playwright 爬取 2slides/slidesgo |
| 无 baseline 对照（已修复） | 无法量化 design 的增益 | 已新增 content-only 对照批次 |
| content_json 解析覆盖不全 | 部分页面内容提取为空 | 补充模板名（template_xx）的解析逻辑 |
| LLM 合成串行，速度慢 | 30 条约 15-20 分钟 | 可改并发（注意 429），或换更快模型 |
