## 三、回流数据结构

### 原始格式

回流数据以 **月包 zip** 交付，例如 `2026-05_创意模式_1.zip`。

```
月包.zip
  └─ YYYY-MM-DD/                    (按日期分目录)
      └─ aipptx-ppt-id-{uuid}.zip  (每套PPT一个zip)
          └─ aipptx-ppt-id-{uuid}/
              ├─ creative-outline-generate_{trace_id}.json   (创意模式)
              ├─ creative-page-generate_{N}_{trace_id}.json  (创意模式，每页一个)
              ├─ html-outline-generate_{trace_id}.json       (html模式)
              ├─ html-page-generate_{N}_{trace_id}.json      (html模式)
              └─ standard-outline-generate_{trace_id}.json   (标准模式)
```

### 三种模式的区别

| 模式 | 有 image_prompt | 有内容(content) | 处理方式 |
|------|:-:|:-:|------|
| 创意模式 | ✅ 回流自带完整生图 query | ✅ | 直接用原 query 生图 |
| 标准模式 | ❌ 只有内容无设计 | ✅ | 需要配设计 prompt，LLM 合成 query |
| html模式 | ✅ 有 image_gen_final_prompt | ✅ | 可直接用原 query 生图（同创意模式） |

### 提取脚本

已有提取脚本（以创意模式为例）：
```
/home/gui-5d025-2/zyy/data/xhx_return_data_creative_mode_260204/extract_images.py
```
功能：解压 zip → 解析 JSON → 提取 page_outputs.jsonl / outlines.jsonl 等结构化文件。

## 四、处理管线

### 4.1 创意模式 / html模式管线

**脚本**: `scripts/creative_mode_pipeline.py`

```bash
# 全量运行
python -u scripts/creative_mode_pipeline.py --sample 0 --workers 8 --batch-size 30

# 测试
python -u scripts/creative_mode_pipeline.py --sample 10 --workers 2
```

**流程**:
```
page_outputs.jsonl (含 image_prompt)
  → 规则 + LLM G6 分类 (13类)
  → gpt-image-2 生图 (1536×864, quality=medium)
  → metadata.jsonl + images/G6-XX/
```

**关键参数**: `--sample`(0=全量), `--workers`(并发线程), `--batch-size`, `--classify-only`

**输入**: 需要 `page_outputs.jsonl`（含 `image_prompt` 字段）和 `outlines.jsonl`（含 `ppt_title`）

**输出**: `metadata.jsonl` + `images/G6-XX_类别名/{ppt_id}_p{page_num}.png`

### 4.2 标准模式管线

**脚本**: `scripts/0613_run_full_standard.py`

```bash
python -u scripts/0613_run_full_standard.py --synth-workers 6 --img-workers 10
```

**流程**:
```
std_mode_full.jsonl (内容页，无设计)
  + 设计prompt池 (L3手工300 + L2蒸馏495)
  → 每页抽5候选设计 → Claude 择优合成英文 query
  → gpt-image-2 生图
  → G6 分类 → synthesized_queries.jsonl + images/
```

**设计 prompt 池位置**:
- L3: `/home/gui-5d025-2/zyy/data/prompt_sources/handoff_public_machine_2026-06-11/01_final_formal_split/manual_content_design_handwritten_current.jsonl`
- L2: `data/standard_mode/0613_l2_design_pool.jsonl`

**输入**: `std_mode_full.jsonl`，每行一页 PPT 内容（ppt_id, page_idx, ppt_title, page_title, content_json）

**输出**: `synthesized_queries.jsonl`（合成记录）+ `images/{img_name}`

### 4.3 标准模式输入文件生成

标准模式的输入 `std_mode_full.jsonl` 从回流数据提取：
```python
# 每行格式
{
    "ppt_id": "uuid",
    "page_idx": 0,
    "ppt_title": "...",
    "page_title": "...",
    "content_json": {...},   # 页面结构化内容
    "content_text": "..."    # 拼接的纯文本摘要
}
```

## 五、G6 分类体系

13 类 PPT 版式分类（按页面结构，非内容主题）：

| 编号 | 类别 |
|------|------|
| G6-01 | 标题页/封面 |
| G6-02 | 大纲/目录页 |
| G6-03 | 章节过渡页 |
| G6-04 | 内容页-纯文字 |
| G6-05 | 内容页-图文混排 |
| G6-06 | 数据页-含图表 |
| G6-07 | 对比页 |
| G6-08 | 时间线页 |
| G6-09 | 流程/步骤/组织关系页 |
| G6-10 | 矩阵/框架分析页 |
| G6-11 | 数据汇总页 |
| G6-12 | 产品/服务介绍页 |
| G6-13 | 结束/致谢页 |

**分类逻辑** (在 `creative_mode_pipeline.py` 中):
1. `rule_classify()`: 规则前置，page_type/标题关键词直判
2. `classify_g6_with_llm()`: Claude 兜底分类

### 6.4 命名规则

| 模式 | 前缀 | 格式 |
|------|------|------|
| 创意模式 | `cm_` | `cm_G6-XX_{ppt_id前12位无横线}_p{页码3位}.png` |
| 标准模式 | `std_` | `std_G6-XX_{ppt_id前12位无横线}_p{页码3位}.png` |
| 标准扩充 | `std_` | `std_G6-XX_{ppt_id12}_p{页码}_s{slot}.png` |
| 视觉设计 | `vd_` | `vd_{type}_{id}.png` |

ppt_id 取前12位，去掉横线。

### 6.5 Meta JSONL 字段

**通用字段**: source, date, image_path(完整s3://路径), image_name, g6_label, g6_label_name, g6_confidence, ppt_id, ppt_title, page_idx, page_title, image_prompt, image_model

**标准模式额外**: content_text, design_tier, design_asset_type, chosen_design_id, chosen_reason, design_text

**image_path 必须是完整路径**: `s3://ppt-data/ppt-image-distill/{batch}/{images}/G6-XX/filename.png`

## 十、注意事项

1. **AOSS 路径格式**: 日期后面要有 `/`，即 `{batch}_{date}/images/G6-XX/`，不是 `{batch}_{date}images/`
2. **meta image_path**: 必须是完整 `s3://ppt-data/...` 路径，不要用相对路径
3. **ppt_id 12位**: 去横线后取前12个字符
4. **文件名不含日期**: 日期在目录层级，不在文件名中
5. **断点续跑**: 所有管线都支持，重新运行会自动跳过已完成的
6. **安全策略拦截**: gpt-image-2 会拒绝部分 prompt（约 3-20% 失败率），这是正常的
7. **quality=medium**: 当前所有批次统一使用 medium（1536×864），非 high
8. **文档命名**: 所有输出文件带日期前缀 `MMDD_`
