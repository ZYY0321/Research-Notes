# 端午数据扩充方案（2026-06-18 ~ 06-20）

> 目标：利用端午三天长假，两条管线并行产出新一批蒸馏图像，扩充数据集多样性与规模。

---

## 一、背景与动机

截至 6/15 交付：创意模式 18,197 + 标准模式 33,784 = **51,981 张**，已上传 AOSS。

当前瓶颈：
- 回流内容已全部消耗（每页内容仅配了 1 个设计生 1 张图）
- 图像类型集中在 PPT 页面，缺少海报、品牌视觉、插画等场景
- 设计多样性不足（795 个设计卡，每页只用了 1 个）

---

## 二、方案总览

| 路线 | 思路 | 预估产量 | 新增价值 |
|------|------|----------|----------|
| **A：同内容×多设计** | 36K 页 PPT 内容 × 每页追加 2~3 个不同设计 | ~108K 张 | 设计多样性：同一内容在不同视觉风格下的表现 |
| **B：非 PPT 视觉设计直出** | 从广泛 prompt 池筛选海报/品牌/插画等 prompt 直接生图 | ~10K~15K 张 | 场景多样性：覆盖 PPT 以外的视觉设计类型 |

两批独立，`source` 字段区分（`standard_mode_v2` / `visual_design`），各自有效，数量不均衡不影响数据可用性。

## 五、技术细节

### 5.1 路线 A：同内容×多设计

#### 核心改动：设计排除 + 多轮生图

第一轮已为每页选了 1 个设计（记录在 `chosen_design_id`），第二轮开始需要排除已用过的设计，保证每次使用的设计不重复。

**已用设计排除逻辑**：
```
1. 从 synthesized_queries.jsonl 读取所有记录
2. 建索引: (ppt_id, page_idx) → set(已用 design_id)
3. sample_candidates() 时跳过已用 design_id
4. 每轮结束后更新索引
```

**文件命名**：在现有命名基础上追加设计 ID 后缀，区分同一页内容的不同设计版本：
```
原来: std_G6-04_795292103aaf_p003.png         （第一轮，唯一）
新增: std_G6-04_795292103aaf_p003_dl2p00062.png  （第二轮，L2设计#62）
      std_G6-04_795292103aaf_p003_dl3p00187.png  （第三轮，L3设计#187）
```

前缀 `dl2p` / `dl3p` / `dgen` 分别表示 L2/L3/generic 来源，后面跟设计编号，一眼可辨。

**每页追加轮数**：设计池共 795 条（300 L3 + 495 L2），第一轮用了 1 条，剩余 794 条。每页追加 2~3 个不同设计生图，设计池绰绰有余。

**合成策略调整**：
- 第一轮每页抽 5 候选选最优，逃逸率 ~13%
- 追加轮可以直接"随机指定 1 个未用设计 + 页面内容"合成 prompt，不再做 5 选 1（因为最优设计已经在第一轮用过了，追加轮本身就是追求多样性）
- 通用兜底设计（generic）在追加轮也作为一个独立设计使用

**输出结构**：
```
data/standard_mode/0618_multi_design/
  round2/
    synthesized_queries.jsonl   # chosen_design_id 全部与第一轮不同
    images/
  round3/
    synthesized_queries.jsonl
    images/
```

#### 产量估计

| 轮次 | 页数 | 设计选择方式 | 预估图片 |
|------|------|-------------|----------|
| Round 2 | 36,573 | 随机指定 1 个未用设计 | ~35,000 |
| Round 3 | 36,573 | 随机指定另 1 个未用设计 | ~35,000 |
| Round 4（如时间允许） | 36,573 | 同上 | ~35,000 |
| **小计** | | | **70,000~105,000** |

### 5.2 路线 B：非 PPT 视觉设计直出

#### 筛选管线

从广泛池 34,595 条中筛出可直接生图的视觉设计类 prompt，三步：

**Step 1 — 关键字类型过滤**（规则，秒级）：
```
保留类型: poster, ad, banner, brand, logo, packaging, infographic,
         illustration, art, product, commercial, UI, web design,
         3D, render, card, invitation, collage, sticker, icon
排除类型: 纯人像写真, 纯自然风景, 纯动物, 纯摄影(无设计元素)
```
预期通过: ~9,000~10,000 条

**Step 2 — Prompt 质量过滤**（规则，秒级）：
```
- prompt 文本长度 > 80 字符
- 非纯 image-editing instruction（排除 "make it brighter" 这类）
- 非 video prompt（排除 "cinematic motion" 等视频描述）
- 去重（指纹哈希，与 L2 蒸馏同方法）
```
预期通过: ~7,000~8,000 条

**Step 3 — LLM 质量判定**（可选，看时间）：
```
- 对 Step 2 结果用 Claude 逐条打分
- 判断: 是否为高质量视觉设计生图 prompt? (1~5分)
- 保留 ≥3 分
```
如果时间紧可以跳过此步，Step 2 产出已经可以直接用。

#### 补充来源

除广泛池外，还有两个补充：

1. **0608 外包整理的 265 条高相关 prompt**：已经有人工相关性标注，直接纳入
2. **19,150 专业设计候选池重筛**：之前 L2 蒸馏时只保留了 PPT 可迁移的设计，现在放宽标准重筛一遍，凡是"视觉设计类"（海报/品牌/插画/信息图等）都保留，不限于 PPT。预计新增 3,000~5,000 条

#### 生图管线

复用创意模式 pipeline（`scripts/creative_mode_pipeline.py` 的生图部分），适配点：
- 输入: 筛选后的 prompt jsonl（每行一个 `image_prompt` 字段）
- 生图: `gpt-image-2`，分辨率根据 prompt 内 aspect ratio 提示自适应（默认 1536×864）
- 并发: 与路线 A 共享 API 额度，各分一半线程
- 输出: `data/visual_design/0618_full/images/` + `synthesized.jsonl`

#### 命名规则

```
vd_{type}_{prompt_id}_001.png

示例:
  vd_poster_p03227_001.png     （海报类 #3227）
  vd_brand_p01900_001.png      （品牌类 #1900）
  vd_illust_p01825_001.png     （插画类 #1825）
```

前缀 `vd_` 区分视觉设计类，`{type}` 为 prompt 类型缩写。

### 5.3 分类与打包

两批均复用现有 13 类分类管线（规则前置 + LLM）。

路线 B 的非 PPT 图像可能出现分类体系不完全匹配的情况（比如品牌 logo 图不太属于任何 G6 类），处理方式：
- 仍然用 G6-01~G6-13 分类（保持统一口径）
- 非 PPT 图自然会集中在 G6-05（图文混排）和 G6-12（产品/服务介绍）
- 如有需要，可追加 G6-14+ 新类别（需讨论）

### 5.4 API 并发分配

两条管线共享 API 额度，建议分配：

| 管线 | 合成并发 | 生图并发 | 说明 |
|------|----------|----------|------|
| 路线 A（合成+生图） | 10 | 15 | 需要先合成 prompt，再生图 |
| 路线 B（直接生图） | — | 25 | prompt 已有，只需生图 |

根据实际 429 频率动态调整。

## 七、风险与预案

| 风险 | 影响 | 预案 |
|------|------|------|
| API 限流（429） | 生图速度下降 | 快速固定间隔重试（3s），不用指数退避 |
| 路线 A 追加轮合成逃逸率升高 | 追加轮设计不是最优匹配，逃逸率可能从 13% 升至 20%+ | 可接受，generic 兜底图仍为有效数据 |
| 路线 B prompt 质量参差 | 部分 prompt 生图效果差 | Step 2/3 过滤把关；生成后可抽检 |
| 磁盘空间（原盘 97%） | 新图存不下 | 直接存 `/data` 盘（1.6TB 空余） |
| 三天跑不完 | 产量不达预期 | 优先保证路线 A 2 轮（~70K），路线 B 次之 |
