## 三、讲解：把整件事串起来

### 3.1 GUI 测试在做什么：三问

自动 GUI 测试可以拆成三个问题：
- **测什么**：让工具点哪里、走到哪个页面。
- **怎么知道错了**：也就是 oracle，判断屏幕上的结果是不是 bug。
- **测得够不够**：覆盖率、检出了多少缺陷。

合作者的大表按这三问打标签。

- **2019–2023 年**，主要研究“测什么”。随机点击、基于模型的探索、强化学习探索，判错基本只看 crash，因为 crash 最容易自动判定。
- **2024 年以后**，LLM 进来了。GPTDroid 让大模型像人一样规划去点哪里，覆盖率上去了，但判错仍然只看 crash。
- **现在的主战场是“怎么知道错了”**。大量 bug 不会崩溃，比如显示错乱、功能结果不对。大表里这一类有几种做法：
  - VisionDroid：直接让多模态模型看截图判断，但 Precision 只有 0.50–0.76，误报很多。
  - GUIPilot：拿设计稿当标准答案。
  - Kea、PropGen、iPBT：把业务规则写成性质，再自动检查。
  - LDMDroid：检查增删改查前后的数据状态。
  - KuiTest：先预测一个控件“应该”有什么功能，再验证实际响应对不对。

规律是：**有外部标准的判定（设计稿、性质、数据状态）比只靠模型常识更可靠。**

### 3.2 UX-Agent 在这张图上的位置

UX-Agent 属于“怎么知道错了”这一类，专门处理显示缺陷，也就是截断、遮挡、重叠、溢出。它的特别之处是不只看截图：

1. 截图提出候选：这里可能有文字被截断。
2. ArkUI 布局树复核：看文字长度是不是真的超过了容器。
3. 主动滑动探测并还原：区分“真截断”和“滑一下就能看到”。

相关文献可以分成三层：
- 经典工作 OwlEye（ASE'20）、Nighthawk（TSE'23）：训练分类器识别截图。
- 新一代 Minuku（工业界，ASE'25）、VisionDroid、UI-Lens：让大模型看图判断。
- 最新趋势是**主动改变界面状态再判断**：
  - dVermin：放大字体后比较。
  - Proactive-MW：主动触发分屏、折叠。分屏和折叠状态下，文字截断比全屏多 184%，遮挡多 196%。
  - RotDroid：横竖屏旋转后比较语义是否等价。

UX-Agent 的“滑动探测”就属于这一类，而且还多了一层布局树复核。
- **鸿蒙上的空白**：现在只有 OH-Overlap 做过 UI 重叠，而且关注的是性能。没有人在 ArkUI 上做过显示缺陷基准。

### 3.3 Agent 当测试员

现在大家在尝试让 GUI Agent 直接去找 bug，但效果还不好：
- GUITester 指出 Agent 有两个毛病：一是把 bug 当障碍绕过去，二是把系统 bug 误判成自己点错了。最好的结果 F1 也只有 48.90%。
- GUITestScape 把找 bug 拆成三步：到达 → 触发 → 识别。最弱的是“识别”，最好的模型 Recall 只有 40.55%。但只要给 Agent 加一个专门的验证器，UI-TARS 的 Recall 就从 7.48% 提到 57.02%。
- **这说明瓶颈在“判定”，不在“操作”**，和 3.1 的结论一致。另外，GUITester 原文明确把截断、重叠这类显示缺陷列为未来工作，正好是我们的地盘。

### 3.4 软工×AI 和 CUA：同一个问题换了个名字

在 AI 这边，训练 CUA 要用强化学习，强化学习需要奖励，奖励就是判断“任务做对了没有”，本质上就是 oracle。近期证据都说明这些判定器不可靠：
- TestJack（代码 Agent）：大约 34.4% 原本“通过”的提交其实违反了任务要求，总解决率从 50.6% 掉到 33.2%。
- AgentHorizon（CUA）：用“看起来完成了但其实做的是另一件事”的轨迹去骗裁判，最好的裁判平衡准确率也只有 80.9%。
- IRA 的回应：不能只看截图，要主动取证，比如查文件、读配置、调工具，准确率 86.9%。这和 UX-Agent “截图不够，要查布局树、要滑动”的思路是同构的。

通义上周发了两篇：
- **MAI-Gym**：大规模合成可重置的模拟 App，每个任务配一个可执行的判定器，用来做强化学习。仿造 App 上训练出来的能力，能迁移到真实手机 App（52 个任务上从 28.8% 提到 48.1%）。
- **OpenGCUA**：让模型把点击、命令行、无障碍树操作写成一段 Python 程序，并由模型自己决定什么时候截图。8 个前沿模型的平均 partial score 提高 19.6 分，步数减少 53%。

它们的判定器都只判断“任务完成了没有”，**不判断界面有没有缺陷**。这就是我们两组方向的连接点：
- A 组（SE）：把 UX-Agent 的判定器做成鸿蒙显示缺陷的方法和基准。
- B 组（AI）：把同样的判定思路变成 CUA 强化学习里可信的奖励，或者训练会找 bug 的 Agent。
