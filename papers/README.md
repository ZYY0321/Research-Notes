计划：软件工程会议 1–2 篇，AI 会议 1 篇。**三篇的思考方式不一样，分开写、分开判断**，不要把一篇的评价标准套到另一篇上。

| 文件 | 场合 | 一句话 | 怎么判断好不好 |
|---|---|---|---|
| [SE1_折叠屏开合显示问题.md](SE1_折叠屏开合显示问题.md) | ICSE / FSE / ASE / ISSTA | 鸿蒙折叠屏上，开合引起的显示问题：有多普遍、分几类、怎么自动检测 | 问题重要、实证扎实、工具好用、找到并被确认的真实 bug |
| [SE2_UX问题导向的GUI探索.md](SE2_UX问题导向的GUI探索.md) | ICSE / FSE / ASE | 探索的目标不是覆盖率，而是尽快走到会出 UX 问题的页面状态 | 同样的预算下找到更多不同的 UX 问题；功能级覆盖；对比 2024 年以后的探索工具 |
| [AI1_可注入缺陷的GUI环境与会找缺陷的智能体.md](AI1_可注入缺陷的GUI环境与会找缺陷的智能体.md) | ICLR / NeurIPS（主会或 Datasets & Benchmarks）/ ACL | 把视觉和功能缺陷程序化地注入可重置的复刻 App，做成能自动核验的训练环境，训出会找缺陷的 GUI 智能体 | 开放、可复用的资源，加一个新的认识；在公开 benchmark 上用同一个基座比；新意落在 GUI 本身的难点上 |

三篇共用同一个技术内核：**可执行环境 + 能自动核验的判定器 + 智能体**。

- SE1 提供判定器和真实数据：开合问题的规则、标注、真机证据。
- SE2 提供真机上的探索方法。
- AI1 把判定器和探索都放进可训练的环境里。
