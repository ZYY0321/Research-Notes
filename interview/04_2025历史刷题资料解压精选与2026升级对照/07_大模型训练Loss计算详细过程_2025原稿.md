# 大模型训练Loss计算详细过程

### 大模型监督微调（SFT）过程中的 Loss 计算详解

在大型语言模型（LLM）的监督微调（Supervised Fine\-Tuning, SFT）阶段，Loss 的计算是指导模型学习如何根据用户指令（Prompt）生成期望回答（Completion）的核心机制。其本质是衡量模型预测的下一个词与真实答案的下一个词之间的差距。

SFT 的 Loss 计算过程可以分解为以下几个关键步骤：

1. 数据准备：Prompt 和 Completion 的拼接

SFT 的训练数据通常是一系列的“指令\-回答”对。在输入给模型之前，需要将这两部分拼接成一个完整的文本序列。

- **原始数据**：

    - `Prompt`: "中国的首都是哪里？"

    - `Completion`: "北京。"

- **拼接后**：

    - `Input Sequence`: "中国的首都是哪里？北京。"

为了让模型知道哪部分是它需要学习模仿生成的内容，通常会使用一个特殊的 `loss mask` 或通过设定计算范围来指明。

2. Tokenization：将文本转换为数字

模型无法直接处理文本，因此需要通过 Tokenizer 将拼接后的文本序列转换为一连串的数字 ID（Token ID）。

- **`Input Sequence`**: "中国的首都是哪里？北京。"

- **`Tokenized IDs`**: `[101, 704, 750, 441, 782, 689, 8043, 102]` \(此为示例ID\)

3. 模型的前向传播（Forward Pass）

将 Tokenized IDs 输入到模型中，进行一次完整的前向传播。模型的核心任务是**预测序列中每一个位置的下一个 Token 是什么**。

对于输入序列中的每一个 Token，模型都会输出一个庞大的向量，称为 **Logits**。这个 Logits 向量的维度等于词汇表（Vocabulary）的大小。向量中的每一个值代表了词汇表中对应 Token 在当前位置出现的可能性得分（未经归一化的对数概率）。

- **输入**: `[101, 704, 750, 441, 782, 689, 8043, 102]`

- **模型输出 \(Logits\)**: 假设词汇表大小为 50000，那么对于输入的 8 个 Token，模型会输出一个形状为 `[8, 50000]` 的 Logits 矩阵。

4. 关键步骤：计算交叉熵损失 \(Cross\-Entropy Loss\)

这是 Loss 计算的核心环节。我们使用交叉熵损失函数来衡量模型预测的概率分布与真实答案（Ground Truth）之间的差异。

计算过程如下：

1. **确定目标 \(Labels\)**：预测下一个词的任务中，目标（Label）就是输入序列向左移动一位的结果。

    - `Input IDs`: `[101, 704, 750, 441, 782, 689, 8043, 102]`

    - `Target Labels`: `[704, 750, 441, 782, 689, 8043, 102, <ignored>]`

    - 换句话说，当模型看到 Token `101` 时，我们希望它预测出 `704`；看到 `704` 时，希望它预测出 `750`，以此类推。最后一个 Token 没有后续，因此其损失通常被忽略。

2. **对齐 Logits 和 Labels**：将模型输出的 Logits 与 Target Labels 对齐。

    - `Logits for position 0`: 模型看到 `101` 后输出的 `[1, 50000]` 向量。

    - `Label for position 0`: `704`

    - `Logits for position 1`: 模型看到 `704` 后输出的 `[1, 50000]` 向量。

    - `Label for position 1`: `750`

    - \.\.\. 以此类推

3. **计算每个 Token 的 Loss**：对每一个位置，独立计算交叉熵损失。具体来说，对于位置 `i`：

    - 首先，对模型输出的 Logits 向量（`Logits[i]`）应用 Softmax 函数，将其转换为一个表示概率分布的向量 `Probs[i]`。

    - 然后，从 `Probs[i]` 中取出目标 Label `Labels[i]` 对应的那个概率值。

    - 最后，计算这个概率的负对数 `-log(probability)`，这就是该位置的交叉熵损失。

4. SFT 的核心：只计算 Completion 部分的 Loss

**这是 SFT 与预训练阶段最大的区别**。在 SFT 中，我们只关心模型能否根据 Prompt 生成正确的 Completion，而不关心它对 Prompt 部分的预测能力（因为 Prompt 是给定的条件，不是学习目标）。

因此，我们需要一个机制来“屏蔽”掉 Prompt 部分的损失，只对 Completion 部分的 Token 计算 Loss。

- **实现方式 1：Loss Mask**

    - 创建一个与输入序列等长的 Mask 向量。

    - Prompt 对应的位置为 0，Completion 对应的位置为 1。

    - `Input IDs`: `[101, 704, 750, 441, 782, 689, 8043, 102]`

    - `Prompt Tokens`: `[101, 704, 750, 441, 782, 689]`

    - `Completion Tokens`: `[8043, 102]`

    - `Loss Mask`: `[0, 0, 0, 0, 0, 0, 1, 1]`

    - 在计算出每个位置的 Loss 后，将其与 Loss Mask 相乘。这样，Prompt 部分的 Loss 就都变成了 0。

- **实现方式 2：标签填充 \(Label Padding\)**

    - 在构建 Target Labels 时，将 Prompt 部分对应的 Label 设置为一个特殊的忽略索引值（例如 `-100`）。

    - `Target Labels`: `[-100, -100, -100, -100, -100, -100, 8043, 102]`

    - 主流的深度学习框架（如 PyTorch）中的交叉熵损失函数会自动忽略这些特殊索引值，不计算它们的 Loss。

**无论哪种方式，最终效果都是一样的：只有 Completion 部分的 Token 产生了有效的 Loss 值。**

5. 聚合与反向传播

6. **计算平均 Loss**：将所有未被屏蔽的 Token 的 Loss 值相加，然后除以产生 Loss 的 Token 数量，得到这个样本的最终平均 Loss。

7. **反向传播 \(Backpropagation\)**：将这个最终的 Loss 值反向传播，计算出模型中所有可训练参数（例如 LoRA 矩阵或全量参数）的梯度。

8. **参数更新**：优化器（如 AdamW）根据计算出的梯度来更新模型的参数，使模型在下一次预测时，能够为正确的 Completion Token 生成更高的概率。

#### 总结

SFT 过程中的 Loss 计算是一个精确控制的“下一个词预测”任务。其核心在于，通过 **Loss Masking** 或 **Label Padding** 等手段，将学习信号**精确地聚焦在模型需要生成的 Completion 部分**，而忽略输入的 Prompt 部分。通过最小化这个目标区域的预测损失，模型逐渐学会了遵循指令、生成符合人类期望的回答。
