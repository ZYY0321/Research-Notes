### Q01：Agent 训练数据合成的主流方法有哪些？结合你的项目讲讲怎么保证合成质量与多样性？
- **核心结论**：当前主流分四条路线——**① 正向轨迹蒸馏（Teacher Rollout + Rejection Sampling）**、**② 逆向探索与环境记忆合成（先探索建图再生题，如 OS-Genesis / OpenMobile）**、**③ 策略切换纠偏采集（Learner 探索 + Expert 接管补错误恢复）**、**④ 可执行环境变异逆向出题（如 SWE-smith / 状态变异造题）**。保证质量靠**执行器/状态 Verifier 硬门禁 + 协议清洗**，保证多样性靠**跨维度正交组合 + 去重过滤**。
- **机制与你的项目落点**：
  1. **逆向探索 + 全局记忆（解决“拍脑袋编题同质化、不可执行”）**：在 **OpenMobile** 中，将探索与出题解耦——先做 10 步随机探索，用 pHash（$\tau=0.95$）聚类去重构建状态转移图，结合邻接屏（短期记忆）与语义 Embedding 检索的远端功能（长期记忆 Top-30 多样性过滤）合成跨功能复合指令，与测试集语义高相似比例仅 **3.5%**。在 **OpenMobile-2** 的 `0815` 造题管线中，喂给模型“导航可达图 + 实体可写字段 + 真实种子 ID + 关键页截图”，严格把生成与人工/规则可执行性审查分离，杜绝编造不存在的商品与功能。
  2. **弱探索 + 强接管 Policy-Switching（解决“纯专家轨迹缺错误恢复信号”）**：学习者跑偏时由监控器触发专家模型介入纠偏，每条轨迹错误恢复次数从纯蒸馏的 **0.42 次提升至 1.56 次**，在 OpenMobile-2 中规模化合成了 **11,643 条** SFT 轨迹。
  3. **正向强教师蒸馏 + 六步协议清洗（解决“教师轨迹带脏协议训坏学生”）**：在小浣熊 **AgentV3** 中蒸馏 16,274 条 Opus 4.7 多轮轨迹，不仅用基于容器 ACP 协议的无状态隔离沙盒防串扰，还专门针对 `<file_action>` 漏发（65%–89%）与末轮悬空早停（12.5%–26.3%）开发了 Qwen 六步修复管线，把协议合规率拉到 **100%**，同时对单页多模态图文通过 L2/L3 设计卡 5 选 1 耦合合成了 **51,981 张** 13 类均衡版式数据。

### Q02：什么是 Auto Research / Deep Research Agent？它的架构、评测难点与常见失败模式是什么？
- **核心结论**：Auto Research（深度研究智能体）是指围绕复杂开放问题，自主执行**多跳检索规划 → 网页/文档原文精读 → 交叉验证消歧 → 长篇结构化带引用报告合成**的长程 Agent。
- **架构拆解**：通常采用 **Planner–Subagent 分层架构**（与我们的 `AgentV3` 内置 `deep-research` Skill 架构一致）：主 Agent 拆解研究子问题并维护全局证据账本（如 `info_pack.json`），派生多个独立上下文的 `SubtaskAgent` 并行调用 `web_search`、`fetch_url`、文档解析工具抓取原始材料，仅将提炼后的高密度事实摘要与引用锚点回填给主 Agent，防止几十篇网页正文直接塞爆主上下文。
- **常见失败模式与评测难点**：
  1. **早停与浅层搜索**：搜一次摘要就草率动笔，不顺着关键实体做二跳核实；
  2. **引用幻觉与张冠李戴**：正文数字与引用源对不上，或把过时网页当最新事实；
  3. **评测解法（迁移 SlideGate 方法论）**：开放式长报告不能靠单一 LLM 印象分，必须像 **SlideGate**（以及 BrowseComp / Mind2Web 2 / DeepResearch Bench）那样拆成**冻结的实例级必含核查清单（Coverage + L0/L1/L2 论述深度）+ 基于抓取源材料的三值忠实度核验（`supported / derived / unsupported`）**，把“漏掉核心论据”与“编造数字”分开精准量化。

### Q03：通用 Agent 的「任务与可执行环境合成」怎么做？怎么保证合成出来的任务一定可解且可验证？
- **核心结论**：环境与任务合成最大的坑是**“只用 LLM 编了题面，却没有确定性状态转移和配套 Verifier，或者改了题面 Verifier 没跟着改”**。工业级可靠方案是 **State-First / Verifier-First 的闭环构造契约**。
- **机制与你的实战证据（OpenMobile-2 五层契约）**：
  1. **确定性可重置底座**：构建前端 UI 与底层业务 Store 强绑定的可重置环境（如我们复刻的 63 个 App，支持固定模拟时钟、初始种子数据与毫秒级干净 `reset()`），确保界面点击与原生工具调用读写同一份真实状态。
  2. **五层捆绑交付（题面、开局初态、环境能力、工具面、状态判定器不可拆分）**：严禁交付只有自然语言 prompt 的裸题。造题后必须过**四步确定性审计（Meta-Verification）**：
     - **空操作审计（No-op Audit）**：初态与终态相同必须 100% 判败（防初态已满足导致白嫖满分）；
     - **正例夹具验证（Positive Fixture）**：构造目标业务状态必须 100% 判过（防止像早期瑞幸购物车把数量当商品 ID 导致永远无法通过的死题）；
     - **近错变异审计（Mutation Audit）**：自动篡改目标实体、少改一个字段或违反反向不变性断言，必须 100% 拦截（我们在 218 道新题上对 **470 个变异错误终态做到 100% 拒绝、0 假阳性**）；
     - **自我对弈进化方向（SPADE / 逆向状态注入）**：进一步自动化时，先在 Store 上程序化执行受控状态变更或注入缺陷，再反向生成题面与自动派生断言，天然保证 100% 可解且可验。

### Q04：了解 GDPval 这类真实经济价值办公生产力评测基准吗？它的评测链路与传统 Benchmark 有何本质区别？
- **核心结论**：GDPval（OpenAI 提出的面向 GDP 高占比职业真实工作产物的评测）代表了评测从“做选择题/短代码题”向**“端到端真实职业可交付物（Deliverables：多表财务模型、商业演示文稿、法律合同、工程方案）”**的范式转移。
- **核心差异与你的直接对标**：
  1. **输入与产出形态**：不再是单轮纯文本问答，而是给一堆真实的异构原始附件（Excel 大表、PDF 研报、旧模板），耗时几十分钟、调用上百次工具产出一个复杂文件包。
  2. **评判核心是“可交付性（Deliverability）”而非表面流畅度**：职场交付物里，**一处关键数字算错、一页表格严重裁切遮挡、或漏掉客户硬性页数/格式要求，整份产物就是不可交付的废品（Blocking Failure）**。这恰恰是我们 **SlideGate** 论文的核心立意——通过 40 个覆盖 7 类真实办公场景的多附件任务、2,191 条冻结实例专属核查项，把指令硬约束（程序化核验）、源材料忠实度与视觉硬伤拆开诊断，解决了传统整体打分对半数以上阻断性硬伤“视而不见”的顽疾。

### Q05：单容器 Terminal / Coding 通用任务合成（如 SWE-smith / Terminal-Bench 思路）具体怎么构建？
- **核心结论**：单容器 Terminal 任务的核心优势是**单 Docker 容器内拥有完整的 Linux 文件系统、编译器、数据库与测试框架，天然具备零噪声的程序化 Verifier（Exit Code / Pytest / 文件哈希与状态断言）**。
- **四步标准合成流水线**：
  1. **基础环境镜像池构建**：选取真实开源仓库、运维配置环境或数据处理管线打包成带完整依赖的 Docker 镜像；
  2. **逆向故障注入 / 状态转换生成任务（SWE-smith / Bug Injection 范式）**：不靠人工找历史 PR，而是让 Agent 或 AST 变异器在正常跑通全量单测的容器里**主动破坏逻辑、删改配置、污染数据格式或提出新特性规约**，以“能把失败测试重新修绿（Fail-to-Pass）且不破坏原有通过测试（Pass-to-Pass）”作为过滤条件；
  3. **双轨验证脱敏**：容器内挂起私有测试目录（防止被测 Agent 在容器里偷看 `tests/` 作弊——正如 AgentCompass 严格隔离 `gt` 私有目录、只挂载 `inputs/` 公开输入），验证初始状态 `verify()==0` 且参考补丁/脚本执行后 `verify()==1`；
  4. **轨迹复杂度分层过滤**：用基线模型试跑，剔除 1 步 `sed` 就能秒解的水题，保留需要多步日志排查、环境探测与错误自愈的 10–50 步高质量任务。

### Q06：Coding 与 Agent 方向的 Data Scaling 怎么做？开源清洗、合成管线与商业采买数据如何配比？
- **核心结论**：现代 Agent Data Scaling 遵循 **「海量开源清洗打底（广度）→ 可执行环境合成放量（深度与错误恢复）→ 少量高精人工/商业采买锚定长尾专业域与评测集（上限）」** 的金字塔结构。
- **分层策略与你的 LingCoder + 小浣熊实战经验**：
  1. **底层广度（百万级，开源清洗 + 标签重配比）**：如我在 **LingCoder** 处理 285 万条多语言代码数据时，按 `Context Tag × Task Type` 二维标签体系精准盘点分布（发现算法题占 73% 而工程实现与 C++/Rust 偏少），用 AST 解析分离出第三方库短板并用 DeepSeek-V3 定向蒸馏补齐；
  2. **中层主力（万～十万级，可执行沙盒/环境多轮合成）**：普通静态问答再多也训不出长程 Agent。必须在真实容器/沙盒（如 Box-Agent ACP 容器、MobileGym++ 63 应用）里合成带工具反馈、文件状态读写与 **Policy-Switching 错误恢复**的多轮轨迹，并做严格的协议合规清洗（如我们 1.6 万条 SFT 清洗管线）；
  3. **顶层稀缺域（千级，商业采买 / 专家精标）**：什么时候必须采买或专家介入？一是**真实复杂私有工作流与多模态设计审美先验**（如我们 PPT 标准模式引入 300 条专家精拆 L3 设计卡撬动 3.3 万张合成图），二是**多步骤复杂办公软件操作（如跨 Excel/WPS/专业工业软件）及零污染测试基准**。采买数据绝不能直接盲训，必须先做可执行回放审计剔除偷懒轨迹。

### Q07：长程任务（Long-Horizon Agent，几十到上百步）核心死穴是什么？从架构和训练两侧怎么系统提升？
- **核心结论**：如 OSWorld 2.0 所示（Opus 平均调 318 次工具，500 步上限下完成率仅 20.6%），长程 Agent 的四大死穴是：**① 复合误差指数级累积（$p^T$ 衰减）**、**② 上下文膨胀导致注意力稀释与遗忘初始硬约束**、**③ 局部死循环与状态漂移**、**④ 训练端终态 0/1 奖励极度稀疏导致信用分配失效**。
- **架构侧（Harness Engineering）四板斧**：
  1. **分层委派与上下文隔离**：像 `AgentV3` 一样用 `MainAgent + SubtaskAgent` 切分阶段，子任务内部几十轮试错留在局部上下文，只把 `<subtask_result>` 结构化结论原位回填主线；
  2. **中间产物显式落盘（File-as-Memory）**：把关键约束和阶段结论固化成 `task_pack.json`、`outline.json`、`todolist` 顶层状态，压缩历史消息时绝不丢失硬约束；
  3. **被动摘要卸载 + 观测滑窗**：工具大输出落盘留句柄，GUI 场景只保留最近 3 帧原图 + 历史动作文本摘要；
  4. **循环检测与错误原样写回**：对连续同名高相似参数调用（`RR` 监控）主动阻断提示换路，工具异常结构化写回供模型自愈（如 `prod_26016eba` 路径纠错）。
- **训练侧三板斧**：
  1. **注入错误恢复轨迹（Policy-Switching / OPD）**：通过弱探索+强接管和在策略蒸馏（OPD），专门训练模型“走偏后怎么退回正轨”；
  2. **状态里程碑密集归因（State-Milestone Credit Assignment）**：利用环境 Store Diff 将终态验证拆解为子目标锚点奖励，解决第 25 步错导致前 24 步全归零的问题；
  3. **DAPO / GSPO 稳定长序列更新**：用 Token-level Loss 防长序列梯度稀释，用序列级重要性比（GSPO）防长链比率方差爆炸。

### Q08：当前大模型 Agent 后训练（Post-Training）的标准范式演进是什么？各阶段分别赋予模型什么能力？
- **核心结论**：工业界（以 DeepSeek、Qwen3、SenseNova Flash 系列为代表）已收敛为 **五段式协同流水线**：
  1. **Agentic Mid-Training / Continue Pretrain**：高比例混入代码库 PR、终端交互日志、工具文档与长上下文语料，建立底层代码、结构化 Schema 与长程状态表征能力；
  2. **冷启动高质量轨迹 SFT（Cold-Start SFT）**：用万级高纯度规范轨迹（含 `<think>` 推理链、结构化 Tool Call 与协议约束）教会模型**格式规矩、工具语法与基础 SOP 拆解**，让模型具备非零的采样命中率；
  3. **在策略蒸馏（OPD, On-Policy Distillation）**：由学生模型自己 rollout 采样前缀，教师模型在学生真实到达的状态上提供逐 token 分布监督（Reverse KL），低成本消除离线 SFT 的**暴露偏差（Exposure Bias）**；
  4. **离线/半在线偏好对齐（全轨迹 DPO / KTO）**：针对线上或批测归因抓出的典型坏毛病（如 DSML 文本伪调用、未出产物虚假交卷 `done_no_html`）构造同题正负轨迹对定向压制；
  5. **可验证环境多轮强化学习（Agentic RLVR：GRPO / DAPO / GSPO）**：在 Docker 代码沙盒或可重置 GUI/MCP 环境（如 MobileGym++）中靠确定性 Verifier 自主探索新路径、优化步数效率与跨工具泛化上限。

### Q09：【高频杀手题】如果外部闭源强模型 API 蒸馏被封禁（或协议禁止蒸馏），你们怎么继续迭代提升自家模型？
- **核心结论**：蒸馏只能追平教师的下限，被封禁后核心出路是从“模仿外部教师输出”转向 **「可验证环境驱动的自举进化（Verifier-Driven Self-Improvement + Self-Play + Online RL）」**——这也是为什么全行业都在重兵投入可执行环境与 Verifier 基建。
- **四步完整破局方案（结合你的项目基建）**：
  1. **用“廉价验证”替代“昂贵生成”（Generator–Verifier Gap -> RFT / Best-of-N）**：验证一道题做没做对比从头生成容易得多。依托我们建好的 **MobileGym++ Store Verifier**、**代码容器单测**或 **SlideGate 冻结原子核查器**，让自家当前最强模型以高温度采样 $G=16\sim 64$ 条轨迹（Test-Time Compute），用确定性 Verifier 筛出真正做对且高效率（高 OE、低 RR）的轨迹做拒绝采样微调（RFT）与自举 DPO（同模型成功最短轨迹 vs 失败轨迹）；
  2. **在线强化学习（DAPO / GRPO）自主探索**：只要有可重置环境和 0 假阳性的 Verifier（如我们的 2,475 道 RL 题），模型无需任何外部教师即可通过组内相对奖励自主涌现错误恢复与更优工具组合；
  3. **多专才自蒸馏与 Context Distillation（自己教自己）**：给自家模型挂载超详细的 `SKILL.md` 规范、完整参考样例和多次重试机会（System-2 慢思考重装备态）跑出成功结果，再剥离掉冗长提示词蒸馏回零样本轻量态（内化 Skill），或用自家代码专才、视觉专才交叉合成训练全能底座；
  4. **逆向环境自博弈出题（Self-Play Environment Synthesis）**：在可控环境状态树上程序化变更初始/目标状态自动扩增新题，打破静态题库枯竭瓶颈。

### Q10：在真实 Agent 业务中，强化学习（RL）相比 SFT 到底带来了什么实际收益？什么时候 RL 没收益甚至倒退？
- **核心结论**：
  - **RL 的三大真实收益**：① **动态错误自愈与重规划**（SFT 只在专家分布内拟合，RL 在自己踩坑的真实分布上试错，学会工具报错、路径不通时换方案）；② **多路径决策与工具选择优化**（同一目标有多条等价路径时，学会挑更快更稳的路径，压缩冗余步数）；③ **压制“看似合理实则未生效”的幻觉交卷**（靠终态 Verifier 硬惩罚）。
  - **RL 没收益甚至倒退的四大反例（实战踩坑总结）**：
    1. **Verifier 有漏洞或噪声大**：如奖励过松被模型刷分（Reward Hacking），或把环境超时崩溃记为 0 分污染梯度，模型越训越怪；
    2. **基座在长链路题上采样全军覆没（`pass@G = 0`）**：如我们在 OpenMobile-2 早期直接拿跨 App 超长题跑稀疏 0/1 RL 未涨点，因为第 20 步错一点就全 0，组内全 0 梯度恒为 0，必须配动态难度采样或中间状态里程碑拆解；
    3. **未修好训推不一致（尤其是 MoE 基座）**：rollout 引擎与训练引擎 logprob 偏离过大导致重要性采样比爆炸，训练直接崩溃；
    4. **私有新工具/新协议尚未经 SFT 冷启动**：模型连合法 JSON 工具调用都发不出，直接上 RL 只在无效乱码空间空转。

### Q11：【高频深挖题】RL 训练后如果 `pass@k`（如 `pass@16`）没涨甚至下降，收敛到了 `pass@1`，背后机理是什么？怎么继续提升上限？
- **核心结论**：这是 2025–2026 Reasoning / Agentic RL 领域的核心发现（“RL 究竟是在激发新能力，还是在做分布锐化 Distribution Sharpening？”）。当 `pass@1` 大幅上升而大 $k$ 的 `pass@k` 持平或下降并向 `pass@1` 收敛时，说明 **RL 把概率质量高度集中到了预训练/SFT 基座原本就能低概率采样出的那一条高回报模式上，伴随着策略熵坍缩（Entropy Collapse），模型失去了探索多样化解法的能力**。
- **突破 `pass@k` 天花板的五大实战手段**：
  1. **先扩充基座先验边界（Mid-training / 跨功能合成 SFT / 错误恢复注入）**：如果基座 `pass@128 = 0`（完全缺失某类工具组合知识），纯靠 0/1 RL 很难凭空捏造；需用 OpenMobile 式的跨功能记忆合成或带提示的合成轨迹把新原子技能注入分布内；
  2. **保熵训练机制（DAPO Clip-Higher + 熵正则 / 适度高温 Rollout）**：对称 PPO Clip（$\epsilon=0.2$）会死死卡住原本概率只有 $0.01$ 的关键转折/探索 token（上限只能涨到 $0.012$），而高概率套路 token 却能从 $0.5$ 涨到 $0.6$，加速模式坍缩。调大上界（如 $\epsilon_{\text{high}}=0.28$）或采用 **CISPO**（裁权重不丢梯度）能保护稀有有效路径不被饿死；
  3. **课程学习与遗憾度自适应出题（Curriculum / Regret-based Sampling）**：动态过滤掉已经 `pass@1 > 0.9` 的简单题（它们只会继续压缩熵），把算力集中在命中率 $0.1 \sim 0.5$ 的前沿边界题上；
  4. **过程/状态里程碑引导（Milestone Credit Assignment）**：对大 $k$ 也采不到完整终态的长程题，给子目标状态达成赋予稠密信号，把指数级搜索空间拆成多项式级分段攻克；
  5. **训练目标直接纳入多样性或 `pass@k` 无偏梯度估计**：鼓励组内不同轨迹通过不同工具路径达成同一终态。

### Q12：Cowork（人机协同 / 前后台双 Agent 共创）方向相比全自主 Agent 还有哪些关键提升点？
- **核心结论**：真实商业场景（如阿里 Accio 外贸商家接待、复杂演示文稿定制）绝不是“丢一句话让 Agent 闭眼狂奔半小时”，因为**需求天然欠指定（Underspecified）、商业动作有不可逆风险（乱发底价/乱改合同）、且长任务跨小时/跨天异步进行**。
- **五大核心技术提升点**：
  1. **精准的主动提问时机决策（Uncertainty-Aware `ask_user`）**：既不能每步都烦商家，也不能在缺失底价/运费政策/目标受众时瞎编。需训练模型识别“高业务风险或高信息增益缺口”时才挂起共创（对应我们 `AgentV3` 在 `task_pack` 缺关键槽位与 `outline` 定稿节点触发 `waiting_user_input`）；
  2. **前后台双 Agent 异步解耦与状态一致性**：前台 Agent 负责秒级响应商家、更新接待策略与审核升级单；后台 Agent 按商家 Skills 异步跟进多渠道买家。关键在于商家在前台临时改了库存/报价策略时，正在挂起或运行中的后台会话必须做**状态冲突检测与上下文热更新**；
  3. **从人工接管与修改Diff中在线沉淀商家专属 Skill（Learning from Edits）**：商家每次手动改掉 Agent 草拟的报价话术，都是极高价值的隐式负反馈——不能只改这一单，而要自动归因抽取出该商家的偏好规则更新进专属 `SKILL.md` 或 `memory.md`；
  4. **操作风险分级与影子预演（Dry-run / Approval Gate）**：只读查库存免批自跑，对外承诺交期/发优惠券生成可预览草稿卡经一键审批后再落地；
  5. **跨天会话挂起恢复（Stateful Checkpointing）**：买家三天后回复时，通过事件日志精准重建当时谈判上下文与待办槽位。

### Q15：没有唯一标准答案的开放式 Agent 任务（如写报告、做 PPT、外贸沟通），怎么设计可靠的自动化评测与奖励信号？
- **核心结论**：开放式任务不能做参考答案 BLEU/ROUGE 匹配（Reference-based），也不能直接让大模型打一个笼统的 1–10 整体印象分（Holistic Score，存在严重长度偏置且掩盖硬伤），标准解法是 **「分层解耦：确定性程序化硬门禁 + 实例级冻结原子 Rubric 逐条验证 + 源材料锚定忠实度」**。
- **三层落地法则（直接复用 SlideGate 验证过的范式）**：
  1. **能写代码判的绝不交模型（Programmatic Ground Truth First）**：格式、字数/页数、语言、必填 JSON 字段、禁发违禁词、链接可访问性，一律用确定性规则做硬门禁（0 噪声，防模型算术出错）；
  2. **主观需求拆解为实例级二元/三元原子 Checklist 并冻结**：从用户原始请求和上下文里经多次独立提取+归并生成任务专属的 Must-Cover 要点与约束清单（判断“有没有提到退换货账期”比判断“这封外贸信写得好不好”一致率高得多，双盲一致率超 80%）；
  3. **事实依据做三值忠实度核查（防幻觉胡编）**：把 Agent 输出中的具体承诺/数字拆成原子陈述，逐一回查商家知识库或输入附件，判为 `supported / derived / unsupported`，一旦出现无依据乱报底价或捏造数据直接触发一票否决（Blocking Failure），作为 DPO 负样本或 RL 负向惩罚。

### Q16：如何提升 Agent 在「未见过的新工具 / 新跨应用组合（Unseen Composition）」上的泛化能力？
- **核心结论**：Agent 在新工具/新组合上掉点，往往是因为 SFT 阶段死记硬背了特定工具名和固定调用顺序（Overfitting to Surface Schema）。
- **四项泛化增强策略**：
  1. **数据层：跨功能远端检索组合合成 + Schema 随机扰动增广**：像 OpenMobile 的长期环境记忆那样刻意把语义相关但平时不挨着的功能拼成复合任务；训练时对工具名、参数键名、候选工具排列顺序做同义改写与无关干扰工具注入（Distractor Tools），逼模型读实时 Schema 描述而非背函数名；
  2. **推理层：显式先读文档/探测再调用（Read-Before-Act）**：像 `AgentV3` 先查目录再 `read_file(SKILL.md)`，或面对陌生 CLI 先跑 `--help` 看真实返回再构造参数；
  3. **错误自愈能力内化**：新工具第一次调错参数很正常，关键是通过 Policy-Switching 与在线 RL 让模型学会**根据 `tool_result` 里的 Schema/类型报错精准修正参数重试**，而不是原地重复或放弃；
  4. **训练层避免过重 SFT**：控制 SFT 轮数防止模式僵化，尽早切入多样化环境下的 OPD / GRPO 在线交互训练。

### Q17：如果给你一批完全没有标准答案和奖励标签的线上回流日志（如外贸对话/办公操作），怎么挖掘出 SFT 和 RL 信号？
- **核心结论**：线上无标回流日志是金矿，核心是利用 **「后验用户行为信号 + 多路一致性自校验 + 规则/Rubric 合成裁判」** 把无标日志转化为分级训练信号。
- **四步实战挖掘流水线**：
  1. **脱敏、分流与环境污染清洗**：先剔除网关超时、沙盒断连等基础设施异常日志（正如我们处理 1–6 月回流 query 时先做输入形态分布分桶与无效会话剥离）；
  2. **挖掘天然隐式人类反馈（Implicit Feedback -> DPO / KTO）**：
     - 在外贸/办公场景中，用户**直接采纳发送 / 下载导出且未追骂重做** = 正向信号；
     - 用户**手动编辑修改了 Agent 草稿** = 天然的黃金偏好对 `(prompt, y_w = 商家修改后版本, y_l = Agent 原草稿)`，可直接训 DPO！
     - 用户连续追问纠正“我说的是 FOB 不是 CIF” = 多轮纠偏轨迹，可压缩中间弯路提取单步一步到位示范，或保留纠偏过程训自愈；
  3. **实例级 Rubric + 强模型 Ensemble 构造合成奖励（RLAIF / RLRF）**：对真实用户 query 自动提取实例专属核查清单（Checklist），采样多条候选回复，用程序化格式/事实门禁 + 细粒度 Rubric 打分构造组内相对奖励跑 GRPO；
  4. **单边好坏信号直接跑 KTO**：对于只有零散点赞/点踩、凑不成同 prompt 成对样本的线上日志，直接使用 KTO（无需成对偏好）消化全量反馈。

### Q18：Agent 场景下训练模型参数量（如 7B/9B vs 30B MoE vs 284B）怎么选型？端云协同或大小模型路由怎么做？
- **核心结论**：没有一个尺寸通吃所有环节，选型取决于 **「任务规划复杂度 × 工具候选集规模 × 单步延迟/成本预算 × 部署端侧限制」**。
- **结合你亲测数据的梯度选型法则**：
  1. **端侧 / 高频确定性子模块（7B–9B Dense，如 `Qwen3-VL-8B` / `Qwen3.5-9B`）**：单卡可跑、首字延迟百毫秒级。经过高质量合成轨迹训练后，在纯 GUI 单应用导航（AndroidWorld 64.7%）或专项清洗改写（如我们用 Qwen 跑 1.6 万条轨迹摘要修复）上性价比极高；**能力边界**：在 300+ 工具的复杂混合空间（Bench 215 Hybrid）容易发生模态路由失调，不适合直接扛超长程开放总控；
  2. **主力生产甜点档（30B-A3B 等中小激活 MoE，如 `Qwen3-30B-A3B` / `Flash-Lite`）**：总参 30B 保证知识与多语言代码容量，每 token 仅激活 3B 参数，推理吞吐接近小稠密模型，非常适合高频在线外贸后台接待、RAG 重排生成与常规多轮工具调用；
  3. **复杂长程总控与教师底座（200B+ 大 MoE + FP8 + MTP，如 `SenseNova-Flash-284B` / `Opus`）**：负责主 Agent 全局拆解、疑难故障自愈、跨十几个子阶段复杂编排（无模板 PPT 评分达 0.809）以及离线合成蒸馏数据；
  4. **大小模型协同架构**：主规划器（Planner）与异常接管用大 MoE，常规局部执行子任务（Subtask / Grounding 点击定位 / 记忆摘要提取）路由给 8B–30A3 轻量专才模型，实现完成率与单商机 Token 成本的帕累托最优。
