## 一、为什么传统 LLM-as-a-Judge 评测复杂 Agent 产物会集体失灵？（论文核心 Motivation）

在六个主流商业 PPT Agent（AnyGen、Kimi、Doubao、Skywork、MiniMax、Manus）生成的 **240 份**完整演示文稿上，我们复现了社区六个代表性评测框架（SlideAudit、LecEval、PPTBench、PPTEval、AutoPresent、PresentBench）：
- **惊人反差**：这六个现有框架打出的平均分全部扎堆在高分区（SlideAudit 均分 **>0.97**，LecEval **>0.90**，PPTBench **>0.81**）；然而人工与细粒度核查发现，240 份文稿中竟然有 **124 份（51.7%）包含至少一处直接阻断实际交付的严重硬伤（Blocking Failure）**！
  - 典型案例 1（指令硬违例被高分掩盖）：某学术演讲明确要求严格限定页数，系统实际严重超页，SlideAudit 仍打出 **0.993**、PPTBench **0.851**、LecEval **0.873**。
  - 典型案例 2（张冠李戴的源材料幻觉）：某培训课件明确要求依据附件“第二课教案”制作，系统却完全照抄“第一课内容”生成——不绑定可解析源材料的评测器看画面精美、逻辑通顺，直接给出高分。
- **统计学铁证**：做 Mann–Whitney $U$ 检验对比“含阻断失败组（124 份）”与“无阻断失败组（116 份）”，**6 个既有框架中有 5 个在两组之间无显著得分差异**；唯一有显著差异的 PPTBench-style 评分，在留一任务交叉验证中若想召回 90% 的失败文稿，误报率（FPR）高达 **78.0%**！

## 二、SlideGate 方法论架构（三维可交付性 + 2,191 条冻结实例级核查项）

### 1. 任务集构成（40 个多模态真实任务 × 6 个系统 = 240 份文稿）
覆盖 **7 大真实场景**（培训教学 8、数据分析 8、学术演讲 6、商业提案 5、项目规划 5、工作汇报 5、述职竞聘 3）与 **5 类输入形态**（文档与要求 17、详细要求 6、简短需求 6、已有文稿与编辑指令 6、模板与资料 5）。

### 2. 第一阶段：多轮独立生成 + 批评归并冻结任务专属 Checklist
- 为消除单次 LLM 提取核查项的随机遗漏，对每道任务的用户请求与**可解析源材料**（文档/表格全文解析）**独立生成 3 份候选核查清单**，再经 Critic 模型审查、去重、归并后**全局冻结**（40 题共冻结 **2,191 条**原子约束，场均约 **55 条**）。
- **公平基线原则**：同一道任务在评测所有系统时严格复用同一套冻结清单，杜绝“边看被测产物边动态生题”带来的裁判漂移与尺度不一。

### 3. 第二与第三阶段：三维解耦评测协议（默认分维报告 + 阻断失败置顶，拒绝单一加权总分掩盖缺陷）

| 维度 | 评什么（子标准） | 核心计算公式与判定机制 | 验证对齐指标 |
|---|---|---|---|
| **① 指令遵循**<br>(Instruction Following) | 页数/宽高比、语言、版式结构、明示必备项、模板保持、增页改写（6 类） | **程序化客观参照优先**（页数、比例、语种直接由代码精确计算，覆盖模型判断）；硬约束满足率：<br>$\text{HCR} = \frac{\text{Pass} + 0.5 \times \text{Partial}}{N^{\text{instr}}_{\text{judged}}}$（剔除 N/A）；任一关键违例触发 **指令硬失败** 置顶 | 程序化客观真值 100% 精确锚定；指令遵循新增维度重测稳定性 **97.8%**，受控扰动检出率 **100%** |
| **② 内容质量**<br>(Content Quality) | 必要项覆盖率 $C$、三层论述深度 $S_{\text{checklist}}$（**L0 存在性 / L1 具体性 / L2 场景适切性**）、有源任务**三值忠实度** $S_{\text{fid}}$（`supported / derived / unsupported`） | 无源材料：$S_{\text{content}} = 0.70 S_{\text{checklist}} + 0.30 C$<br>有源材料：$S_{\text{content}} = 0.60(0.70 S_{\text{checklist}} + 0.30 C) + 0.40 S_{\text{fid}}$<br>必含内容项判为 `missing` 直接记入阻断失败 | 与两名独立双盲标注者一致率达 **80.7%** 与 **85.6%** |
| **③ 视觉呈现**<br>(Visual Presentation) | 逐页 4 类阻断性硬伤 $H$（越界裁切、元素遮挡重叠、排版崩坏、严重残缺）+ 6 项细粒度设计 $S_{\text{fine}}$ + 3 项整体美学与跨页一致性 $G$ | **逐页统计硬伤发生页数**而非用美观均分稀释硬伤；单页与整套视觉分并行输出 | 系统级排名与 3 名专业设计师匿名 Pairwise 偏好排名相关性达 **Spearman $\rho = 0.855$** |

- **权重敏感性消融结论（为什么论文默认分维报告）**：在 66 组不同跨维权重组合下，6 个商业系统出现了 **22 种不同排名**——证明单一线性加权总分没有唯一客观最优解，工业交付必须先过“零阻断硬伤门禁”，再看分维细项。

## 三、工业评测管线实战（94 题双模式看板 + 四层失败归因 + 两大排障经典战例）

在商汤内部日常迭代线（`industry_v2` 47 道题 × 无模板/模板双模式 = **94 题**，总分参考公式 $0.30 \times \text{page} + 0.35 \times \text{deck} + 0.35 \times \text{content}$）上，建立了铁律：**每次交付必须同时报「生成成功数、评分覆盖数 $n$、三维质量分」三个数，绝不允许只报高分隐瞒残缺分母！**

### 1. 四层失败归因体系（出异常绝不盲目甩锅模型侧）
1. **模型 / Checkpoint 层**：如输出字面量 `<｜DSML｜tool_calls>` 伪调用文本、JSON 引号转义反复写错自救死循环、未调生成脚本就空口汇报完成（`done_no_html`）。
2. **Serving / 模型网关与 Tool Parser 层**：如数组形式 `content` 返回 HTTP 500、`tool_choice=none` 返回 400、网关流式解析工具块截断残留 `</invoke>`、展示名与 `/v1/models` 登记 ID 错位。
3. **Agent / Skill 管线层**：如批测自动确认选了与题目要求冲突的模板模式（评测侧污染）、`subtask_counter` 覆盖丢失子任务、路径前缀协议不一致。
4. **沙盒 / 基础设施层**：如客户端 `/tmp` 句柄耗尽 `Too many open files`、网络隧道中途切换掐断长连接导致 `infra_failed`、评分平台全局锁阻塞。

### 2. 经典排障战例 A：侦破「内容分静默虚高 → 假 DPO 退化」乌龙（必讲故事！）
- **起因**：`Flash-Lite step3k DPO` 模板模式看板总分 **64.6**，比无 DPO 基线 `flash3k_tpl`（**68.7**）低了 4.1 分，团队一度怀疑 DPO 把模型训退化了。
- **排查链条**：下钻对比两批逐题打分明细，发现无 DPO 老批有 **42.2%（19/45 题）** 的 `content_eval_dynamic_items == 0`，而新测的 DPO 批次该比例为 **0%**！回查 `content_evaluator.py` 源码定位出静默降级 Bug：老批走旧 Gemini 判分网关时偶发返回空串 `{"content": "", "error": "无候选回复"}`，底层 `call()` 吞掉 `error` 返回空串，`_extract_json("")` 返回 `{}`，`dynamic_checklist` 变成空列表 `[]` 且全程不触发异常；评测器遂只评 6 条极易通过的通用核心项，导致老批 6 个模型 **30%–49% 的样本内容分被系统性虚高**！此外在 `q1495`（2.2 万字考勤大表 + 21 页图）上还抓出裁判模型逐人演算 2.5 万字“话痨失控”不吐 `{` JSON 的边界失效。
- **修复与翻转**：封装 `_call_json_with_retry()`（5 次快速重试仍空或缺字段直接 `raise RuntimeError` 阻断，绝不静默降级）+ 三值忠实度 Prompt 强制首字符为 `{`，并用稳定的 TokenHub Claude Sonnet 4.6 全量重判 6 个历史模型（269 题）。干净同尺对比下，无 DPO 与 DPO 实为 **0.6635 vs 0.6526**（差距仅 -0.011，纯属统计噪声），彻底推翻“DPO 退化”假结论。

### 3. 经典排障战例 B：`SenseNova Flash 284B v16 step400 DPO-v2` 模板模式 25.5% 无产物深度归因
- 47 题中 12 题 `html_pages = 0`（11 个 `render_suspect` + 1 个 `done_no_html`），失败题白白消耗 **7.32 小时**（单题最长 `seq_1157` 达 150.8 分钟）。
- 逐条拆解 `main.json` 证明**全死在页面生成前的编排与协议层**：① 2 题直接把内部 `<｜DSML｜invoke>` 当普通文本吐出导致循环早停；② 6 题把普通绝对路径传给强制要求 `local://` 前缀的工具或找错 `preflight.py` 目录；③ 5 题在写 `info_pack.json` / `outline.json` 时陷入引号转义 `JSONDecodeError` → 写补丁脚本修 → 触发新 `SyntaxError/KeyError` 的自救死循环。这一归因直接指导了下一轮 SFT 清洗 DSML 残留、强化 `local://` 路径示范与全轨迹 DPO 负样本构造。
